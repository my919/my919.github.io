6. 典型案例：电商首页首屏性能优化

问题背景：电商首页 LCP 4.2s（目标 < 2.5s）：JS bundle 1.8MB 阻塞渲染、hero 大图无压缩无预加载、关键接口串行请求、字体 FOIT。实验室 Lighthouse 分数尚可，但真实用户 p75 指标惨淡。

方案：按「关键渲染路径」逐项拆解，每项措施对准一个 Core Web Vitals：

措施 对准指标 手段
JS 代码分割 + 按需加载 FCP / TBT 路由级 import() + manualChunks
hero 图优化 LCP AVIF + preload + fetchpriority=high
字体 swap CLS / FCP font-display: swap + preload
接口并行 / SSR LCP Promise.all / 流式渲染
真实用户度量 全部 web-vitals 上报，看 p75

踩坑点：

  • 只看 Lighthouse 实验室分：实验室环境固定网络/CPU，与真实用户相去甚远——优化必须以 RUM p75 为准。
  • preload 了非关键资源（如底部轮播图）：抢占 hero 图带宽，LCP 反而恶化。preload 只给 LCP 资源。
  • 图片压缩了但没写尺寸：加载后布局跳动，CLS 爆炸。所有媒体必须有 width/height 或 aspect-ratio。
  • 分割后公共库被多入口重复引用：检查 bundle 分析图，用 manualChunks 归拢。

7. 常见误用与陷阱

坑 现象/后果 解法
img 不写尺寸 图片加载后布局跳动，CLS 劣化 width/height 或 CSS aspect-ratio
CSS 用 @import 引入 关键 CSS 串行瀑布，渲染被阻塞 <link> 并行 + 内联关键 CSS
同步加载第三方脚本 统计/客服脚本阻塞主线程，INP 崩 defer / 懒注入 / Web Worker
所有图片都懒加载 首屏 LCP 图也被延迟 首图 eager + fetchpriority=high，其余 lazy
字体无 font-display 文字空白数百毫秒（FOIT） font-display: swap
只优化实验室数据 Lighthouse 95 分，真实用户依旧卡 web-vitals RUM 上报，按 p75 决策
未压缩响应体 传输体积翻数倍 Brotli/gzip + 长缓存 hash 文件名
