第一章：Docker 部署 Redis 实践

概念基础

  1. 镜像即环境：官方 redis 镜像内置匹配版本的 redis-server / redis-cli，一条命令即可获得与生产一致的运行时，避免「本机装不上 / 版本不对」。
  2. 数据目录即卷：容器内数据目录为 /data（AOF / RDB 文件所在），挂载卷后数据独立于容器生命周期，docker rm 不丢数据。
  3. 配置即参数：容器化部署一般不挂 redis.conf，而是通过 redis-server 启动参数（如 --appendonly yes、--requirepass）声明配置，便于在 Compose / K8s 中版本化。
  4. 边界要清楚：本章的单实例部署面向开发 / 小型自托管场景；主从、哨兵、集群等高可用形态应使用 StatefulSet / Operator / Helm Chart，不要把单实例 Deployment 直接水平扩展当集群用。

带着这四点，依次看三种部署形态（单容器 → Compose → K8s），再补充持久化、内存策略、主从哨兵与监控四个生产必配项。

前置条件

本机已安装 docker，并能使用 docker compose（Compose V2 插件，命令为 docker compose；若仍使用旧版独立程序，则将下文中的 docker compose 换成 docker-compose）。

Redis 镜像选择

1. 官方镜像（推荐）

  • 仓库：redis（Docker Hub 官方库：https://hub.docker.com/_/redis/tags）。
  • 常用标签：
    • redis:8.2：8.x 线，当前主流（Redis 8 起许可证回归 RSALv2 / SSPLv1 / AGPLv3 三重授权，生态与客户端兼容面广）。
    • redis:7.2：旧稳定线，仍在维护；redis:latest 跟踪最新（以 Hub 标签为准）。
  • 生产建议：固定小版本标签（如 redis:8.2.x）或记录 digest，避免 latest 漂移导致行为变化。

2. 变体说明

需求 说明
持久化 开发常用 --appendonly yes（AOF）；也可配合 RDB 快照参数，按数据重要性选择。
访问控制 通过 redis-server --requirepass <密码> 或 ACL 配置；未设置密码时任何人可读写，仅用于隔离网络内的临时环境。
ARM64（Apple Silicon 等） 官方 redis 多架构镜像一般可直接拉取；若某标签缺架构，换标签或查 Hub OS/ARCH。
极简/定制 社区有 bitnami/redis 等，环境变量名与默认配置与官方不同，切换镜像时需对照该镜像文档。

3. 数据目录

默认数据目录 /data（AOF / RDB 文件所在）；挂载卷后便于备份与 docker compose down -v 时区分是否保留数据。

持久化：AOF / RDB 配置与挂载

容器里持久化的两个决策：开哪种、文件放哪。

1. 三种策略速选

策略 数据安全 性能 适用
只 RDB（默认快照） 丢最近一个快照周期 最好 纯缓存，可重建
只 AOF（everysec） 最多丢 1 秒 略降 会话、计数等准关键数据
RDB + AOF 重启优先用 AOF 折中 生产推荐

2. 启动参数版（开发）

  • --appendfsync everysec：每秒刷盘，安全与性能的平衡点（always 最安全但最慢，no 交给 OS）。
  • --save "秒 变更数"：满足条件即触发 RDB 快照；多条并存。
  • 落盘文件：dump.rdb 与 appendonlydir/（Redis 7+ 的 AOF 是目录，含 manifest + 增量文件），都在 /data 卷内。

内存策略：maxmemory 与淘汰

容器内存不是无限的，必须显式设上限，否则宿主机 OOM 时 Redis 首当其冲：

配置 说明
maxmemory 512mb 使用上限；不设则默认吃到宿主机内存耗尽
maxmemory-policy allkeys-lru 到上限后淘汰最近最少使用的 key（缓存场景推荐）
volatile-lru 只在设了 TTL 的 key 里淘汰；无 TTL 的 key 永不淘汰，写会报错
noeviction 到上限后拒绝写入（默认）；适合把 Redis 当存储而非缓存
allkeys-lfu / volatile-ttl 按访问频率 / 按剩余 TTL 淘汰，特定场景用

以上配置用启动参数 --maxmemory 512mb --maxmemory-policy allkeys-lru 或写进 redis.conf 均可。容器侧再配合 --memory 768m（大于 maxmemory，留 fork 与缓冲余量），双层护栏。

本章小结

项 说明
前置 已安装 docker 与 docker compose（或 docker-compose）
镜像 优先官方 redis:8.2 / redis:7.2 固定补丁标签；--requirepass 与 ACL 按安全要求配置
单容器 mkdir（可选）后一条 docker run ... redis-server ...
Compose 保存 docker-compose.redis.yml 后 docker compose -f ... up -d
持久化 生产 RDB+AOF 双开、everysec，配置挂 redis.conf，数据挂 /data 卷
内存 必设 maxmemory + maxmemory-policy（缓存用 allkeys-lru）
高可用 学习用主从+哨兵 Compose；生产用 Operator / Helm
监控 redis-exporter 接 Prometheus，盯内存/命中率/淘汰量
Kubernetes 保存 redis-k8s.yaml 后 kubectl apply -f ...

生产环境请启用 TLS、ACL、持久化策略与监控；Secret 建议对接 External Secrets / Sealed Secrets 等管控流程。
