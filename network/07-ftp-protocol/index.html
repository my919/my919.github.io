第七章：FTP 详解：双连接模型、主动/被动与 lftp 示例

发表于 2026-05-01 更新于 2026-10-25 分类于 计算机网络 本文字数： 3.6k 阅读时长 ≈ 3 分钟

第七章：FTP 详解：双连接模型、主动/被动与 lftp 示例

概念基础

  1. 历史最悠久的文件传输协议之一：在 TCP/IP 早期就提供跨异构系统的列目录、上传、下载与断点续传（由扩展命令支持程度决定），命令为可读文本（如 RETR、STOR、LIST），便于人机调试。
  2. 双连接模型是最大特点：TCP 21 的控制连接（命令/响应，全程保持）+ 每次传送动态建立的数据连接（文件内容 / LIST 输出）——与「单连接一用到底」的协议截然不同。
  3. 主动 PORT vs 被动 PASV：主动=服务端从 20 端口反向连出（客户端在 NAT 后时常失败）；被动=客户端连入服务端通告的端口（主流，防火墙须放行被动端口范围）。
  4. 明文是硬伤：用户名、密码与数据默认明文；FTPES 在 TLS 上加密但仍保留双连接复杂性——公网新系统优先 第八章：SFTP 详解：SSH 子系统、协议栈与 sftp 示例 或对象存储 HTTPS 上传。

先看它为什么这样设计：

设计动机（历史作用）

在 TCP/IP 早期提供跨异构系统的文件列目录、上传、下载与断点续传（由扩展命令支持程度决定）；命令为可读文本（如 RETR、STOR、LIST），便于人机调试。

双连接模型（原理）

控制连接全程保持；每条数据传送动态建立数据连接。

一次被动模式下载的时序：



sequenceDiagram
  participant C as Client
  participant S as Server
  C->>S: TCP 21 建立控制连接
  S-->>C: 220 欢迎语
  C->>S: USER / PASS
  S-->>C: 230 登录成功
  C->>S: PASV
  S-->>C: 227 Entering Passive Mode (h1,h2,h3,h4,p1,p2)
  C->>S: 数据连接 → (IP=h1..h4, Port=p1*256+p2)
  C->>S: RETR file.bin（控制连接）
  S-->>C: 150 开始传输（数据连接上发文件）
  S-->>C: 226 传输完成（控制连接）

常用命令与响应码

常见命令（控制连接上的可读文本）：

命令 作用
USER / PASS 登录用户名 / 密码
LIST / NLST 列目录（详细 / 仅文件名，走数据连接）
RETR / STOR 下载 / 上传文件
CWD / PWD 切换 / 打印当前目录
PASV / EPSV 进入被动模式（EPSV 支持 IPv6）
PORT / EPRT 主动模式通告客户端地址
REST 断点续传的起始偏移
TYPE I / A 二进制 / 文本传输模式
QUIT 关闭控制连接

响应码分组（首位数字定语义）：

首位 含义 例子
1xx 初步肯定，等后续 150 即将开始传输
2xx 成功 220 欢迎、226 完成、230 登录成功
3xx 需进一步信息 331 需要密码
4xx 暂时失败，可重试 425 打不开数据连接
5xx 永久失败 530 未登录、550 文件不存在/无权限

主动 PORT 与被动 PASV

1. 主动（PORT）

服务端从 20 端口向客户端在 PORT 命令中声明的 IP:端口 主动连出。客户端在 NAT 后时常失败（内网端口对服务端不可达）。

2. 被动（PASV）（主流）

服务端在应答中给出监听 IP 与端口，客户端主动连入。防火墙须在服务端放行被动端口范围；NAT 下常需配置对外通告地址（如 masquerade_address）。

227 应答的端口计算：(h1,h2,h3,h4,p1,p2) 中数据端口为 p1*256 + p2。例如 227 Entering Passive Mode (192,168,1,10,39,17) → 连接 192.168.1.10:10001（39*256+17=10001）。NAT 场景下服务端若通告了内网地址，客户端会连错目标——这就是「登录正常、列目录超时」的经典成因。

明文与认证

传统 FTP 用户名、密码与数据多为明文；FTPES 在 TLS 上加密，但仍保留双连接复杂性。公网新系统优先 第八章：SFTP 详解：SSH 子系统、协议栈与 sftp 示例 或对象存储 HTTPS 上传。

抓包与排障

Wireshark 显示过滤：ftp（控制连接命令/响应）、ftp-data（数据连接）。

常见故障速查：

现象 优先怀疑
登录成功但 ls 卡死/超时 PASV 端口范围未放行；服务端通告了内网 IP（需 masquerade_address）
主动模式连不上 客户端在 NAT/防火墙后，服务端连不回
传文本文件后内容错乱 误用 TYPE A（文本模式会做换行转换）；改 TYPE I
425 Can't open data connection 数据连接被防火墙/安全组拦截
530 Login incorrect 凭据错或服务端禁用该用户（查 vsftpd 的 userlist/pam 配置）

服务端最小加固（以 vsftpd 为例）

  • 禁匿名写：anonymous_enable=NO、限制本地用户 chroot：chroot_local_user=YES。
  • 显式划定被动端口范围并放行：pasv_min_port=50000、pasv_max_port=50100。
  • 公网务必开 TLS：ssl_enable=YES、force_local_logins_ssl=YES。
  • 公网新系统仍建议直接上 第八章：SFTP 详解：SSH 子系统、协议栈与 sftp 示例，省掉双连接的全部复杂度。

本章小结

要点 结论
架构 双连接：控制连接（TCP 21）全程保持，数据连接按需动态建立
模式 PORT 主动（NAT 后易失败）；PASV 被动为主流，需放行端口范围
安全 默认明文；FTPES 加密但仍双连接，新系统优先 SFTP/HTTPS
实操 lftp 交互/脚本两相宜；nc 手发 USER/PASS 仅限教学
排障 登录通但列表卡死 = PASV 端口/通告地址问题；看 tcpdump 'tcp port 21'
