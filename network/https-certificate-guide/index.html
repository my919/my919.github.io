网络 · HTTPS 与证书上线

从 0 到全站 HTTPS：证书体系 · Let’s Encrypt 免费证书申请 · Nginx 完整配置（HTTP/2/HSTS/OCSP）· 自动续期 · 常见问题排查。配置带详细注释。

类别 选型 用途

证书 Let’s Encrypt（免费 DV） 域名证书
工具 certbot / acme.sh 申请与续期
域名 自有域名 证书绑定

1. 概念说明：HTTPS 与证书

HTTPS 解决什么：加密传输（防窃听）+ 身份验证（防冒充）。没有 HTTPS，密码/订单/登录态在网络上明文传输。

证书类型对比：

类型 验证程度 价格 适用
DV 验证域名所有权 免费（Let’s Encrypt） 绝大多数场景
OV 验证企业身份 数百元/年 企业官网
EV 深度验证+地址栏企业名 数千元/年 金融等高信任场景

2.2 certbot 申请（Nginx 插件自动配置）

为什么用 –nginx 插件：自动完成”申请 → 配置 443 → 配跳转”三步，少踩配置坑。纯手动场景用 certbot certonly --webroot（见常见问题）。

2.3 证书文件说明

文件 用途
fullchain.pem 证书链（服务器证书 + CA 中间证书）→ Nginx 用这个
privkey.pem 私钥（绝不泄露，权限 600）
chain.pem CA 中间证书链

3. 第二步：Nginx 完整 HTTPS 配置

每个配置为什么：

配置 为什么
http2 on 一个连接并发多个请求，首屏更快
TLSv1.2 TLSv1.3 老版本有已知漏洞（POODLE 等）
HSTS 防止首次访问被降级为 HTTP（SSL Strip 攻击）
X-Forwarded-Proto $scheme 后端才知道”当前是 HTTPS”，否则生成错误链接/回调

4. 第三步：证书自动续期（必须配）

为什么每天跑而非 89 天跑一次：万一某天续期失败（域名验证临时失败），第二天会自动重试——每天跑 = 自动容错。

5. 常见问题排查

现象 原因 解决
浏览器报”证书过期” 没配自动续期 配 certbot renew + cron
报”证书链不完整” 只配了 cert.pem 没配 fullchain 用 fullchain.pem
报”域名不匹配” 证书域名 ≠ 访问域名 重新申请带 www 的
手机/旧设备访问失败 只支持 TLS1.2+ 确认业务是否需要兼容
续期失败 http-01 验证不过 80 端口被墙/被跳转 用 dns-01 验证（acme.sh 配 DNS API）
后端回调拿不到 https 没传 X-Forwarded-Proto 补配置

案例：证书静默过期，全站告警的修复全程

问题背景：周一早高峰用户反馈浏览器报”您的连接不是私密连接”。查证：证书周五已过期。cron 里明明配了 certbot renew，但它已静默失败 20 多天，没人发现。

方案：先手动续期恢复业务 → 查清失败根因（80 端口被新服务占用，http-01 验证不过）→ 加失败告警防再犯。

踩坑点：

  • cron 里 --quiet 把失败也吞了：续期必须接告警（失败发邮件/IM），不能只靠日志。
  • http-01 验证要求 80 端口可直达；拿不准时改用 dns-01（acme.sh 配 DNS API），彻底不依赖 80 端口。
  • 修复顺序：先恢复证书（业务在流血），再修根因与监控，不要反过来。
  • Let’s Encrypt 有效期 90 天，--dry-run 每月跑一次当演练，别等真到期才第一次验证续期链路。

8. 常见误用与陷阱

坑 现象/后果 解法
Nginx 只配 cert.pem 不配 fullchain.pem 桌面浏览器能开，手机/小程序报证书链不完整 一律用 fullchain.pem，openssl s_client 验证链完整
HSTS max-age 一上来就设一年 配置出错想回退 HTTP 也回不去（浏览器强制） 从 max-age=300 起步，稳定后再加长
续期 cron 静默失败 证书过期全站告警才发现 去掉 --quiet，失败重定向并接告警
私钥权限 644 任意本机用户可读私钥 chmod 600 privkey.pem，属主 root
续期成功但没 reload Nginx 磁盘上新证书，进程里还是旧证书 永远带 --post-hook "systemctl reload nginx"
启用 HTTPS 后混入 http 资源 浏览器拦混合内容；跨域接口报 CORS 错 全站资源/接口统一 https；后端补 X-Forwarded-Proto 与 CORS 头
