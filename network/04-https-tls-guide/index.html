第四章：HTTPS 详解：TLS 握手、证书与 openssl/curl 示例

发表于 2026-05-01 更新于 2026-10-25 分类于 计算机网络 本文字数： 3.8k 阅读时长 ≈ 3 分钟

第四章：HTTPS 详解：TLS 握手、证书与 openssl/curl 示例

概念基础

  1. HTTP + TLS，不是新协议：HTTPS 就是先经 TLS 加密、再传输 第二章：HTTP 详解：报文、方法、版本与 curl/nc 示例 报文——URL 以 https:// 开头，默认端口 443（明文 HTTP 为 80）。
  2. TLS 提供三件事：机密性（对称加密防窃听）、完整性（MAC / AEAD 防篡改）、身份认证（X.509 证书链证明「服务器是它声称的那个」，可选客户端认证）。
  3. 握手定密钥，传输用对称：TLS 握手（1.3 常 1-RTT）协商出对称会话密钥，之后 HTTP 记录用对称算法加密以获得性能。
  4. 证书链是信任根基：浏览器校验证书是否由受信任 CA 签发、SAN 是否覆盖主机名、是否在有效期内；自签名证书仅限内网与开发。
  5. 不解决什么：TLS 不能替代应用层鉴权与输入校验，https:// 不等于站点没有 XSS/CSRF 等业务漏洞。

先看简化的握手时序：

TLS 握手（简化）



sequenceDiagram
  participant C as Client
  participant S as Server

  C->>S: ClientHello
  S->>C: ServerHello + 证书
  C->>C: 校验证书链
  C->>S: 密钥交换 Finished
  Note over C,S: 对称密钥加密 HTTP

作用与威胁模型

1. TLS 提供什么

  • 机密性：对称加密载荷，防窃听。
  • 完整性：MAC / AEAD 防篡改。
  • 身份认证：服务端（可选客户端）X.509 证书链。

2. 不解决什么

TLS 不能替代应用层鉴权与输入校验；https:// 也不等于站点无 XSS/CSRF 等业务漏洞。

TLS 1.2 / 1.3 握手（原理简述）

1. 共同目标

客户端与服务端协商出对称会话密钥，后续 HTTP 记录用对称算法加密以获得性能。

2. TLS 1.3 特点（相对 1.2）

  • 常 1-RTT 完成握手（0-RTT 可选，有重放风险，敏感操作应禁用或二次校验）。
  • 废弃一批不安全算法；Hello 中即携带密钥共享材料。

TLS 1.2 vs 1.3 关键差异：

维度 TLS 1.2 TLS 1.3
握手往返 2-RTT 1-RTT（0-RTT 可选）
密钥交换 RSA / ECDHE 等可选 仅 (EC)DHE，强制前向保密
对称算法 CBC、RC4 等遗留并存 仅 AEAD（AES-GCM、ChaCha20-Poly1305 等）
握手加密 证书等明文传输 ServerHello 之后大部分加密
重协商 支持 移除（用后握手认证替代）

3. TLS 1.3 完整握手（逐步）



sequenceDiagram
  participant C as Client
  participant S as Server
  C->>S: ClientHello（supported_versions、key_share、SNI、ALPN）
  S->>C: ServerHello（选定版本/套件、key_share）
  Note over C,S: 此后报文均已加密
  S->>C: EncryptedExtensions（ALPN 结果等）
  S->>C: Certificate + CertificateVerify + Finished
  C->>C: 校验证书链 / 签名 / SAN
  C->>S: Finished
  Note over C,S: 开始传输应用数据（HTTP）

key_share 在首个 ClientHello 就带上客户端的 (EC)DHE 公钥，省掉 TLS 1.2 里单独的 ServerKeyExchange 往返，这是 1-RTT 的关键。

证书链与主机名（作用）

浏览器/客户端会校验：

  1. 证书是否由受信任 CA 签发，链是否完整。
  2. Subject Alternative Name（SAN） 或兼容字段是否覆盖当前访问主机名。
  3. 有效期、吊销信息（OCSP Stapling 等）。

自签名证书仅适合内网或开发，公网须使用可信 CA 或组织内 PKI。

证书关键字段速览（openssl x509 -text 可见）：

字段 含义
Subject / Issuer 持有者 / 签发者 DN
SAN 覆盖的域名列表（现代客户端以此为准）
Not Before / After 有效期
Subject Public Key Info 公钥算法与位长（RSA-2048、ECDSA P-256 等）
Authority Key Identifier 指向上级 CA，用于组链

ALPN

常见故障与排查

报错（curl / openssl） 常见原因
certificate has expired 证书过期；续期后未重载 服务
unable to get local issuer certificate 服务端漏配中间证书（应下发完整链）
hostname mismatch SAN 不含访问域名；SNI 未携带
self signed certificate 自签名证书；客户端需显式信任或换 CA 证书
SSL routines::wrong version number 对端端口是明文 HTTP 或谈了不支持的版本
握手超时 防火墙丢 TCP/443；MTU 黑洞（大证书链 + 丢包）

安全加固清单

  • 仅启用 TLS 1.2+（优先 1.3），禁用 SSLv3 / TLS 1.0 / 1.1。
  • 套件只保留 AEAD；开启 OCSP Stapling 减少客户端吊销查询。
  • HSTS：Strict-Transport-Security: max-age=31536000; includeSubDomains，防降级到明文。
  • 私钥权限 chmod 600、与证书分离存放；自动化续期（ACME / certbot）并监控到期时间。
  • 全站 HTTPS：HTTP→HTTPS 301 跳转，页面内杜绝 mixed content。

扩展阅读

  • RFC 8446：TLS 1.3 本体；RFC 6066：SNI 等扩展。
  • 证书链与 ACME 自动化见本站 HTTPS 与证书上线全流程。

本章小结

要点 结论
本质 HTTPS = TLS + HTTP；提供机密性、完整性、服务端身份，不替代业务安全
握手 TLS 1.3 常 1-RTT；0-RTT 有重放风险；ALPN 协商 h2/h3
证书 CA 信任链 + SAN 覆盖主机名 + 有效期；自签名仅限内网
排障 openssl s_client 看证书与协商；curl -v --tlsv1.3 验证版本
加固 仅留 1.2+/AEAD、OCSP Stapling、HSTS、自动化续期
