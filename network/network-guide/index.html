计算机网络从入门到精通

网络 · 计算机网络

从 0 到排查实战。OSI/TCP-IP 分层 · TCP/UDP · 三次握手四次挥手 · HTTP/1.1·2·3 · HTTPS/TLS · DNS · 抓包与排障。

技术栈速查

类别 选型 用途
协议 TCP/IP / HTTP / TLS 网络核心协议
抓包 Wireshark / tcpdump 报文分析
命令行 curl / dig / ss / ping 连通与排查
压测 wrk / h2load 性能验证

1. 概念说明

计算机网络是分层协作的系统，每层只关心自己的职责，向上层提供接口。两种分层模型：

层 OSI 七层 TCP/IP 四层 代表协议
应用层 7 应用 / 6 表示 / 5 会话 应用层 HTTP、DNS、SMTP
传输层 4 传输 传输层 TCP、UDP
网络层 3 网络 网际层 IP、ICMP
链路层 2 数据链路 / 1 物理 网络接口 以太网、WiFi

数据封装：发送方从上到下逐层加头部（Header），接收方从下到上逐层剥头。

2. TCP 核心机制

2.1 三次握手（建立连接）

  • 第一次：客户端 SYN（我准备连接）
  • 第二次：服务端 SYN+ACK（收到，我也准备）
  • 第三次：客户端 ACK（确认双方都能收发）

为什么是三次：两次无法确认客户端接收能力；防止已失效的连接请求突然到达服务端造成资源浪费。

2.2 四次挥手（断开连接）

TIME_WAIT 为什么等 2MSL：保证最后一个 ACK 可达、旧连接报文在网络中消失，避免污染新连接。

2.3 可靠传输三件套

机制 作用
确认应答（ACK） 确认收到
超时重传 / 快速重传 丢失恢复
滑动窗口 + 拥塞控制 流量与拥塞控制（慢启动、拥塞避免、快恢复）

3. UDP 与 TCP 对比

维度 TCP UDP
连接 面向连接 无连接
可靠性 可靠 尽力而为
顺序 保证 不保证
头部 20 字节 8 字节
场景 HTTP、数据库、文件 DNS、视频通话、游戏、QUIC

4. HTTP 协议演进

版本 特点
HTTP/1.1 持久连接、管道化受限、队头阻塞
HTTP/2 二进制分帧、多路复用（一个连接并发请求）、头部压缩 HPACK、服务端推送
HTTP/3 基于 QUIC（UDP），0-RTT、彻底解决队头阻塞

常用状态码（必须掌握）：

分类 代表
1xx 100 继续
2xx 200 OK、201 Created、204 No Content
3xx 301 永久重定向、302 临时重定向、304 缓存命中
4xx 400 参数错、401 未认证、403 无权限、404 不存在、429 限流
5xx 500 服务器错、502 网关错、503 服务不可用、504 网关超时

5. HTTPS 与 TLS

HTTPS = HTTP + TLS，解决加密、防篡改、身份认证。

TLS 握手（简化）：

证书链：浏览器信任根 CA → 中间 CA → 站点证书。自签名证书不被信任（会警告）。

6. DNS 解析流程

CDN 原理：DNS 解析时按地理位置返回就近节点 IP（CNAME 指向 CDN 厂商），实现加速。

8. 常见网络故障排查（黄金流程）

现象 可能原因
ping 通但网页打不开 端口被封 / HTTP 服务问题
curl 卡在 TLS 握手 证书/防火墙拦截 443
偶发超时 丢包、DNS 慢、TCP 重传
TIME_WAIT 堆积 短连接过多（改连接复用）

9. 高频面试题速答

问题 核心答案
三次握手为什么不是两次 需确认双方收发能力，防失效请求
四次挥手为什么四次 服务端 FIN 与 ACK 可分离（CLOSE_WAIT 期间还有数据）
HTTP/2 为什么快 多路复用、头部压缩
为什么需要 CDN 就近访问、回源缓存、抗流量
HTTPS 性能开销 握手一次，后续对称加密开销小；可开会话复用

10. 典型案例

案例：TIME_WAIT 暴涨导致接口偶发超时

问题背景：网关机器在高峰期调用下游服务偶发 connect timeout。ss -tan 显示 TIME_WAIT 状态连接 2 万+，本地临时端口接近耗尽。

方案：确认是高并发短连接导致 → 内核开启端口复用 + 扩大端口范围缓解 → 应用层改长连接/连接池根治。

踩坑点：

  • TIME_WAIT 在主动关闭方产生，是正常机制不是故障；不要开早已废弃的 tcp_tw_recycle（NAT 下丢包，新内核已移除）。

11. 常见误用与陷阱

坑 现象/后果 解法
把 TIME_WAIT 当故障疯狂调参 参数改了一圈问题依旧 先分清主动/被动关闭方；TIME_WAIT 是设计行为，高是症状不是病
启用 tcp_tw_recycle NAT 环境大量连接失败 已废弃（内核 4.12 移除），用 tcp_tw_reuse + 长连接
长连接无心跳 中间件/防火墙静默断连，下次发送才报错 应用层心跳（ping/pong）+ 断线自动重连
只用 netstat 排查高并发 全表遍历慢，连接统计不可靠 用 ss（内核态直接读），ss -s 看汇总
DNS 缓存过久 服务迁移/切换后仍连旧 IP 调低 TTL；应用端定期刷新连接池 DNS
内网服务走公网域名互访（NAT 回环） 绕一圈外网网关，慢且可能不通 内网互访用内网 IP/内网 DNS，或配 hairpin NAT
