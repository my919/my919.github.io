计算机网络总体框架与学习导航。各协议详解、证书上线与排查实战由专题文章承担，本文只讲分层模型与学习路径。

类别 选型 用途

1. 分层模型

计算机网络是分层协作的系统，每层只关心自己的职责，向上层提供接口：

层 OSI 七层 TCP/IP 四层 代表协议
应用层 7 应用 / 6 表示 / 5 会话 应用层 HTTP、DNS、SMTP
传输层 4 传输 传输层 TCP、UDP
网络层 3 网络 网际层 IP、ICMP
链路层 2 数据链路 / 1 物理 网络接口 以太网、WiFi

数据封装：发送方从上到下逐层加头部（Header），接收方从下到上逐层剥头。

2. 核心概念速览

2.1 TCP 与 UDP

维度 TCP UDP
连接 面向连接（三次握手/四次挥手） 无连接
可靠性 可靠（ACK + 重传 + 滑动窗口） 尽力而为
顺序 保证 不保证
头部 20 字节 8 字节
场景 HTTP、数据库、文件 DNS、视频通话、游戏、QUIC

2.2 HTTP 协议演进

版本 特点
HTTP/1.1 持久连接、管道化受限、队头阻塞
HTTP/2 二进制分帧、多路复用、头部压缩 HPACK、服务端推送
HTTP/3 基于 QUIC（UDP），0-RTT、彻底解决队头阻塞

2.3 HTTPS 与 TLS

HTTPS = HTTP + TLS，解决加密、防篡改、身份认证。握手用非对称加密交换预主密钥，后续通信走对称加密；证书链：根 CA → 中间 CA → 站点证书。

4. 高频面试题速答

问题 核心答案
三次握手为什么不是两次 需确认双方收发能力，防失效请求
四次挥手为什么四次 服务端 FIN 与 ACK 可分离（CLOSE_WAIT 期间还有数据）
TIME_WAIT 为什么等 2MSL 保证最后 ACK 可达、旧报文消失
HTTP/2 为什么快 多路复用、头部压缩
HTTPS 性能开销 握手一次，后续对称加密开销小；可开会话复用
为什么需要 CDN 就近访问、回源缓存、抗流量
