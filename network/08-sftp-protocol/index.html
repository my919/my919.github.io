发表于 2026-05-01 更新于 2026-10-25 分类于 计算机网络 本文字数： 2.4k 阅读时长 ≈ 2 分钟

第八章：SFTP 详解：SSH 子系统、协议栈与 sftp 示例

概念基础

  1. 跑在 SSH 上的文件传输子系统：SFTP 是 SSH 协议族中的子系统，直接复用 SSH 的加密、完整性与认证——单端口（22）单连接搞定文件操作。
  2. 不是「FTP over SSH」：与 第七章：FTP 详解：双连接模型、主动/被动与 lftp 示例 的双连接模型无关；也不同 scp（单次拷贝）与 rsync（增量同步，协议不等同 SFTP）。
  3. 为什么是公网首选：默认强加密、防火墙只需放行一个端口、可复用 SSH 密钥免密认证；而 FTPS 虽加密仍保留双连接复杂性。
  4. 交互与批处理兼得：sftp 支持交互浏览目录（ls/cd/get/put），也支持 -b 批处理脚本，适合自动化。

先看它在协议栈中的位置：

作用与协议栈（原理）

SFTP 是 SSH 协议族中的子系统，与 shell 会话可并存于同一 SSH 连接实现上（由服务器策略决定）。

协议报文要点（概念）：SFTP 是二进制请求/响应协议，每条消息为「长度 + 类型 + 请求 ID + 载荷」。客户端发 SSH_FXP_OPEN / READ / WRITE / CLOSE / READDIR / STAT / REMOVE / RENAME 等请求，服务端回 SSH_FXP_HANDLE / DATA / STATUS / ATTRS 等响应；请求 ID 允许多请求并行在途（pipelining），这是它比「一问一答」的 FTP 控制连接更适合高延迟链路的原因之一。协议版本常见为 v3（OpenSSH 实现），扩展能力在 SSH_FXP_INIT 握手时协商。

与 SCP、rsync over SSH 的取舍

工具 说明
SFTP 交互浏览目录、断点续传能力依客户端而定
scp 单次拷贝简单文件
rsync -e ssh 增量同步目录，底层仍是 SSH 隧道，协议不等同于 SFTP

选型口诀：一次性拷贝用 scp；要「看看远端有什么再决定拿哪个」用 SFTP；反复同步大目录用 rsync（只传差异块，最省带宽）。

常见故障速查

现象 优先怀疑
Permission denied (publickey) 公钥未加入 authorized_keys；私钥权限非 600；服务端禁了密钥登录
能 ssh 但 sftp 拒绝 Subsystem sftp 未配；或被 ForceCommand 限制
chroot 后立刻断连 chroot 目录属主/权限不符合要求（须 root 拥有）
批处理挂住不动 出现交互式询问；加 -oBatchMode=yes 暴露错误
大文件慢 单连接窗口与 RTT 限制；试 -B 增大缓冲或用 rsync 分片

安全注意

  • 优先 密钥认证，禁用密码（PasswordAuthentication no，变更前确认已有可用密钥）。
  • 公网暴露 22 必配 fail2ban 或改高位端口 + 安全组白名单；密钥定期轮换。
  • SFTP 全程密文，抓包只能看到加密后的 第九章：SSH 详解：加密远程登录、密钥与端口转发示例 通道流量，排障主要靠客户端 -v 与服务端 auth.log。

本章小结

要点 结论
定位 SSH 子系统：复用 SSH 加密与认证，单端口 22 单连接
选型 交互/批处理选 SFTP；单次拷贝用 scp；增量同步用 rsync
认证 配 SSH 密钥免密；私钥须 chmod 600
服务端 加固靠 chroot、ForceCommand、AllowUsers（sshd_config）
排障 -v 看握手细节；批处理加 -oBatchMode=yes 防挂起
