第九章：SSH 详解：加密远程登录、密钥与端口转发示例

概念基础

SSH（Secure Shell）是运行在 TCP 之上的加密远程管理与通道协议：

  1. 解决什么问题：Telnet / rlogin 等明文远程登录会把账号密码与全部数据暴露在链路上，SSH 用加密与完整性校验防窃听、防篡改。
  2. 两层认证：主机密钥证明「服务器是它自己」（首次连接写入 known_hosts），用户认证证明「你是你」（公钥 / 密码 / 证书，推荐公钥）。
  3. 不只是登录：SSH 还是加密隧道——端口转发（-L/-R/-D）、跳板（ProxyJump），并可承载 SFTP 等子系统。
  4. 为什么可靠：基于 第一章：TCP 协议详解：连接、可靠传输与编程示例 的可靠字节流，配合协议内建的密钥交换与重协商，全程不暴露明文凭据。

理解了定位，再逐层展开协议目标与用法：

一、协议目标（作用）

  • 机密性与完整性：防窃听与篡改。
  • 身份认证：至少认证服务器；可双向证书或密钥。
  • 隧道能力：为其他 第一章：TCP 协议详解：连接、可靠传输与编程示例 应用提供加密通道。

协议分层（概念）——SSH 由三个子协议组成，理解它能解释大部分报错归属：

二、主机密钥与用户认证（原理）

1. 主机身份

首次连接写入 ~/.ssh/known_hosts；指纹变更会报警，需区分重装与中间人。

2. 用户认证方式

方式 说明
公钥 推荐；私钥 chmod 600
密码 简单；配合 fail2ban、速率限制
证书 企业 SSH CA 签发主机/用户证书

3. 公钥认证握手（简化时序）



sequenceDiagram
  participant C as Client
  participant S as Server
  C->>S: TCP 22 连接 + 版本串交换
  C->>S: 算法协商（KEX、加密、MAC）
  Note over C,S: (EC)DH 密钥交换 → 会话密钥；主机密钥签名验证服务器身份
  C->>S: 请求以公钥 X 认证用户
  S-->>C: 挑战（用公钥可验的随机数据）
  C->>S: 私钥对挑战签名
  S->>S: authorized_keys 中找到公钥并验签
  S-->>C: 认证成功，打开会话通道

要点：私钥永不出本机，网上只传签名；服务端靠 authorized_keys 中的公钥验签确认身份。

4. 生成与部署密钥

常见密钥类型取舍：ed25519（短、快、现代首选）、RSA-3072/4096（兼容性最好）、ECDSA P-256（较老环境）；DSA 已废弃，OpenSSH 新版默认拒绝。

三、~/.ssh/config 示例

常用选项补充：IdentitiesOnly yes（只用指定私钥，防 agent 里多把钥匙被服务端拒）、ServerAliveCountMax 3（配合保活间隔，NAT 长连接不掉线）、AddKeysToAgent yes（首次输入口令后交给 agent 托管）。

动态转发（-D）：把 SSH 变成 SOCKS5 代理，浏览器/工具经它访问跳板可达的任意地址：

三者方向速记：-L 本地监听、-R 远端监听、-D 本地 SOCKS 代理；-N 表示不执行远程命令（纯隧道）。

五、跳板：ProxyJump

等价 ~/.ssh/config：

多级跳板可逗号串接：ssh -J jump1,jump2 target。ProxyJump 与「先 ssh 跳板再 ssh 目标」的差别：认证与密钥都留在本机完成，跳板机上看不到目标机的凭据。

六、sshd_config 常见安全项（概念）

  • PasswordAuthentication no：仅密钥（变更前确保不会锁死自己）。
  • PermitRootLogin prohibit-password 或 no。
  • AllowUsers / AllowGroups 限制登录账户。

配套措施：fail2ban 拦爆破、改默认端口（只能减少噪音，不算安全措施本身）、密钥加口令并定期轮换、用 ssh -Q kex 等命令确认可用算法、关注发行版安全公告（如 CVE-2024-6387 regreSSHion 这类高危）。

七、常见故障速查

现象 优先怀疑
Permission denied (publickey) 公钥未部署；私钥权限非 600；sshd 禁了该用户或密钥算法过旧
REMOTE HOST IDENTIFICATION HAS CHANGED 服务器重装/换机，或真遭中间人；核实后删 known_hosts 对应行
连接超时无响应 安全组/防火墙未放 22；sshd 未监听；运营商封端口
登录成功立刻断开 shell 配置报错、ForceCommand 限制、chroot 权限错误
隧道转发被拒 服务端 AllowTcpForwarding no；-R 需 GatewayPorts yes 才对外监听

排查万能第一步：ssh -vvv user@host 看详细协商过程；服务端侧看 /var/log/auth.log（Debian/Ubuntu）或 journalctl -u sshd。
