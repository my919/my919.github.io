6. 典型案例：搜索列表页——状态管理选型与 Hooks 陷阱修复

问题背景：商品搜索页：输入关键词防抖后请求列表，请求期间展示旧数据不闪烁，并把「最近搜索」存本地。团队最初把接口数据塞进 Zustand、手写 useEffect 防抖，结果出现闭包陷阱（定时器读到旧 state）和双份状态不同步两类 bug。

方案：按状态归属选型——服务端状态交给 React Query，全局 UI 状态（最近搜索）交给 Zustand，防抖抽成自定义 Hook：

踩坑点：

  • queryKey 漏掉 debounced：搜索词变了仍命中旧缓存，列表永远不变——key 必须覆盖所有影响结果的入参。
  • 把接口数据也写进 Zustand：与 React Query 缓存双份不同步，刷新即失真。服务端状态只信 React Query（或 RSC）。
  • 防抖 Hook 若漏写依赖数组里的 value：setTimeout 闭包捕获旧值，防抖失效——这是 React 闭包陷阱最高频的现场。

7. 常见误用与陷阱

坑 现象/后果 解法
useEffect 闭包陷阱 定时器/订阅回调里读到旧 state，逻辑「慢一拍」 依赖数组写全；更新用函数式 setX(s => ...)；常量用 useRef
useEffect 里直接 async useEffect(async () => {}) 语法与语义错误 effect 内定义 async 函数再调用，或用 use() + Suspense
setState 后立刻读 state 拿到的还是旧值（批量更新） 需要连续更新用函数式更新；确需新值用 useEffect 监听
列表 key 用数组 index 删除/排序后组件状态错乱、输入串行 稳定唯一业务 id 作 key
useEffect 依赖对象字面量 deps: [{id}] 每次新引用 → 无限重渲染 依赖原始值，或 useMemo 稳定引用
Zustand 整仓解构 任一状态变化整个组件重渲染 选择器订阅：useStore(s => s.x)
服务端状态塞 useState 刷新丢失、多组件不同步、重复请求 React Query / Server Components 做唯一事实源
忘返回清理函数 定时器/订阅泄漏，StrictMode 下行为异常 effect 返回 cleanup，清理一切副作用
