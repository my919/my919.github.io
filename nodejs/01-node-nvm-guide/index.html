第一章：Node 环境管理 nvm 实践

概念基础

  1. 为什么需要版本管理：Node 大版本迭代快，LTS 与 Current 并行发布，不同项目常依赖不同 Node 版本——全局只装一个版本很快就捉襟见肘。
  2. nvm 的解决思路：nvm（Node Version Manager）从源码或官方预编译包拉取 Node，把各版本隔离安装在用户目录 $HOME/.nvm 下，通过 nvm use 切换当前终端使用的 node / npm，各版本互不干扰。
  3. 与全局安装的区别：不把某个 Node 强行装进系统目录，无需 root 权限；切换版本只影响当前 Shell（及子进程），其他终端不受牵连。
  4. 按项目锁定版本：项目根目录放一个 .nvmrc 写明版本号，进入目录执行 nvm use 即可对齐环境，避免「在我机器上能跑」的版本漂移。
  5. 平台边界：经典 nvm-sh 只支持 macOS / Linux；Windows 原生需改用 nvm-windows 或在 WSL 中使用 nvm-sh，详见文末说明。

Windows 与补充说明

  • 经典 nvm（nvm-sh）不支持原生 Windows。若在 Windows 上开发，常见做法有：
    1. 使用 nvm-windows（命令与 nvm-sh 接近但不完全相同，安装包在 Releases 下载）；
    2. 使用 WSL，在 Linux 子系统里按本文 安装 nvm（macOS / Linux）、安装并使用 Node.js v22.22.2 两节安装 nvm-sh；
    3. 使用 fnm、Volta 等跨平台工具（非 nvm，但可管理多版本 Node）。
  • 国内镜像：可在安装 Node 前设置 NVM_NODEJS_ORG_MIRROR（具体变量名与地址以当前 nvm 文档为准），以加速 nvm install。
  • 与系统自带 node 冲突：若曾用包管理器安装过 node，which node 可能仍指向旧路径；确保 nvm use 后 PATH 中 nvm 的 shim 在前，或卸载系统级 Node 后再试。

nvm-windows 实操要点（命令与 nvm-sh 有差异）：

差异点 nvm-sh nvm-windows
切换原理 改 PATH 指向用户目录 改系统 symlink（需管理员）
.nvmrc 自动切换 需 shell 钩子 不支持，需手动 nvm use
生效范围 当前终端 全局（所有新终端）

在 Windows 上做团队开发，更省心的是 fnm / Volta：原生支持 .nvmrc 与 package.json#engines 自动切换，且无需管理员权限。

常见避坑

坑 现象 正确做法
新开终端版本又变了 nvm use 只对当前 Shell 生效，重开终端回到系统 node 用 nvm alias default v22.22.2 设默认；或在项目根写 .nvmrc 并在 shell rc（~/.bashrc/~/.zshrc）里加自动切换钩子
npm i -g 全局包丢了 切换 Node 版本后，全局 @vue/cli、hexo-cli 等找不到 每个 Node 主版本的全局包互相隔离；切换后需要在新版本 npm i -g <pkg> 重装，或用 nvm reinstall-packages <旧版本> 批量迁移
sudo 用 nvm node 失败 sudo node 找不到或走系统 Node nvm 是用户级脚本，sudo 默认不加载；要么避免 sudo（改目录权限），要么用 sudo $(which node) ... 显式调用路径
CI 里 nvm 命令不存在 GitHub Actions / Docker 里 nvm: command not found CI 用官方 actions/setup-node / circleci/node 动作，不要手动装 nvm；Docker 直接选 node:22-alpine 基础镜像
.nvmrc 写了没自动切 进入项目目录没切版本 nvm 本体没有自动切换；在 shell rc 里加 nvm 官方提供的 nvm_find_nvmrc 钩子，或用更现代的 fnm / Volta（原生支持按目录切换）
nvm 装在 root 下但普通用户用不了 which nvm 为空 nvm 必须安装在要使用它的用户的 $HOME/.nvm；多用户各装一份，不要共用 root 的

官方文档：nvm-sh/nvm。

本章小结

要点 结论
nvm 定位 把多版本 Node 隔离安装在用户目录，按终端用 nvm use 切换，不污染系统环境
安装 官方脚本一条命令装到 $HOME/.nvm，重开终端或手动 source 生效
日常使用 nvm install / nvm use / nvm alias default 覆盖安装、切换、默认版本三类需求
项目协作 .nvmrc + nvm use 固定项目 Node 版本，团队环境一致
镜像加速 NVM_NODEJS_ORG_MIRROR 指 npmmirror；npm registry 需单独配置
自动切换 shell 钩子读 .nvmrc；或换 fnm/Volta 原生支持
CI 对齐 setup-node 读 .nvmrc；Docker 镜像钉死 tag，三层同一份版本
Windows nvm-sh 不支持原生 Windows，改用 nvm-windows 或在 WSL 内使用
