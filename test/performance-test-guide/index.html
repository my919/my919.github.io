1. 概念说明

性能测试目的：验证系统在预期负载下是否达标 + 找出瓶颈 + 给出容量结论（”能抗多少 QPS”）。

关键指标：

指标 含义 常见目标
QPS/TPS 每秒请求/事务数 按业务
并发数 同时在处理的请求 与 QPS 关联
RT（响应时间） 平均/P90/P99 P99 < 500ms
错误率 失败请求占比 < 0.1%

测试类型：

最重要概念：P99 而不是平均值——平均延迟被长尾掩盖；P99 反映真实体验。

阶段 并发 时长 观察
冒烟 10 1min 链路通

常见瓶颈速查：

症状 瓶颈
CPU 100% 且 GC 少 业务热点/死循环 → 火焰图
GC 频繁 堆配置/对象过多 → 堆转储

连接池耗尽 连接池小/慢查询占连接
QPS 到某值上不去 数据库/Redis/网络带宽瓶颈

关注长尾 P99/P999 而非平均

14. 常见误用与陷阱

坑 现象/后果 解法
空表/小数据量压测 QPS 虚高数倍，容量结论失真 造生产量级数据 + 冷热分布
只看平均 RT 平均 80ms 掩盖 P99 800ms 长尾 看 P90/P99/P999 与 RT 分布
一次打到最大并发 拐点定位不了 阶梯加压，每级跑满 5 分钟
压测机自身是瓶颈 端口/CPU 耗尽，误判服务问题 监控压测机资源，必要时分布式施压
脚本无业务断言 返回全是 500 也算”高吞吐” 内置业务码断言
未预热就采数 JIT 未编译，数据偏低 先热身 5 分钟再正式采集
QPS 与并发混用 “并发 100 = QPS 100” 换算错误 QPS ≈ 并发 ÷ 平均 RT，分开定义
单机容量直接乘台数 忽略负载不均/共享瓶颈 乘 0.8 系数 + 集群实测验证
忽略缓存命中率 命中率一降容量腰斩 按命中率分层建模
冗余系数取 1 峰值抖动直接过载 冗余 1.5-2，HPA 兜底
只测正向不测降级 依赖故障时毫无容量 演练 Redis/DB 故障场景的降级容量
连接池盲目调大 DB 上下文切换剧增，吞吐反降 10→30→50 小步调，每步复测
