1. 概念说明

**并发（Concurrency）**指多个任务在时间上交替执行（宏观并行、微观串行），**并行（Parallelism）**指多个任务真正同时执行（多核）。并发解决的是”多任务协同”，并行解决的是”更快”。

三个层次：

  • 进程（Process）：操作系统资源分配单位，内存隔离，切换开销大。
  • 线程（Thread）：进程内执行单位，共享进程内存，切换开销较小。
  • 协程（Coroutine）：用户态调度，栈极小，可创建十万级（Java 虚拟线程、Go goroutine、Python async）。

核心问题：多个线程同时读写共享变量会产生竞态条件（Race Condition），导致结果不确定。解决方案：互斥（锁）、原子操作、不可变对象、线程本地存储。

7. 常见误用与陷阱

坑 现象 解法
synchronized 锁 String 字面量 / Integer 缓存对象 不同业务恰好锁住同一个共享对象 → 互相串扰阻塞，线上偶发卡顿难复现 锁对象用 private final Object lock = new Object()；或锁 this 字段独立的实例
双检锁单例不加 volatile 高并发下可能读到「半初始化」对象，运行一段时间才偶发 NPE 单例字段必须加 volatile（禁止指令重排，构造完成才对其他线程可见）
CompletableFuture 链不写 exceptionally 上游异常被吞 → future.join() 永久挂住，线程池被慢慢掏空 链尾加 exceptionally/handle 兜底，再用 orTimeout / completeOnTimeout 设超时
goroutine 内 panic 未 recover 一个协程 panic → 整个进程崩溃退出 协程入口 defer func(){ if r := recover(); r != nil { log.Println(r) } }() 兜底
channel 重复 close 或向已关闭 channel 发送 panic: close of closed channel / send on closed channel 只由生产者方关闭，消费者只读；多生产者用 sync.Once 包裹 close，避免重复关闭
