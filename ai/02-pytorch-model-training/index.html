第二章：PyTorch 模型与训练

发表于 2026-05-01 更新于 2026-10-25 分类于 人工智能 本文字数： 6.4k 阅读时长 ≈ 6 分钟

第二章：PyTorch 模型与训练

概念基础

  1. nn.Module 是模型的骨架：继承后在 __init__ 里声明层、在 forward 里组织数据流；参数注册、.to(device)、state_dict 保存全部自动获得。
  2. Dataset/DataLoader 解耦数据与模型：Dataset 定义「第 i 条样本怎么取」，DataLoader 负责批量化、打乱、多进程预取——大数据训练的前提。
  3. 训练循环是固定四步：optimizer.zero_grad() → forward → loss.backward() → optimizer.step()，一切复杂训练都是这四步的变体。
  4. train/eval 切换不可少：Dropout、BatchNorm 在训练与推理行为不同；验证前必须 model.eval()，验证后 model.train()。
  5. 泛化靠工程手段：验证集监控、早停、学习率调度、正则化（weight_decay/Dropout）共同决定模型能否落地。

本章承接 第一章：PyTorch 入门与张量 的张量与 autograd。代码按 PyTorch 2.x 官方 API 书写（沙箱未装 torch，未逐条运行验证）。

一、定义模型：nn.Module

常用层速查：

层 用途
nn.Linear(in, out) 全连接
nn.Conv2d(cin, cout, k) 图像卷积
nn.BatchNorm2d(c) / LayerNorm 归一化（稳定训练）
nn.ReLU / GELU 激活
nn.Embedding(vocab, dim) 离散 ID → 向量（NLP 必备）
nn.LSTM / nn.TransformerEncoder 序列建模

二、Dataset 与 DataLoader

  • num_workers：多进程预取，CPU 密集的预处理必开；Windows 下要在 if __name__ == "__main__": 里跑。
  • pin_memory=True：页锁定内存加速 CPU→GPU 拷贝（配合第三章）。
  • 变长序列：用 collate_fn 自定义打包（padding + mask）。

三、训练循环：完整模板

四大高频翻车点：

症状 原因
loss 不降 学习率过大/过小；标签与 logits 形状不配
loss 变 NaN lr 过大爆炸、除零、FP16 溢出（见第三章 GradScaler）
验证 acc 虚高 忘了 model.eval()，Dropout 还在随机丢弃
显存随轮次上涨 把带计算图的 loss 累加到 list（应 loss.item()）

四、断点续训：保存与恢复

推荐保存 state_dict() 而非整个模型对象：反序列化整个对象要求类定义路径一致，state_dict 只存权重、跨代码结构可用。

五、回归与二分类的损失选择

任务 输出层 损失函数
多分类 Linear(→n_classes) CrossEntropyLoss
二分类 Linear(→1) BCEWithLogitsLoss
回归 Linear(→1) MSELoss / HuberLoss
多标签 Linear(→n) BCEWithLogitsLoss（标签 multi-hot）

六、nn.Module 机制深入

6.1 参数与 buffer 的注册

self.xxx = nn.Parameter(...) 或赋值一个子 nn.Module 会自动注册进 parameters()；不可训练但要随 state_dict 保存的张量（如 BatchNorm 的 running_mean）用 register_buffer：

机制要点：model.to(device) / model.float() 只作用于已注册的参数与 buffer——随手挂在 self 上的普通张量不会搬家，这是”张量在 CPU、参数在 GPU”报错的常见根因。

6.2 Hook：不改源码看清模型内部

七、DataLoader 性能调优

GPU 利用率忽高忽低，九成是数据侧瓶颈。按这张表调：

参数 作用 建议
num_workers 预取进程数 CPU 核数的 1/2 ~ 全部；0 = 主进程加载（调试用）
pin_memory 页锁定加速 CPU→GPU 拷贝 GPU 训练恒开
persistent_workers epoch 间不销毁 worker 恒开，省重启开销
prefetch_factor 每 worker 预取批数 IO 慢调大到 4~8
batch_size 单批大小 显存内尽量大（配合 AMP）

进一步压榨：图像解码这类 CPU 密集预处理离线做掉，存成 WebDataset/TFRecord 分片；__getitem__ 里别做网络请求与重计算；多卡时每卡用 sampler 切分数据（见第四章 DDP）。

八、早停与训练健壮性

健壮性三件套：早停防过拟合空转；clip_grad_norm_ 防梯度爆炸；每 N step 存 checkpoint 防断电白训（配合第四节断点续训）。

常见坑 FAQ

坑 现象 正确做法
验证忘 eval() acc 忽高忽低 验证前 model.eval() + no_grad
忘切回 train() 再训练 Dropout 失效 训练段开头 model.train()
Windows 多进程报错 反复 spawn / BrokenPipe 入口包 if __name__ == "__main__":
标签 dtype 错 CrossEntropy 报类型错 标签 .long()，logits .float()
shuffle 忘开 训练集顺序泄漏 训练 shuffle=True、验证 False
checkpoint 只存模型 续训优化器状态丢失 模型+优化器+epoch+scheduler 全存
普通张量挂 self .to(device) 后 device 报错 用 register_buffer 注册

生产实践清单

  • 训练/验证循环严格切换 train() / eval()
  • DataLoader 开 num_workers + pin_memory + persistent_workers
  • checkpoint 存全量状态并按版本命名
  • 早停 + 梯度裁剪进默认训练模板
  • 每 epoch 记录 loss/acc/lr/耗时，接 TensorBoard 或 W&B
  • 随机种子、库版本、数据版本写进实验记录

本章小结

要点 结论
模型 继承 nn.Module，__init__ 声明层、forward 串数据流
数据 Dataset 取样 + DataLoader 批量化；变长数据用 collate_fn
训练四步 zero_grad → forward → backward → step；验证前 model.eval()
排障 NaN 查 lr/精度；显存涨查计算图泄漏；acc 虚高查 eval 切换
存取 存 state_dict() + 优化器状态，跨机器恢复
