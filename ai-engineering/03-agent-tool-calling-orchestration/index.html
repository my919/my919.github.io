第三章：Agent 工具调用与函数编排

发表于 2026-09-02 更新于 2026-10-25 分类于 AI 工程化 本文字数： 12k 阅读时长 ≈ 11 分钟

第三章：Agent 工具调用与函数编排

概念基础

  1. Function Calling 是 Agent 的”手”：模型本身只能输出文本，靠工具把意图变成副作用——查数据库、发请求、执行 Shell；没有工具的 Agent 永远只是聊天机器人。
  2. 工具 schema 即接口契约：name / description / parameters 是 LLM 看到的全部信息，模糊的 description 是大部分调用错误根因；schema 一变，模型行为就变。
  3. 并行 vs 串行调用：现代模型一次可返回多个 tool_call，独立工具可并行执行省延迟；有依赖（A 的输出是 B 的输入）必须串行。
  4. MCP 统一工具协议：Anthropic 提的开放协议把”工具定义、传输、客户端”标准化，Server 一次写、多 Client 用，避免每个框架重写工具。
  5. 工具设计决定 Agent 能力上限：颗粒度太粗 LLM 选不到、太细调用爆炸；返回结构化 JSON、错误信息让 LLM 能读懂，工具是 Agent 的”产品接口”。

二、工具设计原则

2.1 好工具 vs 坏工具对比

原则 坏示例 好示例
单一职责 do_anything(action, data) search_orders() / refund_order()
参数最小化 必填 5 个 必填 1 个，其余可选
返回结构化 “成功” {"ok": true, "order_id": "...", "status": "..."}
错误友好 “出错” {"error": "order_not_found", "msg": "..."}
幂等 重复下单扣款 带幂等 key 重复请求安全
命名 proc1 search_orders（动词_名词）

2.2 错误返回要让 LLM 能自救

错误信息含原因 + 重试建议，让模型下一轮能修正参数；纯字符串错误让模型猜半天。

七、MCP 生态进阶

7.1 三类原语

MCP Server 暴露的不只是工具：

原语 控制权在谁 用途
Tools 模型决定何时调 执行动作（查库、发请求）
Resources 应用决定何时读 只读数据（文件、配置、日志）
Prompts 用户/应用触发 预置 prompt 模板

7.2 传输与部署

传输 场景
stdio 本地子进程：Claude Desktop、IDE 插件
Streamable HTTP 远程服务，多客户端共享，支持鉴权

远程 Server 要补三件事：鉴权（OAuth 2.1 / Bearer Token）、限流（按 client 维度）、审计（谁调了什么工具）。社区已有覆盖文件系统、Git、数据库、浏览器的官方参考实现，自建前先查 MCP registry，避免重复造轮子。

7.3 工具检索：规模化解法

工具数超过 30 个后，全量塞进 schema 会稀释模型的选择准确率。标准解法是做工具检索层：用向量索引存工具 description，按用户意图先召回 Top-5 工具再交给 Agent——MCP 网关类组件普遍内置了这种 meta-tool 模式。

八、Prompt 注入防护与权限收敛

工具是注入攻击的执行端：模型被恶意网页骗了之后，靠工具完成真实破坏。防线要落在工具层，不能只指望模型”足够聪明”。

8.1 四道防线

  1. 不可信输入隔离：检索/抓取内容标记为 data 而非 instruction，System Prompt 显式声明。
  2. 参数静态校验：pydantic 模式 + 业务白名单（域名、路径前缀、SQL 只读）。
  3. 权限收敛：一个 Agent 只挂完成任务的最小工具集；数据库账号按”只读/单表”粒度建。
  4. 动作审计：每次调用记录（谁、何时、参数、结果），写操作可回放。

8.2 数据外泄专项

外发类工具（HTTP 请求、发邮件、写 webhook）必须做目标白名单 + 内容审查：模型生成的 URL 先校验域名，payload 过敏感信息（PII/密钥模式）检测后再放行。注入攻击最常见的目标就是把上下文里的秘密外发，这道闸不能省。

常见避坑

坑 现象 正确做法
工具参数描述不清 LLM 乱传值 description 写格式 + 示例
返回超长爆上下文 工具返回 100KB 文本 截断 + 摘要 + 摘要回传
无超时工具 hang 一次卡死整个 Agent httpx/subprocess 都设 timeout
并行工具竞态 写同一文件交错 写类工具串行化、加锁
MCP 版本不兼容 Server/Client 报错 锁 mcp 版本，看 protocol 版本字段
沙箱逃逸 容器内跑恶意代码 network=none + 只读挂载 + 最小镜像
工具过多 LLM 选错 30 个工具选不准 分组路由 + 工具检索（meta-agent）
幻觉调用 调不存在的工具 未知工具直接抛错并提示重选
MCP 远程无鉴权 任何人可调用工具 Streamable HTTP + Token 鉴权
工具权限全家桶 注入后一键删库 按角色最小授权

生产实践清单

  • 每个工具：类型注解 + docstring + 结构化错误返回
  • 网络/子进程调用全部显式超时
  • 高危工具（写/删/付）强制 HITL 确认
  • 工具按角色最小授权，外发类工具配目标白名单
  • MCP Server 远程部署带鉴权、限流、审计
  • 工具数 >20 时上工具检索或分组路由
  • 全量工具调用留审计日志，可回放排查
