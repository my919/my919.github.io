第五章：RAG 与向量检索实战

发表于 2026-05-01 更新于 2026-10-29 分类于 AI 工程化 本文字数： 11k 阅读时长 ≈ 10 分钟

第五章：RAG 与向量检索实战

概念基础

  1. RAG = 检索增强生成：把私有知识向量化入库，提问时先检索最相关的片段塞进上下文，再让 LLM 作答——不用重训模型就能注入领域知识，是 LLM 落地性价比最高的路线。
  2. Embedding 是语义坐标系：文本被编码为高维向量（如 1024 维），语义相近的文本距离相近；「检索」从关键词匹配升级为最近邻搜索。
  3. 向量库专管 ANN：Milvus/Qdrant/pgvector 用 HNSW 等索引做近似最近邻查询，毫秒级从千万级向量里捞 Top-K；小规模用 Redis/Postgres 也能起步。
  4. 效果好坏在数据管道：切块（chunking）粒度、检索 Top-K、重排序（rerank）三件事对答案质量的影响大于换模型。
  5. 评估要有 ground truth：召回率（该找的找没找到）与答案忠实度（说的对不对）分开评，肉眼抽查不可持续。

本章把 RAG 概念落到工程实现。代码按 LangChain 0.3 / OpenAI SDK 官方 API 风格书写（沙箱未装依赖，未逐条运行验证）。

一、RAG 全链路



flowchart LR
  D[文档] --> C[切块 Chunking]
  C --> E[Embedding 向量化]
  E --> V[(向量库)]
  Q[用户提问] --> QE[问题向量化]
  QE --> V
  V --> R[Top-K 检索 + Rerank]
  R --> P[拼装 Prompt]
  P --> LLM[LLM 生成]
  LLM --> A[带引用的答案]

两条管道：

管道 内容 执行时机
离线索引 文档 → 清洗 → 切块 → 向量化 → 入库 文档新增/变更时
在线问答 问题向量化 → 检索 → 拼 Prompt → LLM 每次提问

二、离线索引：切块与向量化

切块经验值：

参数 建议 理由
chunk_size 300~800 字符 太小丢上下文，太大稀释相关性
chunk_overlap 10%~20% 保住跨界句子
元数据 给每块挂 {"source": 文件名, "section": 标题} 答案引用与按来源过滤都靠它

三、在线检索与生成

Prompt 三原则：明确告知「只依据资料」、资料带来源标记（答案可引用）、temperature=0 降低发挥。

四、向量库选型

方案 定位 适用
Qdrant / Milvus 专用向量库，HNSW/量化，十亿级 独立检索服务
pgvector Postgres 扩展 已有 PG、千万级以内（运维最省）
Redis 向量检索 + 缓存一体 热点数据、低延迟
Elasticsearch BM25 + 向量混合检索 已有 ES、关键词+语义混合
FAISS 进程内库 原型、单机实验

五、评估与迭代

调优顺序（从便宜到贵）：

  1. 切块参数：调 chunk_size/separators，对结构化文档用标题感知切块
  2. 检索深度：先取 Top-20 再 rerank 到 Top-4（召回与精排分工）
  3. 混合检索：加 BM25，专治型号、代码、专有名词
  4. 换 Embedding 模型：领域强的换领域微调模型（中文场景 BGE 系列常用）
  5. 最后才动 LLM：检索对了答案基本就对了

六、切块策略对比

策略 做法 优点 缺点 适用
定长切块 按字符数硬切 简单快 断句断语义 日志、流水文本
递归切块 按分隔符优先级切 保句子完整 块大小不均 通用首选
结构感知 按标题/代码块/表格切 语义单元完整 需要解析器 Markdown、技术文档
语义切块 按 embedding 变化点切 主题内聚 慢、贵 长报告、书籍
父子切块 小块入库、命中取父块 精度与上下文兼得 实现复杂 高质量问答

经验：技术文档优先结构感知；拿不到结构再退回递归切块。chunk_size 以 embedding 模型的有效窗口为上限，别盲目调大。

7.2 Rerank：召回与精排分工

检索器（双路各取 Top-20）保证召回率，Cross-Encoder 类 reranker（如 BGE Reranker）对 40 个候选精排取 Top-4 保证精度：

reranker 比检索器慢一个数量级，只跑在几十条候选上；拿它直接扫全库是本末倒置。

八、查询改写

用户问题往往不适合直接检索（太短、有指代、口语化），改写先行能显著救召回：

技术 做法 适用
Multi-Query LLM 扩写成 3~5 个变体并行检索 问题模糊、表述多样
HyDE 先生成假设答案，用答案向量检索 问题与文档表述差异大
Step-back 抽象成上位问题先检索背景 具体但缺上下文的问题
指代消解 结合历史把”它/这个”还原成实体 多轮对话

九、评估指标：从召回到忠实度

指标 度量什么 计算方式
Recall@K 期望文档是否进 Top-K 命中数 / 总用例数
MRR 第一个正确结果排多前 平均 1/rank
Faithfulness 答案是否忠于检索内容 LLM 拆解答案逐句核对来源
Answer Relevancy 答案是否切题 LLM 反问生成 + 相似度

工程化做法：检索侧盯 Recall@K 与 MRR（改动快、反馈快），生成侧用 RAGAS 类框架跑 faithfulness（慢，按版本跑）。两维分开归因——召回差改数据管道，忠实度差改 prompt 与上下文拼装。

十、GraphRAG 简介

向量 RAG 把知识切成碎片，遇到”这些事件之间什么关系””整个语料的主线是什么”这类全局性、关系性问题会失灵。GraphRAG（微软开源）的思路：

  1. 离线索引时让 LLM 从每个 chunk 抽取实体与关系，构建知识图谱；
  2. 社区检测把图谱聚成主题簇，预生成社区摘要；
  3. 在线查询按类型分流：局部问题走实体邻域检索，全局问题走社区摘要问答。

代价是索引成本数倍于普通 RAG（每 chunk 多次 LLM 调用）。结论：默认从向量 + BM25 + rerank 起步，确认有全局分析类刚需再上 GraphRAG。

常见坑 FAQ

坑 现象 正确做法
chunk 过大 答案泛泛、引用不准 300~800 字符起步，按评估调
无元数据 无法引用来源、无法按租户过滤 每块挂 source/section/tenant
只做向量检索 型号、错误码搜不到 加 BM25 双路 + RRF
召回直接拼 prompt 噪声稀释答案 Top-20 召回 → rerank 到 Top-4
多轮指代未消解 “它怎么配置”检索失败 查询改写先行
PDF 解析丢表格 表格变乱码 专用解析器 + 表格转 Markdown
增量更新无去重 旧版文档重复召回 文档 ID 版本化 + 过期删除
评估只看答案 检索差与生成差分不清 召回/忠实度分开归因
embedding 与检索模型不一致 线上召回莫名变差 索引与查询用同一模型同一版本
Top-K 一次到位 好文档被挤出上下文 召回放大（Top-20）+ rerank 收敛
答案无引用 用户无法溯源验证 metadata 带 source，prompt 要求标注
Prompt 注入：文档/用户写”忽略以上指令” 模型泄露提示词、执行越权操作 资料放分隔标记内并声明其为数据；工具白名单 + 关键操作人工审批
上下文超长硬拼 TopK 超窗静默截断，先丢 system 约束 tiktoken 计数，按 Token 预算截断，预留输出空间
temperature 乱用 事实问答用 1.0 胡编，格式漂移 问答/抽取 00.3，创意写作才用 0.71
不重试、不限流 429/超时直接 500，高峰期雪崩 tenacity 指数退避（只重试可恢复错误）+ 信号量限并发
检索不带租户/权限过滤 召回到其他租户的私有文档 检索强制注入 tenant_id，送 LLM 前再做权限校验

生产实践清单

  • 切块挂 source/section/tenant 元数据，答案可引用
  • 双路召回（BM25 + 向量）+ RRF + reranker 精排
  • 多轮对话接入查询改写与指代消解
  • 建 50+ 评测集，Recall@K / MRR / faithfulness 常态化
  • 文档更新有增量索引与旧版本清理流程
  • Prompt 显式要求”仅依据资料”并附引用
  • 检索与生成两层的延迟、命中率分别监控
  • embedding 模型版本固定，索引与查询同版本
  • 答案强制带引用来源，方便用户溯源
  • reranker 只跑小候选集，不直接扫全库
  • 服务化带健康检查接口，流式输出 + 硬超时
  • 检索强制租户过滤，资料放分隔区防 Prompt 注入
  • LLM 调用有指数退避重试与并发限流，Token 预算防超窗截断

本章小结

要点 结论
RAG 本质 检索注入上下文而非重训模型；离线索引 + 在线问答两条管道
切块 300~800 字符 + 重叠 + 标题感知；每块挂 source/section 元数据
检索 向量 ANN 打底；BM25 混合治专有名词；rerank 精排
选型 有 PG 用 pgvector、独立大规模用 Qdrant/Milvus、原型用 FAISS
切块策略 技术文档优先结构感知；通用退回递归切块
混合检索 BM25+向量双路 + RRF；reranker 只精排小候选集
查询改写 Multi-Query / HyDE / 指代消解救召回
评估 召回率与忠实度分开评；调优先动切块与检索，最后动模型
GraphRAG 全局关系类问题再上，默认不必
