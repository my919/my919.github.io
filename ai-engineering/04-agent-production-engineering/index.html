第四章：Agent 生产化与工程实践

发表于 2026-09-02 更新于 2026-10-29 分类于 AI 工程化 本文字数： 12k 阅读时长 ≈ 11 分钟

第四章：Agent 生产化与工程实践

概念基础

  1. Agent 生产化的三大挑战：延迟 / 成本 / 可靠性：单次对话要多次 LLM 调用 + 多次工具调用，首字延迟普遍 5-30 秒、单次成本可能 0.05-0.5 美元，非确定性输出让 QA 难以传统方式覆盖。
  2. 评估比传统软件难：传统软件输入确定 → 输出确定；Agent 同一输入两次结果可能不同，必须用任务完成率 + 工具调用准确率 + 人工标注多维度评估，靠单测不够。
  3. 可观测性是生命线：Agent 调用链跨多步、多工具，没有 trace 就是黑盒；LangSmith / Langfuse 这类 step-level trace 在生产前就要接好，否则出问题无法复盘。
  4. 人在环（HITL）兜底：写操作、支付、删除等不可逆动作必须人工确认；Agent 不该 100% 自主，关键是定义清楚哪些步骤要人、哪些不要。
  5. 从 Demo 到生产的鸿沟：Demo 看 PPT 漂亮，上线要补鉴权、限流、缓存、降级、回滚、监控、审计、合规；80% 的工程量在 Demo 之外。

一、Agent 架构设计

1.1 总体架构

1.2 FastAPI + LangGraph 流式 SSE Agent API

thread_id 维度持久化对话状态，配合 MemorySaver 实现会话续跑；生产把 checkpointer 换成 PostgresSaver 或 Redis。SSE 让用户实时看到每一步在做什么，首字延迟降到 1-2 秒。

二、RAG + Agent 融合实战

2.1 为什么 RAG 需要 Agent

普通 RAG Agent + RAG
单次检索 多轮检索、按需补充
检索后直答 检索后判断相关性、必要时再检索
工具不可调 检索作为工具，可与 SQL/API 并用

2.2 LangGraph Self-RAG Agent

关键点：Agent 自主决定”要不要检索”；检索结果不相关则重检索或换查询词；相关性评估用模型打分（graded），构成自我修正闭环。

6.4 灰度与应急

  • 灰度：header 路由 10% 用户灰度新 prompt，对比 success rate / 成本 / 延迟。
  • 降级：Agent 失败回退固定流程（RAG 直答 / 静态规则）保可用。
  • 回滚：Prompt 版本化存配置中心，一键切回上一版本；写操作走审批队列。

七、安全防线：注入防护与权限收敛

生产环境的 Agent 面对的是真实恶意输入：用户消息、被抓取的网页、邮件正文都可能是注入载体。安全设计按”假设模型一定会被骗”来做：

层 措施 目标
入口 不可信内容标记与隔离 模型分清指令与数据
工具 最小授权 + 参数白名单 + HITL 被骗也干不了坏事
出口 外发域名白名单 + PII 过滤 防数据外泄
审计 全量调用日志 + 定期回放 事后可追溯

工具层具体实现（沙箱、HITL、pydantic 校验）见 第三章：Agent 工具调用与函数编排。

八、成本与延迟优化进阶

8.1 三级缓存

缓存 粒度 命中条件
Prompt Caching（模型侧） 前缀 长 System Prompt / 工具 schema 前缀不变
工具结果缓存 完整调用 参数完全相同
语义缓存 意图 问题向量相似度 > 阈值

8.2 延迟解剖

一次请求 P95 延迟 = Σ（每轮 LLM 延迟 + 工具延迟），优化对应到每一项：

  • LLM 轮数：加”早停”——检索已充分时不再多轮；平均轮数从 4.2 压到 2.8 往往比换模型更有效。
  • 单轮延迟：流式输出降体感；结构化输出用短 schema；小模型承担路由与压缩。
  • 工具延迟：独立工具并行执行；慢工具（>2s）异步化并给用户中间态反馈。

8.3 多租户隔离与配额

按租户设并发数、每分钟 token、每日成本三道配额；批量分析类重负载走队列异步跑，不与在线对话抢推理资源。

常见避坑

坑 现象 正确做法
Demo 完美上线崩 真实流量分布不同 用线上真实数据压测
无成本监控 月底账单爆炸 每请求记 token，配预算告警
无循环检测 死循环烧 token 限 max_iterations + 重复动作计数
prompt 改了没回归 同一问题答不出来 golden dataset 回归
上下文窗口溢出 老对话压垮模型 滑动窗口 + 摘要外置
工具超时无熔断 单工具卡死全链路 工具 timeout + circuit breaker
无 trace 线上黑盒 出问题无法复盘 上线前接 LangSmith/Langfuse
模型升级 breaking 升级后 prompt 失效 升级前跑评估集，灰度上线
语义缓存误命中 相似问题返回过期答案 阈值保守 + TTL + prompt 版本字段
无租户隔离 单客户打爆全站 按租户限流与配额

生产实践清单

  • 上线前接入 step-level trace（LangSmith/Langfuse）
  • 全链路超时：LLM 调用、工具调用、整体请求各一级
  • golden dataset 回归通过才允许发版与模型升级
  • 每请求记录 token 与成本，预算告警到责任人
  • 写操作 HITL 或审批队列，审计日志全量留存
  • 外发请求过域名白名单与 PII 检查
  • 灰度、降级、回滚预案至少演练过一次
  • P95 延迟、错误率、循环步数纳入看板与告警
