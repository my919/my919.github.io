10. 典型案例：CDN 边缘计算（个性化页面 + 动静分离）

问题背景：跨境电商站点用户遍布 30 国，源站在美国：登录态用户的购物车/货币/语言都依赖源站动态渲染，东京用户 RTT 180ms，首页 TTFB 2.1s；大促时源站带宽费用暴涨。目标是：静态资源全球快，动态个性化也不能慢。

方案：动静分离 + 边缘个性化：静态走 CDN 缓存，个性化片段由 Cloudflare Worker 在边缘组装，Cookie/会话不过源站：

层 策略 说明
静态资源 CDN 长缓存 + 指纹版本 sw-cacheable 1 年 + 版本号失效
HTML 外壳 短缓存（60s）+ 语言维度 Vary 全球近源命中
个性化片段 Worker 边缘组装 会话校验/购物车/A-B 在边缘
强一致请求 回源 + mTLS 支付/库存写操作不缓存的场景

关键设计：

踩坑点：① 静态资源没带指纹版本，边缘缓存 1 年改版后用户看到旧 CSS——内容哈希文件名 + 不可变缓存头。② HTML 缓存键漏了语言维度，日本用户命中英文缓存——Vary/缓存键必须覆盖所有影响内容的请求维度。③ 把购物车价格计算放边缘 KV，库存变了边缘还是旧价，用户结算价与展示价不符——边缘只做”展示级个性化”，强一致数据回源并在结算页二次确认。④ Worker 里同步 await 两个慢查询（购物车+推荐），串行叠加延迟——Promise.all 并行 + ctx.waitUntil 把非关键路径（埋点/推荐）挪到响应后。⑤ 边缘 KV 写后读不一致（购物车刚加的 item 不显示），用户重复点击——写操作回源，读展示容忍秒级陈旧 + 客户端乐观更新。

11. 常见误用与陷阱

坑 现象/后果 解法
静态资源无指纹 改版后用户见旧样式 内容哈希文件名 + immutable 缓存头
缓存键漏请求维度 多语言/站点串缓存 键覆盖 URL+语言+站点等全部维度
边缘算强一致数据 展示价与结算价不一致 边缘只做展示个性化，一致性回源
边缘 KV 当强一致存储 写后读不一致，重复提交 写回源，读容忍陈旧 + 乐观更新
Worker 里串行慢调用 边缘延迟反而变高 Promise.all 并行 + waitUntil 后置
会话校验回源 每请求回源，边缘白干 JWT 边缘验签（JWKS 边缘缓存）
无降级预案 边缘故障等于全站故障 Worker 异常时回退纯 CDN 模式
日志只在边缘采样 安全事件无法审计 边缘结构化日志 → 中心聚合（Tail Worker）
跨境合规忽视 用户数据出境违规 按区域路由 + 数据本地驻留（EU→EU）
