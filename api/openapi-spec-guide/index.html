1. 概念说明

OpenAPI（原 Swagger）是描述 HTTP API 的语言无关规范：一个 yaml/json 文件完整描述”有哪些接口、参数、响应、鉴权方式”。作用：

  • 文档即契约：前后端、跨团队按同一份契约开发，杜绝”接口改了不知道”。
  • 可执行：从规范自动生成 SDK、Mock、测试、文档。
  • 工具链成熟：Swagger UI、Redoc、openapi-generator、Prism 全生态。

8. 典型案例：契约驱动开发「订单 API」从 v1 到 v2

问题背景：订单服务由后端 A 团队维护，前端 B 团队与两家外部 ISV 消费。痛点：接口改动靠口头通知，一次把 price 字段含义从「分」改成「元」，ISV 扣款全部算错；前后端联调互相等待，排期对不齐。

方案：

阶段 动作 产出
定义 openapi.yaml 定义 /v2/orders + 统一 Error schema 可评审的契约 PR
并行开发 生成 TS SDK（前端）+ Spring 骨架（后端） 同一契约，字段零口头同步
联调 Prism Mock 先行，后端就绪后切真实地址 联调周期从 2 周缩到 3 天
回归 Schemathesis 在 CI 校验实现不漂移 实现偏离契约 CI 直接红

踩坑点：

  • 生成的 SDK 代码不要手改——重新 generate 会全部覆盖，定制逻辑放 wrapper 层。
  • info.version 只是文档声明，真正的隔离靠路径 /v2/；只升 version 不加路径，旧调用方照样崩。

9. 常见误用与陷阱

坑 现象/后果 解法
文档与实现漂移 文档写有 total 字段，实际早删了，ISV 线上炸 Schemathesis 契约测试进 CI，偏离即红
operationId 缺失或重复 生成的 SDK 方法名冲突/不可读 规范评审卡 operationId 必填且唯一
破坏性变更不升版本 删字段/改类型，旧调用方集体故障 升 /v2/ 路径 + 旧版保留过渡期
schemas 全内联不复用 同一个分页结构抄 10 遍，改一处漏九处 components.parameters/schemas 抽公共件
只定义 200 不定义错误响应 调用方拿到 4xx/5xx 没有结构可解析 每接口声明 401/404/422 + 统一 Error
参数约束不写 min/max 调用方传 page_size=100000 打挂数据库 schema 约束写全，Schemathesis 顺带模糊测试
手改生成的 SDK 代码 重新生成即覆盖，改动全部丢失 定制放 wrapper 层，生成物只读
