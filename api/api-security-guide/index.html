7. 安全基线清单

项 要求
传输 全站 HTTPS（TLS1.2+）
密码 BCrypt（cost≥10），禁止 MD5/SHA 明文
令牌 JWT 短过期 + Redis 黑名单（登出/改密失效）
越权 每接口校验资源归属
输入 参数化 SQL、白名单校验、长度限制
敏感数据 日志脱敏、Payload 不放敏感信息
重放 时间戳 + nonce 幂等
限流 核心接口全部接限流

8. 典型案例：开放平台接入全流程（appId + 签名 + 防重放 + 限流）

问题背景：公司要把「物流轨迹查询」能力开放给第三方 ISV。要求：请求不能被篡改、抓包重放无效、能按 appId 控制每家调用量、Secret 疑似泄露时可快速止损。

方案：

防线 手段 挡住什么
防篡改 参数 + Secret 做 HMAC-SHA256 中间人改参（改一个字节签名必错）
防重放 时间窗 300 秒 + nonce Redis SETNX 抓包原样重发
防滥用 按 AppId 限流（如 100 QPS） 单家 ISV 打爆接口
止损 Secret 可重置 + 宽限期 密钥泄露长期失控

踩坑点：

  • 签名串拼接顺序（appId+ts+nonce+body）必须写进接入文档并附多语言示例，否则「签名错误」工单会排满队列。

  • nonce 的 Redis key 不带 appId 时，不同 ISV 偶发撞 nonce 会互相误杀。

9. 常见误用与陷阱

坑 现象/后果 解法
JWT Payload 存手机号/身份证 base64 一解码就泄露 Payload 只放非敏感声明，敏感数据实时查库
Secret 硬编码在代码/配置仓库 泄露后无法快速止损 配置中心 + 环境变量，支持热重置
签名用 MD5 / SHA1 已可碰撞，防篡改名存实亡 HMAC-SHA256 起步
nonce 写入 Redis 不设过期 键无限膨胀最终 OOM SETNX 同时带 TTL（与时间窗一致）
限流 INCR 只在 count==1 时 expire 进程重启后 key 无过期时间，用户被永久限流 Lua 脚本原子化 INCR+EXPIRE
越权只判「已登录」 用户 A 改 URL 里的 id 就能看 B 的订单 SQL 强制带 user_id（资源归属校验）
登录失败提示「用户不存在/密码错误」 帮攻击者枚举有效账号 统一提示「用户名或密码错误」
OAuth2 回调不校验 state CSRF 授权码注入，账号被绑到攻击者 state 随机值入 Session 并校验
