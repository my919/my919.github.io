第七章：MyBatis-Flex 入门与代码生成

概念基础

  1. 是什么：MyBatis-Flex 是基于 MyBatis 的轻量级增强框架，在保留 MyBatis 全部能力的同时，提供 BaseMapper 通用 CRUD、QueryWrapper/QueryChain 链式查询、内置分页等开箱即用的能力。
  2. 为什么选它：同为「MyBatis 增强」框架，比 MyBatis-Plus 拦截器更轻、SQL 解析更强、自动 Count 更智能，且自动装配，无需手动注册分页插件。
  3. 底层原理：复用 MyBatis 拦截器机制（MyBatisFlexInterceptor → PageInterceptor），分页写法与 MyBatis-Plus 几乎一模一样，可无缝切换。
  4. 代码生成：配合 IDEA 插件 MyBatisX-Generator，在数据库表上右键即可自动生成 CRUD 代码，省去手写模板。
  5. 迁移友好：从 MyBatis-Plus 迁移只需换依赖、换注解包，业务 CRUD 与分页代码零改动。

本文记录 MyBatis-Flex 依赖、配置、IDEA 代码生成与 QueryChain 用法（偏 API 与生成器）。

springboot 仓库完整集成（dynamic-datasource、双库、BaseFlexCrudController）见 第五章：SpringBoot 集成 MyBatis-Flex 与多数据源——生产配置以仓库为准。

MyBatis-Flex 分页原理（通俗易懂 + 流程拆解 + 和 MP 对比）

一、核心结论

MyBatis-Flex 底层也是基于 MyBatis 拦截器，原理和 MyBatis-Plus 大体一样，但设计更轻、SQL 解析更强、自动 count 更智能。

核心逻辑：
MyBatis 拦截器 → 拦截查询SQL → 自动生成 count 总数 → 原SQL 拼接 LIMIT → 封装分页结果

二、核心组件

  1. MyBatisFlexInterceptor
    Flex 全局核心拦截器，替代 MP 的 MybatisPlusInterceptor
  2. PageInterceptor
    专门负责分页拦截，Flex 分页核心逻辑都在这
  3. Page、IPage
    分页载体，和 MP 几乎一模一样：当前页、页大小、总条数、分页数据

三、完整分页执行流程（流程图版）

四、和 MyBatis-Plus 分页原理关键区别

对比点 MyBatis-Plus MyBatis-Flex
拦截器结构 插件嵌套式，较重 极简拦截器，更轻量
Count SQL 生成 简单直接，复杂SQL容易生成低效count 智能优化：自动去掉 order by、优化嵌套SQL
多表/复杂SQL 偶尔分页解析失败 解析器更强，兼容复杂联表、子查询
分页参数传递 必须 Mapper 方法带 Page 参数 支持 Mapper、也支持 Db 静态工具直接分页
配置 必须手动注册分页插件 自动配置，开箱即用，不用手动@Bean

五、代码使用（和 MP 几乎一模一样）

1. 无需手动配置分页插件

Flex 自动自动注入分页拦截器，不用写任何 @Bean 配置

2. 业务分页代码

写法和 MP 完全兼容，无缝切换。

六、底层关键亮点（Flex 比 MP 强的地方）

  1. 自动优化 Count SQL
    原SQL 有 order by，Flex 会自动剔除，避免 count 也排序，提升性能。
  2. 无需手动配置拦截器
    自动装配，少写配置类，少踩坑。
  3. 支持更多数据库方言
    MySQL、PostgreSQL、Oracle、SQLite 等自动适配 LIMIT 语法。
  4. Lambda 分页更丝滑
    不用写 Wrapper，链式直接分页。

七、一句话总结

MyBatis-Flex 分页原理：
复用 MyBatis 拦截机制 → 拦截SQL → 智能生成count → 自动加LIMIT → 封装分页
和 MP 原理同源，但解析更强、配置更少、性能更好、坑更少。
