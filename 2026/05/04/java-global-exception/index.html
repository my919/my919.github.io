第五章：Java 全局异常处理：@RestControllerAdvice 与统一 Result

概念基础

  1. 为什么需要全局异常处理：没有统一捕获时，try-catch 散落在各 Controller，重复代码多，且异常返回格式五花八门。
  2. 核心机制：@RestControllerAdvice + @ExceptionHandler 由 Spring 拦截 Controller 抛出的异常，集中转换为统一响应。
  3. 统一返回体：正常与异常响应都输出 Result<T> JSON（code / msg / data），前端只需处理一种结构。
  4. 异常分层：业务异常（BusinessException，业务代码主动抛出、带业务码）与系统异常（Exception 兜底、记日志）分开处理。
  5. HTTP 与业务码各司其职：协议层语义用 HTTP 状态码（400/405/500），业务语义用 Result.code（如 409/429）。

统一 Result<T> JSON 与 @RestControllerAdvice 全局捕获，避免 Controller 里散落 try-catch。本文给出完整 Handler 源码（通用模板）。

springboot 仓库落地（HTTP 状态码映射、与校验/枚举配合）见 第八章：SpringBoot 统一返回体与全局异常——以仓库代码为准，本文作 Java 层参考。

本章小结

要点 结论
统一出口 @RestControllerAdvice 集中捕获异常，Controller 层零 try-catch
业务异常 BusinessException(code, msg) 主动抛出，Handler 按业务码映射 HTTP 状态
参数校验 配合 @Valid / @Validated，统一捕获校验异常并返回 400 与字段错误信息
兜底策略 Exception 兜底处理器记日志、返回 500，不向前端暴露堆栈
