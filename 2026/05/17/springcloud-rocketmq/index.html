第十一章：Spring Cloud 集成 RocketMQ：异步消息与事件驱动扩展

概念基础

这是 SCA 提供的消息集成能力：把 RocketMQ 接入 Spring Cloud 的编程模型，让业务用「发事件 / 消费事件」的方式解耦：

  1. 接入模型：在 Spring Cloud Alibaba 2025.1.0.0 中，通过 spring-cloud-starter-stream-rocketmq 对接 Spring Cloud Stream，使用函数式 StreamBridge / Consumer，BOM 管理客户端 5.3.1。
  2. 为什么用异步：订单与库存为 同步 Feign + Seata 链路，强一致但耦合紧；下单成功后的通知、积分、日志等旁路动作更适合异步消息（解耦、削峰）。
  3. 本仓库现状：cloud 当前未集成 RocketMQ。订单与库存为 同步 Feign + Seata 链路，见 第八章：订单下单与库存扣减：Feign 链路与 Seata 全局事务。本文供异步解耦、事件驱动扩展参考。
  4. 前置知识：RocketMQ 基础概念（NameServer、顺序/事务消息）见 第四章：RocketMQ 核心概念与架构。
  5. 编码要点：2025.x 使用函数式绑定，勿使用已废弃的 @EnableBinding / @StreamListener。

与 Nacos、Seata 的关系

  • Nacos：仅服务注册；Topic/Group 在 RocketMQ 运维侧管理，DataId 可存 name-server 地址。
  • Seata：异步消息场景需单独设计幂等与补偿，不能照搬当前 POST /order/place 同步全局事务。
  • Sentinel：可对 Stream 绑定名配置流控（需额外规则配置）。

常见问题

Q：本仓库下单为何不用 MQ？
A：示例侧重 Seata 跨服务一致性；MQ 适合异步通知、削峰，需另建消费端与幂等表。

Q：Boot 4 能否用旧版 RocketMQ starter？
A：SCA 2025.1.0.0 起已适配 Boot 4，须用 BOM 2025.1.0.0，勿混旧 SCA。

Q：K8s 内 NameServer 地址怎么写？
A：使用 Service DNS，如 rmq-namesrv.<namespace>.svc.cluster.local:9876，通过环境变量注入。
