第六章：集成 Seata：AT 模式分布式事务

概念基础

  1. 分布式事务：微服务下一次业务操作跨越多个服务与数据库（如下单要写订单库、扣库存库），本地事务无法保证整体原子性，需要全局事务统一协调提交或回滚。
  2. Seata 是阿里开源的分布式事务解决方案，提供 AT、TCC、Saga、XA 等模式；本工程用最常用的 AT 模式——业务 SQL 执行时自动记录前后镜像到 undo_log，异常时据此反向补偿。
  3. 三大角色：TC（事务协调器，独立部署，本工程地址 :30014）、TM（事务发起方，cloud-order 标注 @GlobalTransactional）、RM（资源方，cloud-stock，分支事务注册到 TC）。
  4. 两阶段提交：一阶段各分支本地提交并上报（不长时间锁库，性能好）；二阶段由 TC 统一 commit，或通知各分支用 undo_log 回滚。
  5. 为什么默认开启：下单扣库存是强一致场景，库存不能多扣也不能少扣；AT 模式对业务代码侵入极小——一个注解加一张 undo_log 表即可落地。

概述

Apache Seata 在本项目中以 AT 模式 协调 cloud-order（TM）与 cloud-stock（RM）的跨库事务。默认 开启（SEATA_ENABLED 默认 true），TC 地址 192.168.1.22:30014。与 dynamic-datasource 联用时关闭自动数据源代理，改由 spring.datasource.dynamic.seata: true 接入。

架构



sequenceDiagram
  participant TM as cloud-order
  participant TC as Seata TC :30014
  participant RM as cloud-stock
  participant DB1 as MySQL order
  participant DB2 as MySQL stock

  TM->>TC: begin(xid)
  TM->>DB1: INSERT order (branch)
  TM->>RM: Feign deduct
  RM->>DB2: UPDATE goods (branch)
  alt 成功
    TM->>TC: commit
    TC->>DB1: commit branch
    TC->>DB2: commit branch
  else 失败
    TM->>TC: rollback
    TC->>DB1: undo
    TC->>DB2: undo（若有 UPDATE）
  end

Server 元数据存 MySQL（global_table / branch_table / lock_table 等，脚本见 Seata script/server/db）；注册与配置走 Nacos 时，在 Nacos 创建 seataServer.properties / seata.properties，并保证 service.vgroupMapping.cloud_tx_group=default 与业务 tx-service-group 一致。本仓库客户端当前为 file + grouplist，与单机 TC 对应；上生产请按 SCA Seata 快速开始 切换。

与其它组件的关系

  • Nacos：业务配置可放 application-seata.yml DataId；与 TC 注册分离。
  • Sentinel：无冲突；下单链路同时受 Seata 与 Sentinel 保护。
  • OpenFeign：cloud-order → cloud-stock，XID 由 Seata starter 传播。

关闭 Seata

或 Nacos / application-shared.yml 中 seata.enabled: false（仅本地调试）。

常见问题

Q：ConfigNotFoundException: service.vgroupMapping.default_tx_group？
A：补全 default_tx_group 映射，并保证 tx-service-group 与 mapping 键一致；见本仓库 application-seata.yml。

Q：为何 stock 没有 undo_log 但订单回滚了？
A：分支在 真正执行 UPDATE 之后 才写 undo；库存校验失败时可能无 stock 分支 undo，全局仍回滚 order 分支。

Q：dynamic-datasource 与 Seata？
A：必须 enable-auto-data-source-proxy: false + dynamic.seata: true；勿与自动代理同时开启。历史 issue 见 seata#1511。

Q：单元测试如何跑？
A：cloud-order 集成测试 seata.enabled=false，H2 + Mock Feign，见 OrderPlaceIntegrationTest。
