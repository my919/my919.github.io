发表于 2026-05-17 更新于 2026-09-01 分类于 SpringCloud 本文字数： 2.4k 阅读时长 ≈ 8 分钟

第一章：cloud 微服务工程架构总览与生产落地

概念基础

  1. 微服务是把单体应用按业务边界拆分为一组可独立开发、部署、伸缩的小服务的架构风格，服务间通过 HTTP/RPC 通信；本仓库 cloud 即按 user / app / order / stock 拆分的示例工程。
  2. Spring Cloud 提供微服务公共能力的标准化组件：服务发现、配置管理、网关路由、负载均衡等；本工程基于 Spring Boot 4.0.0 + Spring Cloud 2025.1.0。
  3. Spring Cloud Alibaba（SCA） 在 Spring Cloud 之上补充阿里巴巴系中间件：Nacos（注册 + 配置）、Sentinel（限流熔断）、Seata（分布式事务）、RocketMQ（消息）。
  4. 为什么需要统一架构：拆分后调用链变长、故障面变宽，必须由网关收口流量、注册中心解耦寻址、事务框架保证跨库一致性、限流组件防止雪崩，本工程逐一落地并沉淀上线清单。
  5. 工程定位：生产可落地的参考架构——业务 Jar 与 K8s 中间件解耦部署，地址经环境变量注入，兼顾本地 IDE 调试与容器化上线。

概述

本页为 cloud 微服务工程的文档索引与生产可落地系统架构总览。工程基于 Spring Boot 4.0.0、Spring Cloud 2025.1.0、Spring Cloud Alibaba 2025.1.0.0，已在局域网 K8s 中间件栈（见 服务）上联调验证。

仓库：https://gitee.com/my919/cloud

集成细节见下方专题链接；本文侧重架构决策、部署拓扑与上线清单。

设计目标

目标 落地方式
统一入口 Spring Cloud Gateway，对外仅暴露 :9000
服务发现与配置 Nacos Naming + Config，spring.config.import 分层
跨服务一致性 Seata AT，order（TM）→ stock（RM）
过载保护 Sentinel（Gateway + 业务 + Feign 资源）
多环境 Profile dev / test / prod + Nacos DataId 覆盖
可观测 SkyWalking 链路、Prometheus 指标、Grafana 大盘（可选接入）

配置与多环境

2025.1.x 已移除 bootstrap，Nacos 必须通过 spring.config.import 接入（optional:nacos:...），详见 第二章：Spring Cloud 多环境配置与 Nacos：Profile 与 config.import 分层。

层级 内容
application.yml 激活 Profile、import 链入口
application-shared.yml 公共项、Gateway 路由约定
application-datasource.yml 动态数据源（order/stock）
application-seata.yml Seata 客户端（order/stock）
application-sentinel-client.yml Sentinel transport（import 末尾）
Nacos DataId 按环境覆盖敏感项与开关

生产建议

  • SPRING_PROFILES_ACTIVE=prod，敏感信息（数据库密码、Nacos 密码）放 Nacos 或密钥系统，不入 Git。
  • Nacos 配置变更后依赖 @RefreshScope 或重启策略；Seata / 数据源相关项变更需回归下单链路。
  • application-sentinel-client.yml 保持在 import 链最后，避免 Nacos 中旧端口 8858 覆盖客户端 8719。

可观测性（推荐接入）

能力 组件 说明
链路追踪 SkyWalking Java Agent → OAP :30022 排查 Feign 与 Seata 分支
指标 Micrometer + Prometheus JVM、HTTP、连接池
日志 统一 JSON 或 traceId（MDC） 与 SkyWalking 关联
健康检查 Spring Boot Actuator /actuator/health K8s liveness/readiness

当前仓库以功能联调为主；生产集群建议 Gateway 与各业务 Pod 挂载 Agent，并在 Grafana 配置 JVM 与接口延迟大盘。

上线清单

1. 基础设施就绪

  1. MySQL：执行 sql/init.sql、sql/seata-undo_log.sql、sql/test-data-goods.sql（或生产数据脚本）
  2. Nacos → Seata TC →（可选）Sentinel Dashboard
  3. Nacos 命名空间 / Group 与 DataId 与 application-prod.yml 一致
  4. Seata TC：cloud_tx_group → default 映射与 Nacos 注册一致

2. 应用发布顺序

  1. cloud-stock → cloud-order（Seata 参与方先起）
  2. cloud-user → cloud-app
  3. cloud-gateway（确认 Nacos 已有全部实例）
  4. 冒烟：GET http://127.0.0.1:9000/stock/goods/1，POST /order/place，库存不足回滚用例

3. 构建与质量门禁

代码风格：mvn spotless:apply；CI 建议：mvn verify + 契约测试（place 成功/回滚）+ Nacos 配置 diff 审查。
