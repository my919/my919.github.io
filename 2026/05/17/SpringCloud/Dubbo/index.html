第十章：Dubbo：RPC 与服务治理扩展

概念基础

Apache Dubbo 是一款 Java RPC 与服务治理框架：

  1. 本质是 RPC：消费方像调用本地方法一样调用远端接口，通过注册中心发现 Provider 地址，通信走二进制协议而非文本 HTTP。
  2. 协议与治理：支持 Triple（tri）、经典 dubbo 协议等，内置负载均衡、集群容错、超时重试等服务治理能力。
  3. 与 HTTP + OpenFeign 的取舍：Dubbo 更适合高频、低延迟的内部核心调用；OpenFeign 更贴近 REST 生态，易与 Gateway、Swagger 统一。
  4. 本仓库现状：cloud 当前未集成 Dubbo。服务间调用使用 OpenFeign（如 cloud-order → cloud-stock），注册发现使用 Nacos，见 第八章：订单下单与库存扣减：Feign 链路与 Seata 全局事务、第三章：集成 Nacos：注册中心与配置中心。
  5. 本文定位：供与 SCA 同栈 时扩展参考，说明「如果要用该怎么加、要注意什么」。

前置条件

项 建议 说明
JDK 17+（本仓库为 21）
Nacos 与 SCA 2025.1.0.0 对齐的 3.1.x Server 见 第三章：集成 Nacos：注册中心与配置中心
Dubbo BOM 3.3.x（如 3.3.6，以 Central 为准） 独立于 SCA 发行节奏
本仓库 — 无 dubbo-spring-boot-starter 依赖

若在本仓库旁路集成（步骤概要）

1. 父 POM 增加 dubbo-bom

2. 子模块依赖

执行 mvn dependency:tree 检查与 Nacos Client 3.1.1 无冲突。

3. 配置示意（勿与 cloud-order 现有 Feign 混用同一接口除非刻意迁移）

  • @DubboService：在 Provider（如 stock）暴露接口。
  • @DubboReference：在 Consumer（如 order）注入代理。

注意：registry.address 须与 Spring Cloud 使用的 同一 Nacos 集群；namespace、group 按 Dubbo 文档配置。

配置说明（集成后常用项）

配置项 说明 示例
dubbo.application.name 应用名 cloud-stock
dubbo.registry.address 注册中心 nacos://192.168.1.22:30010
dubbo.protocol.name 协议 tri
dubbo.protocol.port 端口，-1 自增 -1
dubbo.consumer.timeout 调用超时 ms 3000

与 OpenFeign 选型

维度 OpenFeign（本仓库） Dubbo
协议 HTTP/JSON 二进制 RPC / Triple
与 Gateway 易统一 REST 通常内部直连
学习成本 低 需接口 jar、协议约定
适用 BFF、对外 REST 核心域高频调用

迁移下单链路前需评估：Gateway 路由、Swagger、Seata 全局事务 与 Dubbo 过滤器的组合，建议单独分支验证。

验证（独立 Demo）

  1. 按 Dubbo 快速开始 起 Provider/Consumer。
  2. Nacos 控制台除 Spring Cloud 服务外，可见 Dubbo 注册元数据。
  3. 压测对比 Feign 与 Dubbo 延迟（本仓库无现成对比脚本）。

常见问题

Q：本仓库能否同时 Feign + Dubbo？
A：技术上可以分接口使用，但同一业务链路易维护成本高；未在 cloud 中验证。

Q：Dubbo 与 Seata？
A：需按 Dubbo + Seata 官方组合配置事务传播；当前 cloud 的 @GlobalTransactional 基于 Feign。

Q：Nacos 地址用 30010 还是 8848？
A：与 Spring Cloud 一致：对外 NodePort 用 30010；本地 Docker 用 8848。

本章小结

要点 结论
定位 Java RPC + 服务治理框架，支持 Triple/dubbo 协议，适合高频低延迟内部调用
本仓库现状 未集成；服务调用走 OpenFeign + Nacos
集成路径 父 POM 引 dubbo-bom → 子模块加 dubbo-spring-boot-starter → 复用同一 Nacos 注册中心
选型建议 对外 REST 用 Feign/Gateway，核心域高频调用才引入 Dubbo，迁移前单独分支验证
