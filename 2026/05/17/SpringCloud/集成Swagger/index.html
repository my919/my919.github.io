第五章：集成 Swagger：springdoc 接口文档

概念基础

  1. OpenAPI 是 REST API 的描述规范（结构化 JSON/YAML），Swagger UI 把规范渲染成可交互文档：在线查看接口与参数，并直接发起调试请求。
  2. springdoc-openapi 是 Spring Boot 生态的规范实现：启动时扫描 Controller 与注解自动生成 /v3/api-docs，文档与代码同源，不靠手写维护；本工程用 springdoc 3.0.1 配 Spring Boot 4。
  3. 注解驱动：@Schema 描述字段含义，@ExampleObject 提供可复现请求示例（下单成功 / 触发回滚两种），配合常量类避免魔法字符串。
  4. 为什么重要：微服务接口多、调用方多，文档即契约——示例与仓库文件一致，联调效率与前后端/服务间一致性显著提升。
  5. 边界：网关不聚合各服务 OpenAPI，日常走服务直连端口打开 UI；生产环境应关闭文档或加访问控制，避免接口信息泄露。

概述

API 文档使用 springdoc-openapi（父 POM springdoc.version 3.0.1），与 Spring Boot 4 / Spring MVC 兼容。公共路径在 cloud-common 的 application-shared.yml；带 UI 的模块在各自 pom.xml 引入 springdoc-openapi-starter-webmvc-ui。

常见问题

Q：gateway 上打不开 swagger-ui？
A：未配置聚合路由；请用 8003 等直连端口，或自行增加 Gateway 路由到 /v3/api-docs。

Q：springdoc 2.x 升级到 3.x 要注意什么？
A：包名仍为 org.springdoc；需与 Spring Boot 4 对齐，勿混用 Boot 3 的旧 starter 版本。

Q：生产环境要关文档吗？
A：可通过 profile 排除 springdoc-openapi-starter-webmvc-ui 依赖，或 springdoc.api-docs.enabled=false / swagger-ui.enabled=false。

本章小结

要点 结论
技术选型 springdoc-openapi 3.0.1 + Spring Boot 4，UI starter 按模块按需引入
