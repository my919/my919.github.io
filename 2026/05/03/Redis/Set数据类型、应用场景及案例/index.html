第六章：Redis Set 数据类型：概念、命令与案例

概念基础

Set 是无序、不重复的字符串成员集合，直接对应数学里的「集合」：

  1. TYPE key 为 set。
  2. 不保证顺序（遍历顺序实现依赖，勿当有序结构用）。
  3. 成员即字符串；同一成员重复 SADD 只保留一份，判重是 O(1)——这是它与 List 最本质的差异。
  4. 集合间可做 SINTER / SUNION / SDIFF（交 / 并 / 差），把「共同关注」「可能认识的人」这类关系计算下推到 Redis 里完成。

核心原理：编码与复杂度

  1. 两种编码（OBJECT ENCODING key 观察）：
    • intset：成员全部是整数且个数不超过 set-max-intset-entries（默认 512）时使用，有序整数数组 + 二分查找，最省内存。
    • hashtable：一般情况使用，member 作字典的 key、value 恒为 NULL——「唯一性」由哈希表天然保证，SADD / SISMEMBER / SREM 均 O(1)。
  2. 集合运算的代价：SINTER / SUNION / SDIFF 最坏 O(N·M)（两个集合都大时开销显著），且是同步计算——生产上建议用 SINTERSTORE 等 STORE 系列写入新 key，再异步消费结果，避免大运算阻塞在交互命令里。
  3. 随机语义：SPOP 是弹出（取出并从集合删除，不放回）；SRANDMEMBER 只读不删（count 为正给不重复成员、为负允许重复）——抽奖「不放回」用 SPOP、「仅看看」用 SRANDMEMBER。

常用命令（必会子集）

命令 作用
SADD / SREM 增删成员
SMEMBERS 返回全部成员（大集合慎用）
SISMEMBER / SCARD 是否在集合 / 成员个数
SRANDMEMBER / SPOP 随机读 / 随机弹出
SINTER / SUNION / SDIFF 交 / 并 / 差（可带 STORE 写到新 key）

典型应用场景

  1. 标签：SADD article:7:tags Java Redis。
  2. 抽奖池 / 去重 ID 池：SPOP 不放回抽样（需理解并发下多个客户端抢 SPOP 的语义）。
  3. 共同关注：SINTER user:1:following user:2:following。

注意事项

  1. 大 Set：SMEMBERS 一次性拉全量可能阻塞与占带宽，用 SSCAN 迭代。
  2. 与 List：Set 无序且唯一；List 有序可重复。
  3. 需要按分数排序（排行榜）→ 用 ZSet，不要用 Set 硬撑。

本章小结

要点 结论
本质 无序、唯一，O(1) 判重
编码 intset（全整数小集合）→ hashtable
集合运算 SINTER/SUNION/SDIFF，大集合用 STORE 系列异步化
高频命令 SADD / SISMEMBER / SCARD / SINTER / SPOP
场景 标签、去重、抽奖、共同关注
