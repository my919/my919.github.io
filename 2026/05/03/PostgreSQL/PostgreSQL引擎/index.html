第三章：PostgreSQL 存储引擎与表访问方法

发表于 2026-05-03 更新于 2026-09-01 分类于 PostgreSQL 本文字数： 1k 阅读时长 ≈ 3 分钟

第三章：PostgreSQL 存储引擎与表访问方法

概念基础

  1. 表访问方法（Table Access Method）：PostgreSQL 12+ 把「表数据如何组织与读写」抽象为可插拔接口，建表时可用 USING 指定，默认即 heap——这是 PostgreSQL 语境里最接近 MySQL「引擎」的概念。
  2. 堆表（Heap）：行按写入顺序无序堆放在页中，用 tid（块号 + 行号） 定位；索引里存的是 tid，查数据通常要「索引 → 回表」。
  3. MVCC 是配套设计：行头维护 xmin / xmax 版本信息，更新与删除产生新版本 / 死元组，由 VACUUM 回收——这直接决定了 PostgreSQL 的性能调优姿势。
  4. 与 MySQL 的本质差别：MySQL 建表时选 ENGINE=InnoDB，PostgreSQL 没有这个开关：统一内核 + 统一 heap，列存、分片等需求走扩展与架构层，而不是换「引擎」。

先看默认的存储方式：

一、表数据默认怎么存：Heap（堆表）

  • 普通 CREATE TABLE 默认即 heap 表：行以堆页存放，通过 tid（块号 + 行号） 定位。
  • MVCC 在元组头维护版本信息（xmin / xmax 等），更新与删除产生新版本/死元组，依赖 VACUUM 回收（见 第五章：PostgreSQL 索引与性能优化）。
  • 与 InnoDB 聚簇索引即整表不同：PostgreSQL 主键索引是二级索引，堆上存行，主键查找通常「索引 → 回表 tid」。

二、表访问方法（Table Access Method）

PostgreSQL 12+ 起，表可指定 USING heap（默认）；理论上可挂自定义表访问方法（需扩展提供）。
生产常见仍是 heap；列存、混存等多在扩展或外部产品（如某些分析型方案）中实现，不等价于 MySQL 换一个 ENGINE 字符串。

三、与「引擎」易混的几个概念

概念 说明
TABLESPACE 表/索引的文件放置位置（如 pg_default），不是另一种行存储引擎。
TOAST 大字段行外存储机制，对用户基本透明。
Foreign Data Wrapper（FDW） 外部表：数据在远程；语法像本地表，语义与本地 heap 完全不同，不是换存储引擎。
内置索引类型 B-Tree、Hash、GiST、GIN、BRIN 等是索引访问方法，不是替换 heap 的「表引擎」。

四、和 MySQL InnoDB 的粗对照（选型沟通用）

话题 MySQL（MySQL引擎.md） PostgreSQL（本文）
建表选「引擎」 ENGINE=InnoDB 等 无；默认 heap + 统一内核
行存与主键 InnoDB 聚簇主键与数据同树 堆行 + 主键索引
并发读写的核心 InnoDB MVCC + 锁 MVCC + 行锁（见 第六章：PostgreSQL 并发与 MVCC 入门）

五、实务建议

  1. 学习 PostgreSQL 时少问「用哪个引擎」，多问索引类型、执行计划、VACUUM、隔离级别与锁。
  2. 需要列存、分片、多副本高可用时，在架构层选专用扩展或产品（如 Citus、云厂商数仓、读写分离），而不是在 CREATE TABLE 里找一个 ENGINE 开关。
  3. 版本升级（14 → 16 → 17）会带执行器与优化器演进，「升级引擎」口语上常指升级主版本，与 MySQL 的 ENGINE 不是同一概念。

本章小结

要点 结论
默认存储 heap 堆表：行按 tid 定位，主键索引是二级索引，查找需回表
表访问方法 PG 12+ 支持 USING heap 抽象，但生产实际仍是 heap，列存等方案多在架构层
