第二章：SpringBoot 多环境配置：Profile 激活与优先级

概念基础

多环境配置让同一份代码在开发、测试、生产之间只切换配置、不改代码：

  1. Profile 机制：Spring 用 Profile 在 dev / test / prod 之间切换配置；本仓库（springboot）以 application.yaml 承载公共配置，各环境文件只写差异项；相同 key 时环境文件覆盖公共配置。
  2. 激活方式多样：配置文件 spring.profiles.active、环境变量 SPRING_PROFILES_ACTIVE、启动参数 --spring.profiles.active=prod，本项目默认 dev。
  3. 职责划分：端口、应用名、框架级默认值放公共；数据库/Redis 地址与密码、日志级别、Swagger 开关放环境。
  4. 敏感信息外部化：密码经环境变量注入，生产禁止提交 Git；更大规模可接 Nacos 配置中心（共享 dataId + 环境 dataId，后者覆盖前者）。
  5. 测试隔离：src/test/resources/application.yaml 独立于业务 Profile，用 H2 内存库与 Mock 中间件保证 gradlew test 稳定可重复。

微服务多模块 + Nacos spring.config.import 见 第二章：Spring Cloud 多环境配置与 Nacos：Profile 与 config.import 分层（2025.1.x 无 bootstrap，与单体 Profile 思路不同）。

配置加载流程

  A[application.yaml 公共] --> B{SPRING_PROFILES_ACTIVE}
  B -->|dev| C[application-dev.yaml]
  B -->|test| D[application-test.yaml]
  B -->|prod| E[application-prod.yaml]
  C --> F[生效配置合并]

本项目的文件结构

Profile 文件 典型用途
dev application-dev.yaml 本地开发（默认）
test application-test.yaml 联调 / 测试环境
prod application-prod.yaml 生产

激活方式

配置优先级（从低到高）

  1. application.yaml（公共）
  2. application-{profile}.yaml（当前环境，覆盖同名 key）
放公共 放环境
端口、应用名、MyBatis-Flex 日志级别、Swagger 开关
框架级 app.* 默认值 Actuator 暴露、CORS 来源
dynamic-datasource 结构 数据库/Redis 地址与密码

连接池参数见 第十三章：数据库连接池：HikariCP与Druid对比与落地。

各环境差异

dev

  • Swagger / OpenAPI 开启
  • 日志 DEBUG；MyBatis SQL 控制台（StdOutImpl）
  • CORS 允许 localhost / 127.0.0.1

test

  • Swagger 开启；MyBatis SQL 走 Slf4j
  • 日志 INFO

prod

  • Swagger 关闭
  • Actuator 仅 health,info,metrics,prometheus
  • 健康详情 when_authorized
  • CORS 使用 APP_CORS_ORIGINS
  • app.log.request.log-params: false

敏感信息

做法 说明
环境变量 REDIS_HOST、MYSQL_PASSWORD、SPRING_PROFILES_ACTIVE
配置中心 生产可接 Nacos（见 Spring Cloud 专题）
禁止 生产密码提交 Git

局域网中间件地址见 服务（MySQL :30000、Redis :30005 等）。

可选：Nacos 配置中心

与本地多文件思路一致：共享 dataId + 环境 dataId，后者覆盖前者。

Boot 4 + SCA 2025 须用 spring.config.import: optional:nacos:...，详见 第二章：Spring Cloud 多环境配置与 Nacos：Profile 与 config.import 分层。

测试环境（单元测试）

src/test/resources/application.yaml 独立于上述 Profile：

  • H2 内存库替代 MySQL/Pg
  • Mock Redis；关闭 RustFS、防重/幂等

gradlew test 不加载 application-dev.yaml。

本章小结

要点 结论
公共/差异分离 application.yaml 承载公共配置，application-{profile}.yaml 只写差异项
覆盖规则 相同 key 时环境文件覆盖公共配置
