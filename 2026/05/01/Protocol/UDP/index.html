第五章：UDP 协议详解：数据报语义、MTU 与示例代码

概念基础

  1. 无连接的数据报协议：与 第一章：TCP 协议详解：连接、可靠传输与编程示例 相对——无握手、无连接状态机，拿到目的地址首包即可发数据，每个数据报独立路由。
  2. 保留报文边界：一次 sendto 对应一个 UDP 数据报，对端 recvfrom 通常一次收到完整一报；而 TCP 是无消息边界的字节流。
  3. 尽力交付：不保证到达、不保证顺序、不负责重传；可靠性由应用或 第十五章：QUIC 详解：基于 UDP 的可靠传输、TLS 集成与 HTTP/3 等在 UDP 之上补充。
  4. 为什么快：首部仅 8 字节、无握手往返、无状态管理，延迟低、实现简单——适合 第十章：DNS 详解：解析原理、记录类型与命令/代码示例、实时音视频、指标上报。
  5. 代价与风险：载荷过大触发 IP 分片（丢一片常导致整组重组失败）；公网服务须防 UDP 反射放大与滥用。

先看它与 TCP 的本质差异：

设计目标与作用

1. 解决什么问题

  • 低延迟：无握手、无连接状态机，首包即可发数据。
  • 保留报文边界：一次 sendto 对应一个 UDP 数据报；对端 recvfrom 通常一次收到完整数据报（受缓冲区与实现限制；载荷过大时可能失败或行为依平台）。
  • 实现简单：适合 第十章：DNS 详解：解析原理、记录类型与命令/代码示例、实时音视频、指标上报；可靠性由应用或 第十五章：QUIC 详解：基于 UDP 的可靠传输、TLS 集成与 HTTP/3 等在 UDP 之上补充。

2. 与 TCP 的本质差异

维度 UDP 第一章：TCP 协议详解：连接、可靠传输与编程示例
连接 无 有（三次握手 / 四次挥手）
交付 尽力，可能丢、乱序、重复 可靠有序（重传隐藏丢包）
语义 保留消息边界（数据报） 字节流（无消息边界）
套接字 bind + recvfrom / sendto，无 listen/accept listen/accept/connect 等

无连接：通信流程（原理）

UDP 不建立会话状态；每个数据报独立路由，「流程」体现在应用与内核 API 的调用顺序上。

1. 完整通信流程（与套接字 API 对应）

  1. 服务端：socket(AF_INET, SOCK_DGRAM, 0) → bind 本地地址与端口 → 循环 recvfrom（每次返回一整报与对端地址 sockaddr）→ sendto 把应答写回该地址。无 listen、无 accept。
  2. 客户端：socket → 可直接 sendto 指定目的地址；首次发送时内核通常分配临时源端口。若需读回应，再 recvfrom（可配合超时或 select/poll）。
  3. 传数据：每个数据报自带目的信息；无序号、无确认，不保证与发送顺序一致，也不保证不丢。
  4. 关闭：close 仅释放本进程套接字资源；不会在协议层通知对端「连接结束」（与 第一章：TCP 协议详解：连接、可靠传输与编程示例 的 FIN 不同）。

UDP 首部与校验和（原理）

UDP 首部固定 8 字节：源端口、目的端口、长度、校验和。IPv6 下 UDP 校验和必填；IPv4 允许为 0（表示未使用校验和，实践中少见）。校验覆盖伪首部（含 IP 地址与协议号）+ UDP 首部 + 数据，用于检测传输错误；通过校验和 ≠ 应用层已处理完毕（仍可能丢包、乱序）。

MTU 与分片（为何要注意报文长度）

以太网常见 MTU 1500，扣掉 IP 首部后 UDP 载荷不宜过大，否则触发 IP 分片：任一片丢失常导致整组重组失败，丢包代价被放大。应用层常将 UDP 报文控制在 1200 字节左右以下（穿越未知路径更稳），或自行分片与重传。

四元组与套接字

与 第一章：TCP 协议详解：连接、可靠传输与编程示例 相同，IP 层与常见实现仍用 （源 IP，源端口，目的 IP，目的端口） 区分不同「对话」；区别在于 UDP 内核不维护 第一章：TCP 协议详解：连接、可靠传输与编程示例 那样的连接状态机（无 ESTABLISHED / TIME_WAIT 等）。服务端 bind 固定端口（如 53），客户端源端口多为临时端口。
