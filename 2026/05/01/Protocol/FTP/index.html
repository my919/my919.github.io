第七章：FTP 详解：双连接模型、主动/被动与 lftp 示例

概念基础

  1. 历史最悠久的文件传输协议之一：在 TCP/IP 早期就提供跨异构系统的列目录、上传、下载与断点续传（由扩展命令支持程度决定），命令为可读文本（如 RETR、STOR、LIST），便于人机调试。
  2. 双连接模型是最大特点：TCP 21 的控制连接（命令/响应，全程保持）+ 每次传送动态建立的数据连接（文件内容 / LIST 输出）——与「单连接一用到底」的协议截然不同。
  3. 主动 PORT vs 被动 PASV：主动=服务端从 20 端口反向连出（客户端在 NAT 后时常失败）；被动=客户端连入服务端通告的端口（主流，防火墙须放行被动端口范围）。
  4. 明文是硬伤：用户名、密码与数据默认明文；FTPES 在 TLS 上加密但仍保留双连接复杂性——公网新系统优先 第八章：SFTP 详解：SSH 子系统、协议栈与 sftp 示例 或对象存储 HTTPS 上传。

先看它为什么这样设计：

设计动机（历史作用）

在 TCP/IP 早期提供跨异构系统的文件列目录、上传、下载与断点续传（由扩展命令支持程度决定）；命令为可读文本（如 RETR、STOR、LIST），便于人机调试。

双连接模型（原理）

控制连接全程保持；每条数据传送动态建立数据连接。

主动 PORT 与被动 PASV

1. 主动（PORT）

服务端从 20 端口向客户端在 PORT 命令中声明的 IP:端口 主动连出。客户端在 NAT 后时常失败（内网端口对服务端不可达）。

2. 被动（PASV）（主流）

服务端在应答中给出监听 IP 与端口，客户端主动连入。防火墙须在服务端放行被动端口范围；NAT 下常需配置对外通告地址（如 masquerade_address）。

明文与认证
