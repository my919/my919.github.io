第四章：HTTPS 详解：TLS 握手、证书与 openssl/curl 示例

概念基础

  1. HTTP + TLS，不是新协议：HTTPS 就是先经 TLS 加密、再传输 第二章：HTTP 详解：报文、方法、版本与 curl/nc 示例 报文——URL 以 https:// 开头，默认端口 443（明文 HTTP 为 80）。
  2. TLS 提供三件事：机密性（对称加密防窃听）、完整性（MAC / AEAD 防篡改）、身份认证（X.509 证书链证明「服务器是它声称的那个」，可选客户端认证）。
  3. 握手定密钥，传输用对称：TLS 握手（1.3 常 1-RTT）协商出对称会话密钥，之后 HTTP 记录用对称算法加密以获得性能。
  4. 证书链是信任根基：浏览器校验证书是否由受信任 CA 签发、SAN 是否覆盖主机名、是否在有效期内；自签名证书仅限内网与开发。
  5. 不解决什么：TLS 不能替代应用层鉴权与输入校验，https:// 不等于站点没有 XSS/CSRF 等业务漏洞。

作用与威胁模型

1. TLS 提供什么

  • 机密性：对称加密载荷，防窃听。
  • 完整性：MAC / AEAD 防篡改。
  • 身份认证：服务端（可选客户端）X.509 证书链。

2. 不解决什么

TLS 不能替代应用层鉴权与输入校验；https:// 也不等于站点无 XSS/CSRF 等业务漏洞。

TLS 1.2 / 1.3 握手（原理简述）

1. 共同目标

客户端与服务端协商出对称会话密钥，后续 HTTP 记录用对称算法加密以获得性能。

2. TLS 1.3 特点（相对 1.2）

  • 常 1-RTT 完成握手（0-RTT 可选，有重放风险，敏感操作应禁用或二次校验）。
  • 废弃一批不安全算法；Hello 中即携带密钥共享材料。

证书链与主机名（作用）

浏览器/客户端会校验：

  1. 证书是否由受信任 CA 签发，链是否完整。
  2. Subject Alternative Name（SAN） 或兼容字段是否覆盖当前访问主机名。
  3. 有效期、吊销信息（OCSP Stapling 等）。

自签名证书仅适合内网或开发，公网须使用可信 CA 或组织内 PKI。

ALPN

在 TLS 握手中通过 ALPN 协商应用层协议：h2 表示后续走 HTTP/2 帧；h3 与 第十五章：QUIC 详解：基于 UDP 的可靠传输、TLS 集成与 HTTP/3 / HTTP/3 相关（QUIC 内含 TLS 1.3 集成握手）。

本章小结

要点 结论
本质 HTTPS = TLS + HTTP；提供机密性、完整性、服务端身份，不替代业务安全
握手 TLS 1.3 常 1-RTT；0-RTT 有重放风险；ALPN 协商 h2/h3
证书 CA 信任链 + SAN 覆盖主机名 + 有效期；自签名仅限内网
排障 openssl s_client 看证书与协商；curl -v --tlsv1.3 验证版本
