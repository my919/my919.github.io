第三章：Node.js 运行时与服务开发

概念基础

  1. 单线程事件循环：Node 在单线程里跑 JS，用 libuv 事件循环调度 IO；CPU 密集任务会阻塞所有请求——这是它「适合 IO 密集、不适合计算密集」的根源。
  2. 异步是第一公民：回调 → Promise → async/await 一脉相承；Promise.all 并行、AbortController 取消，现代 JS 已能写出清晰的并发代码。
  3. 双模块体系：CommonJS（require）是历史主流，ESM（import/export）是标准方向；Node 22 已稳定支持 ESM，新项目优先 ESM。
  4. Stream 处理大文件：不必把 10GB 日志读进内存——流式读写按块处理，配 pipe/pipeline 组合加工。
  5. 生态即生产力：Express/Fastify 提供路由与中间件骨架，npm/pnpm 管依赖（版本管理见 第一章：Node 环境管理 nvm 实践，类型护栏见 第二章：TypeScript 语言入门：类型系统与工程实践）。

本章代码在 Node v22 下全部运行验证（含事件循环顺序、Stream、AbortController）。

一、事件循环：执行顺序

记忆法：同步代码 → process.nextTick（最高优先级微任务）→ Promise 微任务队列 → 一次宏任务（timer/IO）→ 循环。

top-level await 会改变顺序：ESM 模块带顶层 await 时，模块求值由微任务驱动，实测 nextTick 回调会被推迟到 await 恢复之后执行——库代码里对顺序敏感的逻辑要留意。

常见避坑

坑 现象 正确做法
回调地狱 + 未处理 Promise 嵌套 callback、await 漏写导致 Promise 挂起，崩溃只在日志里看到 UnhandledPromiseRejection 全局统一 async/await；加 process.on('unhandledRejection', …) 兜底记录并退出
阻塞事件循环 JSON.parse 超大对象、正则 Catastrophic Backtracking、fs.readFileSync 放在热路径，吞吐量陡降 CPU 密集拆到 worker_threads 或子进程；正则写好边界；大 JSON 走流式 JSONStream
require 缓存导致单例不一致 两次 require('./db') 拿到不同实例（路径大小写/符号链接不同） 统一引用路径大小写；跨模块共享状态走显式导出的单例对象，不要指望 require 缓存
Express 中间件顺序错放 CORS 放在路由之后 → 预检请求 404；bodyParser 放在路由前漏掉 JSON 解析 顺序：日志 → CORS → bodyParser → 路由 → 404 → 全局错误中间件，共 5 段
req.body 永远空 请求是 multipart/form-data 但只用了 express.json() 文件上传用 multer；纯表单用 express.urlencoded({ extended: true })
next(err) 写成 throw err 在异步 路由 handler 里异步抛异常 Express 4 拿不到，直接炸进程 所有异步路由用 try/catch 包 next(err)；或装 express-async-errors 全局补丁
循环依赖（ESM/CJS 均有） 导出的变量一开始是 undefined，后面才赋值 拆公共模块到第三文件；把引用移到函数内延迟加载
依赖版本漂移 本地跑 OK，CI/线上不一样 提交 lockfile（package-lock.json / pnpm-lock.yaml），CI 用 npm ci / pnpm i --frozen-lockfile
内存泄漏找不到 RSS 持续增长、GC 回收不下来 启动加 --inspect 抓 heap snapshot；常见根因：全局对象/Map 积累、闭包持有大对象、EventEmitter 未 off
.env 提交到仓库 账号密码随 Git 外泄 .env 加入 .gitignore；敏感配置用环境变量 / Secret Manager；模板留 .env.example

本章小结

要点 结论
事件循环 同步 → nextTick → Promise 微任务 → 宏任务；top-level await 会改变 nextTick 时机
模块 新项目用 ESM；静态分析利于 tree-shaking，支持顶层 await
异步 Promise.all/allSettled 管并行；AbortSignal.timeout 管超时；错误带语义化 code
HTTP Express 中间件流水线：解析 → 横切 → 路由 → 错误兜底
Stream pipeline 处理大文件，内存恒定；逐块加工用 Transform
工程 lockfile 提交、配置走环境变量、SIGTERM 优雅退出
