第二章：TypeScript 语言入门：类型系统与工程实践

概念基础

  1. TS = JS + 类型系统：TypeScript 是 JavaScript 的超集，在 JS 语法之上叠加静态类型；合法 JS 代码基本就是合法 TS 代码，存量项目可以平滑迁移。
  2. 编译期检查：类型不匹配、属性拼错、漏传参数在 tsc 编译期就报错，而不是等上线后在运行时炸掉——这是它与纯 JS「跑到才知道」最大的差别。
  3. 类型擦除：TS 只做检查、不改造运行时——类型标注在 tsc 或 esbuild / swc 的转译链路中被整体擦除，最终执行的仍是纯 JS，运行时行为与 JS 完全一致。
  4. 类型即文档：interface / type 描述数据形状，IDE 的补全、跳转、重构都基于它，大型项目跨团队协作成本显著降低。
  5. 渐进式采用：allowJs 允许 JS/TS 混编，// @ts-check 可对单个 JS 文件开启检查，任何规模的现有项目都能按文件、按目录逐步迁移。

为何使用 TypeScript

收益 说明
早期发现错误 类型不匹配、属性拼写在编译期报错
IDE 体验 跳转、重构、补全更可靠
大型项目可维护 接口与类型即文档，跨团队协作成本更低
渐进式采用 allowJs、// @ts-check 可逐步迁移

与纯 JS：运行时行为一致；类型在 tsc 或 esbuild/swc 链路中被擦除。

基本类型与接口

  • 联合类型：string | number
  • 字面量类型：'GET' | 'POST'
  • 类型别名：type Id = string | number

泛型与工具类型

常用内置工具类型：Partial、Required、Pick、Omit、Record、ReturnType。

tsconfig 要点

  • strict: true：启用 strictNullChecks 等，推荐新项目打开。
  • module: NodeNext：与 Node ESM/CJS 互操作对齐（Node 18+ 常见）。

与工程栈的关系

  • Node 后端：配合 Express / Fastify / NestJS，类型定义包 @types/node。
  • 前端：第一章：Vue 3 核心概念与组件开发 + 第二章：Vite 工程化构建与部署 默认 TS 模板；vue-tsc 做类型检查。
  • 构建：tsc --noEmit 仅检查；打包可用 Vite / esbuild 更快转译。

常见避坑

坑 现象 正确做法
any 当万能类型 类型系统形同虚设，重构时编译器不报错 严格模式下用 unknown 替代入参、类型守卫收窄；仅临时对接无类型库时用 any
undefined 没做检查 strictNullChecks 开启后报 “Object is possibly undefined” 用可选链 a?.b、空值合并 a ?? default、或显式 if (x != null) 收窄
interface vs type 混淆 合并声明不生效、或泛型展开报错 合并类/对象扩展用 interface（支持 declaration merging）；联合类型/映射类型用 type
esModuleInterop: false import express from "express" 报类型错误，运行时却正常 tsconfig 固定打开 esModuleInterop: true；写 CommonJS 依赖的导入
as 强制断言过滥 把错误写成类型安全，运行时炸 断言只用于”我比编译器更清楚类型”的边角；复杂收窄写类型守卫函数
忘记 @types/* 用 lodash 等纯 JS 库无类型提示、编译报红 npm i -D @types/lodash @types/node 等类型定义包
tsc 与打包器行为不一致 tsconfig 配了 paths，Vite/Node 运行时报找不到模块 tsconfig 的路径别名只是类型期解析；打包器（Vite/tsup）需另配 resolve.alias，运行时用 tsx / ts-node（ESM 插件）
enum 产生运行时代码 体积膨胀，Tree-shaking 不友好 多数场景改用 as const 的对象 + keyof/typeof，或字符串联合类型
泛型约束只写 <T> 调用时类型全丢失，跟写 any 差不多 加 <T extends HasId> 约束，或用默认类型 <T = unknown>

Node 版本管理见 第一章：Node 环境管理 nvm 实践。

官方手册：https://www.typescriptlang.org/docs/

本章小结

要点 结论
定位 TS 是 JS 超集，类型在编译期检查、运行前擦除
核心收益 编译期报错 + IDE 补全/重构 + 类型即文档
基础语法 interface / type 描述结构，联合与字面量类型收窄取值范围
进阶 泛型 + Partial / Pick / Omit 等工具类型做类型变换
工程入口 strict: true 的 tsconfig + tsc --noEmit 检查，构建交给 Vite / esbuild
