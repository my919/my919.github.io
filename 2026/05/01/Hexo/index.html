Hexo 博客

Hexo 是基于 Node.js 的静态博客框架，用 Markdown 写作，一键生成全站并可免费部署到 GitHub Pages。下面从准备、安装、写作、预览、部署、主题与常用命令，一步步讲清楚。

概念基础

  1. 静态站点生成器（SSG）：Hexo 把 Markdown 源文件在本地渲染成纯 HTML/CSS/JS，无数据库、无后端，托管成本几乎为零。
  2. Node.js 生态：基于 Node.js 运行，hexo-cli 脚手架 + npm 插件体系，主题、部署、压缩、搜索等能力均可插件化扩展。
  3. 写作即发文：hexo new 生成带 front-matter（title/date/tags/categories）的 Markdown 文章，放入 source/_posts/（可按子目录组织）即被站点收录。
  4. 部署自由：GitHub Pages 免费上线，也可用 hexo-deployer-git 推送到 Gitee Pages、VPS 或对象存储。
  5. 主题可定制：NexT 等主题提供分类、标签、站内搜索、SEO、评论等成熟能力，站点配置集中在 _config.yml。

创建时指定分类、标签（可选）

Hexo 会把 hexo new 里除标题、--path、--slug 等保留项以外的参数写进 front-matter，因此可在同一条命令里带上 categories、tags：

  • --categories：一般写一个即可（与分类页一致）。
  • --tags：需要多个标签时，重复写 --tags 标签A --tags 标签B（会生成 YAML 列表）；若只写一个字符串如 --tags "UV,Python"，会落成单个标签字符串，通常不如多次 --tags 清晰。

十二、GitHub Actions 自动部署

手动 hexo d 依赖本地环境；把站点源码推到仓库后，让 GitHub Actions 在云端自动「安装依赖 → 生成 → 发布」，换电脑只管写作。注意：Actions 发布的是 public/ 产物，与 hexo d（hexo-deployer-git）二选一即可，两套同时用会来回覆盖历史。

1. 准备

  • 源码仓库：如 my919/hexo-source（建议私有，存放 _config.yml、source/ 等源文件）
  • 发布仓库：my919/my919.github.io（Pages 仓库）
  • 在源码仓库 Settings → Secrets and variables → Actions 添加 TOKEN：值为 GitHub Personal Access Token（需对发布仓库的写权限；若源码与发布同账号同仓库，可直接用内置的 GITHUB_TOKEN）

十三、常见问题排查

现象 原因与处理
页面样式全丢 theme: 名称写错或主题配置未生效；hexo clean && hexo g 后确认 public/ 下有主题静态资源
文章不显示 front-matter 的 YAML 语法错误（冒号后缺空格、缩进不对），看 hexo g 输出的 warning
post_link 构建报错或渲染成原始文本 引用路径/标题与目标文章 front-matter title 不一致；构建错误信息会指出具体链接
本地预览正常、部署后异常 先 hexo clean 再 hexo g && hexo d；确认部署分支与 Pages 设置一致（如 master）
改主题配置不生效 用「拷贝进 node_modules/hexo-theme-next/」方式时需重新拷贝；Hexo 5+ 也支持根目录 _config.next.yml 作为主题配置（优先于主题内配置，无需拷贝）
中文文件名链接异常 hexo new --path 用英文文件名，页面标题交给 front-matter title 控制
生成越来越慢 检查是否把大资源（PDF/大图/模型文件）放进了 source/；移出 source/ 或改走图床/CDN，大文件交给 Git LFS（见 Git 版本控制入门 十五）

排查三板斧：hexo clean → 看 hexo g 的 warning / error → 比对 public/ 产物。
