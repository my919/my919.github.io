第三章：MyBatis-Plus 快速上手与分页原理

概念基础

MyBatis-Plus（简称 MP） 是 MyBatis 的增强工具，定位是「只做增强不做改变」：

  1. 通用 CRUD：Mapper 继承 BaseMapper 即可获得 selectById、insert、update 等单表增删改查能力，免写 XML。
  2. 插件体系：通过 MybatisPlusInterceptor 注册分页、乐观锁、防全表更新等内部拦截器，按需装配。
  3. 分页零侵入：内置 PaginationInnerInterceptor，基于 MyBatis 拦截器自动生成 count 语句、改写 SQL 拼接 LIMIT，业务代码只传 Page 参数。
  4. 代码生成：配合 IDEA 插件（如 MyBatisX-Generator）可从数据库表直接生成 Entity / Mapper / Service 代码。
  5. Spring Boot 集成：提供 mybatis-plus-spring-boot*-starter 起步依赖，配好 mapper-locations 与驼峰映射即可使用。

MyBatis-Plus 分页原理

一、核心一句话

MP 分页本质：MyBatis 拦截器 + 自动改写 SQL

  1. 你传入 Page<>(当前页,每页条数)
  2. MP 分页拦截器拦截 Mapper 查询方法
  3. 自动帮你生成 count 总数SQL + 拼接 limit 分页SQL
  4. 执行两条 SQL：查总数 → 查当前页数据
  5. 把总数、页码、数据封装到 IPage 返回

二、关键核心组件

  1. MybatisPlusInterceptor
    MP 核心插件容器，所有插件（分页、防全表更新、乐观锁）都往里注册。
  2. PaginationInnerInterceptor
    MP 真正的分页拦截器，核心逻辑全在这。
  3. Page / IPage
    分页参数载体，存：当前页、每页条数、总记录数、总页数、分页数据。

1. 配置分页拦截器（必须配置，否则分页无效）

2. 业务代码使用

3. 底层执行步骤

  1. 进入 Mapper 方法前
    PaginationInnerInterceptor 拦截到 selectPage 查询。
  2. 判断是否是分页查询
    检测方法参数里有没有 IPage/Page 对象，有就走分页逻辑。
  3. 自动生成 COUNT 语句
    原SQL：select id,name from user
    自动生成：select count(*) from user → 查询总记录数
  4. 改写原SQL 加 LIMIT
    原SQL 被改写为：
    select id,name from user limit 0,10
  5. 执行两条 SQL
    • 第一条：查总条数
    • 第二条：查分页数据
  6. 封装分页信息
    把总条数、当前页、每页大小、总页数、数据列表 全部塞进 IPage 返回。

四、为什么不用自己写 limit、不用自己写 count？

MP 拦截器动态解析 SQL、动态拼接 limit、动态生成 count，完全无侵入。

五、分页两个重要特性

1. 分页合理化 reasonable=true

  • 输入页码 <=0 自动变成第 1 页
  • 输入页码 大于总页数 自动返回最后一页

2. 溢出总页数后是否查最后一页

PaginationInnerInterceptor 可配置，防止页码乱输报错。

六、常见坑（原理衍生出来的）

  1. 没配置 PaginationInnerInterceptor → 分页无效，查全部数据
  2. 只有 Mapper 层用 Page 参数才生效，Service 自己写 list 不分页
  3. 自定义 XML SQL 也能自动分页，MP 照样拦截加 limit、count
  4. 多表联查、复杂 SQL 也支持，拦截器会解析原有 SQL 结构

七、极简总结

MP 分页 = 拦截器拦截SQL → 自动查总数 → 自动拼接LIMIT → 封装分页结果

不用手写 count、不用手写 limit，全靠拦截器动态代理实现。

本章小结

要点 结论
引入方式 mybatis-plus-spring-boot4-starter 起步依赖 + @MapperScan 扫描 Mapper 包
分页生效条件 必须注册 MybatisPlusInterceptor 并添加 PaginationInnerInterceptor，否则分页无效
分页原理 拦截器自动生成 count SQL 并改写原 SQL 拼接 LIMIT，两条 SQL 完成分页后封装进 IPage
实用特性 分页合理化 reasonable、溢出回退末页；自定义 XML 与多表联查 SQL 同样支持
常见坑 仅 Mapper 方法携带 Page 参数才触发分页；Service 自行 list() 不会分页
