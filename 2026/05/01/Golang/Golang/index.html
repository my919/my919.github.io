第一章：Golang 语言基础

第一章：Golang 语言基础

概念基础

  1. 为工程而生：Go 由 Google 2009 年发布，目标是解决大型工程的编译慢、依赖乱、并发难三大痛点——编译秒级、go mod 原生依赖管理、语言级并发。
  2. 语法极简：全语言只有 25 个关键字，无类继承、无异常、无隐式转换，强制 gofmt 统一格式——评审时不再为风格争吵。
  3. 静态类型 + 垃圾回收：编译型语言享受类型安全与运行速度，GC 免去手动内存管理；值语义为主，切片/映射/指针是理解内存行为的关键。
  4. 组合优于继承：结构体嵌组合复用，接口隐式实现（duck typing 的静态化），小接口（io.Reader/error）组合出灵活抽象。
  5. 错误是值：没有 try/catch，函数用多返回值显式返回 error，调用方必须处理——代码啰嗦但流向清晰。

本章是 Golang 系列的起点，覆盖语法核心与工程结构。并发是 Go 的招牌，单独成章见 第二章：Golang 并发编程。

一、安装与工具链

命令 作用
go mod init <module> 初始化模块（现代 Go 项目的第一步）
go build ./... 编译当前模块所有包
go run main.go 编译并立即运行
go vet ./... 静态检查可疑代码
gofmt -w . 格式化（或 go fmt ./...）

国内加速模块下载：go env -w GOPROXY=https://goproxy.cn,direct。

基本类型速查：

四、复合类型：数组、切片、映射、结构体

1. 切片 slice（核心）

切片是「底层数组 + 长度 len + 容量 cap」的视图，是 Go 最常用的序列类型：

append 重指向：append 可能返回新底层数组，必须接住返回值 s = append(s, x)；把切片传给函数后 append 无效，是经典 bug。

2. 映射 map

map 遍历顺序随机是刻意设计（防依赖顺序）；nil map 可读不可写（写 panic）；map 不是并发安全，并发读写需加锁或用 sync.Map（见第二章）。

3. 结构体 struct

没有构造函数：惯用 NewUser(...) *User 工厂函数；未列出的字段保持零值。

五、控制流

switch 自动 break + 无类型限制（接口动态类型 switch 是类型分支 x.(type)，见第六节）。

六、函数与 defer

defer 三要点：参数立即求值（defer fmt.Println(i) 记录当时 i）；多个 defer 后进先出；循环内大对象 defer 会堆积，考虑封装成函数。

七、指针与方法

接收者选择口诀：

场景 用指针接收者
方法需要修改接收者 必须
结构体大（避免拷贝开销） 建议
含 sync.Mutex 等不可拷贝字段 必须
小结构体、只读、map 元素访问 值即可

混用规则：同一类型的方法接收者要统一（全值或全指针）；指针类型的方法集包含值方法，反之不成立——接口实现判定依据此规则。

八、接口：隐式实现

接口是方法签名的集合，类型实现所有方法即自动满足接口，无需 implements 声明：

「接受接口，返回结构体」：函数参数用接口（宽进），返回具体类型（严出），调用方拿到的信息更多。接口值 = (动态类型, 动态值) 二元组，nil 接口 ≠ 持有 nil 指针的接口（陷阱：往 error 接口返回了 *MyErr(nil)，err != nil 为真）。

九、错误处理

工具 用途
errors.New 创建静态错误
fmt.Errorf("...: %w", err) 包装并保留原错误链
errors.Is 链上是否等于某错误（替代 ==）
errors.As 链上提取某具体错误类型

包装加上下文、判断用 Is/As，别让 %v 丢掉错误链。panic 只留给「不可能发生」的程序缺陷，业务错误一律 error（panic/recover 见第二章）。

十、包与模块

  • go.mod 三要素：module 模块路径、go 版本、require 依赖及版本（语义化版本 v1.2.3）。
  • 可见性：标识符首字母大写导出、小写包私有——没有 public/private 关键字。
  • import 别名：import zap "go.uber.org/zap" 解决冲突；导入未使用会编译失败（防垃圾导入）。

十一、常见陷阱

陷阱 说明
len 数字节 中文字符串 len 是字节数，数字符用 []rune
append 不接返回值 扩容换底层数组后原变量仍指向旧数组
切片共享底层数组 a[1:3] 改动互相可见，需 copy 隔离
map 并发读写 panic 并发场景用 sync.Mutex/sync.Map
map 遍历无序 顺序随机，勿依赖；需有序先排序 key
nil 接口陷阱 返回「类型非 nil、值 nil」的接口，err != nil 误判
循环变量捕获 Go 1.22 前闭包共享同一变量；显式传参最稳
未使用变量/导入编译失败 Go 强制 cleanliness，用 _ 显式丢弃
for range 复用变量 取地址存切片时 Go 1.22 前全是同一个地址

本章小结

要点 结论
工具链 go mod init 起步，go build/run/vet/fmt 日常四件套
变量 := 推断、零值可用、iota 枚举；字符串是不可变 UTF-8
切片 len/cap 双轴、append 重指向、切片表达式共享底层数组
map 取值双参判存在、遍历随机、非并发安全
函数 多返回值承载错误、defer LIFO 清理、可变参数
方法 指针接收者才能修改；方法集决定接口满足
接口 隐式实现、小接口组合、「接受接口返回结构体」
错误 error 是值，%w 包装 + errors.Is/As 判断
包模块 大写导出；go mod tidy 管依赖；internal 编译器隔离
