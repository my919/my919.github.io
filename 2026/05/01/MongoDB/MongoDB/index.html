第一章：MongoDB 概述与入门

概念基础

  1. 文档数据库：MongoDB 是面向文档的 NoSQL 数据库，数据以 JSON/BSON 文档存储，字段可嵌套、可数组——一个文档天然对应一个业务对象。
  2. 层级模型：Database → Collection → Document，类似关系库的「库 → 表 → 行」，但 Collection 不强制固定 Schema，同一集合内文档字段可以不一致，适合业务快速演进。
  3. 主键默认自带：每个文档有唯一 ObjectId 主键 _id，无需提前设计自增列。
  4. 默认端口与工具：默认监听 27017，交互用 mongosh（替代旧版 mongo CLI），命令风格贴近 JavaScript。
  5. 定位与取舍：需要强事务、复杂 JOIN 时关系库更成熟；需要灵活文档 + 水平扩展时 MongoDB 更常见——二者互补而非替代。

定位与概念

1. 文档模型

  • Database → Collection → Document（类似关系库中的库 → 表 → 行，但文档是 JSON/BSON 结构，字段可嵌套、可数组）。
  • 无固定 Schema：同一 Collection 内文档字段可以不完全一致，适合业务快速演进。
  • 默认 _id：每个文档有唯一 ObjectId 主键。

2. 适用场景

场景 说明
内容管理 文章、配置、用户画像等结构多变的数据
物联网 / 日志 时序或半结构化事件写入
实时分析 配合 Change Streams、聚合管道
缓存替代 部分场景可替代「大 JSON 存 Redis」，但内存与持久化策略不同

与 第一章：MySQL DDL 语句与表设计入门 等关系库对照：需要强事务跨多表复杂 JOIN 时关系库更成熟；需要灵活文档 + 水平扩展时 MongoDB 更常见。

高可用与扩展（概念）

  • 复制集（Replica Set）：一主多从，自动故障转移，读可扩展至从节点（注意读一致级别）。
  • 分片（Sharded Cluster）：按 Shard Key 水平切分数据，适合超大数据量；运维复杂度高于单复制集。
  • 事务：多文档 ACID 事务在复制集上可用（4.0+），但仍有性能与使用范围约束。

生产注意

  • 备份：mongodump / mongorestore 或云厂商快照；复制集不等于备份。
  • 安全：启用认证、限制网络暴露、最小权限用户；勿将 27017 裸奔到公网。
  • 监控：连接数、 opcounters、复制延迟、慢查询（profiler / Atlas 等）。

本章小结

要点 结论
数据模型 Database → Collection → Document，BSON 文档无固定 Schema，_id 默认自带
入门三步 mongosh 连接 → CRUD 增删改查 → 建索引、写聚合管道
索引 单字段 / 复合 / 唯一索引，查询与排序字段要能命中索引
高可用 复制集自动故障转移，分片按 Shard Key 水平切分，多文档事务 4.0+ 可用
生产底线 复制集不等于备份；启用认证，27017 勿暴露公网
