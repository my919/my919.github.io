第二章：Docker 部署 ClickHouse 实践

概念基础

  1. 为什么用容器跑 ClickHouse：一条命令拉起、版本随标签固定、环境与宿主机解耦——本地分析环境与生产部署的基础单元。
  2. 数据持久化是底线：必须把数据目录 /var/lib/clickhouse 挂载到命名卷或宿主机目录，否则容器删除即数据清零。
  3. 初始化语义：.sql / .sh 放入 /docker-entrypoint-initdb.d（卷挂载），仅在首次初始化空数据目录时执行，已有数据卷时不会重复执行。
  4. 端口与账号：HTTP 8123 + Native 9000 双端口对外；CLICKHOUSE_USER / CLICKHOUSE_PASSWORD 配合 CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1 可用 SQL 管理用户与权限。
  5. 三种部署形态：docker run 单容器 → Docker Compose（声明式 + 健康检查）→ Kubernetes（Secret + PVC + 探针），按环境复杂度逐级选用；表引擎与查询用法见 第一章：ClickHouse 列式存储入门。

前置条件

本机已安装 docker，并能使用 docker compose（Compose V2 插件，命令为 docker compose；若仍使用旧版独立程序，则将下文中的 docker compose 换成 docker-compose）。

ClickHouse 镜像选择

1. 官方镜像（推荐）

  • 仓库：clickhouse/clickhouse-server（Docker Hub 官方组织镜像，与 ClickHouse 发行节奏一致）。
  • 常用标签：
    • clickhouse/clickhouse-server:24.8：固定次版本，便于与文档、驱动对齐。
    • clickhouse/clickhouse-server:latest 或 ...-lts：滚动更新（以 Docker Hub clickhouse-server tags 为准）。
  • 生产建议：固定具体补丁标签或记录 digest，避免 latest 漂移导致行为变化。

2. 变体说明

需求 说明
访问控制 设置 CLICKHOUSE_USER、CLICKHOUSE_PASSWORD 时，建议同时 CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1，以便用 SQL 管理用户与权限（与官方镜像说明一致）。
协议与端口 HTTP 默认 8123，Native 默认 9000；客户端按协议选择端口。
ARM64（Apple Silicon 等） 多数标签提供多架构；若拉取失败，换标签或在 Hub 查看 OS/ARCH。
极简/定制 社区编排模板与 bitnami/clickhouse 等路径、变量不同，切换镜像时需对照该镜像文档。

部署方式速查

项 说明
前置 已安装 docker 与 docker compose（或 docker-compose）
镜像 优先 clickhouse/clickhouse-server:24.8 / 固定补丁标签；CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1 与账号环境变量配套使用
单容器 mkdir 后一条 docker run ...（暴露 8123、9000）
Compose 保存 docker-compose.clickhouse.yml 后 docker compose -f ... up -d
Kubernetes 保存 clickhouse-k8s.yaml 后 kubectl apply -f ...

生产环境请配合备份、监控、网络策略与 TLS（8123 对外时务必加固）；Secret 建议对接 External Secrets / Sealed Secrets 等管控流程。

本章小结

要点 结论
镜像选择 官方 clickhouse/clickhouse-server:24.8 起步，生产固定补丁标签或 digest
单容器 mkdir 建卷目录后一条 docker run，暴露 8123 / 9000 双端口
Compose docker-compose.clickhouse.yml + .env 管理敏感项，healthcheck 走 HTTP /ping
Kubernetes Secret + PVC + Deployment（Recreate）+ HTTP 探针，一条 kubectl apply
生产提醒 数据卷 + 备份 + 认证 + TLS（8123 对外务必加固）；Keeper/分片交给 Operator

环境跑通后进入查询实战：第三章：ClickHouse 查询与性能调优 覆盖索引裁剪、物化视图与 JOIN 优化；Keeper、副本分片与 Operator 集群运维可按需深入。
