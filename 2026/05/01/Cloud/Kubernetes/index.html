第二章：Kubernetes 容器编排入门

概念基础

  1. Kubernetes（K8s） 是容器编排平台：把大量容器按声明式期望调度到多台机器上运行，并自动维持「实际状态 = 声明状态」。
  2. 为什么需要编排：单机 Docker 解决不了多机调度、故障自愈、扩缩容、服务发现与负载均衡——这些正是 K8s 的核心能力。
  3. 声明式 API：不写「怎么做」的脚本，而是提交 YAML 描述期望（副本数、镜像、端口），由控制循环持续把集群调到期望状态。
  4. 核心对象：Pod 是最小调度单元；Deployment 管理副本与滚动更新；Service 提供稳定访问入口；ConfigMap / Secret 管理配置与密钥。
  5. 定位：生产环境容器编排的事实标准；本地可用 minikube / kind / k3s 学习，集群上的应用包管理则交给 Helm（见第四章）。

控制面与节点

组件 作用
kube-apiserver REST API 入口，所有对象经此持久化到 etcd
kube-scheduler 为 Pod 选择节点
kube-controller-manager 副本数、节点状态等控制循环
kubelet 节点代理，拉镜像、启停容器
kube-proxy 实现 Service 的集群内负载均衡（iptables/IPVS）
容器运行时 containerd、CRI-O 等（底层仍常跑 第一章：Docker 容器基础 构建出的 OCI 镜像）

配置、密钥与存储

  • ConfigMap：非敏感配置（application.yaml 片段、环境变量）。
  • Secret：Base64 编码存储，仍须配合 RBAC 与加密 at rest。
  • PersistentVolumeClaim：请求块存储或 NFS 等，Pod 重启后数据保留。

网络与 Ingress

  • CNI：Calico、Flannel、Cilium 等实现 Pod 网段与策略。
  • Ingress：HTTP/HTTPS 七层路由，常配合 Ingress Controller（nginx-ingress、Traefik）。
  • DNS：集群内 service.namespace.svc.cluster.local。

本地学习与生产

工具 说明
minikube 单节点本地集群
kind 在 Docker 内起 K8s 节点
k3s / k0s 轻量发行版，适合边缘与小型生产

生产还需：资源 Request/Limit、HPA、PDB、NetworkPolicy、镜像准入与可观测（Prometheus、Loki 等）。本站中间件栈部署可参考 服务 与各 *-Docker 文章中的 K8s 清单示例；可复用应用包与版本回滚见 第四章：Helm 应用包管理入门。

本章小结

要点 结论
定位 容器编排平台：多机调度、自愈、扩缩容、服务发现
声明式 提交 YAML 期望状态，控制循环负责收敛，不写过程脚本
对象 Pod 最小调度单元，Deployment 管副本，Service 管访问
排障 kubectl get / describe / logs 三板斧定位绝大多数问题
学习路径 本地 minikube / kind 起步，应用包管理交给 Helm
