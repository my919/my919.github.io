第一章：Docker 容器基础

概念基础

  1. Docker 是基于容器的应用打包、分发与运行平台：把应用连同依赖环境一起封进镜像，实现「一次构建，到处运行」，解决「在我机器上是好的」的环境漂移问题。
  2. 镜像与容器：镜像（Image） 是只读分层文件系统加元数据；容器（Container） 是镜像的可运行实例，在镜像之上附加一层可写层。
  3. 与虚拟机相比，容器共享宿主机内核、不含客户机 OS，启动秒级、资源密度高；隔离性弱于完整 VM，敏感多租户需额外加固。
  4. 核心工作流：Dockerfile 描述构建过程 → docker build 产出镜像 → 推送到 Registry（Docker Hub / Harbor）→ 任意机器 docker run 拉起容器，多容器栈用 Compose 编排。
  5. 为什么学它：数据库、中间件、应用皆可容器化（本站各 *-Docker 文章即基于此）；单机之上是多机编排与生产化，由 Kubernetes 承接（见第二章）。

核心概念

概念 说明
镜像（Image） 只读分层文件系统 + 元数据，由 Dockerfile 或 docker commit 构建
容器（Container） 镜像的可运行实例，可写层在容器生命周期内存在
仓库（Registry） Docker Hub、私有 Harbor 等，用于推送/拉取镜像
Docker Engine dockerd 守护进程 + docker CLI

Dockerfile 要点

  • 多阶段构建：编译阶段用 JDK 镜像，运行阶段只保留 JRE 与产物，缩小体积。
  • 层缓存：变动少的指令放前面（COPY pom.xml 再 COPY src）。
  • 非 root：生产容器尽量 USER 非特权账号。

网络与数据卷

1. 网络模式（常见）

  • bridge（默认）：端口映射 -p host:container。
  • host：与宿主机共享网络栈（Linux 原生引擎常见；Docker Desktop 行为不同）。
  • 自定义网络：Compose 中服务名即 DNS 名。

2. 卷

-v 或 --mount 持久化数据；容器删除后命名卷仍保留。

本章小结

要点 结论
本质 容器是共享内核的进程级隔离；镜像只读分层，容器附加可写层
工作流 Dockerfile → build 镜像 → push/pull 仓库 → run 容器
数据与网络 -v 卷持久化数据；默认 bridge 网络 + -p 端口映射
多容器 Compose V2 用一份 YAML 描述并管理多容器栈
生产要点 固定镜像版本、资源限制、健康检查、非 root 运行、镜像扫描
