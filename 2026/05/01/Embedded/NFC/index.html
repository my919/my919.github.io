第十四章：NFC 近场通信：工作模式与 NDEF

概念基础

  1. NFC（Near Field Communication，近场通信）工作在 13.56MHz，通信距离仅几厘米——「近」是刻意设计：贴一下才触发，天然防误触，适合支付与门禁。
  2. 有源与无源：Reader 产生射频场并为 passive Tag 供电（无源卡没有电池，靠感应取电通信），这是它与蓝牙等「双方都要电池」技术最本质的差别。
  3. 三种工作模式：读卡/写卡（碰 Tag）、卡模拟（手机变门禁卡/交通卡）、点对点（两设备交换小数据，已较少用）。
  4. NDEF 是通用数据格式：把 URI、文本、Wi-Fi 配置、蓝牙配对信息统一封装进 Tag，手机一碰即触发对应系统动作。
  5. 定位：身份识别、小额支付、设备配对加速器（给 BLE 递密钥）；大数据传输交给 Wi-Fi/蓝牙，NFC 只负责「握手」。

一、工作模式

模式 说明
Reader/Writer 读或写 passive Tag
Card Emulation 手机模拟门禁/交通卡
Peer-to-Peer 两设备交换小数据（较少用）

二、Tag 标准

  • Type 1~4 Tag：不同容量与协议（NFC Forum）。
  • MIFARE Classic/Ultralight：交通、门禁（Classic 安全性已弱，新项目慎用）。
  • ISO 14443 A/B、ISO 15693（稍远，仍近场）。

三、NDEF（NFC Data Exchange Format）

常用 payload 格式，可封装：

  • URI（打开网页）
  • 文本
  • Wi-Fi 配置（WSC）
  • Bluetooth LE 配对 OOB 数据

手机贴近 Tag 即可触发系统动作（依 OS 策略）。

四、与其它接口

  • 第十三章：Bluetooth 与 BLE：GATT 模型与低功耗设计：NFC 传递配对密钥，BLE 传大数据。
  • 第十五章：USB 总线：拓扑、描述符与 CDC 虚拟串口：PC 用 USB NFC 读卡器 开发调试。
  • 支付：EMVCo、HCE（Host Card Emulation）在 SE/TEE 中存密钥。

五、开发

  • Android：NfcAdapter、enableReaderMode。
  • MCU：PN532、MFRC522（SPI/第七章：I2C）+ 天线设计。
  • 安全：Tag 可只读；支付与门禁依赖芯片级密钥，勿明文存敏感数据于可写 Tag。

本章小结

要点 结论
物理层 13.56MHz、几厘米近场，Reader 射频场为无源 Tag 供电
工作模式 读卡/写卡、卡模拟、点对点三类
数据格式 NDEF 统一封装 URI/文本/Wi-Fi/蓝牙配对数据
典型组合 NFC 递密钥加速 BLE 配对，大数据走 BLE/Wi-Fi
安全边界 Tag 勿存明文敏感数据，支付依赖 SE/TEE 芯片级密钥
