第二章：Vite 工程化构建与部署

概念基础

  1. 下一代前端工具链：开发态用原生 ESM 按需编译（不打包整图），生产态用 Rollup 打包，一套配置覆盖 dev / build。
  2. 为什么快：依赖用 esbuild（Go 实现）预构建，比 JS 工具链快一个量级；HMR 速度与项目规模解耦。
  3. 约定优于配置：零配置即可启动，vite.config.ts 按需增强（别名、代理、插件）。
  4. 框架无关：官方插件支持 Vue / React / Svelte 等，也是 Nuxt 3 等元框架的底层构建器。
  5. 边界：dev 与 build 行为有差异（原生 ESM vs 打包产物），上线前必须 vite build && vite preview 验证。

一、为何快：Dev 与 Build 的分工



flowchart LR
  subgraph dev [开发 vite dev]
    SRC[源码 ESM] --> ESB[esbuild 预构建 deps]
    ESB --> HMR[浏览器 HMR]
  end
  subgraph prod [生产 vite build]
    SRC2[源码] --> ROL[Rollup 打包]
    ROL --> DIST[dist 静态资源]
  end
阶段 机制
开发 按需编译单文件，不打包整图；依赖用 esbuild 预打包
HMR 模块热替换，保留应用状态（依模块类型）
生产 Rollup Tree-shaking、代码分割、资源哈希

对比 Webpack dev：大型项目冷启动与 HMR 通常明显更快。

二、创建项目与常用脚本

常用模板：vanilla-ts、vue-ts、react-ts、vue。

  • preview：用本地静态服务器预览 dist，是上线前发现「dev 正常、build 出错」的第一道检查。

三、vite.config.ts 核心配置

  • alias：@ 指向 src，免除深层相对路径。
  • server.proxy：开发期把 /api 转发到后端，规避 CORS；生产环境由 Nginx 承担同样角色。

四、环境变量与模式

  • .env.development / .env.production 按模式加载；只有 VITE_ 前缀变量暴露给客户端，通过 import.meta.env.VITE_XXX 访问。
  • 密钥不要放进 VITE_*：客户端代码可见，后端密钥走服务端环境。
  • import.meta.env.MODE / import.meta.env.PROD 可在代码中区分环境分支。

五、插件生态

  • @vitejs/plugin-vue / plugin-react
  • vite-plugin-vue-devtools
  • Legacy：@vitejs/plugin-legacy 为旧浏览器注入 polyfill

SSR：vite-plugin-ssr 或框架内置方案（Nuxt 3 等基于 Vite）。

六、生产构建与部署

  • 第一章：Vue 3 核心概念与组件开发 官方推荐 **Vite** 作为默认脚手架。
  • 生产 dist 为静态文件，由 第一章：Nginx 入门与静态服务 或 CDN 托管；try_files 支持 SPA history 路由。
  • base：部署在子路径（如 /blog/）时需设置，资源引用前缀随之改变。

官方文档：https://vite.dev/

本章小结

要点 结论
双引擎 开发 原生 ESM + esbuild，生产 Rollup 打包
速度 依赖预构建 + 按需编译，HMR 与项目规模解耦
配置 vite.config.ts：alias、proxy、build 渐进增强
环境变量 仅 VITE_* 前缀暴露到客户端；密钥不进前端
部署 dist 静态托管；SPA 依赖 try_files 回退 index.html
