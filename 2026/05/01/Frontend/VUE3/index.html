第一章：Vue 3 核心概念与组件开发

发表于 2026-05-01 更新于 2026-09-01 分类于 Frontend 本文字数： 986 阅读时长 ≈ 3 分钟

第一章：Vue 3 核心概念与组件开发

概念基础

  1. 渐进式框架：既可以只在页面局部做交互增强，也可以配合 Vue Router / Pinia / Vite 构建完整的单页应用（SPA），复杂度随项目成长。
  2. 响应式系统：基于 Proxy 实现，用 ref / reactive 包装数据，模板自动追踪依赖、精确更新 DOM，几乎无需手写 DOM 操作。
  3. 组合式 API：Composition API（script setup 语法糖 + useXxx 组合式函数）让逻辑按功能组织而非按选项分散，复用与 TS 推导更友好。
  4. 编译期优化：单文件组件（SFC） 在编译期做静态提升、patch flags 等优化，运行时 diff 开销低于传统虚拟 DOM 方案。
  5. 生态成熟：脚手架 Vite、路由 Vue Router 4、状态 Pinia、类型检查 vue-tsc；官方文档 https://vuejs.org/ 。

一、核心概念

  • 单文件组件（SFC）：.vue 文件含 <template>（模板）、<script>（逻辑）、<style>（样式）三段。
  • 响应式：ref（包装任意值，经 .value 访问）/reactive（代理对象）包装数据，模板自动追踪依赖并更新 DOM。
  • 虚拟 DOM + 编译优化：静态提升、补丁标志减少运行时开销。

与 Vue 2 的主要差异：移除 Vue.set、$on 等 API；全局 API 改为 createApp 应用实例；Options API（data/methods/computed）仍兼容，但新项目推荐 Composition API。

二、组件与数据流



flowchart TB
  Props[props 父传子] --> Comp[Vue 组件 SFC]
  Comp --> Emit[emit 子传父]
  Comp --> Store[Pinia 全局状态]
  Store --> Comp
  • props 单向下行：父 → 子传数据；子组件不要直接修改 props，需要变更时用 emit 上报事件，由父组件修改数据源。
  • 单向数据流：数据流向清晰可追踪，是组件可维护性的基础。

三、Composition API

  • script setup：编译期糖，少写 export default，顶层绑定直接在模板可用。
  • computed：带缓存的派生值，依赖不变不重算；副作用用 watch / watchEffect。
  • 生命周期：onMounted / onUnmounted / onUpdated 等组合式写法替代 Vue 2 的选项式钩子。
  • 组合式函数（Composables）：useXxx() 抽离可复用逻辑（如 useFetch、useMouse），是组合式 API 最大的工程价值。

四、组件通信

方式 说明
Props / Emits 父 → 子、子 → 父事件
Provide / Inject 跨层级依赖注入
v-model 双向绑定（modelValue + update:modelValue）
Slots 默认插槽、具名插槽、作用域插槽
  • 组件上的 v-model：等价于传 modelValue prop 并监听 update:modelValue 事件。
  • 作用域插槽：子组件把内部数据暴露给父组件的插槽内容，适合列表项模板定制。

五、路由与状态管理

  • Vue Router 4：createRouter、嵌套路由、导航守卫、懒加载 () => import('./Page.vue')。
  • Pinia：官方推荐状态库，替代 Vuex，模块即 defineStore。
  • 何时需要全局状态：跨页面共享（登录态、主题）或多组件深层传递；局部状态优先留在组件内。
  • 导航守卫：beforeEach 常用于登录校验与权限拦截。

本章小结

要点 结论
响应式 ref / reactive 包装数据，Proxy 依赖追踪自动更新 DOM
组织方式 Composition API + 组合式函数按功能组织逻辑，TS 友好
数据流 props 下行、emit 上行的单向数据流；跨层级用 Provide / Inject
路由与状态 Vue Router 4 管页面，Pinia 管共享状态
工程化 Vite 脚手架 + vue-tsc 类型检查，产物部署到 Nginx / CDN
