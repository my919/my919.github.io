第三章：前端工程化实战

第三章：前端工程化实战

概念基础

  1. 工程化 = 让「多人协作的代码」可持续：规范（Lint/Format）、测试（Vitest）、构建（第二章：Vite 工程化构建与部署）、流水线（CI/CD）四件事，把「能跑就行」变成「敢改敢上」。
  2. 规范靠工具不靠自觉：ESLint 查质量、Prettier 管格式，冲突项关掉；Git hooks + lint-staged 让不合规范的代码进不了仓库。
  3. 测试金字塔：组件测试（Vitest + Testing Library）保交互正确，E2E（Playwright）保关键路径；纯函数/composables 最值得测。
  4. 性能是设计出来的：路由懒加载、分包、图片懒加载、缓存策略——Vite 产物之上仍有一层「加载策略」要自己定。
  5. 上线即流水线：npm run ci 一条命令跑 lint+test+build，CI 机器与本地同标准；产物进 Nginx/CDN（见 第一章：Nginx 入门与静态服务）。

环境说明：沙箱未安装 node_modules（网络受限），本章配置按 ESLint 9 扁平配置 / Vitest 2.x / husky 9 官方语法书写，未逐条运行验证。

一、代码规范：ESLint 9 + Prettier

分工记忆：ESLint 管「代码质量」（未用变量、错误用法），Prettier 管「代码风格」（缩进、引号、换行）；两者规则冲突时以 Prettier 为准（eslint-config-prettier 兜底）。

二、Git hooks：husky + lint-staged

提交时只检查暂存区文件，秒级完成；不想被风格 PR 淹没，就靠这道闸门。

三、测试：Vitest

测什么：优先测纯逻辑（composables、utils、store actions）——它们是 bug 高发区且不怕 UI 改版；快照测试克制使用。

四、性能优化：加载策略

手段 说明
路由懒加载 首屏只带当前页代码，其余按需
manualChunks 框架/大依赖独立分包，业务更新不动它们的 hash
图片 loading="lazy" + WebP/AVIF；图标用 SVG sprite 或 iconfont
请求层 接口合并/预取关键数据；列表用骨架屏替代白屏
缓存 指纹文件名 + expires 7d（Nginx 配置见 第四章：Nginx 缓存与性能调优）
度量 Lighthouse / bundle 产物分析（rollup-plugin-visualizer）

优化闭环：先度量再动手——Lighthouse 分数与构建产物体积是基线，改一项测一项。

五、CI/CD 流水线

一条主线：本地 pre-commit 把关单文件 → CI 把关全量 → dist 产物经 rsync/镜像到 Nginx/CDN。三个关卡标准一致，谁也不许绕。

本章小结

要点 结论
规范 ESLint 管质量、Prettier 管风格；扁平配置里 eslint-config-prettier 放最后
闸门 husky + lint-staged 只查暂存文件，风格问题进不了仓库
测试 Vitest 测 composables/纯函数优先；组件测试用 Testing Library
性能 路由懒加载 + manualChunks 稳定缓存；先 Lighthouse 度量再优化
CI/CD npm ci + lint + typecheck + test + build 一条龙；产物 rsync 上 Nginx

至此前端系列三章完结：第一章：Vue 3 核心概念与组件开发 打好框架基础，第二章：Vite 工程化构建与部署 解决构建，本章补齐规范、测试与流水线。服务端搭档见 第三章：Node.js 运行时与服务开发。
