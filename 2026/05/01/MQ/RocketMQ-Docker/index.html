第五章：Docker 部署 RocketMQ 实践

概念基础

  1. 没有「单容器一体」形态：NameServer 与 Broker 是两个独立进程（5.x 还有一个可选的 Proxy），最小栈就是两个容器——这与 Kafka 的 KRaft 单进程不同，下文用「网络 → NameServer → Broker」三步完成最小栈。
  2. brokerIP1 是第一坑：Broker 启动时把自己注册到 NameServer 的地址就是 brokerIP1，客户端拿这个地址直连 Broker——容器内不显式指定时往往是内网容器 IP，宿主机客户端会「能拿到路由却连不上」。本机访问写 127.0.0.1、跨机写宿主机可达 IP（对照 Kafka 的 advertised.listeners）。
  3. 端口按角色记忆：9876 NameServer；10909 / 10911 / 10912 分别是 Broker 的 VIP / 主 / HA 端口；8080 / 8081 是 5.x Proxy 的 gRPC 端口——只用经典 Remoting 客户端时，Proxy 端口可以不映射。
  4. 数据目录与边界：Broker 数据在 /home/rocketmq/store（日志在 logs），必须挂卷；单机部署面向开发验证，生产多 Master/Slave 或 DLedger 自动切换请用 RocketMQ Operator 或官方推荐拓扑。

前置条件

本机已安装 docker，并能使用 docker compose（Compose V2 插件，命令为 docker compose；若仍使用旧版独立程序，则将下文中的 docker compose 换成 docker-compose）。

RocketMQ 镜像选择

1. 官方镜像（推荐）

  • 仓库：apache/rocketmq（Docker Hub：https://hub.docker.com/r/apache/rocketmq/tags），与 Apache RocketMQ 发行版本对应。
  • 常用标签：如 apache/rocketmq:5.3.2（下文以此为例；升级时请同时核对容器内 ROCKETMQ_HOME 下 conf 路径是否随版本变化）。
  • 生产建议：固定补丁级标签或记录 digest，避免 latest 漂移。

2. 角色与端口（开发常用）

组件 说明 常见映射端口（示例）
NameServer 路由注册与发现 9876
Broker 消息存储与转发 10909、10911、10912 等（与 broker.conf / 启动参数有关）
Proxy（5.x 可选） gRPC 接入等（官方 Docker 快速入门常与 --enable-proxy 一并启用） 8080、8081 等

3. 与官方「Broker + Proxy」快速入门的关系

Apache 文档推荐挂载 broker.conf 并执行 mqbroker --enable-proxy（见 Run RocketMQ in Docker）。下文 Compose 提供带 Proxy 的完整示例；若仅需经典 Remoting 客户端，可将 Broker 的 command 改为 sh mqbroker -n <namesrv>:9876 并去掉 Proxy 相关端口（需自行验证与客户端版本匹配）。

4. 资源与持久化

Broker 磁盘与堆内存占用随主题、队列与流量增长较快；Compose 与 K8s 中为 Broker 数据目录挂载卷，并酌情提高 limits。

1Panel（推荐）：在 Linux 宿主机上若希望少手写命令、仍以容器方式跑 Apache RocketMQ，可先安装 1Panel（开源 Linux 运维面板），在 「应用商店」 中选择 RocketMQ 一键部署：由面板编排 NameServer、Broker（及上架版本若含的 Proxy）与数据卷、端口。与下文 docker / Compose / K8s** 中的 **broker.conf**、**NAMESRV_ADDR**、**brokerIP1` 与端口映射对齐或排障时，自「最少命令启动」起各节仍可作对照。适合单台 VPS、家庭服务器等场景。
