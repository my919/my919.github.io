第一章：OpenSSL 命令行入门与常用操作总览

概念基础

  1. OpenSSL 是一个开源密码学工具包：对外提供 openssl 命令行工具（生成密钥、证书、加解密、签名），对内提供底层密码库（libcrypto / libssl），是 TLS/HTTPS 生态的事实标准。
  2. 它解决三类安全问题：保密性（对称 / 非对称加密）、完整性（哈希 / HMAC）、身份认证（数字证书 + CA 信任链）；HTTPS 正是三者的组合应用。
  3. 四个核心对象：私钥（.key / .pem，必须保密，用于解密、签名）；公钥（从私钥导出，公开分发，用于加密、验签）；证书（.crt / .pem，包含公钥 + 身份信息 + 签名，证明公钥合法）；CSR（证书签名请求，.csr，向 CA 机构申请正式证书的文件）。
  4. 为什么重要：Nginx、curl、Python、Java、手机系统等几乎所有软件的加密通信都依赖它——掌握 OpenSSL 命令行，等于掌握证书、加密、签名的通用钥匙。
  5. 本章定位：侧重命令行实操，给出从摘要、密钥到证书签发、格式转换的完整工作流；各算法的原理与选型详见后续章节。

OpenSSL 是生成、管理非对称密钥和数字证书的标准工具，广泛用于 第四章：HTTPS 详解：TLS 握手、证书与 openssl/curl 示例、SSL/TLS、身份认证等。能力概览见 第二章：OpenSSL 功能全景与自建局域网 CA 实战；算法分类与推荐用法见下表。

摘要与编码（不依赖证书）

1. 文件摘要（MD5、SHA-256）

对任意文件计算密码学摘要，常用于校验下载包、比对文件是否一致。

其他算法同理，例如 -sha512、-sha1（SHA-1 已不推荐用于安全场景）。

2. 字符串 / 管道内容哈希

把待哈希内容通过标准输入喂给 dgst。注意 echo 默认会带换行，校验短字符串时一般用 echo -n。

3. Base64 编码与解码

适合在文本通道里传输二进制，或快速查看二进制内容（Base64 不是加密）。

1. 生成 RSA 私钥（无密码）

  • 2048 是密钥长度（安全推荐）
  • 生成后千万不要泄露

2. 生成带密码保护的私钥（更安全）

每次使用会要求输入密码。

3. 从私钥导出公钥

对称加解密（enc）

用口令派生密钥加密文件，算法以 AES-256-CBC 为例；加解密必须使用相同算法与口令，解密侧需带 -d。

  • -salt：加密时加盐，避免相同明文产生相同密文（若版本默认已加盐，可省略显式写法，以本机 openssl enc -help 为准）。
  • 生产环境更推荐 随机二进制密钥 + 明确 KDF/模式（或直接用 age、GnuPG 等高层工具），口令仅作演示或临时场景。

非对称：公钥加密与私钥解密（RSA）

RSA 直接加密只适合很短载荷（长度受密钥与填充限制）；长数据应使用「随机对称密钥加密数据 + RSA 加密对称密钥」等混合方案（TLS、CMS 即类似思路）。

下面假设已有 PEM 私钥 private.key 与对应 公钥 public.key（见上文「从私钥导出公钥」）。

旧资料中的 openssl rsautl 已逐步被 pkeyutl 取代，新脚本优先用后者。

数字签名与验签

用私钥对消息摘要签名，任意持有公钥的一方可验证完整性及来源（前提是公钥可信）。

1. 私钥签名、公钥验签

验签成功会打印 Verified OK。

2. 从证书提取公钥再验签

生成自签名证书（开发/测试必备）

自签名证书 = 私钥 + 自己签发的证书
适合本地开发、内网测试，不能用于公网生产环境。

一步生成 私钥 + 证书（有效期 10 年）

  • -nodes：私钥不加密
  • -days 3650：有效期 10 年
  • 执行后按提示填信息（可以全部回车）

最终得到两个文件：

  • private.key：私钥
  • cert.crt：自签名证书

如果你要申请阿里云/腾讯云/Let’s Encrypt 正规证书，必须先生成 CSR。

提交 cert.csr 给 CA 机构，就能拿到正式证书。

本章小结

要点 结论
概念 私钥、公钥、证书、CSR 分工明确；私钥绝对不能泄露（证书失效且签名可被伪造）
摘要与编码 md5 / sha256 / dgst（文件或管道）；base64 与 -d 解码；Base64 不是加密
密钥 genrsa 生成、-aes256 保护、rsa -pubout 导出公钥
加解密 对称 enc（算法与口令一致）；非对称短数据 pkeyutl；长数据走混合加密或 TLS
签名 dgst -sign / -verify；可从 x509 -pubkey 取公钥验签
证书 开发用自签名；生产用 CSR → CA；会查看、匹配 modulus、格式转换与部署
