第五章：高可用与备份恢复

发表于 2026-05-01 更新于 2026-09-01 分类于 Oracle 本文字数： 2.8k 阅读时长 ≈ 9 分钟

第五章：高可用与备份恢复

概念基础

  1. 三层防护：Oracle 高可用由「集群防节点故障（RAC） + 容灾防站点故障（Data Guard） + 备份防逻辑/物理损坏（RMAN）」三层叠加构成，各有侧重、互补配合。
  2. RAC 解决单点：多实例共享存储并发读写，任一节点宕机业务自动漂移，做到节点级高可用 + 横向扩展，但不防存储损坏与站点灾难。
  3. Data Guard 解决容灾：主库 redo 实时同步到异地备库，可只读/灾备切换，做到站点级容灾 + 数据零丢失，是 RAC 之外的异地防线。
  4. RMAN 解决恢复：物理备份 + 归档日志支持任意时点恢复，配合闪回快速逆转人为误操作——备份是最后一道防线，”没备份就准备跑路”不是玩笑。
  5. 本章目标：掌握 RAC、Data Guard、RMAN、闪回四大支柱的原理与实操，构建企业级容灾方案。

本章承接 第四章：体系结构与存储管理。高可用设计的前提是理解实例/数据库/归档的运行机制，本章在此基础上构建可用性方案。

一、高可用全景



flowchart TB
  APP[应用层] --> SCAN[SCAN 虚拟 IP]
  SCAN --> RAC[RAC 集群 - 节点高可用]
  RAC --> ASM[共享存储 ASM]
  RAC -.redo 同步.-> DG[Data Guard 备库 - 站点容灾]
  RAC --> RMAN[RMAN 备份 - 物理恢复]
  DG --> DR[异地灾备中心]
  RMAN --> TAPE[磁带/对象存储]
  RAC -.逻辑误操作.-> FB[闪回 Flashback]
威胁场景 应对手段
节点宕机 RAC 故障切换
存储损坏 Data Guard 切到备库 + RMAN 恢复
站点灾难 Data Guard 异地切换
误删/误改（逻辑错误） 闪回 或 RMAN 时点恢复
数据块损坏 RMAN BLOCKRECOVER / 块介质恢复

二、RAC 集群

1. 架构

RAC（Real Application Clusters）多实例共享访问同一数据库：



flowchart TB
  APP[应用] --> SCAN[SCAN DNS 3 虚拟 IP]
  SCAN --> VIP1[节点1 VIP]
  SCAN --> VIP2[节点2 VIP]
  VIP1 --> I1[实例1 SGA+进程]
  VIP2 --> I2[实例2 SGA+进程]
  I1 <-->|Cache Fusion 融合| I2
  I1 & I2 --> ASM[共享存储 ASM]
  I1 & I2 --> VOTE[投票盘]
  I1 & I2 --> OCR[OCR 集群注册表]
组件 作用
SCAN Single Client Access Name，单一接入点，客户端连 SCAN 不连节点
VIP 节点虚拟 IP，故障时漂移，快速失败转移
ASM 共享存储，所有节点访问同一套数据文件
OCR Oracle Cluster Registry，集群配置仓库
投票盘 Voting Disk 衄裂脑检测，决定哪个节点存活
Cache Fusion 节点间通过私有网络传递数据块锁，统一内存视图

2. 工作机制

  1. 多实例共享同一数据文件，各自有独立 SGA/Redo Thread。
  2. 节点 A 要改节点 B 缓存的块，通过私有网络（Cache Fusion）传递，而非走磁盘。
  3. 节点宕机时，VIP 漂移、SCAN 重定向，会话重连到存活节点。
  4. 私有网络心跳丢失时，投票盘决定少数派节点被驱逐（evict）防脑裂。

3. 优缺点

优势 代价
节点故障自动切换 架构复杂、运维门槛高
横向扩展读、部分扩展写 写仍共享存储，扩展性有限
在线滚动升级 License 昂贵
单库视图，应用透明 Cache Fusion 网络是瓶颈

RAC 防节点不防存储：共享存储是单点，必须配合 ASM 镜像或外部 RAID。RAC 也防不了站点灾难，需 Data Guard 异地容灾。应用要做「无状态 + 重连」才能享受故障切换红利。

三、Data Guard 容灾

1. 架构

主库 redo 实时传输到备库重做应用，形成异地冗余：



flowchart LR
  PRIMARY[主库 Primary] -->|LGWR/LNS 传 redo| STBY[备库 Standby]
  STBY -->|MRP 重做应用| APPLY[数据同步]
  APPLY -.可读.-> RO[只读查询]
  APPLY -.可切换.-> SWITCH[角色切换]

2. 三种保护模式

模式 数据丢失风险 性能影响 适用
最大保护 MAXPROTECTION 零丢失，redo 必须落备库主库才提交 高 金融核心
最大可用 MAXAVAILABILITY 故障时可能丢少量 中 关键业务
最大性能 MAXPERFORMANCE 异步，可能丢 低（默认） 一般容灾

3. 备库类型

类型 应用方式 只读
物理备库 redo 应用，块级一致 12c+ Active Data Guard 可只读+应用
逻辑备库 redo 转 SQL 应用，可改结构 可读写，可做报表
快照备库 暂停应用做快照 可读写，恢复时回滚

4. 角色切换

切换类型 场景 数据丢失
Switchover 计划维护，主备都正常 无
Failover 主库宕机，强制激活备库 取决于模式与延迟

Active Data Guard 让备库边应用 redo 边只读，可分摊报表负载；Fast-Start Failover 配合 Observer 实现故障自动切换。生产容灾演练要定期做 Switchover 验证可用性。

五、闪回（Flashback）

闪回利用 UNDO / 闪回日志快速逆转逻辑错误，无需从备份恢复，远快于 PITR：

闪回类型 机制 用途
Flashback Query UNDO 查看历史时点数据
Flashback Table UNDO 整表回到过去时点
Flashback Database 闪回日志 整库回到过去（需开闪回）
Flashback Drop 回收站 恢复误删表
Flashback Version Query UNDO 查行历史版本
Flashback Transaction UNDO 逆转单个事务

闪回 ≠ 备份：闪回依赖 UNDO/闪回日志，窗口有限（UNDO 被 ORA-01555 覆盖即失效）；物理损坏仍需 RMAN。闪回是处理「误删/误改」最快的手段，应作为首选，备份兜底。

2. Active Data Guard + 远程同步

  • Active Data Guard：备库边应用边只读，分摊读负载。
  • Far Sync：零丢失的近端中转实例，主库同步传 Far Sync，Far Sync 异步传异地备库，兼顾零丢失与远距离。

3. GoldenGate（逻辑复制）

GoldenGate 通过日志解析做异构逻辑复制，支持 Oracle↔MySQL↔Kafka 等，用于实时数据集成、双活、零停机迁移。区别于 Data Guard 的物理块级同步，GoldenGate 是逻辑级、可选择性、可异构。

七、容灾方案设计要点

  1. RPO/RTO 目标：RPO（可丢数据量）决定同步模式，RTO（恢复时间）决定切换自动化程度。
  2. 三层叠加：RAC 防节点 + Data Guard 防站点 + RMAN 防物理损坏，缺一不可。
  3. 演练：定期 Switchover 演练验证容灾可用，”未演练的容灾等于没有”。
  4. 备份验证：备份不仅要”做了”，要定期”恢复验证”——未验证的备份可能在恢复时才发现损坏。
  5. 监控：归档空间、备库延迟、RMAN 备份成功率、闪回保留窗口纳入监控告警。
  6. 人为误操作优先闪回：闪回分钟级，RMAN 时点恢复小时级，先试闪回。

八、常见陷阱

陷阱 说明
NOARCHIVELOG 无时点恢复 生产必须开归档，否则只能恢复到上次备份
备份未验证 恢复时才发现损坏，定期做恢复演练
归档目录满挂起库 监控 + 保留策略 + 自动清理
RAC 不防存储损坏 共享存储单点，配 ASM 镜像/Data Guard
Data Guard 不同步 网络延迟、备库未应用，定期查 v$dataguard_stats
闪回窗口过短 UNDO 被覆盖闪回失效，调大 UNDO_RETENTION 与 DB_FLASHBACK_RETENTION_TARGET
Failover 后丢数据 最大性能模式异步可能丢，关键业务用最大可用/保护
RESETLOGS 后忘新基线 化身改变，旧增量备份失效，需立即全量

本章小结

要点 结论
三层防护 RAC 防节点 + Data Guard 防站点 + RMAN 防物理损坏
RAC 多实例共享存储，Cache Fusion 统一内存，SCAN 接入；防节点不防存储
Data Guard redo 同步容灾，三种保护模式；Switchover 计划切换/Failover 故障切换
RMAN 物理备份标准工具，全量+增量+归档；PITR 时点恢复
闪回 利用 UNDO/闪回日志快速逆转逻辑错误，优先于 RMAN
策略 周日 0 级 + 周中 1 级 + 每日归档；定期演练与恢复验证
选型 关键业务零丢失用最大保护；异构/双活用 GoldenGate
