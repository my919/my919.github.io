第二章：SQL 查询与内置函数

概念基础

  1. SQL 标准为主、方言为辅：Oracle 支持 ANSI SQL，但有自己的方言细节——VARCHAR2 而非 VARCHAR、DUAL 伪表、ROWNUM 伪列、字符串拼接用 ||。
  2. 空值是未知而非空：Oracle 中 NULL 表示「未知」，与任何值比较（含 = NULL）都返回未知，必须用 IS NULL / NVL/COALESCE 处理，否则过滤条件静默失效。
  3. 事务默认手动提交：INSERT/UPDATE/DELETE 后必须 COMMIT，与 MySQL 默认 autocommit 相反；DDL（建表/改表）会隐式提交。
  4. 分析函数是杀手锏：ROW_NUMBER/RANK/LAG/LEAD/SUM OVER 等窗口函数能在一条 SQL 内完成排名、同环比、累计——这是 Oracle 区别于早期 MySQL 的强项。
  5. 本章目标：覆盖查询、连接、子查询、分页、分析函数与常用内置函数，写出生产级 SQL。

本章承接 第一章：Oracle 数据库入门 的最小示例，假设已建好 emp 表。SQL 语法不依赖实例状态，可在 SQL*Plus / SQL Developer 中逐条验证。

九、数据操作 DML

TRUNCATE 是 DDL，立即提交不可回滚且重置高水位线（HWM），速度远快于 DELETE，但不能加 WHERE。生产慎用。

十、常见陷阱

陷阱 说明
= NULL 查不到 NULL 用 IS NULL，比较运算对 NULL 返回未知
未提交就断连 DML 后没 COMMIT，会话结束自动回滚
VARCHAR vs VARCHAR2 用 VARCHAR2，VARCHAR 未来可能改语义
单双引号混用 单引号字符串、双引号标识符，与 MySQL 相反
ROWNUM 直接分页 排序前分配，必须嵌套子查询
COUNT(列) 漏 NULL 计 NULL 用 COUNT(*) 或 COUNT(1)
DDL 隐式提交 建表/改表/TRUNCATE 前未提交的 DML 会被提交
日期格式依赖 NLS TO_DATE 不指定格式靠 NLS_DATE_FORMAT，生产环境显式写格式

本章小结

要点 结论
方言 DUAL 伪表、VARCHAR2、`
空值 NULL 是未知，IS NULL 判断、NVL/COALESCE 替换
分页 12c+ 用 OFFSET FETCH；旧版 ROWNUM 须嵌套子查询
连接 ANSI JOIN 优先；(+) 是旧式外连接
分析函数 ROW_NUMBER/RANK/LAG/LEAD + OVER(PARTITION BY ... ORDER BY ...) 不合并行
函数 字符/数值/日期/转换四类，TO_CHAR/TO_DATE 配掩码
DML DML 需 COMMIT；TRUNCATE 是 DDL 不可回滚；MERGE 做 Upsert
陷阱 =NULL 失效、ROWNUM 分页、DDL 隐式提交
