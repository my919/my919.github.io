第六章：性能调优与运维

发表于 2026-05-01 更新于 2026-09-01 分类于 Oracle 本文字数： 3.5k 阅读时长 ≈ 12 分钟

第六章：性能调优与运维

概念基础

  1. 优化器是起点：Oracle 用 CBO（基于代价的优化器） 为每条 SQL 选执行计划——统计信息准不准、索引有没有、写法合不合理，决定了计划好不好。调优的第一性原理是「让优化器拿到准确信息、做出正确决策」。
  2. 等待事件是症状：性能问题最终都表现为会话在「等什么」——db file sequential read 等索引块、log file sync 等提交、enq: tx - row lock 等锁。读懂等待事件就找到了瓶颈。
  3. 三层调优：应用层（SQL/索引）→ 实例层（内存/参数）→ 系统层（IO/CPU）。80% 问题在应用层，改一条 SQL 收益常大于加内存。
  4. AWR 是病历：Automatic Workload Repository 周期采集性能快照，是回溯分析的依据——「昨晚 3 点慢」靠 AWR 复盘。
  5. 本章目标：掌握执行计划、索引、统计信息、AWR/ASH、锁与等待，建立系统化的调优方法论。

本章承接 第五章：高可用与备份恢复，是 Oracle 系列的收官章。调优能力 = 统计信息 + 执行计划 + 等待事件 + AWR，四件套缺一不可。

一、CBO 优化器

1. RBO 与 CBO

优化器 机制 现状
RBO（Rule-Based） 基于固定规则（有索引就走索引） 10g 起废弃
CBO（Cost-Based） 基于统计信息估算代价，选最低成本计划 默认，现代标准

CBO 的「成本」是估算的 IO + CPU 开销，依赖对象统计信息（行数、唯一值、直方图）。

2. 统计信息

参数 作用
estimate_percent 采样比例，DBMS_STATS.AUTO_SAMPLE_SIZE 自动
method_opt 直方图策略，SIZE AUTO 自适应
cascade 是否同时收集索引统计
degree 并行度

统计信息失真=计划变差：大批量删除/导入后未及时收集，CBO 据错误行数选错计划（如本该走索引却全表扫）。直方图对「数据倾斜列」（如状态枚举）尤其重要。

3. 绑定变量与游标共享

解析类型 说明
硬解析 Hard Parse 新 SQL，解析+优化+生成执行计划，昂贵
软解析 Soft Parse 命中 Shared Pool，跳过优化

绑定变量是 OLTP 性能的生命线：不绑定的系统硬解析吃满 CPU、Shared Pool 争用。cursor_sharing=FORCE 是应急补丁，正确做法是应用层用绑定变量。

二、执行计划

执行计划是 SQL 如何执行的「图纸」，调优必看。

1. 获取执行计划

2. 读懂执行计划

列 含义
Operation 操作，缩进表示父子关系，先执行叶子
Rows 估算输出行数（来自统计信息）
Cost 估算成本，越小越好
Name 用的索引/表

3. 常见访问路径

操作 说明 何时出现
TABLE ACCESS FULL 全表扫描 无索引/索引不优/小表
INDEX RANGE SCAN 索引范围扫 等值/范围走索引
INDEX UNIQUE SCAN 唯一索引等值 主键等值
TABLE ACCESS BY INDEX ROWID 回表取行 索引不含所需列
INDEX FAST FULL SCAN 索引快速全扫 索引覆盖所需列
HASH JOIN 哈希连接 大表等值连接
NESTED LOOPS 嵌套循环 小表驱动大表，索引访问
SORT ORDER BY 排序 无法用索引消除排序

判断执行计划好坏的核心：估算行数（Rows）是否接近实际——偏差大说明统计信息失真。关注高 Cost 节点与「FULL SCAN + 大表」组合。

4. Hint 提示

临时强制执行计划（治标，慎用）：

Hint 是「硬编码计划」，脆弱：数据变化后可能更差。优先靠统计信息+索引让 CBO 自动选对，Hint 仅作诊断或应急。也可用 SQL Profile / SQL Plan Baseline 固定好计划。

三、索引

1. 索引类型

类型 说明 适用
B-Tree 默认，平衡树 高基数列，等值/范围
Bitmap 位图，每值一个位图段 低基数列（性别、状态），OLAP 专用
Unique 唯一 B-Tree 主键/唯一约束
Function-based 函数/表达式索引 WHERE UPPER(name)=...
Reverse Key 反转键值 消除热点块（序列主键插入热点）

2. 创建与维护

3. 索引失效场景

场景 原因
函数操作列 WHERE UPPER(name)=... 不走普通索引，建函数索引
隐式类型转换 WHERE id = '1'（id 是 NUMBER）可能不走索引
<> / NOT IN 不等条件常不走索引
LIKE '%xxx' 前导通配符无法用索引
NULL B-Tree 索引不含全 NULL 行，IS NULL 不走（建含 NULL 的函数索引）
统计信息失真 CBO 估算全表更便宜
复合索引非最左前缀 (dept,salary) 查 salary 不走

4. 复合索引设计

复合索引遵循最左前缀：把等值条件列放前、范围条件列放后。等值列选择性高的放前。覆盖索引（含 SELECT 所需全部列）可免回表。

四、AWR 与 ASH

1. AWR

AWR 每 1 小时自动采集一次快照（STATISTICS_LEVEL=TYPICAL+），保留 8 天，存 SYSAUX：

AWR 报告核心区域：

区域 内容
Top SQL by Elapsed 最耗时 SQL（首要优化对象）
Top 5 Timed Events Top 等待事件
Load Profile 负载画像（每秒事务/解析/redo）
Instance Efficiency 实例效率（解析命中率、缓冲命中率）
SQL Statistics 各类 SQL 统计

2. ASH

ASH（Active Session History）每秒采样活跃会话，保留内存 1 小时、写盘到 AWR：

工具 粒度 适用
AWR 快照间汇总（小时级） 回溯长时间段、找 Top SQL
ASH 秒级活跃会话 定位短时尖峰、单会话瓶颈
ADDM 自动诊断（基于 AWR） 给出改进建议

“昨晚 3 点慢”用 AWR（找时间段报告）；”刚才卡了 10 秒”用 ASH（秒级定位）。ADDM 自动分析 AWR 给建议，是新手入门调优的好起点。

五、等待事件与锁

1. 等待事件分类

Wait Class 典型事件 含义
User I/O db file sequential read 单块读（索引回表）
db file scattered read 多块读（全表扫）
log file parallel write LGWR 写日志
Commit log file sync 提交等 LGWR
Concurrency enq: tx - row lock contention 行锁争用
library cache lock/pin 共享池争用
latch: cache buffers chains 块争用（热块）
System I/O log file parallel write 后台 IO
Application SQL*Net message from client 等客户端（空闲）

2. 锁机制

Oracle 锁分两类：

锁类型 粒度 行为
TM（表级 DML 锁） 表 防止 DDL 改结构
TX（行级事务锁） 行 行级排他，提交释放
  • 行级锁：UPDATE 一行只锁该行，靠数据块 ITL 实现，不 escalation（不升级为表锁）。
  • 读不阻塞写、写不阻塞读：查询靠 UNDO 读一致性，不锁行。

3. 经典等待分析

等待 原因 对策
log file sync 提交等 LGWR IO 慢/过度提交；redo 放快盘
db file sequential read 索引回表 回表过多，看能否覆盖索引
db file scattered read 全表扫 缺索引/统计失真
enq: tx - row lock 行锁争用 应用串行化热点行；尽快提交
library cache lock 硬解析/DDL 争用 绑定变量、避免高峰 DDL
buffer busy waits 块争用 减少热点块（反转索引、散列分区）
free buffer waits Buffer Cache 不足 调大 DB_CACHE

八、调优方法论

  1. 先定位再动手：用 AWR/ASH 找 Top SQL 与等待事件，避免盲目改参数。
  2. 应用层优先：80% 问题在 SQL/索引，改一条 SQL 收益常大于加内存。
  3. 统计信息保新：大批量 DML 后手动收集，避免 CBO 走错计划。
  4. 绑定变量必须：OLTP 不绑定等于慢性自杀。
  5. 验证再推广：调优改动在测试环境验证执行计划，生产用 SQL Plan Baseline 平滑切换。
  6. 监控常态化：空间、归档、长事务、慢 SQL 纳入监控告警。
  7. 避免过度优化：满足业务 SLA 即可，过度优化增加复杂度与风险。

九、常见陷阱

陷阱 说明
统计信息陈旧 CBO 估算失真选错计划，大批 DML 后收集
不用绑定变量 硬解析吃 CPU、Shared Pool 争用
滥用 Hint 数据变化后更差，优先统计+索引
索引越多越好 写放大、DML 变慢，只建必要的
Bitmap 上 OLTP 并发更新锁整段，OLAP 专用
AWR 默认保留 8 天 周期性慢需调长保留
杀会话不查源头 治标不治本，定位持锁 SQL
ALTER SYSTEM 改生产 先在测试验证，spfile 改动要备份

本章小结

要点 结论
CBO 基于统计信息选计划；统计准=计划好；绑定变量防硬解析
执行计划 DBMS_XPLAN 看真实计划；估算行数与实际比对
索引 B-Tree 通用、Bitmap 限 OLAP；复合索引最左前缀；避免失效写法
AWR/ASH AWR 回溯时段、ASH 秒级定位、ADDM 给建议
等待事件 读懂 db file/ log file sync/ enq: tx 等找瓶颈
锁 行级 TX 锁，读不阻塞写；查 v$lock/blocking_session
调优方法论 先定位后动手、应用层优先、统计信息保新、验证再推广
