第六章：高级技巧与性能调优

概念基础

  1. 批量与自动化：生产环境很少单条命令手敲，更多是批处理转码、管道串联、监听目录——把 ffmpeg 嵌入脚本与流水线。
  2. 硬件加速链路：单独用硬件编码器只是冰山一角，真正的提速是 解码→缩放→编码全链路走 GPU，避免 CPU↔GPU 来回拷贝。
  3. 性能瓶颈在 I/O 与编码：磁盘读写、编码 preset、滤镜复杂度决定吞吐；调优先量化（-progress/time），再针对性优化。
  4. 质量度量要客观：肉眼判断不可靠，PSNR/SSIM/VMAF 给出客观分数，用于对比编码器与参数。
  5. 本章定位：把前五章零散的硬件、批处理、监控手段系统化，给出生产级调优清单与陷阱汇总，是 FFmpeg 进阶的收尾。

本章综合 第二章：编解码与转码 编解码与 第五章：流媒体与直播推流 流媒体，面向高吞吐生产场景。

一、硬件加速全链路

仅用 -c:v h264_nvenc 只加速编码，解码与缩放仍走 CPU，且数据要 CPU↔GPU 拷贝。全链路 GPU 才是最大化提速：

  • -hwaccel cuda：硬件解码。
  • -hwaccel_output_format cuda：解码后帧留在 GPU 显存，避免拷回 CPU。
  • scale_cuda：GPU 缩放滤镜（替代 scale）。
  • h264_nvenc：GPU 编码。

对应 Intel QSV：-hwaccel qsv -c:v h264_qsv -vf scale_qsv；Apple VideoToolbox 链路类似。

取舍：全链路 GPU 提速数倍，但滤镜生态不如 CPU 丰富（subtitles/drawtext 等多在 CPU），需在 GPU 滤镜前后用 hwdownload/hwupload 转换，复杂度上升。纯转码提速用全链路；复杂滤镜用 CPU 或混合。

六、字幕、章节与元数据

软字幕 vs 硬字幕：硬字幕烧进画面（第四章 subtitles 滤镜），软字幕保留为独立流可开关。

七、生产级调优清单

维度 调优项
编码速度 软编调 -preset（medium→fast）；硬编全链路 GPU
画质体积 -crf 选 18–23；2-pass 精控体积
I/O 源与输出分盘，避免磁盘带宽瓶颈；SSD 加速小文件
并行 软编并行度 ≤ CPU 核数；硬编监控 GPU 路数上限
内存 大文件 -analyzeduration/-probesize 限制探测；高分辨率留意帧缓冲
直播延迟 zerolatency + 小 GOP + nobuffer + flush_packets
监控 -progress 接脚本；speed < 1 即跟不上实时，直播会丢帧
质量验证 上线前用 PSNR/VMAF 对比，防画质回退

八、常见陷阱汇总

陷阱 说明
硬编画质差却不知 NVENC 默认参数偏弱，需 -preset p5+/-cq 调优，并用 VMAF 对比
GPU 显存泄漏 全链路 GPU 异常退出未释放显存，需监控 nvidia-smi
并行超 CPU 软编 -P 超核数反而争抢变慢
预设误用 归档用 ultrafast 导致体积翻倍；实时用 veryslow 跟不上
-c copy 改滤镜 任何滤镜都需重编码，copy 模式滤镜静默无效
批处理无 -y 输出已存在 ffmpeg 交互询问，脚本卡死；脚本必加 -y 或 -n
进度解析错 frame 是累计帧非实时；实时看 fps 与 speed
音频采样率不匹配 不同源混音/拼接前统一 -ar 44100，否则爆音或失败
10bit/HDR 降级 不加 -pix_fmt yuv420p 普通播放器黑屏或偏色

本章小结

要点 结论
全链路 GPU -hwaccel cuda+scale_cuda+h264_nvenc，帧留显存免拷贝；复杂滤镜仍走 CPU
多路输出 一次解码多次编码，比多次命令快
批处理 shell 循环 + xargs -P/parallel -j 并行；脚本必加 -y
进度 -progress pipe:1 输出 key=value；speed<1 跟不上实时
质量度量 PSNR/SSIM/VMAF 客观对比，防画质回退
软硬字幕 软字幕 -c:s mov_text 可开关；硬字幕 subtitles 滤镜烧画面
调优 速度靠 preset/GPU，画质靠 crf/2-pass，I/O 靠分盘，监控靠 progress
陷阱 硬编需调参、并行勿超核、copy 不能加滤镜、批处理必 -y
