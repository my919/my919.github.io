第一章：PostgreSQL 概述与 DDL 入门

概念基础

  1. PostgreSQL 是开源的对象-关系型数据库：以 SQL 标准兼容与丰富的数据类型、扩展生态著称；数据按 数据库 → 模式（SCHEMA）→ 表 分层组织，客户端用 psql 或 JDBC 等驱动访问。
  2. SQL 按职责分两层：DDL（数据定义语言）管结构——库、模式、表、列、索引等对象的创建与变更；DML（数据操作语言）管数据——行级增删改查。本章聚焦 DDL。
  3. 为什么从 DDL 学起：结构是一切的地基——后面的高级查询、索引与性能、并发与 MVCC 都建立在「先有表结构」之上；类型与约束设计得当，能直接挡住一大批脏数据。
  4. 一条主线：CREATE 建、ALTER 改、DROP 删；生产环境永远先确认影响面（活跃连接、依赖对象），并养成 IF EXISTS 幂等习惯。

先看一条 DDL 在「客户端 → 引擎」链路中的位置：

DDL：数据定义语言

DDL：Data Definition Language 数据定义语言
作用：定义/修改/删除 数据库、模式（SCHEMA）、表、字段、索引等对象结构，不直接操作「行级业务数据」本身（数据由 DML 写入）。

DDL 主要分 3 大类

  1. 库 / 模式：CREATE / ALTER / DROP DATABASE；CREATE SCHEMA 等（SCHEMA 类似命名空间，用于组织表与权限）。
  2. 表与列：CREATE / ALTER / DROP TABLE；约束、默认值、自增（IDENTITY / SERIAL）。
  3. 其他对象：VIEW、INDEX、SEQUENCE、EXTENSION 等（入门可先把 表 + 索引 吃透）。

常用类型（节选）：

  • integer / bigint：整型
  • varchar(n) / text：变长字符串（text 无长度上限，多数场景可优先 text + CHECK）
  • boolean：布尔
  • date / timestamp / timestamptz：日期与时间（推荐 timestamptz 存绝对时刻）

常用约束：

  • PRIMARY KEY
  • GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY（推荐）或 SERIAL / BIGSERIAL（底层仍是序列，语义略宽）
  • NOT NULL、DEFAULT
  • UNIQUE、REFERENCES（外键）

UNIQUE（唯一约束）

  • 与主键：每表一个 PRIMARY KEY，可有多个 UNIQUE。
  • NULL：PostgreSQL 里 UNIQUE 认为 NULL 与 NULL 不相等，故多行可取 NULL（与 SQL 标准一致）；若业务只允许一行未填，需 NOT NULL 或部分唯一索引（UNIQUE … WHERE col IS NOT NULL）等。

三、DDL 与 DML 区别（必记）

分类 全称 作用 常用语句
DDL 数据定义语言 管库、模式、表、索引、视图等结构 CREATE / ALTER / DROP
DML 数据操作语言 管表内行数据 INSERT / UPDATE / DELETE / SELECT

简单记：DDL 改架子；DML 改数据。

四、入门必背 DDL 极简清单

本章小结

要点 结论
DDL 定位 改架子不落数据：库/模式/表/索引等结构由 DDL 管，行数据交给 DML
三大操作 CREATE 建、ALTER 改、DROP 删，生产务必带 IF EXISTS 并确认影响面
层级模型 库 Database → 模式 SCHEMA → 表，search_path 决定默认命名空间
类型与约束 推荐 bigint + IDENTITY 主键、timestamptz 存时间；UNIQUE 允许多行 NULL
删除纪律 DROP TABLE / DROP CONSTRAINT 慎用 CASCADE，先查依赖再动手
