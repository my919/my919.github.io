适配器模式详解（Adapter）

发表于 2026-09-14 本文字数： 1k 阅读时长 ≈ 3 分钟

设计模式 · 适配器模式

GoF 结构型模式。意图 · 结构 · 类适配器与对象适配器 · 代码实现 · 应用场景 · 优缺点。代码带详细注释。

1. 模式概述（意图）

适配器模式（Adapter）把一个类的接口转换成客户端期望的另一个接口——让不兼容的接口能一起工作，如同电源转换插头。

2. 要解决的问题

问题 说明
新旧系统对接 老系统的接口与新技术栈不匹配
第三方库适配 库的 API 与业务需要的形式不同
无法改源码 遗留代码/外部库不能直接改

典型场景：接入第三方支付（各家 API 不同 → 统一成自己的接口）、老系统 ESB 对接、Arrays.asList()（数组 → List 的适配）、日志门面 slf4j 适配 log4j/logback。

3. 结构（角色）

两种实现方式：

方式 原理 适用
对象适配器（推荐） 组合：Adapter 持有 Adaptee 通用，解耦
类适配器 继承：Adapter extends Adaptee 需覆写 Adaptee 行为时才用

4. 代码实现（对象适配器）

5. 应用场景

场景 说明
第三方 SDK 统一 支付/短信/OSS 各家 API 统一成自家接口
老系统对接 遗留 ESB/数据库适配新架构
JDK 实例 Arrays.asList()、InputStreamReader（字节流→字符流）
日志门面 slf4j → logback/log4j 适配器
数据格式转换 旧数据格式适配新模型

6. 优缺点

优点 缺点
让不兼容接口协同工作 过度使用导致”包装套包装”难排障
客户端解耦（只认目标接口） 适配层增加调用链
无需修改被适配者 需要理解双方接口差异
可插拔（换适配器即换实现） 适配逻辑要写好转换与异常

7. 与其他模式对比

模式 区别
装饰器 装饰器增强功能不改接口；适配器转换接口
代理 代理控制访问（同接口）；适配器转接口
门面 门面聚合多个接口为高层接口；适配器一对一转换
