1. 概念说明

单机 Redis 有两大天花板：可用性（宕机全挂）和容量/吞吐（单节点上限）。进阶要解决：

  • 主从复制：数据冗余 + 读写分离（解决可用性基础）。
  • 哨兵（Sentinel）：监控主节点，宕机自动选举新主（解决自动故障转移）。
  • 集群（Cluster）：数据分片到多主多从（解决容量与吞吐）。
  • Lua 脚本：把多条命令打包原子执行（解决”检查-执行”竞态）。

2. 主从复制

复制原理：全量同步（RDB 快照 + 增量）→ 增量同步（命令传播）。从库只读，默认 replica-read-only yes。

4. Redis Cluster 集群

集群要点：key 按 CRC16(key) % 16384 落到槽位；多 key 操作需同槽（用 hash tag {user:1001}）；客户端需支持集群协议（Lettuce/Redisson 开箱即用）。

7. 内存淘汰策略

策略 说明 适用
noeviction（默认） 满则不写，直接报错 不推荐生产
allkeys-lru 淘汰最久未使用 通用缓存（推荐）
allkeys-lfu 淘汰使用频率最低 热点明显的缓存
volatile-ttl 淘汰快过期的 有设置过期时间的场景

8. 性能排查

大 key 危害：阻塞单线程（删除/迁移都慢）。应对：拆分、UNLINK（异步删除）。

10. 高可用架构选型

规模 方案
单机开发 单节点 + AOF
读多写少（中小） 主从 + 读写分离
需要自动故障转移 哨兵（1 主 2 从 3 哨兵）
大数据量/高吞吐 Cluster（≥3 主 3 从）
云上托管 云 Redis（自带高可用与备份）
