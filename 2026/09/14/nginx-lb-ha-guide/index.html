1. 概念说明

负载均衡：多台应用服务器分担流量——提升吞吐（横向扩展）与可用性（单点故障不影响）。

Nginx 负载均衡核心：upstream（后端服务器组）+ proxy_pass（转发）+ 调度算法（怎么分流量）。

高可用：Nginx 自身不能是单点——两台 Nginx 用 Keepalived 共享一个虚拟 IP（VIP），主挂备自动接管。

现代替代：K8s Ingress、云 LB（ALB/SLB）；但 Nginx 仍是自建与边缘网关主力。

3. 调度算法对比

算法 行为 适用
轮询（默认） 依次分发 通用
weight 按权重 机器性能不均
ip_hash 同 IP 固定同后端 需要会话保持（老系统）
least_conn 发给连接最少 请求耗时差异大
hash $request_uri 同 URL 固定节点 缓存命中

注意：加/减后端节点会改变 hash 分布——优先用 Redis 会话共享实现无状态，而不是依赖 ip_hash。
