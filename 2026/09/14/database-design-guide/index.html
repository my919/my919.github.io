1. 概念说明

数据库设计的目标：数据一致、查询高效、易维护、可扩展。

核心矛盾：范式化（消除冗余，写友好）vs 反范式化（冗余加速读）。生产实践：逻辑上按范式设计，物理上按查询反范式（冗余字段、汇总表）。

设计五步：需求分析（实体与关系）→ 概念设计（ER 图）→ 逻辑设计（表结构）→ 物理设计（索引/存储）→ 评审上线。

3. 范式 vs 反范式

3.1 三范式速记

范式 要求 反例
1NF 字段原子，不可再分 一个字段存”北京,朝阳”
2NF 非主键完全依赖主键 订单表存了用户名
3NF 非主键不传递依赖 订单表通过用户ID存了用户电话

3.2 实战取舍

冗余准则：快照类冗余（价格、名称）安全；可计算类冗余要保证一致性（更新点少）。

5.2 分表策略

策略 规则 适用
水平分表 按 id 取模/范围拆多表 单表数据量大
垂直拆分 按字段拆分到不同表 大字段/冷热字段

7. 设计评审清单

检查项 要求
主键 BIGINT，禁止业务字段当主键
金额 DECIMAL，禁止浮点
时间 DATETIME，统一时区
字符集 utf8mb4（支持 emoji）
软删除 is_deleted TINYINT + 唯一索引带 deleted_at
大字段 TEXT/BLOB 拆到附属表
索引 每表 ≤5 个联合索引，覆盖高频查询
默认值 NOT NULL + DEFAULT，避免 NULL 统计坑
注释 表/字段全注释（COMMENT 必填）
迁移 所有 DDL 走 Flyway，禁止手改生产
