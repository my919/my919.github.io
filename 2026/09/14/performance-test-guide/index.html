1. 概念说明

性能测试目的：验证系统在预期负载下是否达标 + 找出瓶颈 + 给出容量结论（”能抗多少 QPS”）。

关键指标：

指标 含义 常见目标
QPS/TPS 每秒请求/事务数 按业务
并发数 同时在处理的请求 与 QPS 关联
RT（响应时间） 平均/P90/P99 P99 < 500ms
错误率 失败请求占比 < 0.1%
吞吐量 每秒处理字节数 大文件场景

测试类型：

最重要概念：P99 而不是平均值——平均延迟被长尾掩盖；P99 反映真实体验。

3.2 压力阶梯设计（找拐点）

阶段 并发 时长 观察
冒烟 10 1min 链路通
基准 50 2min 基线数据
负载1 100 5min RT 是否线性
负载2 200 5min RT 拐点在哪
负载3 400 5min 超时/错误开始
容量 500+ 5min 极限

判定：RT 急剧上升 + 错误率增加的交界 = 系统拐点。

5. 瓶颈定位方法论

常见瓶颈速查：

症状 瓶颈
CPU 100% 且 GC 少 业务热点/死循环 → 火焰图
GC 频繁 堆配置/对象过多 → 堆转储
RT 高但 CPU 低 锁竞争/IO 等待/依赖慢
连接池耗尽 连接池小/慢查询占连接
QPS 到某值上不去 数据库/Redis/网络带宽瓶颈

7. 性能测试最佳实践

实践 说明
数据量真实 100 万条与 10 条的查询性能天差地别
环境隔离 压测不要影响生产（独立环境/集群）
逐步加压 一次打满无法定位拐点
同步监控 压测同时采集资源，否则无法归因
关注长尾 P99/P999 而非平均
结果可复现 记录环境、脚本、参数
