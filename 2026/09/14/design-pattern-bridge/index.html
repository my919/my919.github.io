桥接模式详解（Bridge）

发表于 2026-09-14 本文字数： 903 阅读时长 ≈ 3 分钟

设计模式 · 桥接模式

GoF 结构型模式。意图 · 结构 · 代码实现 · 应用场景 · 优缺点 · 与适配器对比。代码带详细注释。

1. 模式概述（意图）

桥接模式（Bridge）把抽象部分与实现部分分离，让它们可以独立变化——用组合代替继承，解决”多维度变化”的类爆炸问题。

2. 要解决的问题

经典例子：消息系统有类型维度（普通/紧急/加急）和渠道维度（短信/邮件/企微）。用继承组合，类数 = 类型 × 渠道 = 9 个类：

桥接解法：9 个类 → 3 个类型类 + 3 个渠道类（组合桥接）。

4. 代码实现

类数公式：类型 N 个 + 渠道 M 个 = N+M 个类（而不是 N×M）。

5. 应用场景

场景 说明
多维度变化的业务 消息(类型×渠道)、支付(业务×渠道)、通知
跨平台 JDBC（驱动实现）× 业务抽象
UI 控件 形状 × 颜色（JDK AWT 的经典例子）
驱动架构 抽象 API × 平台驱动实现

6. 优缺点

优点 缺点
消除继承爆炸（N×M → N+M） 抽象与实现都要维护两套层级
两个维度独立扩展 需要先识别出”两个变化维度”
符合开闭原则 没有多维度变化时是过度设计
实现细节对抽象隐藏 理解门槛略高

7. 与适配器对比

模式 区别
适配器 解决”接口不匹配”（事后补救）
桥接 解决”维度独立变化”（事先设计）
策略 策略只变算法；桥接抽象+实现双维度
