1. 概念说明

CI/CD 是”自动化交付”的三种实践的合称：

  • 持续集成（CI, Continuous Integration）：每次代码提交都自动触发构建 + 测试，尽早发现集成问题。核心是”频繁合并、快速反馈”。
  • 持续交付（CD, Continuous Delivery）：CI 通过后自动把产物（镜像/包）准备好，处于”随时可发布”状态。
  • 持续部署（Continuous Deployment）：产物自动部署到生产环境，全流程无人干预。

**流水线（Pipeline）**是这些阶段的编排：提交代码 → 安装依赖 → Lint → 单元测试 → 构建镜像 → 推送制品 → 部署。**质量门禁（Quality Gate）**指某一步失败即中断流水线，保证坏代码无法进入下一步。

2. GitHub Actions 从零开始

2.1 概念：Workflow / Job / Step

术语 含义
Workflow 一个 .yml 文件，定义整条流水线
Event 触发条件（push、PR、定时）
Job 一组 Step，默认并行执行
Step 最小执行单元（一条命令或一个 action）
Runner 执行环境（ubuntu-latest 等）

实践 说明
流水线快 缓存依赖（npm cache / docker layer cache）
失败即中断 每一步都是质量门禁
部署用制品 不要重复构建，测试通过的镜像一路到生产
环境隔离 dev/staging/prod 三套环境与密钥
密钥不入库 全部走 Secrets / Vault
并行化 无依赖的 Job 并行跑，缩短总时长
