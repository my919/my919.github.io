1. 概念说明

GitLab CI 是 GitLab 内置的持续集成/部署系统：提交代码 → Runner 执行流水线 → 构建/测试/部署。

核心概念：

概念 说明
Pipeline 一次 CI 执行（每次 push 触发）
Stage 阶段（build → test → deploy），同阶段并行、跨阶段串行
Job 一个任务（一个 stage 下的具体命令）
Runner 执行任务的机器（共享/特定）
Artifacts 任务产物（如 jar），可传递给后续任务

工作流：Merge Request 触发 → 校验（lint/test）→ 合并后自动部署到测试环境 → 手动/自动部署生产。

7. 最佳实践与坑

实践 说明
密钥走 Variables 不写进 yml/仓库，用 Masked + Protected
artifacts 设过期 防止存储膨胀
cache 配 key 分支间隔离缓存
阶段划分清晰 build/test/deploy 分离，便于定位
超时限制 timeout: 30m 防任务挂死
镜像固定版本 避免 latest 漂移导致偶发失败
失败重试 retry: 2 处理网络抖动
