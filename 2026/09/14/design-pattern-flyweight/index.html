享元模式详解（Flyweight）

发表于 2026-09-14 本文字数： 1.1k 阅读时长 ≈ 4 分钟

设计模式 · 享元模式

GoF 结构型模式。意图 · 结构 · 内部/外部状态 · 代码实现 · 应用场景 · 优缺点。代码带详细注释。

1. 模式概述（意图）

享元模式（Flyweight）通过共享大量细粒度对象来减少内存占用——把对象拆成”可共享的不变部分（内部状态）”和”不可共享的变化部分（外部状态）”。

2. 要解决的问题

问题 说明
对象数量巨大 百万个字符/棋子/图标，每个都 new 内存爆炸
大量对象只有小差异 重复内容多，可共享
内存压力 大流量场景 GC 频繁

核心思想：内部状态（不变，共享）+ 外部状态（变化，调用时传入）。

状态 说明 示例（字符对象）
内部状态 不可变、可共享 字符本身的字形
外部状态 随场景变化 字符的位置、颜色

5. 应用场景

场景 说明
字符串常量池 JVM 字符串驻留（"a" == "a"）
包装类缓存 Integer.valueOf 缓存 -128~127
线程池/连接池 复用对象（池化思想）
文字渲染 字符/图标/棋子
JDK String String 对象不可变共享

6. 优缺点

优点 缺点
大幅减少内存（共享） 需要区分内/外部状态（设计复杂）
对象复用减少 GC 外部状态管理增加调用复杂度
池化提高创建效率 状态拆分不当会引入并发问题（内部状态必须不可变）

关键约束：内部状态必须不可变——享元被共享，任何人不能改它；外部状态由调用方持有（不共享），否则并发下互相污染。

7. 与其他模式对比

模式 区别
单例 单例全局唯一；享元是一类对象的池化共享（多实例）
对象池 对象池复用”昂贵对象”；享元共享”小对象”
工厂 享元工厂负责缓存与创建
