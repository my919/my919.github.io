协议对比：

协议 延迟 浏览器支持 适用
RTMP 1-3s ❌ 需插件/封装 推流、内部播放
HLS 5-15s ✅ 原生 点播、直播（默认首选）

延迟取舍：HLS 延迟高但兼容最好（稳定首选）；低延迟互动场景用 HTTP-FLV 或 WebRTC。

3. HLS 直播（浏览器原生播放）

SRS 默认把 RTMP 流转封装为 HLS，无需额外配置：

HLS 原理：直播流切成 4-6 秒的 .ts 分片 + m3u8 播放列表（索引），播放器逐片拉取。延迟 = 切片时长 + 列表缓冲。

降低延迟：-hls_time 2（切 2 秒片）+ 播放器 lowLatencyMode。

4. 多码率转码（自适应）

观众带宽不同 → 服务器转出多档码率，播放器自动切换（ABR）。

生产注意：转码是 CPU/GPU 密集——用硬件编码（NVENC/QuickSync）、转码集群化，或只用 SRS 专业版/云转码。

8. 常见问题排查

现象 原因与解决
推流失败 端口/地址错、token 拒绝 → 检查 1935 端口与回调日志
播放卡顿 带宽不足 → 多码率/降低码率
延迟越来越高 播放器缓冲 → lowLatencyMode + 服务端 GOP 设置
音画不同步 时间戳异常 → 推流端检查采集
HLS 播放不了 m3u8 路径/跨域 → 检查 CORS 头与路径
观众多就卡 源站带宽瓶颈 → CDN 分发
