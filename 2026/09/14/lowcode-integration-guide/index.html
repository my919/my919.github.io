1. 概念说明

低代码落地三层：

核心价值：业务快速上线（天级）、变更灵活、减少重复 CRUD 开发；边界：复杂算法、高并发、强一致性场景仍要专业开发。

关键原则：低代码平台是”业务中台的一部分”，必须可编程扩展（脚本/API），否则是死路。

一致性注意：全量+增量结合；同步失败重试；字段映射文档化（源→目标）。

7. 权限与治理

7.1 权限模型

  • 数据权限：客服只能看自己的工单；主管看全组；管理员全部。
  • 字段权限：金额、手机号仅指定角色可见。
  • 审计：关键表操作留审计日志。

7.2 上线治理清单

项 要求
环境分离 dev/test/prod 三套平台
变更流程 模型变更走评审（影响 API 契约）
备份 平台数据库定期备份
监控 平台可用性 + 流程失败告警
文档 模型字典 + 集成接口文档
代码版本化 平台脚本/流程导出入库管理

8. 与专业开发的边界

场景 选择
内部管理台/报表/审批流 低代码（天级上线）
高并发交易（支付/秒杀） 专业开发
复杂业务规则引擎 专业开发 + 规则配置
数据大屏/仪表盘 低代码 + 专业报表
面向客户的复杂产品 专业开发

最佳实践：低代码负责”管理型/流程型”业务；专业开发负责”交易型/算法型”；两者通过 API 协同。
