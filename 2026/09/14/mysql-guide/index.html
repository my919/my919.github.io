1. 概念说明

MySQL 是流行的开源关系型数据库，数据以表为单位组织，通过 SQL 操作。核心概念：

  • 表（Table）/ 行（Row）/ 列（Column）：二维结构组织数据。
  • 主键（Primary Key）：唯一标识一行，默认聚簇索引。
  • 索引（Index）：类似书的目录，加速查询，代价是写入变慢、占空间。
  • 事务（Transaction）：一组 SQL 要么全部成功要么全部回滚，满足 ACID（原子性、一致性、隔离性、持久性）。
  • 存储引擎：默认 InnoDB，支持事务与行级锁（MyISAM 已过时，不再推荐）。

为什么选 8.4 LTS：MySQL 8.4 是长期支持版（LTS），支持到 2032 年；8.0 系列已进入维护末期。生产选 LTS，不选创新版（Innovation Release）。

4. 索引优化（核心技能）

4.1 索引类型

类型 说明 场景
主键索引 聚簇索引，唯一非空 每表一个
唯一索引 值唯一 email、手机号
普通索引 加速查询 查询条件列
联合索引 多列，最左前缀 (user_id, status)
覆盖索引 索引含查询所有列 避免回表

4.2 实战：慢查询优化流程

EXPLAIN 关键列：

列 看什么
type const > eq_ref > ref > range > index > ALL（ALL 必须优化）
possible_keys / key 实际使用索引
rows 预估扫描行数，越小越好
Extra Using index（好）/ Using filesort（加排序索引）/ Using temporary（危险）

4.3 索引失效常见场景（避坑）

  • 对索引列做函数/运算：WHERE YEAR(created_at)=2026 ❌ → 改为范围 created_at >= '2026-01-01'
  • 隐式类型转换：WHERE phone = 13800138000（phone 是 varchar）❌ → 加引号
  • 联合索引不满足最左前缀
  • LIKE '%xxx' 前导模糊
