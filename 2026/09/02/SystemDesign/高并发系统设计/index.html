第三章：高并发系统设计

概念基础

  1. 高并发三指标 QPS/RT/并发数：QPS 每秒请求数、RT 响应时间（区分 P50/P99/P999）、并发数同时在线请求数，三者满足 QPS = 并发数 / RT——降 RT 与提并发数都能提 QPS，但 RT 是用户体验底线。
  2. 扩展性：垂直 vs 水平：垂直扩展是单机升配（CPU/内存/SSD），有上限且成本指数增长；水平扩展是多实例分摊流量，理论上无上限，但要解决状态分布、数据分片、一致性。
  3. 缓存不是银弹：缓存能扛住读 QPS，但带来一致性、穿透、雪崩、击穿四大难题；写多读少或强一致场景缓存收益小且风险大，滥用缓存是高并发系统最常见的事故源。
  4. 降级保核心：流量洪峰时主动牺牲非核心功能（评论、推荐、日志）保全核心链路（下单、支付），降级要预案先行、开关可灰度，而非临时手忙脚乱。
  5. 容量规划先行：先估算峰值 QPS 与单机容量，倒推实例数与资源水位线，再配弹性伸缩；没有容量规划的高并发是赌博，全链路压测是上线前的强制校验。

本章聚焦缓存、数据库扩展、削峰、限流降级四板斧；缓存与数据库基础见 第一章：Redis 概述、安装与 CLI 入门 与 第一章：MySQL DDL 语句与表设计入门。

一、缓存架构

多级缓存

请求从前到后层层兜底：浏览器 → CDN → Nginx → 本地缓存（Caffeine）→ Redis → DB，每层挡住一部分流量，越靠前越快也越易失效。

缓存穿透 / 击穿 / 雪崩

问题 现象 解决方案
穿透 查不存在的 key，缓存 DB 都没有，每次打 DB 布隆过滤器拦截；空值缓存短 TTL
击穿 单个热点 key 过期瞬间，海量请求直击 DB 互斥锁（只放一个回源）+ 热点永不过期后台刷新
雪崩 大量 key 同时过期，DB 瞬时压力暴增 TTL 加随机偏移；多级缓存兜底；熔断限流

缓存一致性策略

策略 做法 一致性 复杂度
Cache Aside 先更 DB 再删缓存，读时回填 最终一致 低，推荐
Read Through 缓存代理回源，应用只读缓存 较强 中
Write Through 写穿缓存再写 DB，同步 强 中
Write Behind 写缓存即返回，异步刷 DB 弱但快 高

Cache Aside 的删缓存时机：先更 DB 后删缓存，配合延迟双删（删→更→延迟再删）可缓解主从延迟导致的脏读。

热点 Key

热点 Key 单分片扛不住时：本地缓存吸收读、分片打散（key 加随机后缀分散到多分片）、只读副本分流。

二、数据库扩展

读写分离

主库写、从库读，主从复制异步。代码层用 ShardingSphere 自动路由：写走 master、读走 slave。

分库分表

  • 垂直拆分：按字段拆表（商品基本信息 vs 商品详情长文），解决单表字段过多。
  • 水平拆分：按分片键（如 user_id）把数据分散到多库多表，解决单表数据量过大。

分片键选择与全局 ID

  • 分片键：选高频查询条件（如 user_id），避免跨片查询；不带分片键的查询会广播所有分片。
  • 跨片查询：用 ES 建二级索引，或宽表汇总，避免广播扫描。
  • 全局唯一 ID：雪花算法（时间戳+机器 ID+序列号），趋势递增利于 B+树插入。

三、消息队列削峰

消息队列在高并发里干三件事：削峰填谷（把瞬时洪峰蓄进队列、匀速消费）、异步解耦（写完即返回、下游异步处理）、最终一致（事件驱动跨服务状态同步）。

消费者背压与幂等

死信队列：消费失败重试达上限后转入 DLQ 人工介入；位移提交：业务成功后再 MarkMessage，避免处理失败丢消息。MQ 基础见 第一章：Kafka 消息中间件入门：核心概念与架构。

四、限流与降级

限流算法

算法 特点 场景
计数器 固定窗口、临界突刺 简单限频
滑动窗口 平滑、无突刺 接口 QPS 限流
令牌桶 允许突发、匀速补桶 网关入口限流
漏桶 匀速出水、削峰 下游保护

降级与熔断实战

  • 降级分级：读降级（缓存/默认值）、写降级（同步转异步）、功能降级（关评论/推荐）。
  • 熔断：错误率/RT 超阈值触发，OPEN 直接拒绝，休眠后 HALF_OPEN 探活恢复。

熔断限流工程落地见 第七章：集成 Sentinel：流控、熔断与服务保护。

五、CDN 与静态化

CDN 边缘缓存与动静分离

CDN 把静态资源缓存到离用户最近的边缘节点，回源率是成本与体验的关键。动静分离让动态请求走应用、静态走 CDN/Nginx。

页面静态化与图片服务

  • 页面静态化：把活动页/详情页预渲染成 HTML 推 CDN，QPS 由应用层降到 CDN 层。
  • 图片服务：上传后转多尺寸+WebP，CDN 按尺寸回源；预热提前把热点资源推 CDN，刷新保证更新及时。

Nginx 静态服务与反向代理见 第一章：Nginx 入门与静态服务。

六、容量评估与压测

QPS 估算与压测工具

峰值 QPS 估算：日均 PV ÷ 秒数 × 峰值系数（通常 5~10 倍），再按二八定律收敛到高峰时段。

全链路压测与弹性伸缩

  • 全链路压测：在影子库影子表上模拟真实流量走过所有服务，发现瓶颈与雪崩点。
  • 容量水位线：CPU/内存/RT 水位线，超过扩容、低于缩容。
  • K8s HPA：按 CPU 或自定义指标自动伸缩 Pod 数。

容器编排与弹性伸缩见 第二章：Kubernetes 容器编排入门。

常见避坑

坑 现象 正确做法
缓存与 DB 强一致执念 加各种锁保强一致，性能崩盘 接受最终一致，用延迟双删+消息补偿
热点 key 过期集中 同时过期引发雪崩击穿 TTL 加随机偏移，热点永不过期后台刷
分片键选错 按自增 ID 分片导致写入热点 选离散度高的业务键（user_id），避免时间序
跨片查询广播 不带分片键的查询扫所有分片 建二级索引（ES/宽表），或冗余分片键
消费位移提前提交 处理未成就位移，宕机丢消息 业务成功后再 MarkMessage，处理失败重试
限流只限单机 单机限不住全局，总量仍超 网关层 + Redis Lua 做分布式限流
降级开关临时找 故障时才现加开关，来不及 预埋降级开关，演练验证可降级路径
压测压单接口 单接口扛住了，链路仍崩 全链路压测，覆盖依赖与共享资源
HPA 扩容滞后 流量突增时 Pod 还没起就过载 预留 buffer + 预扩容 + 缩容冷却防抖
缓存击穿用大锁 互斥锁锁全局，并发退化串行 锁粒度细化到 key，或逻辑过期异步刷新

本章小结

要点 结论
缓存 多级缓存兜底，穿透/击穿/雪崩三防，Cache Aside 主流
数据库 读写分离+分库分表，雪花算法做全局 ID
削峰 MQ 削峰填谷+异步解耦，消费幂等与位移提交是底线
限流降级 令牌桶为主、Redis Lua 分布式，降级分级保核心
静态化 动静分离+页面静态化，CDN 边缘扛量
容量 先估 QPS 再全链路压测，HPA 弹性伸缩兜底

高并发管流量与资源，其服务间的拆分与容错来自 第二章：微服务架构模式，微观构件的模式来自 第一章：设计模式精要。配套基础设施：缓存主力 第一章：Redis 概述、安装与 CLI 入门、数据库分片 第一章：MySQL DDL 语句与表设计入门、动静分离 第一章：Nginx 入门与静态服务、弹性伸缩 第二章：Kubernetes 容器编排入门，三者层层递进构成完整系统设计骨架。
