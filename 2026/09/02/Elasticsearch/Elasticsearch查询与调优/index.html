第二章：Elasticsearch 查询与性能调优

概念基础

  1. Query DSL 是 JSON 化的查询语法：一切查询走 GET /idx/_search { body }，body 由 query / aggregations / sort / size / from 等组成——告别 SQL，拥抱嵌套 JSON。
  2. 精确匹配 vs 全文检索：term 对 keyword / 数值精确匹配（不打分），match 对 text 分词后匹配并打分——用错类型是新手头号坑。
  3. 相关性评分 BM25：ES 7+ 默认 BM25（替代 TF-IDF），核心是「词频饱和 + 文档长度归一」——短文档命中高权重，长文档被稀释。
  4. 聚合 = 分桶 + 算指标：bucket agg（terms / date_histogram / range）分组，metrics agg（avg / sum / cardinality）算值，可嵌套——OLAP 分析能力。
  5. 分页深翻是 ES 的痛：from + size 超过 10000 默认被拒（max_result_window），深翻用 search_after 游标或 scroll——选错方式直接 OOM。

本章承接 第一章：Elasticsearch 入门与索引管理 的索引与 mapping；查询 DSL、聚合、调优在此展开。ES 按 8.x 语法。

一、Query DSL 全览

维度 query（查询上下文） filter（过滤上下文）
是否打分 是（算 _score） 否
是否缓存 不缓存 缓存（bitset 复用）
性能 慢 快
适用 全文检索要排序 精确条件、范围、时间过滤

过滤条件能进 filter 就进 filter：不打分 + 可缓存，同样命中快数倍。

二、复合查询与相关性

手法 作用
function_score 销量 / 时间 / 距离等业务字段加权
boosting 负向降权不剔除
constant_score filter 转查询、固定分

电商搜索排序不是单纯 BM25：标题匹配分 + 销量 + 新鲜度 + 是否促销，function_score 是标准答案。

三、聚合分析

agg 类型 作用
terms 按字段值分组（Top N）
date_histogram 按时间分桶（日 / 时 / 月）
range 按数值区间分桶
cardinality 去重计数（近似，HyperLogLog）
nested 聚合 nested 对象数组

cardinality 是近似去重（误差约 1%），size: 0 表示只取聚合不要文档明细——大表聚合必备。

四、分页与深度翻页

方式 上限 适用 状态
from + size 10000（max_result_window） 浅分页、要跳页 通用
search_after 无上限 深翻、顺序翻（不可跳页） 推荐
scroll 无上限 全量导出、一次性 7.10+ 渐进弃用，优先 search_after

from + size 超过 10000 报错：协调节点要把 from+size 条数据都取到内存再截断，深翻是性能与内存双重压力。导出用 search_after 或 scroll。

五、性能调优

  • 分片数：单分片 30~50GB 为宜；过多分片使聚合 scatter-gather 开销大、元数据重。
  • filter 缓存：精确条件进 filter 上下文，bitset 复用。
  • routing：按维度（如 user_id）路由，查询带 routing 少扫分片。
  • 索引拆分：按时间（logs-2026.09）或业务隔离，缩扫描范围。
硬件项 建议
堆内存 物理内存 50%，剩给 Lucene 文件系统缓存
JVM 不超 31GB（指针压缩阈值），用 G1GC
磁盘 SSD 必备；HDD 只读副本勉强
副本 读 QPS 高加副本；写入期临时归零

六、运维与监控

Kibana → Stack Monitoring 可视化集群健康、节点负载、索引速率；ILM 让日志索引自动滚动归档，运维省心。

常见避坑

坑 现象 正确做法
text 字段用 term 查不到（term 不分词，匹配已分词的 term） text 用 match，keyword 用 term
from + size 超 10000 报错或 OOM 改 search_after 游标翻页
全用 must 打分 慢、缓存失效 精确条件进 filter，不打分且缓存
cardinality 要精确 误差大 调大 precision_threshold 或换 terms agg（代价高）
聚合不带 size:0 返回大量文档明细拖慢 聚合查询设 size:0
深翻用 scroll 做分页 游标占内存、不可跳页 在线分页用 search_after，scroll 只导出
nested 聚合漏声明 结果错误 nested 聚合要包 nested agg 路径
堆设超 31GB 指针压缩失效、内存浪费 堆不超 31GB，多余给文件缓存
分片过多 元数据重、聚合 scatter-gather 慢 单分片 30~50GB，别一上来 50 分片
写入不批量 单条 PUT 频繁 refresh 慢 用 bulk，5~15MB 一批

本章小结

要点 结论
Query DSL match 分词打分、term 精确不打分；bool 组合
query vs filter 精确条件进 filter，不打分 + 缓存
相关性 BM25 默认；function_score 做业务加权
聚合 bucket（terms/date_histogram）+ metrics（sum/avg/cardinality）嵌套
分页 浅用 from+size，深用 search_after，导出用 scroll
调优 写入期降副本 + 大 refresh；查询进 filter 缓存 + routing
硬件 堆 50%、不超 31GB；SSD 必备
运维 _cat API 看健康；ILM 自动滚动归档；forcemerge 压只读索引
