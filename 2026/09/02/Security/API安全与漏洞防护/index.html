第二章：API 安全与漏洞防护

概念基础

  1. 输入即恶意：所有来自客户端的数据（表单、查询串、Header、Cookie、上传文件、回调 URL）都应被视为不可信。任何拼接到 SQL、命令、模板、URL 的字符串，都必须先校验或参数化，再使用。这是防注入、防 XSS、防 SSRF 的共同前提。
  2. 最小权限：数据库账号、服务间调用凭据、容器运行用户，都应只授予完成职责所必需的权限。Web 应用别用 root 连库，业务服务别用集群 admin，这样即使被攻破，横向移动与数据外泄也被限制在最小范围。
  3. 纵深防御：单一控制点失败不应导致全盘失守。前端转义 + 后端参数化 + WAF 规则 + 数据库最小权限，多层叠加；任一层漏了，下一层仍能拦截。安全不靠”一招制敌”，而靠”层层衰减”。
  4. API 安全与 Web 安全的差异：Web 安全聚焦浏览器交互（Cookie、CSRF、同源策略），而 API 安全更关注无状态令牌、输入注入、越权访问、速率限制与重放。前后端分离后，跨站脚本通过 API 返回的 JSON 传播，XSS 防护点也从服务端模板转移到前端渲染。
  5. 速率限制是第一道防线：暴力破解、撞库、爬虫、CC 攻击都表现为高频请求。令牌桶/漏桶算法限制每秒请求数，配合幂等令牌防重放，能在业务逻辑前拦下大多数自动化攻击，保护后端资源不被打满。

一、SQL 注入防护

SQL 注入（A03）的本质是：不可信数据被拼进 SQL 语句并被当作代码执行，导致绕过鉴权、拖库、甚至执行命令。

二、XSS 防护

XSS（跨站脚本）让攻击者把恶意脚本注入到他人浏览器执行，可窃取 Cookie、伪造操作、改写页面。

1. 三种类型

类型 注入点 触发方式
反射型 URL 参数 用户点击恶意链接，参数回显到页面
存储型 服务端数据库 恶意内容被存库，所有访问者中招（危害最大）
DOM 型 前端 JS 前端把不可信数据写入 DOM，不经服务端

三、CSRF 防护

CSRF（跨站请求伪造）利用浏览器自动带 Cookie 的特性，在用户已登录站点 A 时，被恶意站点诱导对 A 发请求。

1. Token 方案（Synchronizer Token）

服务端为每个会话生成随机 token，嵌入表单隐藏域，提交时校验。攻击者所在站点跨域读不到 A 的表单，自然拿不到 token：

服务端在 before_request 中比对 session['csrf_token'] 与表单提交值，不一致或缺失即返回 400。

2. SameSite Cookie

最简防御：设 SameSite=Lax 阻止跨站 POST 自动带 Cookie（Strict 更严，连链接跳转都不带）：

3. 双重提交 Cookie

无状态的 CSRF 方案：token 同时放 Cookie 与请求头，服务端比对二者一致。攻击者无法跨域读 Cookie 也就伪造不出请求头：

纯 API（Bearer Token，不依赖 Cookie）场景天然无 CSRF 风险，但仍需 XSS 防护配合，否则脚本可读 token 后直接调用。

六、依赖漏洞管理

A06（易受攻击的组件）是被忽视的高发风险：Log4Shell、Fastjson 反序列化都源于含漏洞的依赖库。

1. SCA 软件成分分析

SCA（Software Composition Analysis）扫描直接/间接依赖的已知漏洞（CVE），并与版本库比对：

常用工具：Trivy（CI/镜像/IaC）、Snyk（多语言+自动 PR）、Dependabot（GitHub 内置）、OWASP Dependency-Check（Java 生态）。

2. 治理实践

  • 锁版本：用 lockfile 锁定间接依赖，避免”昨天还安全今天就被带入漏洞”。
  • 最小依赖：定期清理无用依赖，依赖越少攻击面越小。
  • CI 阻断：trivy --exit-code 1 在 CI 中阻断高危，强制修复后才合并。

常见避坑

坑 现象 正确做法
MyBatis ${} 拼用户值 SQL 注入 用户值一律用 #{}，结构值白名单
ORM 拼原生 SQL 注入点被忽视 用参数绑定，禁拼接
只过滤 <script> <img onerror> 绕过 按上下文编码或白名单清洗
富文本不过滤属性 onload/style 仍可执行 DOMPurify 白名单标签+属性
Content-Type 信任前端 改后缀绕过 用魔数判断真实类型
上传用原文件名 路径穿越/解析漏洞 UUID 重命名 + 限定目录
SSRF 只校验域名 DNS 重绑定打内网 二次解析校验实际 IP
限流只按 IP NAT 后误杀/代理后失效 按用户 + IP 双维度
重放无防护 截获请求重复提交 幂等 key + nonce + 时间窗口
依赖不锁版本 间接依赖被带入漏洞 lockfile + SCA 扫描 + CI 阻断
错误信息回显堆栈 泄露技术栈与路径 统一错误页，日志详查对外简略

本章小结

要点 结论
输入即恶意 所有客户端数据不可信，先校验/参数化再使用
SQL 注入 参数化查询是根本，MyBatis 用 #{} 不用 ${}
XSS 按上下文输出编码 + CSP + HttpOnly Cookie
CSRF SameSite Cookie + Token/双重提交，API 用 Bearer 可豁免
SSRF/上传 白名单主机 + 魔数校验 + 路径规范化
限流防重放 令牌桶限流 + 幂等令牌 + nonce/时间窗口
依赖管理 锁版本 + SCA 扫描 + CI 阻断高危
纵深防御 多层叠加，单点失效不致全盘失守

接口层的防护需要和运维层的加固配合才能真正安全。Web 认证授权基础详见 第一章：Web 安全与认证授权；而证书、TLS、密钥与容器加固等生产议题详见 第三章：安全运维与生产加固。建议三章连读，把”设计—编码—运维”串成完整闭环。
