第四章：Agent 生产化与工程实践

概念基础

  1. Agent 生产化的三大挑战：延迟 / 成本 / 可靠性：单次对话要多次 LLM 调用 + 多次工具调用，首字延迟普遍 5-30 秒、单次成本可能 0.05-0.5 美元，非确定性输出让 QA 难以传统方式覆盖。
  2. 评估比传统软件难：传统软件输入确定 → 输出确定；Agent 同一输入两次结果可能不同，必须用任务完成率 + 工具调用准确率 + 人工标注多维度评估，靠单测不够。
  3. 可观测性是生命线：Agent 调用链跨多步、多工具，没有 trace 就是黑盒；LangSmith / Langfuse 这类 step-level trace 在生产前就要接好，否则出问题无法复盘。
  4. 人在环（HITL）兜底：写操作、支付、删除等不可逆动作必须人工确认；Agent 不该 100% 自主，关键是定义清楚哪些步骤要人、哪些不要。
  5. 从 Demo 到生产的鸿沟：Demo 看 PPT 漂亮，上线要补鉴权、限流、缓存、降级、回滚、监控、审计、合规；80% 的工程量在 Demo 之外。

二、RAG + Agent 融合实战

2.1 为什么 RAG 需要 Agent

普通 RAG Agent + RAG
单次检索 多轮检索、按需补充
检索后直答 检索后判断相关性、必要时再检索
工具不可调 检索作为工具，可与 SQL/API 并用

2.2 LangGraph Self-RAG Agent

关键点：Agent 自主决定”要不要检索”；检索结果不相关则重检索或换查询词；相关性评估用模型打分（graded），构成自我修正闭环。

3.2 模型路由器 + 结果缓存

3.3 单次对话成本估算

场景 模型组合 Tokens/次 估算成本/千次
简单问答 gpt-4o-mini ×1 1.2k ~$0.18
单工具 Agent gpt-4o-mini ×3 + 工具 4k ~$0.60
多工具 Agent gpt-4o ×2 + gpt-4o-mini ×3 12k ~$3.60
多 Agent 协作 gpt-4o ×4 30k ~$15.00

成本随轮数 × 模型档位线性增长；先用小模型做路由器 + 缓存能把 80% 流量压到最便宜档位。

6.4 灰度与应急

  • 灰度：header 路由 10% 用户灰度新 prompt，对比 success rate / 成本 / 延迟。
  • 降级：Agent 失败回退固定流程（RAG 直答 / 静态规则）保可用。
  • 回滚：Prompt 版本化存配置中心，一键切回上一版本；写操作走审批队列。

常见避坑

坑 现象 正确做法
Demo 完美上线崩 真实流量分布不同 用线上真实数据压测
无成本监控 月底账单爆炸 每请求记 token，配预算告警
无循环检测 死循环烧 token 限 max_iterations + 重复动作计数
prompt 改了没回归 同一问题答不出来 golden dataset 回归
上下文窗口溢出 老对话压垮模型 滑动窗口 + 摘要外置
工具超时无熔断 单工具卡死全链路 工具 timeout + circuit breaker
无 trace 线上黑盒 出问题无法复盘 上线前接 LangSmith/Langfuse
模型升级 breaking 升级后 prompt 失效 升级前跑评估集，灰度上线
