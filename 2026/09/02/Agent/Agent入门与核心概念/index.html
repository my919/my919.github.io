第一章：AI Agent 入门与核心概念

概念基础

  1. Agent = LLM + 记忆 + 工具 + 规划：在 LLM 这一”大脑”之外再装上短期/长期记忆、外部工具与任务规划，模型从”会聊天”升级为”会做事”。
  2. 自主决策 vs 固定流程：传统 Pipeline 把每一步写死在代码里；Agent 由 LLM 在运行时自主选择调哪个工具、调几次、何时结束，路径是动态的。
  3. ReAct 推理-行动循环：Thought（思考）→ Action（行动）→ Observation（观察） 反复迭代，是当前大多数 Agent 的执行骨架，灵感来自 ReAct 论文（Yao et al., 2022）。
  4. Tool Use 改变 LLM 的边界：纯 LLM 的知识截止训练日期、不能联网、不会算精确值；函数调用（Function Calling） 让模型触发外部代码，能力从”语言”延伸到”真实世界”。
  5. Agent vs Workflow vs Pipeline：Pipeline 是确定性流水线，Workflow 是有限分支编排，Agent 是模型驱动的动态决策；越往后灵活性越强、可控性越弱，选型要看任务可变性。

读完本章后，建议接着看 第二章：Agent 框架实战 把概念落到 LangChain/LangGraph 等框架，再读 第三章：Agent 工具调用与函数编排 深入工具协议。本章示例基于 LangChain 0.3 + OpenAI Python SDK 1.x 风格编写（沙箱未装依赖，未逐条运行验证）。

一、什么是 AI Agent

1.1 Agent 定义与演进



flowchart LR
  R[规则系统<br/>IF-THEN] --> RP[RPA<br/>脚本化录屏]
  RP --> CA[聊天机器人<br/>意图识别+槽位填充]
  CA --> LA[LLM Agent<br/>推理+工具+记忆]
阶段 决策方式 局限
规则系统 人工写 IF-THEN 覆盖不全，维护爆炸
RPA 录制 UI 操作回放 UI 改动即失效
传统 Chatbot 意图分类 + 槽位 多轮上下文弱
LLM Agent LLM 推理 + 工具 延迟、成本、可靠性

1.2 核心组件



flowchart LR
  subgraph Agent
    LLM[大脑<br/>LLM]
    MEM[记忆<br/>Memory]
    TOOL[工具<br/>Tools]
    PLAN[规划<br/>Planning]
  end
  LLM <--> MEM
  LLM <--> TOOL
  LLM <--> PLAN
  TOOL <--> W[外部世界<br/>API/DB/文件]
  • 大脑（LLM）：负责理解、推理、决策、生成自然语言。
  • 记忆（Memory）：短期对话窗口、长期向量检索、Scratchpad 工作记忆。
  • 工具（Tools）：搜索、数据库、Shell、HTTP API，对外执行真实操作。
  • 规划（Planning）：任务分解、子任务编排、失败重试。

1.3 与传统聊天机器人的本质区别

聊天机器人是”输入 → LLM → 输出“一次过；Agent 是”输入 → LLM → 工具调用 → 观察结果 → 再推理 → … → 输出“多轮闭环，有副作用（真的发了请求、改了数据库）。

六、Agent 应用场景速览

场景 一句话描述 核心挑战
个人助手 日程、邮件、待办的统一入口 多工具协同
智能客服 售前咨询 + 售后工单 知识时效、转人工
数据分析 自然语言 → SQL → 可视化 取数准确、只读约束
代码生成 需求 → 多文件代码 + 测试 长上下文、可运行
研报撰写 资料检索 → 大纲 → 成稿 引用可信、风格一致
场景 复杂度 推荐模式
个人助手 中 ReAct + 长期记忆
客服 低 Workflow + 兜底转人工
数据分析 高 Plan-and-Execute
代码生成 高 多 Agent + Reflection
研报撰写 高 多 Agent 协作

常见避坑

坑 现象 正确做法
无限循环 Agent 反复调同一工具不收敛 设 max_iterations + 重复动作检测
幻觉调用不存在的工具 模型编造工具名 schema 限定 + 未知工具直接抛错
上下文爆炸 历史消息越积越长 滑动窗口 / 摘要压缩 / 长期记忆外置
规划过粗 一步到位常失败 拆 3-6 步，每步可验证
规划过细 步骤太多 LLM 跑偏 关键节点保留，细节交子 Agent
记忆污染 旧对话干扰新任务 任务切换清空短期记忆
工具描述模糊 LLM 选错工具 description 写清何时该用
无终止条件 一直说还没做完 FINISH 显式信号 + 步数上限
简单任务用 Agent 杀鸡用牛刀，慢且贵 简单问答直接用 LLM/RAG

本章小结

要点 结论
定义 Agent = LLM + 记忆 + 工具 + 规划，模型驱动决策是本质
架构 ReAct 是骨架；Plan-and-Execute、Reflection、多 Agent 按需选
记忆 短期窗口控成本，长期向量沉淀偏好，Scratchpad 存中间结果
规划 CoT/ToT/GoT 决定推理深度；DAG 编排 + 失败重试保可靠
落地 System Prompt + Function Calling 就能跑一个 Agent
选型 简单任务别上 Agent；可控性 vs 灵活性要权衡
