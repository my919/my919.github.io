第二章：Agent 框架实战

概念基础

  1. 框架价值在于抽象通用模式：ReAct 循环、记忆管理、工具注册这些代码每次重写易错，框架把消息编排、状态流转、工具 schema封装好，开发者只需写业务工具与 Prompt。
  2. LangChain 生态最全：从文档加载、向量检索到 Agent、链与 LangGraph，一站式且社区最大；缺点是抽象层多、API 变化快、版本间常有 breaking change。
  3. LlamaIndex 侧重 RAG + Agent 融合：以”数据连接”为核心，QueryEngineTool 让 Agent 调用向量索引，适合”文档密集型 Agent”场景。
  4. 框架 vs 裸 SDK 取舍：原型阶段裸 OpenAI SDK 更直观；当工具 >3、需要并行/重试/状态机/人工审批时，框架的红利压过其复杂度。
  5. 生产就绪度差异大：LangGraph 的 checkpoint 持久化、CrewAI 的角色管理、AutoGen 的群聊各有侧重；框架不是银弹，要看是否支持流式、可观测、回滚。

上一章 第一章：AI Agent 入门与核心概念 介绍了 Agent 的核心概念，本章把它们落到五大主流框架。下一章 第三章：Agent 工具调用与函数编排 深入工具协议。环境管理推荐 第一章：Python 的 UV 工具：极速 Python 环境与包管理。代码基于 LangChain 0.3 / LlamaIndex 0.11+ / CrewAI 0.30+ / AutoGen 0.4+（沙箱未装依赖，未逐条运行验证）。

六、框架选型对照表

维度 LangChain LangGraph LlamaIndex CrewAI AutoGen
适用场景 通用 Agent 复杂状态机 RAG + Agent 多 Agent 角色协作 对话式多 Agent
学习曲线 中 较陡 中 低 中
灵活性 中 高 中 中 中高
生产就绪 中 高 中 中 中
社区活跃 最大 大 大 中 中

选型决策树：单工具简单 Agent → LangChain create_tool_calling_agent；多状态、需断点续跑 → LangGraph；以文档问答为主 → LlamaIndex；多角色写报告 → CrewAI；多 Agent 对话打磨代码 → AutoGen。不互斥，可混用，例如 LlamaIndex 的 QueryEngine 当 LangChain 的 Tool。

常见避坑

坑 现象 正确做法
框架版本 breaking change 升级后 API 不识别 uv pip compile 锁版本，看 CHANGELOG
工具 schema 错误 LLM 调不出工具 docstring + 类型注解齐全，必填参数最小化
AgentExecutor 无 max_iterations 死循环烧 token 构造时显式传 max_iterations=8
LangGraph 状态不可变 bug 节点返回后 state 没变 节点返回 dict 增量，不是原地改
多 Agent 死循环 互相推诿不结束 设终止条件 + max_turns + 超时
内存类型不匹配 history 不进 prompt memory_key 与 prompt 占位符一致
API key 泄漏到 prompt 模型把 key 输出给用户 环境变量加载，工具层做脱敏
框架封装太深难调试 verbose 仍看不清 切到 LangGraph 显式状态图

本章小结

要点 结论
选型 按任务复杂度从 LangChain → LangGraph 递进
状态管理 LangGraph 显式 TypedDict 比 AgentExecutor 可控
RAG 融合 LlamaIndex 的 QueryEngineTool 是文档 Agent 的利器
多 Agent CrewAI 重角色，AutoGen 重对话，终止条件都要设
工具复用 框架间 Tool 可桥接，但 description 要重写
调试 verbose + LangSmith trace 双管齐下

本章把五大主流框架的代表性用法跑了一遍，关键不在背 API 而在理解抽象映射：ReAct 循环 → AgentExecutor / ReActAgent；状态机 → LangGraph；多角色 → CrewAI/AutoGen。回到 第一章：AI Agent 入门与核心概念 复盘核心概念，继续看 第三章：Agent 工具调用与函数编排 深挖工具协议，最后 第四章：Agent 生产化与工程实践 讲部署与监控。Python 环境管理推荐 第一章：Python 的 UV 工具：极速 Python 环境与包管理，比传统 pip 几乎每个项目都更省心。
