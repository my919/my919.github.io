第一章：Python 的 UV 工具：极速 Python 环境与包管理

概念基础

UV 是 Astral（Ruff 的开发团队）用 Rust 编写的 Python 包与项目管理器：

  1. 快是核心卖点：依赖解析与安装比传统 pip / pip-tools 快 10~100 倍，得益于 Rust 实现、并行下载与全局缓存。
  2. 一体化工具链：一个 uv 命令覆盖 Python 解释器管理（uv python）、虚拟环境（uv venv）、包安装（uv pip / uv add）、项目初始化与同步（uv init / uv sync）与命令运行（uv run），替代过去 pyenv + venv + pip + pip-tools 的多件套拼装。
  3. 兼容 pip 生态：uv pip 提供 pip 兼容接口，老命令、老脚本可平滑迁移；同时拥抱 pyproject.toml 标准与 uv.lock 锁文件，保证环境可复现。
  4. 适用场景：从单脚本、单项目到 monorepo 工作区都能胜任；本章先掌握安装、解释器、虚拟环境、依赖管理四大基础能力。

说明：

  • 查看当前 pin：若已有 .python-version，执行 uv python pin（不写版本号）会打印当前固定版本；若无该文件则会报错。

  • 仅在当前用户全局默认：可用 uv python pin 3.14.3 --global（具体行为以官方文档为准）。

常见避坑

坑 现象 正确做法
没激活 venv 直接 python 进了系统 Python，import 找不到包 永远用 uv run python；或 shell 里 source .venv/bin/activate 后再运行
pyproject.toml 手动乱改 版本约束与 uv.lock 不同步，uv sync 报错 依赖变更走 uv add / uv remove / uv pin；只在确有必要时手工编辑
在非项目根执行 uv 找不到 pyproject.toml 或用错锁文件 cd 到项目根再执行；跨目录命令加 --project <path>
uv.lock 不提交仓库 同学/CI 装出来依赖版本不同，”我这能跑” lockfile 必须提交；CI 用 uv sync --frozen，要求锁与 toml 完全一致
本地 vs 生产 Python 小版本差异 uv sync --python 3.11 在生产 Python 3.10 上装包失败 统一 .python-version；Docker 镜像精确指定版本；CI 用 uv 安装同版本解释器
把 --dev 依赖用于生产 安装了 pytest/pylint/ruff，镜像体积膨胀、启动命令被 dev 脚本污染 生产镜像用 uv sync --no-dev 或 --only-dev-group ''（只装主依赖组）
全局 uv tool install 与项目脚本混淆 ruff 用的是全局 0.6.x、项目要求 0.7.x 风格检查冲突 开发工具作为 dev 依赖写入项目（uv add --dev ruff），运行用 uv run ruff
国内 PyPI 镜像没配好 uv add 慢或超时 写 pyproject.toml 的 [[tool.uv.index]] 或环境变量 UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
多解释器混用残留 .venv 从 3.12 换到 3.14 后 .venv 里仍是 3.12，运行报 ABI 错 换解释器前 删除旧 .venv，重新 uv venv --python 3.14 && uv sync

更完整的子命令与配置见官方文档：uv 文档。

本章小结

要点 结论
uv 定位 Rust 实现的一体化 Python 工具链，替代 pyenv + venv + pip + pip-tools 多件套，速度快 10~100 倍
安装与验证 官方脚本一键安装，uv --version 确认可用
解释器管理 uv python install 安装版本，uv python pin 写入 .python-version 固定项目解释器
虚拟环境 uv venv 创建 .venv；日常建议直接 uv run 免激活执行
依赖与项目 uv pip install 兼容 pip；uv init + uv sync 走标准项目化工作流
