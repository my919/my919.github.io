第五章：视频与深度学习

发表于 2026-05-01 更新于 2026-10-25 分类于 OpenCV 本文字数： 8.5k 阅读时长 ≈ 8 分钟

第五章：视频与深度学习

概念基础

  1. 视频 = 时序帧序列：在单图处理之上多了「帧间关系」——运动检测、光流、跟踪都依赖相邻帧对比，是视频理解的核心。
  2. 背景建模分离运动：固定摄像头下，建立背景模型后，当前帧与背景之差即运动前景，是安防检测的经典思路。
  3. cv2.dnn 是推理不是训练：OpenCV 能加载 ONNX/Caffe/部分 TF 模型做前向推理，跨平台部署轻量模型；训练仍在 PyTorch 等框架完成。
  4. 前后处理是 OpenCV 的主场：深度模型要的 resize、归一化、BGR/RGB 转换、NMS、画框，全是 OpenCV 擅长的数组操作。
  5. 本章目标：掌握视频读写、光流、背景减除、dnn 推理与后处理，把前四章能力串成完整 CV 流水线。

本章承接 第四章：特征与几何，面向时序与深度模型衔接。视频编解码底层见 第一章：FFmpeg 音视频处理入门。

一、视频读写

1. VideoCapture 读取

摄像头/网络流 CAP_PROP_FRAME_COUNT 不可用；网络流用 cv2.CAP_FFMPEG 后端读 RTMP/RTSP。

2. VideoWriter 写出

  • fourcc：mp4v/avc1/X264 等，依后端可用编码；写不出时先换 fourcc。
  • 尺寸必须与帧一致，否则写空。
  • 底层依赖 FFmpeg 编解码——这就是 OpenCV 与 第一章：FFmpeg 音视频处理入门 的联系。

读网络流与丢帧策略

实时流的核心矛盾是「处理慢于产出」：缓冲默认会堆积旧帧，表现为画面越来越滞后。对策：缓冲设 1、或独立线程读帧只留最新、处理线程按需取（生产者-消费者模式）。GStreamer 管线也可经 cv2.CAP_GSTREAMER 接入，适合硬解码（如 Jetson 的 nvv4l2decoder）。

按帧率与时长定位

二、帧差法与背景减除（运动检测）

更鲁棒的背景建模（自动更新背景）：

  • 帧差法：简单但对静止目标失效。
  • MOG2/KNN：自适应背景，相机轻微抖动也能用，detectShadows 标阴影需二次阈值过滤。

MOG2 与 KNN 对比及掩膜后处理

减除器 特点 参数要点
MOG2 高斯混合模型，多模态背景（摇曳树叶） history 学习窗口、varThreshold 灵敏度
KNN K 近邻背景统计，前景存在久后纳入背景快 dist2Threshold

原始掩膜必带噪点，标准后处理三件套：开运算去碎点 → 闭运算连断块 → 轮廓面积过滤：

这套「减除 → 形态学 → 轮廓过滤 → 画框」就是无深度模型的轻量安防检测流水线。

三、光流（密集与稀疏）

光流估计像素运动场，用于跟踪与运动分析：

  • 稀疏 LK：跟踪特定角点，快，适合实时跟踪。
  • 密集 Farneback：全图运动，慢但信息全，可视化运动方向。

密集光流可视化（HSV 编码）

经典可视化技巧：把运动向量的大小/方向编码到 HSV 的 V/H 通道：

LK 金字塔的实际用法是「三级金字塔 + 双向校验」：calcOpticalPyrLK 内部已做多尺度，再在反向跑一次筛掉往返不一致的点，能显著提升跟踪稳定性。

四、cv2.dnn 推理（加载 ONNX）

1. 加载模型与预处理

  • blobFromImage：scalefactor 缩放、size 目标尺寸、swapRB BGR→RGB、crop 是否中心裁剪。
  • swapRB=True：模型多按 RGB 训练，OpenCV 读的是 BGR，需交换。
  • GPU：编译时启用 CUDA 后端可 DNN_TARGET_CUDA 加速。

2. YOLO 风格后处理（NMS）

深度检测模型输出需后处理成最终框——解码框 + 置信度过滤 + NMS：

  • NMS（非极大值抑制）：重叠框只保留置信度最高的，0.4 是 IoU 阈值。
  • 训练用 第一章：PyTorch 入门与张量，导出 ONNX 后用 OpenCV 部署，是常见的轻量推理链路。

C++ 侧 dnn 推理对照

YOLOv8 输出布局注意：output0 为 (1, 4+nc, 8400)，每列是一个候选框（Python 侧 outs[0][0].T 转成 (8400, 84) 再按行解析），且无 objectness 通道（v5 的 det[4] 在 v8 已并入类别分）。解析错布局是 YOLO 后处理最常见的坑。

blobFromImage 变体

  • blobFromImages：批量输入多张图，一次 forward 多帧，吞吐更高。
  • mean=(...)：减均值（ImageNet 模型常用 (104, 117, 123) 或按模型训练配置）。
  • crop=True：先按长边等比缩放到目标尺寸的短边再中心裁——分类模型的标准预处理；检测模型必须 crop=False 并自己记录缩放系数做坐标还原（letterbox 需另加 padding 补偿）。

五、多目标跟踪：ByteTrack 思路（简述）

检测 + 关联是跟踪的通用框架：

  1. 每帧用检测器（YOLO/dnn）出框。
  2. 用 IoU 或卡尔曼预测把当前框与上一帧轨迹关联。
  3. 未匹配的检测开新轨迹，未匹配的轨迹保留若干帧后删除。

OpenCV 自带轻量跟踪器（单目标）：

多目标跟踪生产级多用 ByteTrack/ SORT + 深度检测器组合，OpenCV 负责检测前后处理与可视化。

内置单目标跟踪器选型

跟踪器 速度 精度 说明
TrackerCSRT 慢 高 判别相关滤波+可靠性，精度优先场景
TrackerKCF 快 中 核相关滤波，速度与精度平衡，最常用
TrackerMOSSE 极快 低 纯速度场景，遮挡即丢

注意：TrackerCSRT/KCF/MOSSE 在 contrib 包（opencv-contrib-python）；4.10+ 主包提供 TrackerNano/TrackerVit（深度轻量跟踪器，需另下模型文件）。通用建议：先用 KCF 打底，精度不够再换 CSRT 或 Nano。

五·补充、性能优化清单

CV 流水线提速按收益排序：

  1. 降分辨率：处理前 resize 到够用即可（检测常 640 宽）——像素数减半耗时约减四分之三。
  2. 向量化与算子：消灭 Python 像素循环（第二章）；批量 blobFromImages 一次推理多帧。
  3. ROI 先行：只处理感兴趣区域，跳过整图运算。
  4. UMat/OpenCL：cv2.UMat 让支持算子自动走 GPU（第一章），大图大核收益明显。
  5. CUDA 模块：源码编译 WITH_CUDA=ON 后用 cv2.cuda_GpuMat / cv::cuda::*，含专用滤波、dnn 后端。
  6. 多线程读解：读帧（IO 瓶颈）与处理（CPU 瓶颈）分线程，队列缓冲。
  7. dnn 后端：有 NPU/OpenVINO 设备时 DNN_BACKEND_INFERENCE_ENGINE 等专用后端。

六、完整流水线：视频检测可视化

七、常见陷阱

陷阱 说明
VideoWriter 尺寸不符 帧尺寸与构造参数不一致，写出空文件
fourcc 不支持 某些编码依赖后端，写失败先换 mp4v
blobFromImage 漏 swapRB BGR 送进 RGB 模型致检测错乱
忘归一化 不除 255 送 0-255 像素进模型，结果全错
NMS 阈值不当 IoU 阈值过小漏框、过大残留重复框
背景减除不去阴影 detectShadows 阴影为 127，需二次阈值
光流用彩色图 LK/Farneback 需灰度单通道输入
dnn 后端未编译 CUDA 设了 CUDA 后端但 OpenCV 未编译支持会回退或报错

本章小结

要点 结论
视频读写 VideoCapture 逐帧读、VideoWriter fourcc+尺寸写出；底层靠 FFmpeg
网络流 RTSP 配 CAP_FFMPEG；缓冲设 1 防延迟堆积；读写分线程
运动检测 帧差法简单、MOG2/KNN 背景减除自适应
光流 稀疏 LK 跟踪角点（双向校验提质）、密集 Farneback 全图运动场，HSV 编码可视化
dnn 推理 readNetFromONNX + blobFromImage 预处理 + forward；非训练
YOLO 后处理 v8 输出 (1,4+nc,8400) 需转置；置信度过滤 + NMSBoxes
跟踪器 KCF 均衡常用、CSRT 高精度、MOSSE 极速（均在 contrib）；4.10+ 主包有 Nano/Vit
性能 降分辨率 > 向量化 > ROI > UMat/CUDA > 多线程；getTickCount 计时
流水线 读帧→dnn 检测→NMS→画框→写帧，串联前四章能力
