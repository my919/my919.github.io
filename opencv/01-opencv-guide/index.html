第一章：OpenCV 计算机视觉入门

发表于 2026-05-01 更新于 2026-10-25 分类于 OpenCV 本文字数： 7.1k 阅读时长 ≈ 6 分钟

第一章：OpenCV 计算机视觉入门

概念基础

  1. 计算机视觉基础库：OpenCV 提供图像读写、滤波、几何变换、特征提取、视频处理等数百个现成算法，是 CV 领域事实上的标准库，1999 年由 Intel 发起，现由 Itseez/OpenCV.org 维护。
  2. 图像即数组：图像在 Python 中以 NumPy 数组表示，注意 OpenCV 默认 BGR 通道顺序而非 RGB，所有处理本质上都是数组运算——理解这一点就抓住了 OpenCV 的本质。
  3. C++ 内核、多语言绑定：核心由 C++ 实现保证性能，Python 通过 cv2 绑定调用，兼顾开发效率与运行速度；亦有 Java/JS 绑定。
  4. 传统 CV 与深度学习的桥梁：自带 cv2.dnn 可加载 ONNX 等模型推理，更多时候负责深度模型前后的预处理与后处理。
  5. 跨平台易上手：桌面、移动、嵌入式均可运行，pip install opencv-python 即可开始。

一、安装与版本选择

contrib 与主包二选一，不要同时装（冲突）。需要 SIFT 旧实现或额外模块才用 contrib；4.x 后 SIFT 专利已到期、主包即可用。

二、图像即 NumPy 数组（核心心智模型）

OpenCV 读入的彩色图是 H×W×C 的 uint8 数组，通道顺序 BGR：

三个易错点：

  1. 坐标顺序：img[y, x] 是「行、列」，即先纵坐标 y 再横坐标 x，与 (x, y) 直觉相反。
  2. BGR 不是 RGB：matplotlib 显示需先 cv2.cvtColor(img, cv2.COLOR_BGR2RGB)，否则红蓝颠倒。
  3. shape 顺序：shape = (H, W, C)，高在前；cv2.resize(img, (W, H)) 传参是「宽、高」，两处顺序相反。

Mat 内存模型（C++ 侧同理）

cv::Mat 是「头 + 数据体」结构：头记录维度、类型、步长（step/strides），数据体按引用计数共享——

Python 侧对应关系：img2 = img 是视图/引用，img2 = img.copy() 是深拷贝，img[y1:y2, x1:x2] 切片也是视图（写切片会写回原图，需要独立副本时加 .copy()）。数据连续与否可用 img.flags['C_CONTIGUOUS'] / mat.isContinuous() 判断——连续的 Mat 可以一次性 memcpy 整块，很多底层优化依赖这一点。

dtype 与通道数：CV_8UC3 = uint8 × 3 通道（Python 中体现为 dtype=uint8, shape=(H,W,3)）。常见还有 CV_32FC1（float32 单通道，滤波/深度图常用）。用错 dtype 是数值类 bug 之源：比如把 uint8 梯度直接相加会饱和，需先 img.astype(np.float32)。

三、最小读写示例

  • imread 失败返回 None 而非抛异常——务必判空，否则后续 img.shape 报 AttributeError 让人困惑。
  • imread 第二参：cv2.IMREAD_GRAYSCALE（灰度）、cv2.IMREAD_UNCHANGED（含 alpha 通道）。
  • waitKey：返回按键 ASCII；& 0xFF 是跨平台惯例；1 表示等 1ms（视频循环用）。

常用读入标志与格式注意

标志 效果
cv2.IMREAD_COLOR（默认） 强制 3 通道 BGR，丢弃 alpha
cv2.IMREAD_GRAYSCALE 直接解码为单通道灰度，省一次 cvtColor
cv2.IMREAD_UNCHANGED 保留原通道（PNG 的 alpha、16bit TIFF）
cv2.IMREAD_REDUCED_COLOR_2/4/8 边解码边缩 1/2、1/4、1/8，大图预览提速

注意：JPEG 无 alpha；16 位 PNG/TIFF 须 IMREAD_UNCHANGED 否则被压成 8 位；HEIF/AVIF 需 4.8+ 且后端支持。写盘时 imwrite 可用 cv2.IMWRITE_JPEG_QUALITY 等参数控制质量：

四、视频读写骨架

视频本质是逐帧图像循环——掌握单图处理，视频就只是加层 while。摄像头传设备号 0/1；写视频用 cv2.VideoWriter（见第五章）。

四·补充、性能速览：UMat 与透明 GPU 加速

OpenCV 3 起引入 T-API（Transparent API）：把 Mat 换成 UMat，支持的算子会自动走 OpenCL 加速（核显/独显），API 不变：

要点：只在「核函数大、图像大」时收益明显；小图上 host↔device 传输反而亏。是否生效看 getBuildInformation() 里 OpenCL 项。CUDA 专属加速另有 cv::cuda 模块（需源码编译 WITH_CUDA=ON）。第五章再给优化清单。
