迭代器模式详解（Iterator）

发表于 2026-09-14 更新于 2026-10-25 分类于 设计模式 本文字数： 3k 阅读时长 ≈ 3 分钟

设计模式 · 迭代器模式

GoF 行为型模式。意图 · 结构 · 代码实现 · 应用场景 · 优缺点。代码带详细注释。

1. 模式概述（意图）

迭代器模式（Iterator）提供一种方法顺序访问聚合对象（集合）内的元素，而不暴露其内部表示——遍历逻辑与集合结构解耦。

2. 要解决的问题

问题 说明
遍历与集合耦合 每种集合写一套遍历代码
内部结构暴露 客户端知道底层是数组还是链表
遍历方式单一 正序/逆序/过滤需要不同遍历器

典型场景：所有 Java 集合的 iterator()、Java 8 之后基本被 for-each/Stream 取代——迭代器已是语言级内建，本模式主要理解思想与 Iterable 接口。

4. 代码实现（自定义迭代器）

遍历期间修改：迭代器遍历时修改集合会抛 ConcurrentModificationException（Java 用 modCount 快照检测）；需要安全的移除用 iterator.remove()。

5. 应用场景

场景 说明
Java 集合 List/Set/Map 的 iterator()
for-each 语法 编译器展开为迭代器
数据库游标 结果集逐行遍历
自定义数据结构 树/图的自定义遍历
Stream Java 8+ 更声明式的遍历

6. 优缺点

优点 缺点
遍历与集合解耦 简单集合用迭代器是多余抽象
隐藏内部结构（信息隐藏） 迭代器状态管理要小心
支持多种遍历方式 函数式语言中常被 Stream/for-each 取代
统一接口（换集合不改客户端） 并发修改检测增加复杂度

7. 与其他模式对比

模式 区别
组合模式 组合定义树结构；迭代器遍历它
访问者 迭代器遍历+访问者操作节点
工厂方法 createIterator() 就是工厂方法

8. 常见误用与陷阱

坑 现象 解法
遍历时直接改集合 for-each 中调用 list.remove()，抛 ConcurrentModificationException 用 iterator.remove() 或 Java 8 removeIf()
迭代器不复用 每次遍历 new 迭代器，大数据量时 GC 压力大 内部迭代器（forEach/Stream）替代外部迭代器
迭代器状态泄露 迭代器持有游标，跨线程共享导致遍历错乱 迭代器设为方法局部变量，禁止共享
嵌套遍历死循环 外层迭代器遍历时内层再 createIterator()，逻辑混乱 改用 Stream 的 flatMap 或收集到 List 再遍历
