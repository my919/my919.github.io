PostgreSQL：高级查询

发表于 2026-05-03 更新于 2026-10-29 分类于 数据库 本文字数： 12k 阅读时长 ≈ 11 分钟

PostgreSQL：高级查询

概念基础

  1. 单表 SELECT 之上：多表连接（JOIN）、子查询与 EXISTS、集合运算（UNION）、CTE（WITH）、窗口函数——把散落在多张表里的数据拼成业务想要的答案。
  2. 为什么重要：报表、榜单、去重、累计等需求，本质都是查询表达能力；能用一条 SQL 讲清楚的，就不必拉到应用内存里拼装。
  3. PostgreSQL 特色武器：DISTINCT ON 每组取一条、FILTER 条件聚合、string_agg 有序拼串——这些在 MySQL 里要绕着写的写法，PG 是一等公民。
  4. 学习方法：先用下文「示例数据」一键建表，逐条 SQL 亲手跑一遍并对照示例结果；会写之后再进阶到执行计划（见 PostgreSQL：索引与性能优化）看快不快。

五、递归 CTE：层级与树形查询

WITH RECURSIVE 把 CTE 升级为「自己引用自己」：锚点成员（起始行集）+ UNION ALL + 递归成员（引用自身产出下一层），直到递归成员返回空集为止。典型场景：组织架构、评论树、栏目层级、BOM 物料清单。

六、窗口函数

窗口函数在一组与当前行相关的行（窗口）上计算，却不折叠行数——这是它与 GROUP BY 的本质区别。

1. 组内编号 row_number

示例结果：研发部门内 李四 rn=1、张三 rn=2；市场部门内 王五 rn=1（NULLS LAST 把无工资的赵六排在后面）。

2. 上一行 / 下一行：lag / lead（环比神器）

示例结果：张三第二笔 200.50 的 prev_amount = 100.00、delta = 100.50；每人的首行 prev_amount 为 NULL（可用 lag(amount, 1, 0) 给默认值）。WINDOW w AS (…) 让多个窗口函数共用同一份窗口定义，避免重复书写。

3. 分桶与首尾：ntile / first_value / last_value

  • ntile(n)：把结果尽量均匀地切成 n 桶，「前 50% 客户」类分层一行搞定。
  • last_value 的默认帧只到当前行，要拿「全窗口最后一名」必须显式写到 UNBOUNDED FOLLOWING——最常见的踩坑点。

4. 帧子句：累计与滑动窗口

帧（frame）决定「窗口里到底算哪些行」，三种模式：

模式 语义 典型用途
ROWS 按物理行数框定 精确的前 N 行累计
RANGE 按值差框定（同值行同进同出） 「前后 7 天内」的区间聚合
GROUPS 按同值分组框定 介于两者之间

示例结果：张三两行 running_sum 依次为 100.00、300.50；moving_avg_3 取「上一行 + 当前行 + 下一行」的均值，是滑动平均的标准写法。

七、LATERAL：让子查询引用左侧的行

普通子查询不能引用 FROM 里前面表的列；LATERAL 解除这个限制——右侧子查询对左侧每一行各算一次，语义类似「相关子查询的 JOIN 版」，是每组取 Top-N 的通用解法。

每个员工取最近 2 笔订单：

示例结果：张三两行（200.50、100.00）、李四一行、王五一行；没订单的赵六、钱七被 CROSS JOIN 滤掉——想保留他们就换 LEFT JOIN LATERAL (…) t ON true。

与 DISTINCT ON 的分工：DISTINCT ON 每组只能取一条，LATERAL 每组可取 N 条且能带任意复杂逻辑；配合 (emp_id, order_date DESC) 索引性能最好。

十一、GROUPING SETS / ROLLUP / CUBE：一条 SQL 出多层小计

报表里「明细 + 维度小计 + 总计」不必跑多条查询再 UNION ALL 拼接，GROUPING SETS 一族一次算全：

三种写法的分组组合：

写法 等价分组集合
ROLLUP (a, b) (a,b) ∪ (a) ∪ ()（逐层上卷，最常用）
CUBE (a, b) (a,b) ∪ (a) ∪ (b) ∪ ()（2ⁿ 种组合全要）
GROUPING SETS ((a), (a,b), ()) 括号里写什么算什么，自由组合，() 表示总计行

GROUPING() 函数：小计/总计行里被「卷掉」的列显示为 NULL，与数据本身的 NULL 撞车——GROUPING(d.name) = 1 表示该行是部门维度的小计行，应用层据此渲染「合计」标签而不是显示空白。

示例结果（节选）：研发 行下挂 张三（2 / 300.50）、李四（1 / 300） 两个明细行，随后一行 emp_name 为 NULL、g_emp = 1 即研发小计；最后一行 g_dept、g_emp 都为 1，即全表总计。

十二、JSONB 查询与操作符

jsonb 以二进制分解格式存储 JSON，可索引、可按路径查询——半结构化数据（商品属性、日志字段、配置快照）不必再建一堆稀疏列。

1. 取值：-> 与 ->>

口诀：-> 给 jsonb（中途站），->> 给文本（终点站）；数组用下标（attrs -> 'tags' ->> 0），深层用 #>> '{a,b}'。

2. 包含与存在：@>、?、?|、?&

3. SQL/JSON 路径与数组展开

复杂条件（数组过滤、谓词匹配）用路径表达式；数组展开成行走 jsonb_array_elements：

示例结果：路径谓词命中 电竞鼠标；展开后键盘得 办公、有线 两行，鼠标得 电竞、无线 两行。

4. 更新 JSON 内部字段：jsonb_set

大表按 JSONB 检索要配 GIN 索引（CREATE INDEX ON product USING gin (attrs);，等值含键查询可用更紧凑的 jsonb_path_ops），细节见 PostgreSQL：索引与性能优化。

十三、分页 LIMIT / OFFSET

深 OFFSET 大表性能差，生产常用键集分页（WHERE (hire_date, id) < ($1,$2) 一类）。同理，大表用 COUNT(*) 算分页总数也是每次全扫——总数改用估算值或缓存。

十六、速查小结

场景 PostgreSQL 典型写法
多表 JOIN / LEFT JOIN
去重取每组一条 DISTINCT ON (…) … ORDER BY
每组取 Top-N CROSS JOIN LATERAL (… LIMIT n)
条件计数 COUNT(*) FILTER (WHERE …)
拼串 string_agg(expr, sep ORDER BY …)
可读拆分 WITH
层级 / 树形 WITH RECURSIVE … UNION ALL …
组内排序编号 row_number() OVER (PARTITION BY …)
环比上/下期 lag() / lead() OVER (…)
多层小计合计 ROLLUP / CUBE / GROUPING SETS
JSONB 检索 ->> 取文本、@> 包含、GIN 索引
全文检索 to_tsvector + @@ to_tsquery，GIN 索引加速；中文用 zhparser/pg_jieba

更多执行计划与索引：见 PostgreSQL：索引与性能优化。

本章小结

要点 结论
连接 JOIN 取交集、LEFT JOIN 保左表；聚合前先想清楚以哪张表为基准
子查询 IN 适合列表匹配、EXISTS 适合存在性判断且常更高效
结构化复用 WITH（CTE） 把复杂查询拆成有名字的中间结果；层级递归升级 WITH RECURSIVE
窗口函数 不折叠行数的组内计算；lag/lead 环比、ntile 分层，帧子句决定累计/滑动范围
LATERAL 右侧子查询逐行引用左侧，每组 Top-N 的通用解法
JSONB -> 取 jsonb、->> 取文本、@> 包含；大表检索配 GIN 索引
报表聚合 ROLLUP/CUBE/GROUPING SETS 一条 SQL 出多层小计，GROUPING() 区分合计行
PG 特色 DISTINCT ON 每组一条、FILTER 条件计数、string_agg 有序拼串
分页 浅分页 LIMIT/OFFSET 够用；深分页改键集分页
