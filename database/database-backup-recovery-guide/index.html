数据库 · 备份与恢复

从 0 到可演练的备份体系。备份类型与 RPO/RTO · mysqldump 逻辑备份 · XtraBackup 物理热备 · binlog 时间点恢复（PITR）· 自动化脚本 · 恢复演练。代码带详细注释。

技术栈速查

类别 选型 用途
数据库 MySQL 8.4 LTS 主存储
逻辑备份 mysqldump（自带） 全量、跨版本迁移
物理备份 Percona XtraBackup 8.4 热备、增量、恢复快
增量 binlog 时间点恢复（PITR）
定时 cron / systemd-timer 自动备份

1. 概念说明：先想清楚要什么

备份的核心是两个指标：

指标 含义 目标
RPO（恢复点目标） 最多丢多少数据 越小越好（如丢 ≤5 分钟）
RTO（恢复时间目标） 多久恢复可用 越小越好（如 1 小时内）

备份类型：

类型 说明 特点
全量备份 备份全部数据 基础，恢复最简单
增量备份 备份上次备份后的变化 省空间、恢复要叠加
逻辑备份 导出 SQL（mysqldump） 可读、跨版本、恢复慢
物理备份 复制数据文件（XtraBackup） 快、恢复快、依赖同版本

为什么必须定期演练恢复：备份”能备份”不等于”能恢复”——不演练的备份等于没有备份。

2. mysqldump 逻辑备份（入门必备）

2.1 单库全量备份

每个参数为什么：

参数 作用 为什么必须
--single-transaction 用 InnoDB 快照一致性备份 不加则锁表，线上直接卡死
--routines/--triggers/--events 导出存储过程/触发器/事件 默认不带，漏了恢复后功能缺失
-p'密码' 密码紧贴 -p 无空格 有空格会当成库名报错

2.2 恢复

恢复前检查清单：目标库版本 ≥ 备份库版本；字符集一致（utf8mb4）；先恢复到临时库验证再切。

2.3 跨版本/迁移场景

逻辑备份的适用边界：数据量 < 50GB 用 mysqldump 够；更大必须上 XtraBackup（mysqldump 恢复太慢）。

为什么必须有 prepare 步骤：热备期间数据文件在不断变化，备份的是”不一致”的瞬间——prepare 把 redo log 应用进去，才得到一致性快照。不做 prepare 直接恢复 = 数据损坏。

3.4 恢复

为什么恢复快：物理备份是直接复制数据文件，恢复=拷贝+启动，不用重放几万条 INSERT。

4. binlog 时间点恢复（PITR，RPO 趋近 0）

4.1 前提：binlog 必须开启

为什么 binlog 是恢复的最后一环：全量备份只能恢复到”备份时刻”，备份之后到故障前的数据变化全在 binlog 里——binlog 追到故障前一刻，数据丢得最少。

7. 恢复失败排查速查

现象 原因 解决
导入报 Unknown database 目标库不存在 先 CREATE DATABASE
导入报字符集乱码 字符集不一致 两端都 utf8mb4
XtraBackup 报权限不足 缺少 BACKUP_ADMIN 授权或换 root
恢复后启动失败 没 prepare 或属主错 重新 prepare + chown mysql:mysql

备份文件损坏 磁盘/中断 备份后校验（文件大小+binlog_info 存在）

问题背景：周三 14:20，开发在生产误执行 DROP TABLE shop.order（本想在内网演练库操作）。要求：数据尽量零丢失、1 小时内恢复业务。

方案（止损 → 恢复 → 追 binlog → 校验 → 复盘）：

踩坑点：① DROP 是 DDL，不能用 --stop-position “跳过它继续追”——DDL 在 binlog 中无法像 DML 一样按行回滚，只能”恢复全量 + 追放到 DROP 前”；② 事故期间 binlog 绝不能停、绝不能重启清理；③ 一键停写流程演练过，这次才没手忙脚乱——预案的价值在演练时兑现。

10. 常见误用与陷阱

坑 现象/后果 解法
只备份不演练 真出事时发现备份损坏/位点对不上 每季度临时实例演练，记录实测 RPO/RTO
XtraBackup 备完不 prepare 恢复后启动失败或数据不一致 脚本内置 prepare + 校验 xtrabackup_binlog_info
binlog 保留期 < 备份周期 中间 binlog 已被清理，无法追平 expire ≥ 7 天并与备份周期对齐
--stop-datetime 设到故障之后 误操作被原样重放，恢复白做 停在误操作前一秒，先 grep 定位误操作位点
密码写进脚本进 git 凭据泄露 密钥文件权限 600，脚本只读文件
备份与数据同盘 磁盘坏 = 数据与备份一起没 独立卷 + 一份异地/对象存储
mysqldump 漏 –single-transaction 备份期间锁表，线上卡死 InnoDB 必加该参数；大表改用 XtraBackup
恢复后忘修属主 mysql 启动失败 permission denied chown -R mysql:mysql /var/lib/mysql 写进脚本
