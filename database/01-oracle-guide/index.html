第一章：Oracle 数据库入门

发表于 2026-05-01 更新于 2026-10-25 分类于 数据库 本文字数： 7.5k 阅读时长 ≈ 7 分钟

第一章：Oracle 数据库入门

概念基础

  1. 企业级关系型数据库：Oracle Database 是老牌商业 RDBMS，在银行、电信、政务等对稳定性、安全合规与厂商支持要求高的核心系统中长期占主导地位。
  2. 实例与数据库分离：Instance（内存 SGA + 后台进程）挂载并打开 Database（物理文件集合），多实例可共享访问同一套库（即 RAC）。理解「实例是内存进程、数据库是文件」是入门第一关。
  3. 逻辑存储分层：数据组织在表空间（SYSTEM / SYSAUX / USERS / TEMP / UNDO）中，向下再划分为段、区、块——这套分层决定了建库、扩容、调优的思维方式。
  4. 高可用与容灾：RAC 多节点共享存储集群、Data Guard 主备容灾，配合 RMAN 备份恢复构成企业级方案，这是 Oracle 区别于开源库的核心竞争力。
  5. PL/SQL 过程化扩展：存储过程、包、触发器可在库内实现复杂业务逻辑，减少应用与数据库之间的往返——既是优势也是「业务逻辑下沉」的双刃剑。

本章是 Oracle 系列的总览与起点。先建立「实例/数据库/Schema」的体系结构心智模型，再跑通最小 SQL 与连接示例，后续章节逐层深入 SQL、PL/SQL、存储、高可用与调优。

一、版本与发行版

Oracle 版本号采用「主版本.数据库发布更新」的形式，常见长期支持版本：

版本 发布 特性要点 支持状态
11g 2007 引入 Result Cache、ADDM 成熟 EOL，存量系统
12c 2013 多租户 CDB/PDB、Identity Column、JSON Extended Support
19c 2019 长期支持版（LTS）、自动索引、Active Directory 存量主流（延长支持期，建议规划升级）
23ai 2024 AI 向量原生支持、Boolean 类型、Microcluster 当前长期支持版（云上已演进至 26ai）

23ai 是当前长期支持版（AI 向量原生支持），存量生产系统仍以 19c 为主（已处延长支持期，建议规划升级）。学习建议用免费版 XE / Database Free。

免费发行版：

  • Oracle Database Express Edition（XE）：固定上限（2 CPU、2GB SGA、12GB 用户数据），适合学习与小型部署。
  • Database Free（23ai 起改名）：开发与容器化友好，container-registry.oracle.com 提供官方镜像。
  • Oracle Cloud Always Free：云端永久免费层，含 2 个 Autonomous Database（各 20GB），免安装体验 23ai。

23ai 新特性尝鲜：免费版即可体验 Boolean 类型（CREATE TABLE t (flag BOOLEAN)）、IF NOT EXISTS（CREATE TABLE IF NOT EXISTS t (...) 避免重复建表报错）、AI 向量（VECTOR 类型 + 向量距离函数）。这些在 19c 及之前均不存在，学习环境建议直接上 23ai Free。

二、体系结构总览（核心心智模型）

Oracle 体系结构是理解一切后续章节的根基。一个运行中的 Oracle 由三层构成：



flowchart TB
  subgraph Client[客户端]
    APP[应用 JDBC/SQL*Plus]
  end
  APP --> LSNR[监听器 Listener 1521]
  LSNR --> INST
  subgraph INST[Instance 实例 - 内存 + 进程]
    SGA[SGA 共享内存: Buffer Cache / Shared Pool / Redo Log Buffer / Large Pool]
    PGA[PGA 私有内存: 排序/会话]
    BG[后台进程: PMON / SMON / DBWn / LGWR / ARCn / CKPT]
    SGA --- BG
    PGA --- BG
  end
  INST <--> DB
  subgraph DB[Database 数据库 - 物理文件]
    DF[数据文件 .dbf]
    CF[控制文件 control.ctl]
    RDO[联机重做日志 redo.log]
    ARC[归档日志 archive]
  end
  DB --> ASM[磁盘存储 / ASM]

1. 三层对应关系

层次 组成 性质
Instance 实例 SGA（共享内存）+ 后台进程 内存态，重启即重建
Database 数据库 数据文件、控制文件、重做日志 磁盘态，持久存在
Schema 模式 用户拥有的对象（表、视图、过程等） 逻辑概念，隶属于用户

关键区分：实例是「跑起来的内存进程」，数据库是「磁盘上的文件」。实例挂掉数据不丢（落盘），但内存中的未提交事务会因 undo 回滚。这套机制详见 第四章：体系结构与存储管理。

2. 后台进程速记

进程 职责 记忆点
PMON 进程监控，清理异常死掉的会话 Process Monitor
SMON 系统监控，实例恢复、合并空闲空间 System Monitor
DBWn 数据库写进程，把脏块从 Buffer Cache 落盘 DataBase Writer
LGWR 日志写进程，把 Redo Log Buffer 写联机日志 LoG Writer（写顺序的命脉）
CKPT 检查点，同步数据文件头与控制文件 CheckPoint
ARCn 归档进程，联机重做日志写满后拷贝归档 Archiver（ARCHIVELOG 模式才有）

LGWR 是性能与安全的命脉：事务提交时 LGWR 把 redo 落盘即算提交成功，DBWn 则延迟批量落盘。所谓「日志先行（WAL）」即此。

Oracle 默认不自动提交——INSERT/UPDATE/DELETE 后必须 COMMIT 才落盘，断开会话未提交会回滚。这与 MySQL 默认 autocommit 不同，是新手踩坑高发点。

五、与开源数据库的对照

维度 Oracle MySQL / PostgreSQL
许可 商业（含 XE/Free 免费版限制） 开源为主
体系结构 Instance（SGA+进程）+ Database（文件） MySQL 实例与库耦合；PG 进程模型
优化器 成熟 CBO，绑定变量与执行计划管理丰富 各版本持续演进
集群 RAC 共享存储多活、Data Guard 容灾 主从、Patroni、Group Replication 等
过程化 PL/SQL（块、包、触发器生态成熟） MySQL 存储过程弱；PG 的 PL/pgSQL
分页 12c+ FETCH；旧版 ROWNUM MySQL LIMIT；PG LIMIT OFFSET
适用 存量 Oracle 核心、合规与厂商支持 互联网、云原生、成本敏感

数据类型对照

迁移或双库并行开发时最常对照的类型：

语义 Oracle MySQL PostgreSQL
变长字符串 VARCHAR2(n) VARCHAR(n) VARCHAR(n) / TEXT
数字 NUMBER(p,s) DECIMAL / INT / BIGINT NUMERIC / INT / BIGINT
日期时间 DATE（含时分秒）/ TIMESTAMP DATETIME / TIMESTAMP TIMESTAMP
大文本 CLOB TEXT TEXT
大二进制 BLOB BLOB BYTEA
自增 12c+ IDENTITY；旧版序列+触发器 AUTO_INCREMENT SERIAL / IDENTITY
布尔 23ai+ BOOLEAN；旧版 NUMBER(1) 模拟 TINYINT(1) BOOLEAN

行为差异要点

  1. 事务：Oracle 默认手动提交；MySQL 默认 autocommit=1；PG 默认自动提交但 DDL 可回滚（Oracle 的 DDL 隐式提交且不可回滚）。
  2. 空字符串：Oracle 把 '' 当 NULL；MySQL/PG 视为空串——WHERE col = '' 在 Oracle 永远查不到。
  3. 大小写：Oracle 未加引号的标识符自动转大写；PG 转小写；MySQL 依操作系统。迁移时带引号的混合大小写对象名是坑。
  4. 隔离级别：Oracle 默认 READ COMMITTED（语句级读一致）；MySQL InnoDB 默认 REPEATABLE READ。
  5. 序列：Oracle SEQUENCE 是独立对象，可多表共用、可缓存（CACHE 20）；MySQL 自增列绑定单表。

六、常用数据字典视图速查

Oracle 把元数据全部暴露在数据字典中，分静态字典视图与动态性能视图两类，是日常查询与排障的入口。

1. 静态字典视图（USER_ / ALL_ / DBA_ 三前缀）

前缀 可见范围 典型视图
USER_* 当前用户拥有的对象 USER_TABLES、USER_INDEXES、USER_OBJECTS
ALL_* 当前用户可访问的对象（含被授权的） ALL_TABLES
DBA_* 全库对象（需 DBA 权限） DBA_TABLESPACES、DBA_USERS、DBA_DATA_FILES

2. 动态性能视图（V$）

V$ 反映实例运行时状态，随库运行持续更新、重启即清空：

视图 内容
V$INSTANCE 实例名、状态、启动时间
V$DATABASE 库名、日志模式、当前 SCN
V$SESSION 会话清单（含 SQL_ID、等待事件）
V$SQL 共享池中的 SQL 与执行统计
V$VERSION 版本横幅
V$PDBS 12c+ 各 PDB 状态

记忆法：USER_ 看自己、ALL_ 看能用、DBA_ 看全库、V$ 看运行时。查对象定义找静态视图，查运行状态找 V$。更完整的诊断视图清单见 第四章 与 第六章。

七、运维红线速记

  • 字符集：建库时定 AL32UTF8，后期修改成本极高（需导入导出重建）。
  • 归档模式：生产必须 ARCHIVELOG，否则只能恢复到上次备份、无法时点恢复。
  • 连接数：应用侧用连接池控制会话数，避免耗尽 processes / sessions。
  • 补丁周期：LTS 与 Extended Support 周期需与采购合同对齐，过期无补丁有安全风险。
  • UNDO/TEMP：别在 UNDO/TEMP 表空间建业务表，SYSTEM/SYSAUX 亦然。
