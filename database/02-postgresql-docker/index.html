发表于 2026-05-01 更新于 2026-10-25 分类于 数据库 本文字数： 8.6k 阅读时长 ≈ 8 分钟

第二章：Docker 部署 PostgreSQL 实践

概念基础

  1. PostgreSQL 是 C/S 架构的关系库：服务端 postgres 进程监听 5432 端口，客户端（psql、JDBC）通过连接串访问；「部署」的本质就是两件事——把服务端进程跑起来、让数据落在可靠的地方。
  2. 容器化 = 环境即代码：镜像内置二进制与依赖，一条命令起库；POSTGRES_USER / POSTGRES_PASSWORD / POSTGRES_DB 环境变量完成初始化，首次空数据目录时还会自动执行 /docker-entrypoint-initdb.d 下的脚本。
  3. 三种部署形态由小到大：docker run 单容器（本地开发）→ Docker Compose 编排（健康检查、.env 管敏感项）→ Kubernetes（探针、PVC 持久化、集群化运维）。
  4. 数据与容器分离：容器随时可删，数据必须在**卷（Volume）**上——镜像升级换容器、卷不动，这是容器化数据库的第一原则。

二、PostgreSQL 镜像选择

1. 官方镜像（推荐）

  • 仓库：postgres（Docker Hub 官方库，由 PostgreSQL / Docker Official Images 维护）。
  • 常用标签：
    • postgres:18：当前最新大版本（2025 年 9 月发布）。
    • postgres:17 / postgres:16：存量常用大版本，仍在支持期内（以 Docker Hub postgres tags 为准）。
  • 生产建议：固定小版本标签（如 postgres:18.x）或记录 digest，避免 latest 漂移导致行为变化。

2. 变体说明

需求 说明
超级用户与库 POSTGRES_USER 为数据库超级用户名（默认 postgres）；POSTGRES_PASSWORD 为其密码；POSTGRES_DB 为首次创建的库名（未设置时默认与 POSTGRES_USER 同名）。
ARM64（Apple Silicon 等） 官方 postgres 多架构镜像一般可直接拉取；若某标签缺架构，换标签或查 Hub OS/ARCH。
极简/定制 社区有 bitnami/postgresql 等，环境变量与数据路径与官方不同，切换镜像时需对照该镜像文档。

3. 编码与本地化

需要固定库编码、排序规则时，可通过 POSTGRES_INITDB_ARGS 传入 initdb 参数（如 --encoding=UTF8 --locale=C），与业务 client_encoding、迁移脚本约定一致。

1Panel（推荐）：在 Linux 宿主机上若希望少手写命令、仍以容器方式跑 PostgreSQL，可先安装 1Panel（开源 Linux 运维面板），在 「应用商店」 中选择 PostgreSQL 一键部署：由面板管理镜像版本、数据持久化、端口与备份等。与下文 docker run / Compose / K8s` 的环境变量、卷路径对齐或排障时，自 第三节 起各节仍可作对照。

九、高可用简介：单容器之后怎么走

本章的单容器/Compose/K8s 清单都是单实例形态；生产高可用的标准答案：

方案 形态 适用
流复制主备 主库 + pg_basebackup 拉起的物理备库，WAL 实时回放 读扩展、手动切换
Patroni + etcd 自动选主、故障转移、配置下发 自建机房/虚机
CloudNativePG K8s Operator，声明式管集群 已上 Kubernetes
云 RDS 厂商托管主备 + 自动备份 不想养 DBA

共同地基都是流复制：主库把 WAL 流式推给备库回放。容器化落地时备库同样挂独立卷、连主库 5432 拉流——细节属专用编排范畴，切勿靠给 Deployment 加副本数来「做主备」。

本章小结

要点 结论
形态选择 本地开发 docker run；自包含小栈用 Compose；集群化用 K8s 清单或 Operator
镜像纪律 优先官方 postgres:18，生产固定小版本标签或 digest，避免 latest 漂移
数据持久化 数据必须落在卷上；pg-init 初始化脚本只在首次空数据目录时执行
初始化脚本 *.sql / *.sh 按文件名序执行：装扩展、建业务账号、追加 postgresql.conf
逻辑复制 -c wal_level=logical 开槽 + CREATE PUBLICATION；闲置槽会撑爆磁盘，必监控
备份 宿主机 docker exec pg_dump -Fc 即可；物理备份走 pg_basebackup + WAL 归档
高可用 流复制是地基；Patroni / CloudNativePG / RDS 按平台选型，勿用 Deployment 副本冒充主备
健康与探针 Compose 用 pg_isready 健康检查；K8s 配 readiness/liveness 探针与 strategy: Recreate
生产红线 密码走 .env / Secret 并接入管控；配套备份、监控、网络策略与 TLS
