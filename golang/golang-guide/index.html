3. 泛型（Go 1.18+）

泛型用类型参数消除 interface{} 转换样板：func Map[T any, U any](slice []T, fn func(T) U) []U；类型约束用 ~int | ~int64 | ~float64 这类并集表达底层类型，comparable/any 是内置约束。标准库 slices/maps 已全面泛型化，日常开发直接调用即可。

泛型不是银弹——接口优先，泛型用于容器与算法这类「与元素类型无关」的场景。约束设计、泛型结构体、与接口的取舍见工程实践章。深入了解：第三章：Golang 工程实践

5. 错误处理

Go 的错误是值：函数返回 error，调用方必须显式处理。标准范式是 fmt.Errorf("上下文: %w", err) 包装保留错误链，判断用 errors.Is（比对哨兵错误）与 errors.As（提取自定义错误类型）。

团队落地时要统一「在哪里包装、在哪里兜底日志」，避免错误被吞或重复记录。规范细节与工程化实践：深入了解：第三章：Golang 工程实践

6. 并发编程

goroutine + channel 是 Go 的招牌：go f() 启动轻量协程，sync.WaitGroup 做汇合点，channel 传递数据与所有权（仅发送方 close），select 多路等待，errgroup 收集并发错误并联动取消。核心原则：每个 go 都要回答「它怎么退出」，channel 收发必须可取消（select + ctx.Done()）。

GMP 调度模型、channel 底层结构、sync 全家桶（Mutex/RWMutex/Once/Pool/Cond）、Worker Pool 等生产模式：深入了解：第一章：Golang 并发编程

7. slog 结构化日志（标准库）

Go 1.21+ 内置 log/slog：生产用 slog.NewJSONHandler 输出 JSON，字段以键值对追加（logger.Info("用户登录", "user_id", id)），logger.With(...) 派生带上下文的子 logger——比 fmt.Println 好 100 倍。

级别配置、自定义 Handler、与 HTTP 中间件集成：深入了解：第二章：Golang 标准库

8. Web 开发

标准库 net/http（Go 1.22+ 支持 GET /api/users/{id} 方法+通配符路由）已能零依赖起服务；生态框架里 Gin/Chi 提供路由分组、参数绑定等便利。生产服务必配 http.Server 三个超时（ReadHeaderTimeout/ReadTimeout/WriteTimeout），中间件就是「包一层 Handler 再返回 Handler」。

生产级 JSON API、中间件模式、embed 静态资源：深入了解：第二章：Golang 标准库

9. 项目结构

社区惯例布局：cmd/ 入口、internal/ 内部包（不对外暴露，编译器强制）、pkg/ 可复用公共包、configs/ 配置。配套命令：go mod tidy 整理依赖、go build ./... 编译、go test ./... -race 测试+竞态检测、go vet ./... 静态检查。

依赖管理、测试范式、CI/CD 流水线与工具链规范：深入了解：第三章：Golang 工程实践

10. 典型案例：goroutine 泄漏排查

问题背景：订单搜索服务在 Grafana 上 goroutine 数曲线只涨不降（从 200 涨到 5 万），一周后 OOM。重启缓解但必复发——典型的「无界 channel + 不可取消的发送」泄漏。

方案：pprof 定位卡点 → 根因分析 → select + ctx 修复。核心教训三条：① channel 发送必须 select 监听 ctx.Done()，取消即退出，否则消费方提前 return 后发送方永久卡死；② close(ch) 由发送方负责，忘关会让消费方 range 永久阻塞；③ 生产服务启动时就该挂上 net/http/pprof，否则出事只能重启。

11. 常见误用与陷阱

坑 现象/后果 解法
向已 close 的 channel 发送 panic: send on closed channel close 由发送方负责；多发送方用 WaitGroup 收口后再 close
忘记 close channel 消费方 range 永久阻塞 发送完成后 defer close；接收方判断 ok
nil channel 上收发 永久阻塞，goroutine 泄漏 只使用 make 出的 channel；小心结构体零值里嵌 channel
defer 在循环里 fd/锁延迟到函数结束才释放，长循环资源耗尽 抽成小函数，或循环内手动 Close
无界 buffer 掩盖设计问题 内存暴涨，问题后移 有界队列 + 明确背压策略（阻塞或丢弃）
for 循环里用 time.After 每轮新建 timer，旧版本下短 timer 不回收 time.NewTimer + Reset 复用
忽略 err 或重复处理 错误被吞/日志双写 每处 error 要么处理要么 fmt.Errorf("%w") 上抛
