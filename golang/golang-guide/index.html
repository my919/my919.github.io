10. 典型案例：goroutine 泄漏排查

踩坑点：

  • 只给函数加了 ctx 参数，但 select 里忘了写 <-ctx.Done() 分支——等于没加。
  • 忘 close(ch)：消费方 range ch 永久阻塞，变成另一种泄漏；close 由发送方负责。
  • 生产未暴露 pprof 端口：出事只能重启。服务启动时就该挂上 net/http/pprof。

11. 常见误用与陷阱

坑 现象/后果 解法
向已 close 的 channel 发送 panic: send on closed channel close 由发送方负责；多发送方用 WaitGroup 收口后再 close
忘记 close channel 消费方 range 永久阻塞 发送完成后 defer close；接收方判断 ok
nil channel 上收发 永久阻塞，goroutine 泄漏 只使用 make 出的 channel；小心结构体零值里嵌 channel
defer 在循环里 fd/锁延迟到函数结束才释放，长循环资源耗尽 抽成小函数，或循环内手动 Close
无界 buffer 掩盖设计问题 内存暴涨，问题后移 有界队列 + 明确背压策略（阻塞或丢弃）
for 循环里用 time.After 每轮新建 timer，旧版本下短 timer 不回收 time.NewTimer + Reset 复用
忽略 err 或重复处理 错误被吞/日志双写 每处 error 要么处理要么 fmt.Errorf("%w") 上抛
