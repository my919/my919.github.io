简单场景 Spring @Scheduled 单机够用

1. 方案选型：先判断要不要用调度中心

方案 适用 不适用
Spring @Scheduled 单机/开发环境 多实例（会重复执行！）
XXL-Job 生产分布式、要监控/重试/路由 任务极少且单机
Quartz 老系统 维护成本高，新项目不推荐

核心问题：集群部署时，@Scheduled 会在每个实例上各执行一次 → 定时任务重复执行（重复发券/重复扣款）。

判断标准：实例数 > 1 且任务有副作用 → 必须用分布式调度（XXL-Job）。

2. Spring @Scheduled 基础（单机够用的场景）

@Scheduled 的三个坑：

  1. 任务默认单线程串行：一个任务卡住，其他任务全部排队 → 必须配线程池
  2. 任务异常默认吞掉（只打日志）→ 要自己 try-catch 上报
  3. 不支持分布式（多实例重复执行）

3. XXL-Job 架构与部署

3.1 架构

为什么用调度中心：集中管理任务（启停/一次执行/查看日志）+ 支持路由策略（分片广播）+ 失败重试 + 报警——这些都是 @Scheduled 没有的。

3.2 部署调度中心（Docker）

为什么配 accessToken：调度中心与执行器之间用 token 鉴权——不配则任何人都能调度你的任务。

路由策略怎么选：

策略 行为 适用
第一个/最后一个 只有一台执行 单点任务
轮询 轮流分发 多执行器分担
分片广播 所有执行器各跑一次（带分片参数） 批量任务首选
故障转移 失败换一台 重要单点任务

分片广播为什么适合批量：10 万条数据，3 台执行器各处理 1/3（按 shardIndex/shardTotal 取模）——并行快 3 倍。

6. 常见问题

问题 原因 解决
调度中心看不到执行器 端口没通/token 不一致 查 9999 端口与 accessToken
任务执行但没结果 JobHandler 名字不一致 核对 @XxlJob value
任务重复执行 路由策略/阻塞处理不对 分片广播任务内部去重；阻塞选”丢弃后续”

任务日志查不到 logpath 没建/权限 建目录 + 配权限

7. 检查清单

8. 典型案例：百万订单超时关闭的分片广播改造

问题背景：促销日订单量暴涨，每天凌晨累积约 80 万笔超时未支付订单。原方案是单实例定时任务每 5 分钟执行一次 UPDATE ... LIMIT 1000，出现三个症状：① 单轮要跑 800 次、处理不过来，未关订单越积越多；② 大事务导致主从延迟飙到 40 秒，读库上”订单已支付但仍被关闭”的客诉出现；③ 执行实例重启时任务中断，无重试、无告警，只能靠客服反馈发现。

方案：改用 XXL-Job 分片广播 + 按主键取模切片，3 台执行器并行处理各自分片；每批小事务 + 批间限速，避免主从延迟；失败自动重试 + 邮件告警：

配置项 值 理由
路由策略 分片广播 3 台并行，吞吐 x3
阻塞处理 丢弃后续调度 上一轮没跑完就跳过，防止任务堆积雪崩
失败重试 2 次 批处理失败自动补偿
调度过期策略 忽略 重启后不补跑历史调度，避免重复关单
批大小 500 条 控制单事务时长 <100ms，主从延迟可控

踩坑点：

  1. 早期版本用”查询 500 条 id 到内存 → 逐条 UPDATE”，查询与更新之间订单恰好支付，出现”已支付订单被关闭”——改为单条 UPDATE 带状态条件（WHERE status = 0），数据库层做最后校验。
  2. 分片总数固定写死 3，某天扩容到 5 台后老分片逻辑漏处理 1/3 数据——分片数必须用 getShardTotal() 动态获取，且 SQL 用 MOD 而不是按 id 范围硬切。
  3. 任务改成每分钟一次后忘了把”调度过期策略”设为忽略，发布重启的 3 分钟里积压的调度全部补跑，同一批订单被两台机器同时处理——重启场景必须选”忽略”。
  4. 批间没加 sleep，3 台执行器满速写主库，主库 CPU 100%、主从延迟 40s——批量写任务必须限速，批大小 x 频率 x 执行器数要对齐主库写入能力。

9. 常见误用与陷阱

坑 现象/后果 解法
多实例部署仍用 @Scheduled 每台实例同时触发，重复发券/重复扣款，资损事故 实例数 >1 且任务有副作用 → 必须 XXL-Job 等分布式调度
阻塞处理选”单机串行” 任务卡死后调度不断堆积，重启后疯狂补跑压垮 DB 长任务选”丢弃后续调度”；配单轮配额 + 分批处理
大事务一次 UPDATE 几十万条 锁表、主从延迟飙升、undo 膨胀，线上其他写操作全部超时 LIMIT 分批（500-1000 条）+ 批间限速 sleep + 循环到配额
JobHandler 名字大小写不一致 调度中心显示”执行成功”但业务毫无变化 @XxlJob value 与控制台 JobHandler 严格一致，发布前用”执行一次”验证
任务异常只 log 不上报 控制台永远显示成功，失败三天没人发现 用 XxlJobHelper.handleFail 回传失败 + 配置告警邮件/群机器人
cron 秒级任务（0/1 * * * * ?） 上一轮没跑完下一轮又触发，数据重复处理 批量任务最低 1 分钟粒度；确实需要高频时配合分布式锁或幂等键
分片逻辑按 id 范围硬编码（0-10万/10-20万） 扩缩容后区间错乱，部分数据无人处理 分片参数动态取 shardIndex/shardTotal，SQL 用 MOD 分片
