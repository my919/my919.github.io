1. 概念说明

Java 是面向对象、跨平台的编程语言：”一次编写，到处运行” 靠 JVM 实现 ——.java 编译为字节码 .class，由 JVM 解释 / 即时编译执行。

核心组成：

  • JDK（Java Development Kit）：开发工具包，含编译器、JVM、类库。

  • JRE（Java Runtime Environment）：运行环境（JDK 已包含）。

  • JVM（Java Virtual Machine）：字节码执行引擎，内存管理、垃圾回收。

为什么选 JDK 21 LTS：长期支持版本（支持至 2031），带来虚拟线程、记录类（Record）、模式匹配等现代特性。生产环境优先 LTS（21 或 25）。

10. 典型案例：会员到期提醒服务（Optional 防空 + 时间处理）

问题背景：定时任务每天扫描会员表发”即将到期”提醒。初版代码层层 if (user != null) 判空仍漏了两处（运营后台补录的数据缺手机号），凌晨 NPE 中断；到期时间用 Date + Calendar 计算，测试环境与生产时区不同导致提醒早发了 8 小时，用户半夜收到短信投诉。

方案（Optional 链式防空 + java.time 统一时间口径）：

隐患 初版写法 优化后
空指针 嵌套 if-null，漏判即 NPE Optional 链一次表达
时间时区 new Date() 依赖机器时区 显式 ZoneId，Instant 存 UTC
天数计算 Calendar 手工加减易错 ChronoUnit.DAYS.between
格式化 SimpleDateFormat（线程不安全） DateTimeFormatter（线程安全）

踩坑点：

  1. SimpleDateFormat 定义成 static 常量被多任务线程共用，日志里出现 2026-13-45 这类错乱日期——换 DateTimeFormatter（不可变、线程安全）。
  2. 数据库用 UTC 存时间，应用按东八区取 LocalDate.now()，跨天临界点把”明天到期”算成”今天”——存储用 UTC/Instant，计算与展示统一显式 ZoneId。
  3. Period（日期段）与 Duration（时间段）混用，Duration.between(twoLocalDates) 直接抛异常——日期用 Period/ChronoUnit，时刻用 Duration。
  4. 用 Optional 做了实体字段，Jackson 序列化报错——Optional 只出现在方法返回值。

11. 常见误用与陷阱

坑 现象/后果 解法
split(“.”) 不转义 返回空数组，逻辑静默失效 split(“\.”)（. 是正则元字符）
热点路径频繁 String.split 每次调用都编译正则，CPU 浪费 简单分隔用 indexOf/StringTokenizer 或预编译 Pattern
循环内 + 拼接字符串 海量临时对象，接口耗时抖动 StringBuilder.append
== 比较字符串内容 new 出来的串比较恒为 false equals / Objects.equals
Integer 用 == 比较 127 相等、128 不等（缓存池边界） equals 或拆箱为 int 再比
SimpleDateFormat 共享 并发下日期错乱、NumberFormatException DateTimeFormatter + java.time 全家桶
new Date() 隐式依赖机器时区 测试/生产时区不同，差 8 小时 显式 ZoneId，存储用 Instant(UTC)
catch (Exception e) {} 吞异常 故障静默丢失，排障无日志 记日志后抛业务异常
