1. 方案选型：为什么用 FastExcel

对比：

方案 状态 结论
Apache POI 全功能但内存爆炸（10 万行直接 OOM） 小文件可用，大文件不行
EasyExcel 阿里出品，已停止维护（2024 年后无更新） ❌ 不符合”长期维护”标准
FastExcel dromara 开源，原 EasyExcel 作者团队维护，活跃，API 兼容 EasyExcel ✅ 生产首选

为什么 FastExcel 省内存：流式读写——边读边写、不把整个文件加载进内存（POI 是全部加载）。10 万行导出，POI 可能 500MB 内存，FastExcel 稳定在几十 MB。

为什么分页 5000 而不是 10 万一次查：DB 一次查 10 万行 + 内存一次驻留 10 万对象 = 数据库和 JVM 双重压力——分页后单次只有 5000 行驻留。

6. 常见问题

问题 原因 解决
10 万行导出 OOM 一次查全量 分页流式（§3.3）
日期列变数字 Excel 日期格式 DTO 用 LocalDateTime + 注解格式化

为什么日期建议用字符串接收：Excel 日期有”文本/数值/日期”三种形态，直接映射 LocalDateTime 经常解析失败——用 String 接收，代码里统一解析最稳。

8. 典型案例：10 万行订单导入的异步化改造

问题背景：运营每月上传 10 万行的渠道订单表。同步导入接口（校验+入库一次完成）频繁超时：网关超时 60s 后前端断开，但后端还在继续写库，运营以为失败又传一次，结果两份数据各入库一半，出现 3 万条重复订单，清洗花了两天。

方案：大文件改”提交任务 → 异步处理 → 进度查询 → 结果下载”四步走；导入幂等用「文件 MD5 + 任务去重 + 订单号唯一索引」三层防护：

环节 方案 关键点
防重复提交 文件 MD5 + 任务表唯一约束 同一文件处理中/已成功，再次上传直接拒绝
行级幂等 订单号唯一索引 + INSERT IGNORE 语义 重复导入自动跳过，不产生脏数据
进度反馈 任务表 processed/total 字段 前端轮询，不再卡转圈
错误明细 错误表存”行号+原因” 完成后生成错误明细文件下载
超时保护 单任务处理上限 + 批间限速 防止导入任务拖垮业务库

踩坑点：

  1. 异步线程里用了主线程的 MultipartFile——请求返回后临时文件被 Spring 清理，异步读到一半报 FileNotFoundException。提交时必须把文件落盘/转存到对象存储，异步任务只碰持久化副本。
  2. 进度更新直接 UPDATE task SET processed = processed + 1000，任务表成为热力行，导入高峰锁等待——进度更新降频到每 10 批一次，或改内存计数定时刷库。
  3. 没做 MD5 去重时，运营在”转圈”期间重复点了 4 次提交，4 个任务并行导入同一份数据——唯一索引 + INSERT IGNORE 保证了数据不重，但 4 个任务空转浪费了 1 小时，加 MD5 去重后彻底解决。
  4. 错误明细 8 万行全部堆在内存 errors 列表里，任务把老年代撑爆触发 Full GC——错误明细改为分批写入错误表/文件，内存只留计数。
  5. 导入完成后没有通知机制，运营每 10 秒手动刷新进度页——补了完成后站内信 + 状态推变（轮询间隔可放宽到 5s）。

9. 常见误用与陷阱

坑 现象/后果 解法
导出异常时响应头已写、再写 JSON 错误页 前端收到损坏的 .xlsx 或二进制乱码 写响应头前完成参数校验；异常用单独错误码约定（或先写内存再落响应）
每行 insert 一次 1 万行导入 10 分钟，DB 连接被长时间占用 攒批 500-1000 条 saveBatch/批量 VALUES 插入，速度提升 20 倍以上
@ExcelColumn 不写 order 列顺序随字段定义变化，模板对不上，导入列错位 每列显式 order，模板下载与导入模型共用同一 DTO
日期字段直接映射 LocalDateTime “2026/1/5”、文本日期等格式解析抛异常，整批失败 用 String 接收，代码里统一多格式解析；或注解指定固定格式
导入不做幂等 用户重复上传同一文件，订单重复入库 文件 MD5 任务级去重 + 业务唯一索引行级兜底
重复消费同一 InputStream 先算 MD5 再读文件，正式解析时流已到 EOF，报”文件为空” file.getInputStream() 每次重新获取（Spring 每次返回新流），或先落盘再处理
headRowNumber 配错 第一行数据被当表头吃掉，或表头被当数据解析 表头 1 行必须 headRowNumber=1；多级表头按实际行数配置并自测
导入/导出共用业务线程池 大导出打满线程，普通接口排队超时 导入导出走独立线程池 + 并发上限，大任务异步化
