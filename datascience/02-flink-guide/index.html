第二章：Flink 流式计算入门

发表于 2026-05-01 更新于 2026-10-25 分类于 数据工程 本文字数： 7.8k 阅读时长 ≈ 7 分钟

第二章：Flink 流式计算入门

概念基础

  1. Apache Flink 是分布式流式计算引擎：把数据当作连续不断的事件流处理，毫秒~秒级延迟持续产出结果，天然适合实时数仓与实时监控。
  2. 编程模型：在 DataStream 上做 map / filter / keyBy / window 等转换，Source 从 Kafka 等连接器读数据，Sink 写 JDBC/ES 等。
  3. 事件时间语义：以 Event Time 为准，用 Watermark 追踪事件时间进度来处理乱序数据，窗口（滚动 / 滑动 / 会话）按事件时间触发，结果才准确。
  4. 状态与容错：Keyed State 管理每 key 状态，Checkpoint 异步分布式快照配合两阶段提交实现端到端 exactly-once；Savepoint 支持升级与扩缩容。
  5. 与 Spark 分工：Flink 强在低延迟实时与复杂事件处理；超大离线批与 ML 生态 Spark 更成熟（见上一章）。

编程模型



flowchart LR
  K[Kafka Source] --> Map[map/filter]
  Map --> Key[keyBy]
  Key --> Win[Window + Watermark]
  Win --> Sink[Sink JDBC/ES]
  Win -.-> CP[Checkpoint 状态快照]
  • Transformation：map/filter/keyBy/window 等。
  • Source / Sink：Kafka、JDBC、文件系统、Pulsar 等连接器。

部署架构

组件 职责
JobManager 调度作业、协调 Checkpoint、故障恢复
TaskManager 执行算子链，资源单位是 Slot（内存均分、线程隔离）
并行度 算子级并行度 × Slot 数决定吞吐；算子链把窄依赖算子合进一个 task 省序列化

部署形态：Session 集群（多作业共享）、Per-Job、Flink Kubernetes Operator（云原生主流，声明式管理作业生命周期）。



flowchart TB
  JM[JobManager<br/>调度 + Checkpoint 协调]
  TM1[TaskManager<br/>Slot × N]
  TM2[TaskManager<br/>Slot × N]
  JM --> TM1
  JM --> TM2
  TM1 <--> TM2
  JM -.->|元数据| HDFS[(Checkpoint 存储)]

Flink 2.x 动向：生产建议暂以 1.20 LTS 为主；2.x 重点方向是云原生与解耦状态存储（ForSt/Disaggregated State）、移除老旧 API（DataSet API 已删除）、SQL 语法进一步向标准靠拢——升级前需评估存量作业的状态兼容与 API 迁移成本。

DataStream API 进阶

窗口聚合不覆盖的逻辑用 ProcessFunction——可访问状态与定时器，是 DataStream 的「万能算子」：

  • 侧输出（Side Output）：ctx.output(tag, e) 把迟到/异常数据分流到旁路流，不阻塞主链路。
  • 异步 IO：AsyncDataStream 并发查外部系统（维表 Join、调用 RPC），配 unorderedWait 保吞吐。

事件时间与窗口

概念 说明
Processing Time 算子机器本地时钟
Event Time 数据自带业务时间戳
Watermark 衡量事件时间进度，触发窗口计算
Window Tumbling、Sliding、Session

乱序数据需 Watermark 延迟 与 allowedLateness 平衡准确性与延迟。

窗口类型与选择

窗口 语义 典型场景
Tumbling 滚动 固定长度、不重叠 每分钟 PV/UV
Sliding 滑动 长度 + 步长，可重叠 最近 10 分钟均值每 1 分钟更新
Session 会话 按 gap 切分 用户会话行为分析
Global 全局 全量 + 自定义 Trigger 计数触发、定时批量输出
  • Watermark 策略：forBoundedOutOfOrderness（有界乱序，最常用）、forMonotonousTimestamps（严格递增）。
  • 触发时机：Watermark 超过窗口结束时间即触发；allowedLateness 内迟到数据触发增量更新，超过则丢弃或进侧输出。
  • WindowFunction：AggregateFunction 预聚合 + ProcessWindowFunction 拿窗口元信息，组合用避免全量数据驻留内存。

状态与 Checkpoint

  • Keyed State：与 keyBy 绑定，如 ValueState、ListState。
  • Checkpoint：异步分布式快照，配合 Kafka 两阶段提交 实现 端到端 exactly-once（依 Sink 支持）。
  • Savepoint：手动一致性快照，用于升级与扩缩容。

状态原语

状态 结构 适用
ValueState[T] 单值 计数器、最近一次事件
ListState[T] 列表 缓冲待合并的小批次
MapState[K,V] 字典 每 key 的多字段画像
ReducingState / AggregatingState 增量聚合 滚动累加，省内存
State TTL 过期清理 StateTtlConfig 防止状态无限膨胀

状态后端选型

后端 工作态存储 适用
HashMapStateBackend JVM 堆 状态小（GB 内）、延迟极致
EmbeddedRocksDBStateBackend 本地 RocksDB（增量快照） 大状态（TB 级）生产标配

Checkpoint 调优

  • 对齐 vs 非对齐：背压严重时 barrier 排队导致快照超时，Unaligned Checkpoint 跳过排队直接快照 inflight 数据（1.13+ 稳定，1.20 推荐开启）。
  • Changelog State Backend（1.15+ 实验→渐稳）：状态变更持续写日志，把 Checkpoint 耗时压到秒级，代价是双份 IO。
  • Savepoint 操作：flink savepoint <jobId> hdfs:///sp/ 手动快照；升级、改并行度、换代码后从 Savepoint 恢复（-s 参数指定）。

端到端 Exactly-Once

内部一致性由 Checkpoint（Chandy-Lamport 变体） 保证；端到端需要 Sink 配合：

Sink 方案 机制 例子
两阶段提交（2PC） 预提交 + Checkpoint 完成后提交 Kafka 事务 Sink
幂等写入 主键覆盖写，重复无害 MySQL upsert、Redis HSET
事务性写入 写到临时区，Checkpoint 后可见 文件系统 Sink

Source 侧 Kafka 位移随 Checkpoint 保存，故障恢复时重置位移重放，配合 2PC Sink 即端到端精确一次。

CEP：复杂事件处理

FlinkCEP 用模式（Pattern）在事件流里匹配「A 之后 B、且中间没有 C」这类时序规则，典型场景：风控（短时间内多次失败登录）、运营（下单后 15 分钟未支付提醒）。

  • 匹配语义：next（紧邻）、followedBy（中间可有其他事件）、notNext（禁止出现）。
  • 跳过策略：AfterMatchSkipStrategy 控制重叠匹配，避免误报风暴。
  • 规则频繁变更的场景，常把模式定义外置到配置中心动态加载（Aviator/Groovy 表达式）。

常见避坑

坑 现象 正确做法
Watermark 不前进 窗口永远不触发、状态膨胀 检查空闲 Source 分区，加 withIdleness
状态无限增长 RocksDB 磁盘打满、Checkpoint 超时 配 State TTL；key 维度爆炸需业务层限界
背压导致快照超时 Checkpoint 频繁失败、恢复变慢 开 Unaligned Checkpoint；先解决背压源头
allowedLateness 过大 窗口结果反复变更，下游困惑 按业务可接受时长设定，超迟到走侧输出兜底
并行度随手改 状态无法恢复或 KeyGroup 错配 从 Savepoint 恢复；最大并行度提前规划
Lookup Join 直连库 数据库被流打爆 维表前置 Redis 缓存 + 异步 IO

本章小结

要点 结论
编程模型 DataStream 转换链 map/filter/keyBy/window，Source/Sink 走连接器
时间语义 Event Time + Watermark 处理乱序，allowedLateness 平衡准确与延迟
状态 Keyed State 五原语 + State TTL；大状态选 RocksDB 增量快照
容错机制 Checkpoint 分布式快照 + 两阶段提交实现端到端 exactly-once，Savepoint 支持升级
SQL 能力 Table API/SQL 与 DataStream 互转，窗口 TVF + Temporal Join，Flink CDC 同步 MySQL
CEP Pattern API 匹配时序规则，风控/超时提醒场景利器
选型分工 毫秒级实时与 CEP 选 Flink，超大离线批与 ML 生态选 Spark
