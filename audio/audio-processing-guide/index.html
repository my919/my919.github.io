1. 概念说明

数字音频是把连续声波采样成离散数字序列。三个核心参数：

  • 采样率（Sample Rate）：每秒采样的次数，单位 Hz。CD 为 44100 Hz，视频通用 48000 Hz。采样率决定可还原的最高频率（奈奎斯特定理：最高频率 = 采样率/2）。
  • 位深（Bit Depth）：每次采样用多少 bit 表示振幅，16 bit（CD）、24 bit（录音室）。位深决定动态范围。
  • 声道（Channels）：单声道（mono）、双声道（stereo）或多声道（5.1）。

常见格式：WAV（无损 PCM）、MP3 / AAC（有损压缩）、FLAC（无损压缩）、M4A / OGG。

核心处理手段：转码（格式/码率转换）、剪辑（截取/拼接）、音量调整（增益/归一化）、降噪（滤波）、提取（音视频分离）、混音（多轨叠加）。

9. 典型案例：播客上架流水线（响度标准化 → 去静音 → 切章）

问题背景：编辑部每周收到 20+ 期播客音频，音量忽大忽小、片头片尾静音几十秒，人工整理一期要半小时；上架平台还常被打回”响度不达标”。

方案：批处理流水线一次搞定——两遍 loudnorm 标准化到 -16 LUFS（播客主流标准）→ 检测并切除首尾静音 → 按静音点合并切片成章节 → 输出 m4a 并回写元数据，全部脚本化并行执行。

踩坑点：

  • 单遍 loudnorm 是动态压缩，语音有”呼吸感”失真——两遍测量 + linear=true 才是正解。
  • split_on_silence 的 silence_thresh 要按素材实测响度调整，标准化后用 -40dBFS 才稳。
  • librosa/pydub 读 mp3 底层依赖 ffmpeg，服务器必须先装，否则报 CouldntDecodeError。
  • pydub 全量载入内存，2 小时节目先确认内存余量，超长素材改用 ffmpeg 流式处理。

10. 常见误用与陷阱

坑 现象/后果 解法
峰值归一化当响度标准化 峰值一致但响度差 6dB，平台判定不达标 用 loudnorm（EBU R128 / LUFS）：播客 -16、流媒体 -14
单遍 loudnorm 直出 语音动态被压，忽强忽弱有”呼吸感” 两遍测量 + linear=true 精确修正
重采样只改采样率标签 变速变调，音频时长错乱 用 -ar 重采样（ffmpeg 内部做 SRC），禁止手工改文件头
pydub 处理超长文件 OOM 或进程被 kill 长素材用 ffmpeg 流式处理，pydub 只切短段
批处理无并行无断点 200 个文件跑 3 小时，中途崩了全重来 parallel/多进程并行 + 已完成跳过（幂等）
忽略元数据与封面 上架平台封面丢失、章节错乱 export 带 tags；封面用 -map_metadata 保留
