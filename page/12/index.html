2. Spring @Scheduled 基础（单机够用的场景）

@Scheduled 的三个坑：

  1. 任务默认单线程串行：一个任务卡住，其他任务全部排队 → 必须配线程池
  2. 任务异常默认吞掉（只打日志）→ 要自己 try-catch 上报
  3. 不支持分布式（多实例重复执行）

8. 典型案例：百万订单超时关闭的分片广播改造

问题背景：促销日订单量暴涨，每天凌晨累积约 80 万笔超时未支付订单。原方案是单实例定时任务每 5 分钟执行一次 UPDATE ... LIMIT 1000，出现三个症状：① 单轮要跑 800 次、处理不过来，未关订单越积越多；② 大事务导致主从延迟飙到 40 秒，读库上”订单已支付但仍被关闭”的客诉出现；③ 执行实例重启时任务中断，无重试、无告警，只能靠客服反馈发现。

方案：改用 XXL-Job 分片广播 + 按主键取模切片，3 台执行器并行处理各自分片；每批小事务 + 批间限速，避免主从延迟；失败自动重试 + 邮件告警：

配置项 值 理由
路由策略 分片广播 3 台并行，吞吐 x3
阻塞处理 丢弃后续调度 上一轮没跑完就跳过，防止任务堆积雪崩
失败重试 2 次 批处理失败自动补偿
调度过期策略 忽略 重启后不补跑历史调度，避免重复关单
批大小 500 条 控制单事务时长 <100ms，主从延迟可控

HTTPS = HTTP + TLS，不是新协议——先经 TLS 加密、再传输 HTTP 报文。URL 以 https:// 开头，默认端口 443（明文 HTTP 为 80）。

TLS 提供三件事：

4. 朴素贝叶斯（Naive Bayes）

4.1 原理

基于贝叶斯定理 + 特征独立假设：

  • P(类别)：先验（各类占比）

  • 预测：取后验概率最大的类别

训练算法：从数据统计出先验和似然（连续特征假设高斯分布：算每类的均值、方差），无需梯度下降。

8. 常见误用与陷阱

坑 现象 解法
数据泄漏：全量标准化/编码/特征选择后再划分 线下指标漂亮、上线明显回落 先 split；一切 fit 只碰训练集，或封进 Pipeline

只看 accuracy 类别不平衡时严重失真 Precision/Recall/F1/AUC 综合判断
未标准化就上正则化/距离模型 LR/SVM/KNN 被大尺度特征支配，收敛慢 先 StandardScaler（决策树等树模型不需要）
sigmoid 输出又喂给 BCELoss 重复激活、梯度饱和，训练不稳 输出裸 logits，统一 BCEWithLogitsLoss
KNN 不标准化且 K 拍脑袋 距离被量纲绑架，K 偶数还可能平票 标准化 + 奇数 K，用交叉验证选 K
小类别未 stratify 某折/测试集正类为 0，评估无意义 stratify=y 分层抽样
线上特征列顺序与训练不一致 列错位后”认真地预测错误答案” 特征列清单随模型保存，预测前按清单重排
