第十三章：Bluetooth 与 BLE：GATT 模型与低功耗设计

概念基础

  1. Bluetooth（蓝牙）工作在 2.4GHz ISM 频段，是短距离无线技术；今天物联网的主角是 BLE（Bluetooth Low Energy，蓝牙低功耗，4.0 起），为纽扣电池供电的小设备而生。
  2. BLE 的核心是 GATT：设备暴露服务（Service）→ 特征值（Characteristic）的属性树，手机等 Central 通过读写/订阅特征值与 Peripheral 交互，数据模型像访问资源一样清晰。
  3. 广播先行：BLE 设备平时广播（可携带自定义数据，即 Beacon），Central 扫描后再发起连接——不连不上、先广播，这与 Wi-Fi「先关联再通信」完全不同。
  4. 为什么省电：深度休眠 + 快速建立连接，只在事件发生时短暂收发；配合 Notify/Indicate 让外设主动推送，避免轮询空耗电。
  5. 定位：手环、传感器、智能家居直连手机的场景；需要跨厂商标准化互操作时选 Zigbee（见 第十六章：Zigbee：基于 802.15.4 的 Mesh 组网），配对加速可用 NFC 递密钥。

一、BLE 角色

角色 说明
Central 发起连接，如手机、网关
Peripheral 广播、被连接，如手环、温湿度计
Broadcaster / Observer 仅广播/扫描（Beacon）

连接后通过 ATT/GATT 读写特征值（Characteristic）。

广播与扫描的过程

要点：

  • 广播信道只有 3 个（37/38/39），避开 Wi-Fi 拥堵的 1/6/11 信道间隙，降低干扰碰撞。
  • 广播包 31 字节（BLE 4.x），5.0 起扩展广播可达 255 字节（在数据信道二次加载）。
  • Beacon（iBeacon/Eddystone）：永远只广播不连接，靠 MAC + 自定义字段做定位与触发，是 Broadcaster 角色的典型应用。
  • 连接间隔是功耗旋钮：间隔短延迟低但耗电，传感器常设 500 ms~1 s。

二、GATT 模型

  • UUID：16 位标准 UUID 或 128 位自定义。
  • Notify/Indicate：外设主动推送数据，省 polling 功耗。

ATT 属性协议的本质

GATT 是 ATT（Attribute Protocol） 的上层组织。ATT 把一切都抽象为属性：

  • Handle：属性的地址，客户端按 handle 读写。
  • Permissions：读/写/加密/认证要求，越权访问返回错误码。
  • 服务发现：客户端连接后先遍历属性表，找到各 Service/Characteristic 的 handle——这就是「连接后先转圈一秒」在做的事。

Characteristic 的三件套

以自定义温度特征为例：

组成 UUID 类型 内容
Declaration 0x2803 声明：这是个特征，属性在下一个 handle，支持 Read+Notify
Value 自定义 128 位 真正的数据（如 4 字节 float 温度）
CCCD 0x2902 Client Characteristic Configuration：客户端写它开关 Notify

CCCD 是 Notify 的开关：Central 写 0x0001 到 CCCD 后，Peripheral 才有权推送——忘写 CCCD 是「为什么我的 Notify 不工作」的头号原因。

Notify 与 Indicate 的差别

Notify Indicate
应用层确认 无 有（客户端回 Confirmation）
可靠性 尽力投递 应用层可靠
速度 快，可连续发 一次一个，等确认
适用 高频传感器流 关键状态变化

三、配对与安全

  • Just Works / Passkey / OOB 等配对模式。
  • LE Secure Connections（ECDH）防中间人。
  • 与 第十四章：NFC 近场通信：工作模式与 NDEF tap-to-pair：NFC 交换临时信息辅助 BLE 配对。

密钥与绑定

  1. 配对（Pairing）：协商临时密钥 TK，派生短期密钥 STK/LTK 加密链路。
  2. 绑定（Bonding）：保存 LTK，下次重连免配对。
  3. 地址解析：设备用 Resolvable Private Address（RPA） 防追踪，绑定过的对端用 IRK 反推真实身份。
  4. 实务建议：传感器类 Just Works + 绑定够用；支付/门锁类必须 Passkey 或 OOB，且特征值权限要求加密链路。

发表于 2026-05-01 更新于 2026-10-25 分类于 嵌入式 本文字数： 4k 阅读时长 ≈ 4 分钟

第十二章：LoRaWAN：远距离低功耗星型组网

概念基础

  1. LoRaWAN 是构建在 LoRa 扩频射频之上的开放网络协议：终端节点通过网关接入 Network Server，典型覆盖公里级，专为电池供电、小数据量、上报为主的物联网场景设计。
  2. LoRa ≠ LoRaWAN：LoRa 是 Semtech 的物理层调制技术（Chirp Spread Spectrum，灵敏度高、抗干扰强）；LoRaWAN 是其上的 MAC 层协议（入网激活、速率自适应、双向调度）——「电台」与「通信规约」的关系。
  3. 星型拓扑换功耗：节点只与网关直连一跳，不做 mesh 路由转发，省去中继耗电，换来数年电池寿命；覆盖靠增加网关与 ADR 速率自适应来平衡。
  4. 速率换距离：SF（扩频因子）越大，速率越低、传得越远，网络侧按链路质量动态调整，本质是「速率-距离-容量」的三角权衡。
  5. 定位：智能抄表、资产追踪、农业监测等公里级、极低速率场景；高吞吐走 Wi-Fi/以太网 + MQTT/HTTP，局域 mesh 则选 Zigbee / 蓝牙 Mesh。

先看整体架构：

星型拓扑架构



flowchart TB
  Dev1[终端节点] --> GW[LoRa 网关]
  Dev2[终端节点] --> GW
  GW --> NS[Network Server]
  NS --> App[应用服务器]

一、架构

  • Gateway：只做射频转发，不解密应用 payload（取决于模式）。
  • ADR（Adaptive Data Rate）：网络侧调节 SF/功率平衡距离与容量。

LoRa 物理层速览

  • Chirp Spread Spectrum：信号在带宽内线性扫频，扩频带来处理增益，接收灵敏度低至 -137 dBm（比 FSK 好 20 dB 以上）。
  • SF7~SF12：SF 每加 1，速率减半、距离增加、空中时间翻倍。
  • 正交性：不同 SF 的信号可在同频同时存在互不干扰，网关 8 通道并行接收。
  • 带宽：常用 125 kHz（EU868/CN470）、500 kHz（US915 上行）。

各角色职责

角色 职责
End Device 采集数据、按 Class 调度收发、维护会话密钥
Gateway 纯射频中继：把 RF 帧加元数据（RSSI/SNR/时间戳）转 IP，不做协议裁决
Network Server 去重（多网关收到同一帧）、ADR 控制、帧计数校验、路由到应用
Application Server 解密 AppSKey payload、业务逻辑

「网关笨、服务器聪明」让网关可以做到几十美元级，是 LoRaWAN 部署成本低的关键。

二、区域参数

区域 典型频段
EU868 863–870 MHz
US915 902–928 MHz
CN470 470–510 MHz

需遵守当地无线电法规；模块需合规认证。

区域差异不止是频率：

  • EU868：占空比限制（Duty Cycle，常见子带 1% 或 0.1%）——设备每小时最多发 36 秒，直接限制上报频率。
  • US915：频率跳变（FHSS），上行 64+8 信道；无占空比但有 400 ms 驻留时间限制，限制单包大小。
  • CN470：96 上行信道，国内合规主流选择。
  • 选型红线：硬件模块、固件 region 参数、网络服务器频段计划三者必须一致，否则入网即失败。

三、设备 Class

Class 下行窗口 功耗
A 仅上行后两个短窗口 最低，传感器常用
B 附加信标窗口 中
C 几乎常开接收 高，供电设备

Class A 时序（必须掌握）

  • 节点发完才听：RX1 用上行的同信道/速率（或由网络指定），RX2 用固定信道与 SF12（EU868 为 869.525 MHz）。
  • 两个窗口都没收到 → 回去睡觉，下行丢失。下行永远是「发上行时的副产品」，这就是 Class A 省电的本质。
  • 服务器想主动下发？只能等节点下一次上行——做「远程控制路灯」这类需求要么接受分钟级延迟，要么上 Class C。
  • Class B 增加网关周期广播的 Beacon，节点按预约时隙额外开窗；Class C 常供电、常开窗，下行近乎实时（电表、路灯控制器）。

四、MAC 帧结构（概念）

字段 说明
MHDR 消息类型（Join-Request / Confirmed-Up / Unconfirmed-Up 等）
DevAddr 4 字节设备地址，入网后分配
FCnt 帧计数器，防重放；ABP 模式下掉电归零会导致服务器拒收
FOpts 捎带 MAC 命令（如 ADR 应答）
FPort 0 = 纯 MAC 命令；1~223 = 应用端口（应用层多路复用）
MIC 4 字节消息完整性码，NwkSKey 计算

Confirmed 消息要求对端回 ACK，未收到则重发（默认 8 次）——但占空比宝贵，上行通常用 Unconfirmed，靠周期冗余保证到达率。

五、安全

  • Join：OTAA（Over-The-Air Activation，推荐）或 ABP（预置密钥）。
  • AES-128：NwkSKey、AppSKey 分层加密与完整性。
  • 应用层仍可封装 第十一章：CoAP：REST over UDP 的物联网应用协议 或自定义二进制。

OTAA 入网流程

  • 根密钥 AppKey/NwkKey 只出厂烧录一次，永不上空口传输；OTAA 每次入网派生新会话密钥，设备换网络也安全。
  • ABP 直接预置 DevAddr + 两把会话密钥，省一步握手，但密钥固定、FCnt 复位问题多，仅建议实验室用。
  • 双层加密的边界：NwkSKey 管到 Network Server 的完整性，AppSKey 端到端加密到应用服务器——网关和 NS 看不到应用数据明文（诚实网关模型）。

调试手段：

  • 网关日志：ChirpStack/TTN 控制台可看每帧的 SF、RSSI、SNR、FCnt，入网失败先在这里看请求到没到。

需求 选择

链路预算与部署规划

  • 链路预算：发射 14 dBm + 灵敏度 -137 dBm ≈ 151 dB，是 LoRa 公里级覆盖的物理基础；城市环境实际按 110130 dB 可用预算估算（穿墙损耗 1020 dB/堵）。
  • 网关选址：越高越好、天线视距覆盖；室内网关穿楼板后 SF 普遍抬到 10+，容量急剧下降——宁可多加网关，不要全靠提高 SF。
  • 容量估算：单网关理论数千节点，但受占空比与 SF 分布制约；大量 SF11/12 节点会挤占空中时间，规划时让节点尽量落在 SF7~9。
  • 天线：频段匹配、驻波比 < 2；节点小天线效率低是常态，预算里要留损耗余量。

生态与相关技术

  • 私有 LoRa：只用 LoRa 物理层做点对点/私有星型，不走 LoRaWAN 协议——园区自组网常见，省去 NS 部署但失去漫游与生态。
  • Amazon Sidewalk / Helium：基于 LoRa 的公共网络变体，商业模式各异。
  • LR-FHSS：LoRaWAN 新增的跳频模式，为海量卫星/密集场景扩容。
  • 中继（Relay）：LoRaWAN 1.0.4 引入的电池中继节点，补盲区覆盖。
  • 与 NB-IoT 对比：NB 走运营商基站、SIM 计费、免自建网；LoRaWAN 自建网络、无月租——「买服务 vs 买设备」的路线之争。

第十一章：CoAP：REST over UDP 的物联网应用协议

概念基础

  1. CoAP（Constrained Application Protocol，受限应用协议）是给单片机、低带宽网络用的应用层协议：把 Web 的 REST 模型（GET / PUT / POST / DELETE 操作资源）搬到 UDP 之上。
  2. 为什么轻量：报文头仅 4 字节起（对比 HTTP 动辄数百字节），二进制紧凑编码，默认端口 5683 / 5684（DTLS），RAM/Flash 占用极小，可直接跑在 6LoWPAN 等受限链路上。
  3. 请求/响应 + 订阅两种模式：既支持类 HTTP 的请求-响应，又通过 Observe（RFC 7641） 让服务器在资源变化时主动推送 NOTIFY，传感器上报无需反复轮询。
  4. 可靠性自选：UDP 本身不可靠，CoAP 用 CON / NON / ACK / RST 消息类型自己决定要不要确认重传——把「要不要可靠」交给应用按需选择。
  5. 定位：资源型设备（一台设备就是一组可读写的资源）的首选；海量消息汇聚与发布订阅则更适合 Broker 型的 MQTT，二者在同一系统里常互补出现。

第十章：LIN 总线：单主多从与调度表

概念基础

  1. LIN（Local Interconnect Network，局部互联网络）是低成本的单主多从串行总线：一根总线挂一个 Master 与若干 Slave，常见于车窗、座椅、雨刮等车身电子。
  2. 为什么便宜：基于普通 UART 硬件即可实现，物理层常用单线、12V 电平，收发器（如 TJA1021）远比 CAN 便宜，从节点甚至可用廉价 8 位 MCU——它就是 CAN 的「经济版补充」。
  3. 无仲裁、靠调度：与 CAN 的竞争仲裁不同，LIN 由 Master 固定调度：Master 发 Header（含 PID），对应 Slave 填 Response，时序确定、天然无冲突。
  4. 帧结构简单：Break + Sync(0x55) + PID + Data(1~8) + Checksum，速率约 20 kbps，只适合非安全、低带宽场景。
  5. 定位：动力底盘走 CAN、车身舒适系统走 LIN，网关 ECU 常同时挂两种总线；它的「单主轮询」思想与工业里的 Modbus 主从也一脉相承。

一、角色

  • Master：通常由 Body ECU 担任，发送 Header（含 PID）。
  • Slave：响应 Data 或发布自身数据；无仲裁，时隙由 Master 调度。

更精确地说，Master 节点内部还分两个任务：

  • Master Task：产生帧头（Break/Sync/PID），决定「现在轮到哪个 ID」。
  • Slave Task：Master 自己也挂一个从任务，用于响应「主节点自己需要发布的帧」（如整车状态）。

总线上只有 Master Task 能发起通信——任何时刻只有一个调度者，这就是「确定性」的来源，也是 LIN 不适合对等网络的原因。

二、帧结构（简化）

  • Break：显性低电平较长，同步从机。
  • PID：含 6 位 ID + 2 位奇偶。
  • Checksum：Classic 或 Enhanced（LIN 2.x）。

逐字段剖析

字段 细节
Break 至少 13 位显性低电平 + 间隔符；UART 无法产生普通帧里这么长的低电平，从机据此识别「新的一帧来了」
Sync 0x55 位型 01010101，从机用它测量主时钟并自动校准波特率（自同步），省去晶振——便宜的底气之一
PID 低 6 位 Frame ID（0~63，0x3C/0x3F 等保留）；P0 = ID0⊕ID1⊕ID2⊕ID4，P1 = ¬(ID1⊕ID3⊕ID4⊕ID5) 两位奇偶校验
Data 1/2/4/8 字节，长度由 ID 约定
Checksum Classic 只对 Data 求和取反（进位回卷）；Enhanced（LIN 2.x）把 PID 也纳入，诊断帧仍用 Classic

帧时序与间隔

Header 与 Response 之间有响应间隔，帧与帧之间有帧间隔（均为若干位时间），由调度表定义。从机必须在规定时间内响应，否则主站记为无响应错误。

三、调度表（Schedule Table）

Master 按固定周期发送各 Frame ID，保证确定性延迟；配置在 LDF（LIN Description File）中，工具链生成驱动代码。

调度表实例

  • 周期槽：每个帧分配固定时隙，最坏延迟可计算——这是 LIN 做「车窗防夹」类软实时功能的依据。
  • LDF 文件：描述节点、信号、帧、调度表、波特率，上游工具（如 Vector LINworks）生成 C 驱动骨架，主从双方共用同一份定义保证一致。
  • 事件触发帧：多个从机共用一时隙，仅在数据变化时抢答；冲突时主站回退到逐一轮询（Collision Resolving Table）。

硬件要点：

  • 电平：LIN 线在 0V（显性）与 VBAT（隐性，约 12V）间摆动；Master 端典型 1kΩ 上拉到 VBAT，Slave 端 30kΩ——兼作终端与漏电保护。
  • 收发器职责：把 MCU 的 3.3V UART 电平与 12V LIN 电平互换，并做短路/过温保护。
  • 休眠与唤醒：总线空闲超时后进入休眠（VBAT 侧微安级电流）；任一节点拉低总线 ≥250µs 即唤醒全网。

  • 0x3C（Master Request）/ 0x3D（Slave Response）：保留的诊断帧 ID，载荷按 ISO 15765 类诊断服务组织，用于读故障码、刷写配置。

  • 配置服务：读写从机的供应商 ID、功能 ID、版本号，OTA 与售后依赖这套机制。

第九章：CAN 总线：帧结构、多主仲裁与 CAN FD

概念基础

  1. CAN（Controller Area Network，控制器局域网）是 Bosch 为汽车电子设计的多主串行总线：所有 ECU 节点挂在一对差分线（CAN_H / CAN_L）上，以广播帧通信，各节点按 ID 自行过滤收帧。
  2. 为什么抗干扰：差分传输让共模噪声相互抵消，配合总线两端的 120Ω 终端电阻抑制信号反射，适合发动机舱等电磁环境恶劣的场景——这与单端电平的 RS232 是本质差别。
  3. 多主无损仲裁：总线空闲时任意节点都可发送，逐 bit 仲裁中发显性 0 的胜出、ID 越小优先级越高，败者自动退为接收方，既不丢帧也不需要中心主站。
  4. 硬件级可靠性：帧尾 CRC + ACK 硬件检错与确认，出错自动重发；故障节点经错误计数进入 bus-off 主动离线，不会拖垮整条总线。
  5. 定位：汽车动力、底盘、网关等实时、安全相关场景的主力总线，速率 125 kbps ~ 1 Mbps；CAN FD 把数据段扩到 64 字节并提升数据段速率；车身低成本传感器则交给 LIN（见 第十章：LIN 总线：单主多从与调度表）。

字段 说明

数据帧逐段剖析（标准帧）

  • SOF：1 个显性位，标志帧开始，所有节点据此硬同步。
  • 仲裁段：标准帧 11 位 ID；扩展帧拆为 11 位基本 ID + SRR + IDE + 18 位扩展 ID。
  • IDE 位：区分标准（显性）与扩展（隐性）帧。
  • ACK 槽：发送方发隐性，任一正确接收的节点拉显性——发送方只知道「至少有人收到」，不知道是谁。
  • 位填充（Bit Stuffing）：连续 5 个相同电平后强制插入反相位，保证时钟同步；计算帧长时要计入。

远程帧与错误帧

  • 远程帧（RTR=1）：请求对方发送某个 ID 的数据帧，无数据段；现代设计多用周期发送替代。
  • 错误帧：任一节点检出错误立即发送 6 个显性位「打破」当前帧，所有节点丢弃该帧，发送方稍后自动重发。
  • 过载帧：接收方来不及处理时请求延时，极少使用。

二、多主仲裁

总线空闲时多个节点可同时发送；ID 仲裁时逐 bit 比较，发显性 0 的胜出，失败者自动退为接收方，无中心主站。

第八章：SPI

概念基础

  1. SPI（Serial Peripheral Interface）是 Motorola 提出的四线同步全双工总线：SCLK / MOSI / MISO / CS，板级高速外设互联的主力。
  2. 主驱时钟：主站产生 SCLK，数据按约定边沿采样；主从的 CPOL/CPHA 模式必须一致（Mode 0~3），这是 SPI 调试最常见的坑。
  3. 片选寻址：没有地址概念，每个从机一根独立 CS 线，多占一根线换取高速度；MISO 未选中时需保持三态。
  4. 为什么快：无地址开销、全双工、时钟可达几十 MHz，Flash、SD 卡、TFT 屏等高带宽外设首选。
  5. 取舍：线数多（每从机 +1 CS）、只适合短 PCB 走线；长距离/多机改用 RS485，少线低速场景可用 I2C，异步调试打印仍用 UART。

命名别名注意：部分芯片手册用 SDI/SDO（视角是从机）或 DIN/DOUT，接线时认准数据流向而非名字。COPI/POCI 是新推荐的术语（Controller/Peripheral），含义与 MOSI/MISO 相同。

全双工的真相

SPI 没有「读」或「写」的概念——每个时钟沿两个方向同时移一位。读 Flash 数据时主机也要持续发 dummy 字节（通常 0x00 或 0xFF）来产生时钟；写数据时 MISO 上同样有位移入，只是被忽略。理解这一点才能看懂 HAL_SPI_TransmitReceive 为什么收发共用一个长度。

二、CPOL / CPHA（模式 0~3）

  • CPOL：空闲时 SCLK 电平（0=低，1=高）。
  • CPHA：第几个边沿采样（0=第一边沿，1=第二边沿）。

主从 模式必须一致（数据手册会写 Mode 0 等）。

四种模式速查

模式 CPOL CPHA 空闲电平 采样边沿
Mode 0 0 0 低 上升沿
Mode 1 0 1 低 下降沿
Mode 2 1 0 高 下降沿
Mode 3 1 1 高 上升沿

Mode 0 与 Mode 3 最常见（采样边沿都是上升沿，仅空闲电平不同）。模式不匹配的症状：读到的数据整体移位、首位丢失或完全错乱——调试新器件第一步就是核对模式。

其他关键参数

  • 位序：MSB first 为主流，少数器件（如某些 LCD 控制器）要求 LSB first。
  • 时钟极性外的速度参数：波特率分频、数据位宽（8/16 bit）、NSS 软/硬管理。
  • 建立/保持时间：高速时查从机手册的 t_setup/t_hold，走线长或负载大时需降速。

三、实战：读写 SPI Flash（W25Qxx）

要点：CS 包住完整事务，命令+地址+数据在一次 CS 低电平内完成；事务中途拉高 CS 会被从机视为中止。

四、多从机

  • 独立 CS：每个从机一根 CS，MOSI/MISO/SCLK 共享（MISO 需三态，未选中不高驱）。
  • Daisy Chain：如部分 Shift Register、LED 驱动，数据串行穿过多芯片。

多从机工程注意：

  1. CS 互斥：任何时刻只有一个 CS 有效；出错症状是两从机 MISO 对推、数据全乱甚至烧 IO。
  2. 三态问题：个别廉价器件 MISO 在 CS 高时不释放总线，需要串电阻或外加三态缓冲。
  3. 不同模式共存：总线上挂 Mode 0 和 Mode 3 的器件时，每次切换从机要重新配置 SPI 外设模式。
  4. Daisy Chain 场景：多片 ADC/移位寄存器串联，CS 共用，主机一次移位穿过所有芯片——省 CS 线，但所有芯片必须同模式、时序兼容。

五、典型应用

  • Flash（W25Q）、SD 卡（SPI 模式）、ADC/DAC、TFT 屏、RF 模块（NRF24L01）。
  • 速率常 MHz~ tens of MHz，短 PCB 走线；长距离不如 第六章：RS485。

高速布线与变体：

  • 走线要求：超过 20 MHz 后 SCLK 与数据线等长、远离干扰源；SD 卡 SPI 模式官方建议 ≤ 25 MHz。
  • Dual/Quad SPI：Flash 读加速变体，用 2/4 根数据线并行传输（IO0~IO3），W25Q 的 QSPI 模式读带宽可翻 4 倍。
  • 3 线半双工：部分器件省掉 MISO，单数据线双向，需主机切换引脚方向。

六、调试与抓包

  • 逻辑分析仪 SPI 解码：sigrok/PulseView 选 SPI 协议、配置模式与位序，直接还原命令流——读 Flash ID 不对时先看波形有没有发出去。
  • 示波器看点：SCLK 空闲电平对不对（CPOL）、数据在采样边沿是否稳定、CS 低电平是否覆盖完整事务。
  • 软件模拟 SPI（bit-bang）：排查硬件外设配置问题时，用 GPIO 慢速模拟一遍协议，能通说明是外设配置问题，不通则检查接线与器件。

第七章：I2C

概念基础

  1. I2C（Inter-Integrated Circuit）是 Philips 发明的两线同步总线：SCL 时钟 + SDA 数据，是板级互联传感器/存储器等外设的事实标准。
  2. 地址寻址多从：每个从设备有 7 位地址（0x00~0x7F），主设备以地址帧寻址——两根线即可挂多个器件，扩展外设几乎不加线。
  3. 开漏 + 上拉：SDA/SCL 均为开漏输出加上拉电阻，天然支持多主仲裁与时钟同步，也决定了速率上限（100k/400k/1M/3.4M）。
  4. 协议机制清晰：START/STOP 条件界定传输，逐字节 ACK/NACK 确认；读操作用重复 START 切换方向。
  5. 取舍：线最少、成本低，EEPROM/RTC/IMU/OLED 全支持；但速率不如 SPI，上拉取值需按总线电容与速率权衡。

一、信号与起始/停止

  • 空闲：SDA、SCL 均为高（靠上拉电阻）。
  • START：SCL 高时 SDA 下降沿。
  • STOP：SCL 高时 SDA 上升沿。
  • 数据位：SCL 低时 SDA 变化，SCL 高时采样。

一次完整写传输的波形语义

几个容易忽略的细节：

  • ACK 由接收方发出：第 9 个时钟，发送方释放 SDA（保持高），接收方拉低表示 ACK。
  • NACK 不一定是错误：主设备读最后一个字节时故意回 NACK，告诉从机「别再发了」，然后发 STOP。
  • 时钟延展（Clock Stretching）：从机来不及处理时可在字节间把 SCL 拉低不放，主机必须等待——主机代码若不支持检测 SCL 实际电平，与慢速从机通信会莫名失败。
  • 开漏的意义：任何设备都能拉低总线，没有人能推高——这是多主仲裁与 ACK 机制的电气基础。

第六章：RS485

概念基础

  1. RS485（TIA/EIA-485） 是差分电气标准：用 A/B 两线电压差表示信号，抗共模干扰强、可达上千米，是工业现场最常用的物理层。
  2. 总线型多机：一条双绞线手拉手（daisy-chain）挂多个节点，配合地址协议实现多机组网；总线两端各接 120Ω 终端电阻。
  3. 半双工：两线制同一时刻只能一个方向发送，收发器需 DE/RE 引脚切换方向。
  4. 只管电气不管语义：RS485 只解决「电信号怎么传」，上层要跑 Modbus RTU 等主从协议才能完成有效通信。
  5. 与 UART 的关系：MCU 的 UART 产生字节流，经 MAX485/SN65HVD 收发器转成差分信号——UART 管逻辑、485 管物理。

  • 半双工：同一时刻只能一个方向发送；需 DE/RE 引脚控制收发器方向。

差分电平怎么判定

接收端只看压差，不参考绝对地——所以电机启停、地电位浮动产生的共模噪声被天然抵消。这是 485 能在车间拉几百米的根本原因。

三、与 Modbus RTU

第一章：Modbus RTU 在 RS485 上最常见：主站轮询、从站地址 1~247、CRC16 帧尾。
与 第三章：Modbus ASCII 比，RTU 更紧凑、工业现场更常用。

RS485 本身不限制上层协议，现场还能见到：

  • Modbus RTU：绝对主流。
  • Profibus DP：西门子系 PLC 现场总线，同样跑在 485 电气层上。
  • 自定义主从协议：小型设备集联常自定义「地址 + 长度 + 数据 + 校验」帧。
  • DMX512：舞台灯光控制，也是 485 物理层。

五、布线注意

  • 双绞线、屏蔽层单端接地（现场依规范）。
  • 终端电阻 120Ω 仅在总线两端；中间节点不加。
  • GND 参考：虽为差分，仍建议可靠参考地，避免共模超范围。
  • ESD 与浪涌：户外/电机旁加保护器件。

终端电阻与偏置电阻

  • 为什么 120Ω：匹配双绞线特征阻抗，吸收线末反射。总线两端各一个，等效 60Ω 负载——这也是驱动器输出能力按 60Ω 设计的原因。
  • 失效偏置（Fail-safe bias）：总线空闲无驱动时，A/B 压差接近 0，接收端输出不确定，可能被误判为起始位而产生幽灵字节。解法：总线上（通常主站侧）加一对上拉/下拉偏置电阻（如 560Ω~1kΩ），强制空闲时 A>B；现代收发器（如 SN65HVD 系列）内置失效保护，输出固定为高，可省掉外部偏置。
  • 中间节点 Stub 越短越好：分支引线超过几十厘米会形成反射点；星型拓扑是 485 大忌，必须用集线器。

六、调试与排查

  • USB-485 适配器搭车监听：旁路挂在总线上只收不发，记录主从全部流量。
  • 示波器看差分：探头分别接 A、B 用 MATH 相减，或差分探头直接看；重点看摆幅、反射台阶、共模漂移。
  • 逐节点排除法：总线异常时按手拉手顺序逐个断电，定位拉垮总线的故障节点（收发器击穿会把整条总线钳死）。
  • 万用表静态检查：断电测 A-B 间电阻 ≈60Ω；测各节点 A/B 对地电压，异常节点常有明显偏移。

七、隔离与失效保护设计

工业级节点的常见加固手段：

  • 隔离收发器：ADM2483、ISOW7841 等把 UART 侧与总线侧电气隔离（磁耦/电容隔离 + 隔离电源），阻断地环流与高压串入，变频器、电力柜场景几乎必选。
  • TVS + 自恢复保险丝：A/B 线上双向 TVS（SMBJ12CA 类）吸收浪涌，PPTC 限制持续故障电流。
  • 共模电感：端口侧串共模扼流圈抑制高频干扰，常与 TVS 组成 EMC 三件套。
  • 失效保护收发器：SN65HVD 系列等在总线开路/短路/空闲时输出固定逻辑，替代外部偏置电阻。
  • 上电静默：MCU 复位期间 DE 引脚电平不确定，可能误发数据污染总线——DE 加上下拉电阻固定初态，或选上电三态的收发器。

八、485 集线器与拓扑扩展

当现场布线确实无法手拉手（多楼层、多方向出线），**RS485 集线器（Hub）**是合规解法：每个端口是独立隔离的收发段，主站侧一条线接入，下行分出多条总线，同时实现：

  • 星型布线的物理便利 + 每段独立的终端电阻配置；
  • 故障段自动隔离，不影响其他分支；
  • 级联延长距离，突破单段 1200 m 限制。

注意 Hub 只做电气转发，地址冲突仍需靠上层协议（如 Modbus 地址规划）解决；各级延迟叠加也要算进主站超时时间。

第五章：RS232

概念基础

  1. RS232 是 EIA 定义的串行物理层标准，规定电气电平、信号线与连接器（DB9）——「PC 老式 COM 口」背后的标准。
  2. 负逻辑电平：逻辑 1 是负电压（-5V~-15V），逻辑 0 是正电压（+5V~+15V），与 MCU 的 TTL UART（0/3.3V）完全不同，必须经 MAX232 等芯片做电平转换。
  3. 点对点、单端：一收一发加共地，抗干扰弱、典型距离 < 15m，速率与距离反相关。
  4. 为什么仍要学：工业仪器、老式 PLC、条码枪仍大量保留 DB9 口；PC 侧 USB 转 RS232 线依然是常用调试手段。
  5. 与 UART 的关系：UART 是控制器逻辑，RS232 是物理层电气标准；其上仍可跑 Modbus RTU 或自定义帧协议。

一、电平与特点

  • 逻辑 1：负电压（如 -5V ~ -15V）
  • 逻辑 0：正电压（如 +5V ~ +15V）
  • 单端：抗干扰弱于 第六章：RS485 差分；距离通常 < 15m（与波特率反相关）。
  • 点对点：多机需额外切换，不像 RS485 总线型。

MCU 侧为 TTL 第四章：UART（0/3.3V），需 MAX232、SP3232 等芯片做电平转换。

电平门限细节

区域 发送端输出 接收端判定

不定区 — -3V ~ +3V
逻辑 0（Space） +5V ~ +15V +3V ~ +15V

±3V 之间是接收端的「不确定区」，给了线路衰减的裕量。注意两个容易混淆的点：

  • 空闲状态是逻辑 1 = 负电压，所以量到 -9V 左右说明链路正常待机，不是故障。
  • RS232 与 TTL 不仅电压不同，极性也相反（负逻辑 vs 正逻辑），MAX232 同时完成「升压」与「反相」两件事。

二、最小三线连接

交叉连接 TX/RX；不要把 RS232 口直接接 MCU UART 引脚。

DB9 引脚定义（DTE，PC 侧）

引脚 信号 方向 说明

3 TXD 输出 发送数据
5 GND — 信号地
7 RTS 输出 请求发送
8 CTS 输入 允许发送
4 DTR 输出 数据终端就绪

DTE（数据终端，如 PC）与 DCE（数据设备，如 Modem）引脚定义相反，因此 DTE↔DCE 用直通线，两台 DTE 互连用交叉线（Null Modem）——买线时分清「直连串口线」和「交叉串口线」，接错表现为完全无数据。

三、流控（可选）

信号 作用
RTS/CTS 硬件流控，防缓冲区溢出
DTR/DSR 设备就绪（Modem 时代遗留）
软件流控 XON/XOFF 字符

嵌入式调试常 115200 8N1 无流控。

流控什么时候需要：

  • 硬件流控 RTS/CTS：接收方缓冲区将满时拉低 CTS（对端视角），发送方暂停。高速、大数据量、双方处理速度不匹配时启用。
  • 软件流控 XON/XOFF：接收方发 0x13（XOFF）要求停发、0x11（XON）恢复。只占用数据线，但二进制数据中若恰好出现 0x11/0x13 会被误吞，不适合透传任意二进制。
  • 多数现代场景：处理速度足够 → 直接无流控，配大缓冲区 + DMA 更省心。

四、速率与距离的关系

RS232 标准限定负载电容 ≤ 2500 pF，普通电缆每米约 40~150 pF，由此决定距离上限：

波特率 经验最大距离
9600 ~15 m（标准上限）
19200 ~15 m（需低电容电缆）
115200 2~3 m 内较稳妥

超出范围的表现不是「完全不通」，而是误码率上升、偶发乱码。要长距离：换 第六章：RS485 或加光电隔离中继。

五、应用场景

  • 工业仪器、老式 PLC、条码枪 DB9 口。
  • USB 转 RS232 dongle 在 PC 上模拟 COM 口。
  • 长距离、多机、抗干扰场景优先 RS485 或 以太网（第二章：Modbus TCP）。

协议层仍可能是 第一章：Modbus RTU 或自定义 ASCII 帧。

调试技巧

  • 环回测试：短接 DB9 的 2、3 脚，终端敲键应回显——30 秒确认串口线和驱动没问题。
  • 量电平：万用表测 TXD 对 GND，空闲应为 -5V 以下；若是 0V/+3.3V，说明量到的是 TTL 侧而非 RS232 侧。
  • 示波器看摆幅：健康 RS232 信号摆幅 ±9V 以上；只有 ±5V 的边缘设备在长线缆下容易误判。
  • 共地干扰：两台设备由不同插座供电时，地电位差会叠加在单端信号上——这是 RS232 在车间现场误码的头号原因，必要时上光电隔离 RS232 隔离器。

六、隔离与中继

车间现场地电位差与浪涌是 RS232 的两大杀手，工程解法：

  • 光电隔离器：串接在链路中的 RS232 隔离器（内部光耦 + DC/DC 隔离电源），隔离耐压常见 2500Vrms，专治地环流与浪涌。
  • RS232↔RS485 转换器：不换协议只换物理层，距离立刻从 15 m 变 1200 m，是存量设备延寿的便宜方案。
  • 串口服务器：RS232 转以太网，老仪器直接接入局域网，上位机用虚拟 COM 或原始 TCP socket 访问。
  • 浪涌保护：户外进线加 TVS；雷击多发区光电隔离与 TVS 并用。

七、历史坐标

RS232 诞生于 1962 年（电传打字机与 Modem 互联），比大多数读者年龄都大；它的握手信号（DTR/DSR/RI）全是电话 Modem 时代的遗物。理解这些信号为什么存在，比背引脚定义更有价值——今天嵌入式常用的「三线最小连接」就是把 Modem 语义全部裁剪后的结果。它的思想（异步帧、流控、DTE/DCE 角色）也完整遗传给了后来的 USB CDC 与各种串口透传方案。

顺带一提连接器变迁：早期还有 DB25（完整 25 针定义），PC 时代收缩为 DB9，今天设备上更多是 3.5mm 耳机座、RJ45 走 RS232 电平等「伪装」形态——思科网络设备的 console 线就是 RJ45 承载 RS232 的著名例子。遇到非标接口先量电平再接线，是比查线序更保险的第一步。

一句话记忆：422 是「差分版 232」（单向广播、全双工），485 是「总线版 422」（多机、半双工）。三者电平互不兼容，互接必须用对应收发器或转换器，不能靠转接头混线。

工程现场还有一个隐蔽场景：不少设备的「RJ45 串口」内部其实是 RS422 电平而非 RS232，万用表量不到负电压时不要想当然——查设备手册的电气规格章节，确认是 232/422/485 哪一种，再决定转换方案。

第四章：UART

概念基础

  1. UART（通用异步收发器）是异步串行通信控制器：只用 TX/RX 两根信号线加共地，不传时钟，收发双方按约定的波特率各自采样。
  2. 异步帧：起始位(0) + 数据位(通常 8) + 可选校验位 + 停止位(1)；空闲为高电平，起始位拉低完成一次同步，数据 LSB 先发。
  3. 为什么无处不在：实现极简、调试直观，日志打印、AT 指令、GPS NMEA、Bootloader 都走 UART，是嵌入式最基础的调试与互联手段。
  4. 只是逻辑层：UART 引脚是 TTL 电平（0/3.3V），接 PC 老串口或工业总线需 MAX232（RS232）、MAX485（RS485） 等收发器转换物理层。
  5. 点对点：无从机地址、无仲裁，多机组网要靠上层协议或改用总线型物理层。

一、异步帧结构

  • 空闲：线路高电平。
  • 起始位：拉低，通知接收方开始采样。
  • LSB 先发：数据位从低位到高位。
  • 校验：None / Odd / Even（可选）。
  • 停止位：1 或 2 位高电平，恢复空闲。

逐位时序（以发送 0x55 为例，8N1）

接收方的采样策略：

  • 检测到下降沿后，等待 0.5 个位时间，在起始位中央采样确认仍为低（防毛刺误判）。
  • 之后每隔 1 个位时间采样一次，硬件 UART 通常每位过采样 16 次取中间值，容忍一定时钟误差。
  • 采样到停止位不是高电平 → 报帧错误（Framing Error），常见于波特率不匹配或线路干扰。

二、波特率

常见：9600、115200、921600。收发双方波特率必须一致（误差通常 < 2%）。

波特率误差从哪来

  • 分频取整误差：72 MHz 时钟要 115200，USARTDIV = 39.0625，取整后实际 115107，误差 -0.08%，可接受；但某些时钟/波特率组合误差可达 1% 以上。
  • 内部 RC 振荡器温漂：HSI 典型 ±1%，高低温下更差——工业级产品串口建议用外部晶振。
  • 双方误差叠加：两端各偏 1%，叠加后逼近 2% 极限，边界工况开始丢字节。

经验法则：收发总误差 < 2% 可靠工作，< 1% 安心；超了就会出现「大部分正常、偶发乱码」这种最难排查的症状。

三、收发方式：轮询 / 中断 / DMA

选型建议：调试打印用阻塞或 DMA；AT 指令逐字节中断；GPS/数传等连续流式数据用 DMA + Idle 中断，配合环形缓冲区几乎不丢字节。

层次 说明
TTL UART MCU 引脚 3.3V/5V，直连 USB-TTL 模块

UART 指控制器逻辑；对外物理层常加 MAX232、MAX485 等芯片。

电平匹配的坑：

  • 3.3V 与 5V 互连：多数 5V 器件把 ≥2.0V 识别为高，3.3V TX → 5V RX 通常可行；反向 5V TX → 3.3V RX 可能损坏 MCU 引脚，除非引脚标注 5V-tolerant，否则要分压或电平转换芯片。
  • USB-TTL 模块输出电压可选（跳线 3.3/5V），接错档是烧引脚的常见原因。
  • 反相问题：个别廉价「RS232 转 TTL」模块输出的是未反相的 RS232 逻辑，接 MCU 全乱码——认准 MAX232 类芯片完成的电平与极性双转换。

调试工具箱

  • 串口助手：Windows 下 SSCOM / XCOM / MobaXterm；跨平台 Tabby、cutecom。
  • 逻辑分析仪：十几块钱的 24 MHz 8 通道 USB 款即可解码 UART 协议，自动标出每字节与帧错误，调波特率问题极快。
  • 示波器：量位宽反推实际波特率（波特率 = 1 / 位时间），识别电平异常、振铃。
  • 环回自测（loopback）：把模块自身 TX、RX 短接，发送应原样收回——快速区分「线缆/对端问题」还是「本端配置问题」。

七、环形缓冲区与帧协议

裸 UART 只给字节流，消息边界要自己造。常见三种帧封装思路：

  1. 定长帧：协议简单但死板。
  2. 长度字段：头 + 长度 + 数据 + 校验，灵活主流。
  3. 转义分隔：如 SLIP（0xC0 结尾，数据中出现则转义），PPP/GPS 类常用。
