区块链 · 元宇宙开发

把区块链变成一个可以”走进去”的空间：Three.js 实时渲染 · WebXR 进入 VR · MetaMask 钱包验票入场 · ERC-721 NFT 画廊 · WebSocket 多玩家。原理成段讲透，附可直接双击打开的单文件 Demo，代码全中文注释。

1. 技术栈分层：从区块链到头显

“元宇宙”不是某一项黑科技，而是一条五层技术栈。理解每一层只解决什么问题，比记住具体框架重要得多：

层 代表技术 解决的问题
① 结算层 L1/L2 Ethereum、Polygon、Base、Arbitrum 资产所有权的确权与转移：门票归谁、NFT 归谁、交易怎么结算；L2（Rollup）把 gas 费和确认时间打下来
② 资产存储层 IPFS + Filecoin、Arweave 3D 模型、贴图、元数据等大文件的去中心化、可寻址、可校验完整性的存储
③ 身份层 DID 钱包地址、ENS、SIWE、did:pkh “你是谁”：一个地址跨应用携带身份、持票凭证与声誉，无需向每个网站注册密码
④ 渲染引擎层 Three.js、Babylon.js、PlayCanvas 场景图管理、PBR 材质、光照、骨骼动画，把资产数据实时算成画面
⑤ 终端层 浏览器 WebXR、Quest、Vision Pro 6DoF 空间追踪、立体显示、手柄/手势输入，让画面变成可以走进去的空间

数据是自下而上流动的：链上结算所有权指针 → 指针指向去中心化存储里的资产 → 地址（DID）证明你有权访问 → 引擎把资产渲染出来 → XR 终端把画面送进双眼。层与层之间靠标准接口拼接（合约 ABI、ipfs:// URI、glTF、WebXR Device API），所以每一层都能替换：把 Ethereum 换成 Polygon、把 Three.js 换成 Babylon，上层应用不必重写。

为什么 3D 模型不直接写进区块链？EVM 的 calldata 按字节收费，一个 5 MB 的 glb 上链成本可能上百美元且毫无必要。正确做法是链上只存一个内容标识符（tokenURI 或内容哈希），字节本身存 IPFS/Arweave，读取后再用哈希校验完整性——所有权在链上，资产的”肉体”在链下。

2. 实时渲染原理速通

场景图（scene graph）：Three.js 的世界是一棵 Object3D 树。每个节点都有自己的位置、旋转、缩放（TRS），引擎先把它们合成一个本地矩阵，再沿父子链逐级相乘得到世界矩阵。移动一个 Group，挂在它下面的所有 Mesh 整体跟随——这就是为什么门要用 Group 做枢轴、画框要用 Group 把”框 + 画”包成整体。

Mesh = Geometry + Material：Geometry 是纯几何数据（顶点位置 position、法线 normal、uv、索引 index），Material 是着色器参数与光照模型。同一份 Geometry 可以被多个 Mesh 复用，区别只在材质。

相机与投影矩阵一句话：视图矩阵把世界坐标搬到相机空间，投影矩阵把视锥体（frustum）压缩到 −1～1 的归一化设备坐标（NDC）；透视投影靠最后的透视除法产生”近大远小”。

WebGL 渲染管线：顶点着色器逐顶点做矩阵变换并输出 varying → 图元装配成三角形 → 光栅化把三角形插值成片元（fragment）→ 片元着色器逐像素计算光照和贴图颜色 → 深度测试、混合后写入帧缓冲。一次 draw call，就是 CPU 向 GPU 提交一次这样的绘制任务；draw call 之间切换材质/纹理的状态切换开销，是 3D 性能的主要敌人之一。

帧循环与 delta time：requestAnimationFrame（Three 中统一为 renderer.setAnimationLoop）在浏览器每次重绘前被调用，形如 位置 += 速度 × delta，其中 delta 是距上一帧的秒数。游戏逻辑为什么必须用时钟而不能用帧数？因为刷新率因设备而异（60 / 90 / 120 / 144 / 240 Hz），写死”每帧前进 0.1”，在 144 Hz 屏幕上人物会”飞起来”，60 Hz 上却像爬行；掉帧、后台切换也会让帧间隔抖动，只有基于真实时间才能保证速度一致。VR 头显通常要求稳定 90 fps，低于这个帧率用户会立刻感到眩晕。

3. Three.js 核心对象与 glTF 资产

  • Scene：场景图的根节点，同时承载背景色与雾（fog）。
  • Camera：典型用 PerspectiveCamera(fov, aspect, near, far)，它本身不渲染画面，只是一组观察参数。
  • Renderer：WebGL 上下文的封装，setSize、setPixelRatio、阴影开关、XR 开关都在这里设置。
  • Group：没有视觉外观的纯变换节点，是组织复杂物体（门、画框、avatar）的基本单位。
  • Mesh：Geometry 与 Material 的组合实例，可挂灯光投影、可被射线拾取。
  • Light：AmbientLight 给全域打底亮度，DirectionalLight 模拟太阳并可投射阴影，PointLight 模拟灯泡。使用 MeshStandardMaterial（PBR 物理材质）时，物体必须有光照才会显出质感。

glTF 为什么是”3D 界的 JPEG”：glTF 是 Khronos 定义的实时传输格式，一个文件里统一封装网格、PBR 材质、骨骼蒙皮、动画剪辑和纹理引用，扩展还支持 Draco 几何压缩与 KTX2 纹理压缩。它面向”传输和加载”而非”编辑”（正如 JPEG 不是 PSD），Three.js、Babylon、Unity、Unreal 全部原生支持，ready.player.me、Mixamo 等工具链也直接导出它。Draco 压缩一句话：用少量解码 CPU 时间，把顶点缓冲压到原来的 1/5～1/10，网络分发大模型时几乎必开。

纹理加载与跨域：TextureLoader 是异步加载，r152 之后颜色贴图必须设置 tex.colorSpace = THREE.SRGBColorSpace，否则画面会发灰。另外 WebGL 一旦要读取像素（压缩、后处理），就要求图片服务器返回 CORS 头（Access-Allow-Origin），TextureLoader 默认以 crossOrigin="anonymous" 请求；IPFS 公共网关大多带 CORS，但你自己的对象存储别忘配置。file:// 双击打开时跨域策略最严格，纹理与 WebXR 测试都应走 http://localhost。

4. 3D 交互：Raycaster 拾取与空间 UI

3D 场景里没有 DOM 的 click 事件，”点中了哪个物体”靠射线拾取完成。先把鼠标屏幕坐标换算为 NDC（x、y 都落在 −1～1），再调用 raycaster.setFromCamera(pointer, camera)——它从相机位置出发、穿过指针在近裁面上的点构造一条 3D 射线；intersectObjects(objects, true) 返回按距离排序的命中数组，每项包含距离、交点 point、法线、uv 等。注意射线打中的往往是画框的子 Mesh（背板或画面），业务代码要沿 parent 链向上找到挂了标记的根 Group。

典型交互链是：pointermove 时做射线检测 → 命中画框就提高材质 emissive（自发光）做悬停高亮、鼠标变手型 → 点击时放大展示。点击与拖拽必须区分：在 pointerdown 记录坐标，pointerup 时若位移超过几个像素就视为”拖拽转向”而非点击，否则一转视角就误开图片。传送门也是同理：命中特定 Group 后，把 player 位置插值移动到入口坐标，配一个黑场过场即可；本文 Demo 的图片墙就是这套机制的完整落地。

3D 空间 UI 与传统 DOM UI 的取舍：表单、长文本、钱包授权弹窗、输入法相关的内容，坚决用 DOM——成熟、可访问、布局成本低；而”墙上的开关””悬浮的传送门””画廊信息牌”这类沉浸元素用 3D 几何体，配合射线或手柄捏合操作，空间感才不会被一块浮层打破。实战中两者混用：DOM 负责 HUD 层，3D 负责世界本身。

5. WebXR：从浏览器进入 VR

WebXR Device API 原理：浏览器把形形色色的硬件（Quest、Vive、Index、手机 AR）抽象成一套统一接口。标准流程是：

  1. navigator.xr.isSessionSupported('immersive-vr') 探测设备是否支持；
  2. xr.requestSession('immersive-vr') 建立沉浸式会话，并通过 session.requestReferenceSpace('local-floor') 取得”以地面为原点”的参考空间（XRReferenceSpace）；
  3. 会话自己的 requestAnimationFrame 每帧给你一个 XRFrame，调用 frame.getViewerPose(referenceSpace) 得到头部位姿；
  4. pose 中的 views 通常有两个（左眼、右眼），每个 view 带 transform（位置与朝向矩阵）和 projectionMatrix，渲染器分别绑定左右眼视口各画一遍，合成立体画面；手柄则通过 getPose 拿到 6DoF 位姿。

Three.js 把这整套流程封装在 renderer.xr 中：开启 renderer.xr.enabled = true 后，setAnimationLoop 会在 XR 会话中自动改用 XRFrame，相机的位姿由头显驱动。

VRButton 做了什么：VRButton.createButton(renderer) 生成的按钮内部是一台完整状态机——先检测 navigator.xr，不支持就置灰提示；支持则点击调用 requestSession，会话建立后执行 renderer.xr.setSession(session)，并在会话结束时恢复按钮状态。所以”一键进入 VR”并不是浏览器送的魔法，而是这套检测—建会话—绑定—回收的流程。

inside-out 追踪与 6DoF：现代头显用朝外的多个摄像头做 SLAM（同步定位与建图），靠房间特征点反推自身位置，不需要外部基站，这就是 inside-out。6DoF（六自由度）= x/y/z 三个平移自由度 + 三个旋转自由度，可以真实走近、后退、蹲下、探头；老式手机纸盒只有 3DoF（仅旋转）。VR 手柄同样是 6DoF 的。

空间音频：把 AudioListener 挂在相机上，声源用 PannerNode 赋予位置和朝向，浏览器依据距离衰减和双耳声像（pan）计算，让声音像”长在 3D 空间里”——画框讲解音从墙上传来，而不是从电脑喇叭的固定方向。

无头盔时的降级：检测不到 XR 设备时，桌面端用 WASD + 鼠标拖拽提供第三人称漫游（本文 Demo 已内置）；移动端还可以退化为单目全景 + 设备姿态（deviceorientation）控制视角。同一份代码、两档体验，是 WebXR 相对原生 VR 应用最大的分发优势。

6. Web3 × 3D：钱包门禁与 NFT 画廊

持票入场门禁：页面加载时门是关闭的，玩家只能在门外自由漫游；点击”连接钱包并验票”后，MetaMask 弹出授权（eth_requestAccounts），用 ethers 取得 signer，然后对 ERC-721 合约调用 balanceOf(signer.address)：返回值大于 0（ethers v6 返回的是 bigint，写作 > 0n）才调用 openDoor()，门 Group 以指数阻尼旋转打开；余额为 0 则在状态栏给出铸币链接。想做成”编号席位”（特定门票、特定座位），改用 ownerOf(tokenId) === address 逐张校验；需要服务端配合时，用 SIWE（Sign-In with Ethereum）让钱包签一段防重放的消息，后端再查链验证。

特别要清醒认识：前端门禁只是用户体验层，不是安全边界。任何人都能打开控制台绕过动画、直接从公共网关拉取图片。真正需要保护的资产（私享展览、付费模型），应当由后端完成”验签 + 查链”后再下发私有 URL 或短时访问令牌，3D 空间里的门只是这个结果的可视化。

NFT 画框挂墙：ERC-721 的元数据约定是 tokenURI(id) 返回一段 JSON，至少包含 name、description、image 三个字段。image 很可能写成 ipfs://Qm... 形式，浏览器无法直接请求这个协议，需要统一替换成 https://ipfs.io/ipfs/... 之类的网关地址（生产环境建议自建/付费网关并配置 CORS），再交给 TextureLoader 加载贴图、替换画框材质的 map。网络失败、限流、坏数据都要兜底占位图，绝不能让一面墙黑屏。

7. 多玩家联机：状态同步思路

多玩家不要追求”看到所有人的所有细节”。主流做法是：一个权威服务器（Colyseus 自带房间与状态同步；原生 WebSocket + Node 也能写），客户端以 10～20 Hz 的固定频率把自己的精简状态 {x, z, ry}（坐标 + 朝向）发给服务器，服务器广播快照；其他客户端不直接套用坐标，而是把快照放进约 100 ms 的缓冲并做插值移动，用来抵消网络抖动。远端玩家一律先显示简单胶囊体，距离靠近后再按需加载其 glTF avatar；房间管理、断线剔除、兴趣范围（只同步附近的人）都在服务器做。两条铁律：不要每帧广播（浪费且雪崩），不要信任客户端上报的坐标（反作弊必须服务器校验）。

8. 性能优化：让浏览器稳住帧率

  • draw call 合批：每次 draw call 都伴随 CPU 状态切换，几百个零散网格足以让帧时间暴增。静态物体用 BufferGeometryUtils.mergeGeometries 合并；草地、座椅等重复物用 InstancedMesh（一次提交、实例化绘制）；多个小贴图合成图集并共享材质。
  • 纹理尺寸：未压缩贴图显存占用约等于 宽 × 高 × 4 字节，开启 mipmap 再乘约 1.33。移动端贴图长边控制在 1024～2048，尺寸取二的幂以生成 mipmap；要求高的场景用 KTX2/Basis 做 GPU 压缩纹理，显存可降到 1/6～1/8。
  • 限制像素比：renderer.setPixelRatio(Math.min(devicePixelRatio, 2))。dpr=3 的屏幕片元数量是 dpr=1 的 9 倍，这是高刷屏手机最常见的”秒卡”原因。
  • LOD（细节层次）：同一物体准备高/中/低三档模型，用 THREE.LOD 按距离切换，远处物体几乎不占几何开销。
  • 其他卡顿来源：阴影贴图 mapSize 过大与多盏动态光；在帧循环里 new 向量、颜色、闭包导致 GC 抖动（应循环外预分配、复用临时对象）；首次出现某材质时 shader 编译造成的顿帧（可预先渲染一帧或用 renderer.compile 预热）；纹理 decode 与网络请求挤占主线程；过度的粒子与后处理通道。排查时先看 renderer.info.render.calls（draw call 数）和显存，再逐块关闭功能定位。

第20章 抽象代数深度指南

微积分研究”变化”，线性代数研究”线性空间”，而抽象代数研究的是运算本身的结构。小学算术告诉我们 3 + 5 = 8，抽象代数问的是更深一层的问题：为什么整数加法和矩阵乘法、置换复合、时钟上的取模加法”长得那么像”？它们共享同一套公理——把 + 和 × 的共性抽出来，就得到了”群”；把加减乘除全部抽出来，就得到了”域”。

这套看似纯粹烧脑的抽象游戏，统治着现代工程的半壁江山：魔方的最小解法步数、晶体的 230 种对称分类、AES 加密里那张大名鼎鼎的字节替换表、二维码被遮住一半仍能扫出的纠错码、比特币签名用的椭圆曲线——背后全是群、环、域的语言。可以说，密码学就是”在有限群上制造计算难题”的艺术，而纠错码就是”在有限域上做线性代数”的工程。

本指南以工程师视角重排标准教材（Artin《Algebra》、Dummit & Foote 的主干）：从群的定义与海量例子出发，经子群与 Lagrange 定理、同态与商群、群作用，进入环与有限域，然后以密码学应用（RSA / DH / ECC / 纠错码）作为重头戏收尾，最后给出 CS 对照表、Python 实战与验收清单。读完后你应当能：验证一个代数结构是不是群、手推 Lagrange 定理、用群论语言重写 RSA、实现椭圆曲线点加、说清楚为什么 256 位 ECC 等价于 3072 位 RSA。

一、群的定义与直觉：对称性的代数

1.1 四公理

群（group）是”一个集合 + 一种运算”满足四条公理的结构：

四条公理一条都不能少，且结合律最不起眼却最关键——矩阵乘法不可交换但可结合，所以可逆矩阵成群；减法连结合律都不满足（(3−2)−1 ≠ 3−(2−1)），所以 (ℤ, −) 不是群。

直觉上，群就是**”可逆操作的全集”**：每个操作都能做、能复合、能撤销、有”什么都不做”。魔方转动的复合、棋子的合法移动、加密与解密，都是这个直觉的化身。

第6章 变分法深度指南

普通微积分解决的问题是：给定一个函数 f(x)，在点 x 里找极值；而变分法（Calculus of Variations）解决的问题是：在一个函数族里找极值——自变量本身就是函数 y(x)，被求极值的对象叫泛函 J[y]。如果说普通微积分是在地图上找最低的山谷，变分法就是在”所有可能路线”的空间里找最优的那条路。工程师关心的最速降线、悬链线、测地线、最小作用量、最短时间控制、路径规划，乃至 VAE 的变分下界，全部是这一个思想的不同面孔。

第7章 微分几何深度指南

微分几何只做一件事：用微积分研究弯曲的空间。

普通几何学（欧几里得那一套）研究的是平直世界里的直线、圆、三角形；而现实世界充满了弯曲——地球是球面、卫星轨道是空间曲线、广义相对论里时空本身就是弯的。微分几何的核心思想是：把弯曲的对象局部线性化（切线、切平面、切空间），用导数刻画”弯曲的程度”，再把这些局部信息拼回整体。

全篇最重要的一个概念是曲率（curvature）。它的直观定义只有一句话：

曲率 = 局部偏离平直的程度。

  • 直线处处不偏离直线 → 曲率为 0；
  • 圆处处均匀偏离 → 曲率为常数，半径越小弯得越狠，曲率越大；
  • 球面向各个方向都弯 → 高斯曲率为正；
  • 马鞍面一个方向向上弯、另一个方向向下弯 → 高斯曲率为负。

工程师为什么要学它？因为机器学习里的”流形学习”、图形学里的”网格平滑”、机器人里的”姿态插值”、深度学习里的”自然梯度”，骨子里全是微分几何。数据往往落在高维空间的一个低维弯曲子流形上，不理解曲率，就理解不了这些算法在做什么。

本篇对应 Bronstein 数学手册第 3 章几何学的微分几何部分，按”曲线 → 曲面 → 内蕴几何 → 流形”的顺序展开，所有公式用 Unicode 书写，所有代码用 SymPy 可直接运行。

1.2 正则曲线（regular curve）

定义：若 r’(t) 处处连续且 r’(t) ≠ 0，称曲线是正则的。

为什么要求 r’ ≠ 0？因为 r’(t₀) = 0 的点，切向量退化，曲线在该点可能出现尖点（cusp）或停顿，微积分工具失效。几何上好的曲线必须先排除这类病态点。正则性保证每一点都有唯一确定的单位切向量。

七、流形初步（点到为止）

7.1 n 维流形

n 维流形（manifold）：一个局部看起来像 ℝⁿ 的空间。精确地说，每一点都有一个邻域，可以通过坐标卡（chart） 与 ℝⁿ 的开集建立双射（同胚）；一族覆盖整个空间的坐标卡叫图册（atlas），坐标卡之间重叠区域的转换函数要求光滑（微分同胚）。

地球表面是最贴切的例子：地球整体是球面（不是平面），但每座城市的地图都是平的——一张张平面地图合起来就是图册。流形 = “由局部平坦的地图拼接而成的整体弯曲空间”。

7.2 切空间

流形上每一点 P 处可以定义切空间 T_P M：该点所有切向量构成的 n 维线性空间——它是流形在该点的最佳线性逼近，是把微积分搬到弯曲空间上的舞台。曲线论中的 T、曲面论中的切平面，都是切空间的低维特例。
