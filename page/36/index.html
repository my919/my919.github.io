第三章：滤波与几何变换

概念基础

  1. 滤波 = 用邻域算出新值：每个像素根据周围邻域（核）重新计算——模糊、锐化、边缘、形态学都是滤波的不同形式。
  2. 频域直觉：低通滤波（模糊）去噪但模糊边缘，高通滤波（锐化/边缘）增强细节但放大噪声，二者是图像处理的阴阳。
  3. 几何变换改位置不改值：缩放、旋转、仿射、透视改变像素「在哪」，需插值填补新格点的值。
  4. 阈值二值化是分割起点：把灰度图按阈值切成前景/背景，是许多检测流水线的第一步。
  5. 本章目标：掌握常用滤波（高斯/中值/双边）、形态学（腐蚀/膨胀/开闭运算）、几何变换（缩放/旋转/仿射/透视）、阈值化，能组合去噪与分割。

五、阈值化

  • 全局阈值：光照均匀时够用。
  • 自适应阈值：光照不均（如文档阴影）按局部邻域二值化，11 是块大小（奇数），2 是减常数。
  • Otsu：自动找最佳阈值，配合 THRESH_OTSU 标志，阈值参数传 0。

其他阈值类型速查

类型 行为
THRESH_TRUNC 超阈值截到阈值（封顶）
THRESH_TOZERO 低于阈值置零，其余保留
THRESH_TOZERO_INV 高于阈值置零

选阈值的经验：先 matplotlib 画灰度直方图看是否双峰——双峰用 Otsu；缓坡/光照不均用自适应；已知物理意义（如灰度>200 即过曝）用全局固定值。triangle 阈值（THRESH_TRIANGLE）适合单峰长尾分布（如细胞图像）。

第四章：特征与几何

概念基础

  1. 特征 = 图像中可辨识的局部模式：角点、斑点、边缘交点等，在不同光照、尺度、视角下仍能被稳定检测与匹配，是图像配准、拼接、跟踪的基础。
  2. 检测 + 描述两步：先检测关键点位置，再计算描述子（高维向量）表征其邻域；匹配即比较描述子距离。
  3. 几何从像素到世界：单应性（Homography）描述两视图间的平面映射，4 对匹配点即可解出，用于拼接、AR、文档矫正。
  4. 轮廓是连通区域边界：从二值图提取轮廓，可算面积、外接矩形、近似多边形，是传统目标检测与计数的利器。
  5. 本章目标：掌握角点/特征检测与匹配、单应性求解、轮廓分析，理解传统 CV 几何处理的边界与深度模型的分工。

角点在两方向都有强梯度，是稳定的特征点：

  • goodFeaturesToTrack：直接返回前 N 个角点坐标，参数为（最大点数、质量阈值、最小间距）。

二·补充、霍夫变换：直线与圆

霍夫变换把「图像空间的点共线/共圆」转成「参数空间的投票峰值」，是从边缘图提取几何基元的标准方法：

  • HoughLinesP（概率版）比标准版 HoughLines 实用：直接给线段而不是无穷直线方程。
  • HoughCircles 对噪声敏感，param2（累加阈值）越大越严格；前置中值/高斯模糊几乎必须。
  • 应用：车道线、文档边框、仪表盘指针读数、圆形工件检测。

  • RETR_EXTERNAL：只取最外层轮廓；RETR_TREE 取全部层级。
  • CHAIN_APPROX_SIMPLE：压缩水平/垂直/对角冗余点，省内存。

四·补充、相机标定入门（calib3d）

摄像头镜头有畸变，精确测量（尺寸/三维）前必须标定。标准流程用棋盘格：

  • K：3×3 内参（焦距 fx/fy、主点 cx/cy）；dist：径向/切向畸变系数。
  • 标定板需多姿态多角度 15+ 张，覆盖画面边缘（畸变最大处）；ret 是重投影误差，<0.5 像素为佳。
  • 去畸变后 findHomography/测量才有几何意义；鱼眼镜头改用 cv2.fisheye 系列 API。

六、传统 CV 与深度模型的分工

任务 传统（本章） 深度模型

七、常见陷阱

陷阱 说明
Harris 输入未转 float32 cornerHarris 需 float32 灰度，uint8 报错
ORB 用 L2 距离 ORB 二进制描述子须用 NORM_HAMMING

模板匹配遇旋转 matchTemplate 不抗旋转缩放，需改特征匹配
findContours 改原图 该函数会修改输入图，传副本

第五章：视频与深度学习

概念基础

  1. 视频 = 时序帧序列：在单图处理之上多了「帧间关系」——运动检测、光流、跟踪都依赖相邻帧对比，是视频理解的核心。
  2. 背景建模分离运动：固定摄像头下，建立背景模型后，当前帧与背景之差即运动前景，是安防检测的经典思路。
  3. cv2.dnn 是推理不是训练：OpenCV 能加载 ONNX/Caffe/部分 TF 模型做前向推理，跨平台部署轻量模型；训练仍在 PyTorch 等框架完成。
  4. 前后处理是 OpenCV 的主场：深度模型要的 resize、归一化、BGR/RGB 转换、NMS、画框，全是 OpenCV 擅长的数组操作。
  5. 本章目标：掌握视频读写、光流、背景减除、dnn 推理与后处理，把前四章能力串成完整 CV 流水线。

一、视频读写

1. VideoCapture 读取

摄像头/网络流 CAP_PROP_FRAME_COUNT 不可用；网络流用 cv2.CAP_FFMPEG 后端读 RTMP/RTSP。

2. VideoWriter 写出

  • fourcc：mp4v/avc1/X264 等，依后端可用编码；写不出时先换 fourcc。
  • 尺寸必须与帧一致，否则写空。
  • 底层依赖 FFmpeg 编解码——这就是 OpenCV 与 第一章：FFmpeg 音视频处理入门 的联系。

读网络流与丢帧策略

五·补充、性能优化清单

CV 流水线提速按收益排序：

  1. 降分辨率：处理前 resize 到够用即可（检测常 640 宽）——像素数减半耗时约减四分之三。
  2. 向量化与算子：消灭 Python 像素循环（第二章）；批量 blobFromImages 一次推理多帧。

  4. UMat/OpenCL：cv2.UMat 让支持算子自动走 GPU（第一章），大图大核收益明显。
  5. CUDA 模块：源码编译 WITH_CUDA=ON 后用 cv2.cuda_GpuMat / cv::cuda::*，含专用滤波、dnn 后端。
  6. 多线程读解：读帧（IO 瓶颈）与处理（CPU 瓶颈）分线程，队列缓冲。
  7. dnn 后端：有 NPU/OpenVINO 设备时 DNN_BACKEND_INFERENCE_ENGINE 等专用后端。

第四章：Nginx 缓存与性能调优

概念基础

  1. 缓存在网关层最划算：proxy_cache 让重复的后端响应停在 Nginx 本地磁盘/内存，QPS 高峰被削平，后端直接减负。
  2. 压缩是免费带宽：gzip（文本）与 brotli（第三方模块）能把 JS/CSS 压到原体积 20%~30%，首屏时间立竿见影。
  3. 静态路径靠 sendfile：sendfile + tcp_nopush 走内核零拷贝，open_file_cache 缓存文件元数据——静态服务的三连优化。
  4. 容量公式要心里有数：最大连接 ≈ worker_processes × worker_connections；长连接 keepalive 减少握手次数。
  5. 调优先测量：改参数前先 ab/wrk 压测拿基线，盯 access_log 的 $request_time 与系统 CPU/内存，避免「凭感觉调参」。

一、proxy_cache：网关层缓存

1. 两段式配置（http 定义区，server 使用）

2. 缓存命中排查

动态接口慎缓存：带 Cookie/Authorization 的响应默认不该缓存；必要时用 proxy_cache_bypass $http_authorization; + proxy_no_cache $http_authorization; 显式绕开。缓存清理的完整方案见下文「缓存清除三种路子」。

3. 缓存目录分层与键设计

  1. levels=1:2：缓存文件按哈希建两级子目录（如 /var/cache/nginx/app/c/29/），避免单目录几十万文件拖垮文件系统查找；
  2. keys_zone 容量：1MB 共享内存约存 8000 个 key 的元数据——50MB ≈ 40 万条缓存，据此估算规模；
  3. proxy_cache_key 默认值：$scheme$proxy_host$request_uri——注意不含任何请求头；
  4. 多语言/多端站点：把差异维度加进 key，如 proxy_cache_key "$scheme$host$request_uri$http_accept_language";，否则中文用户可能拿到英文缓存。

4. 防回源击穿

热点 key 过期瞬间，上万请求同时穿透到后端（缓存击穿）——四个参数按住：

组合含义：lock 挡并发、stale 兜底、background_update 提前刷新、min_uses 防缓存被长尾污染。

顺带区分两个易混概念：

  1. 缓存穿透：查询不存在的数据，缓存永不命中、请求直达后端——对空结果也缓存短 TTL（proxy_cache_valid 404 1m;）或前端布隆过滤器应对；
  2. 缓存雪崩：大量 key 同时过期——给 TTL 加随机抖动（基础 10m ± 2m），避免齐刷刷同时失效。

proxy_buffers 怎么估：

参数 装什么 建议
proxy_buffer_size 响应头 4k~8k，带大 cookie 的场景调大

六、OpenResty：会写 Lua 的 Nginx

第三章：Nginx HTTPS 与安全

概念基础

  1. TLS 终结点：证书挂在 Nginx，客户端到 Nginx 走加密，Nginx 到后端走内网明文——证书申请、续期、算法升级集中在一处。
  2. 证书链要完整：浏览器校验的是「站点证书 → 中间证书 → 根证书」整条链，漏发中间证书是「本地 curl 通、用户浏览器报错」的常见根因。
  3. 301 比配置加密更重要：HTTP 全站 301 跳转 HTTPS，并配合 HSTS 头让浏览器后续强制走 TLS。
  4. 安全是分层的：TLS 之外，还有限流（limit_req）、访问控制（allow/deny、auth_basic）、安全响应头，每层挡一类攻击。
  5. 密码学背景看 OpenSSL：算法、密钥、证书格式等原理见 第一章：OpenSSL 命令行入门与常用操作总览，本章聚焦落地。

四、限流：limit_req 与 limit_conn

参数 含义
rate=10r/s 平均速率（也可 30r/m）
burst=20 允许突发排队 20 个请求

五、安全响应头

第四章：PyTorch 部署与分布式

概念基础

  1. 训练与推理是两种工程：训练求快求全（Python 动态图），部署求稳求小（静态图、无 Python 依赖、常驻服务）。
  2. ONNX 是推理通用货币：把模型导出为 ONNX 后，可用 ONNX Runtime、OpenCV cv2.dnn（见 第五章：视频与深度学习）、TensorRT 等引擎推理，摆脱 Python 环境。

第三章：PyTorch GPU 加速与混合精度

概念基础

  1. GPU 擅长并行不擅长分支：大矩阵乘/卷积在 GPU 上快几十倍；数据搬运（CPU↔GPU）反而是瓶颈，少拷贝、大批次是优化方向。
  2. 设备要对齐：模型与数据必须在同一设备，RuntimeError: Expected all tensors to be on the same device 是新手第一错。
  3. AMP 混合精度的本质：前向用 FP16/BF16 省显存提速，梯度更新用 FP32 保精度；autocast + GradScaler（FP16 场景）成对出现。
  4. 显存不够不等于换卡：梯度累积等效大 batch、梯度检查点用算力换显存、小批次 + 累加，都是工程正解。
  5. 测量优先：torch.cuda.synchronize() + 计时、nvidia-smi 看占用，先定位瓶颈（数据加载 or 计算 or 搬运）再优化。

第二章：PyTorch 模型与训练

概念基础

  1. nn.Module 是模型的骨架：继承后在 __init__ 里声明层、在 forward 里组织数据流；参数注册、.to(device)、state_dict 保存全部自动获得。
  2. Dataset/DataLoader 解耦数据与模型：Dataset 定义「第 i 条样本怎么取」，DataLoader 负责批量化、打乱、多进程预取——大数据训练的前提。
  3. 训练循环是固定四步：optimizer.zero_grad() → forward → loss.backward() → optimizer.step()，一切复杂训练都是这四步的变体。
  4. train/eval 切换不可少：Dropout、BatchNorm 在训练与推理行为不同；验证前必须 model.eval()，验证后 model.train()。
  5. 泛化靠工程手段：验证集监控、早停、学习率调度、正则化（weight_decay/Dropout）共同决定模型能否落地。

7.1 计算图是怎么建的

requires_grad=True 的张量参与运算后，产出的新张量带 grad_fn 属性指向上一步的求导函数；backward() 从标量出发沿 grad_fn 链反向遍历，把梯度写进叶子张量的 .grad。

八、视图、共享内存与就地操作

  • view/reshape/permute/t 多数是视图（共享底层存储），改视图会改原张量；
  • 就地操作带下划线：add_/mul_/zero_()，省显存但会破坏 autograd 需要的中间值，训练计算图里慎用；
  • clone() 才是深拷贝；x.data 已弃用，绕开 autograd 请用 detach()。

高频报错：RuntimeError: a view of a leaf Variable that requires grad is being used in an in-place operation——把就地运算改成普通运算即可。

8.1 einsum：复杂收缩一行可读

多 batch 多维张量的矩阵乘用 einsum 写，维度含义一目了然，比连环 permute + matmul 更不易错。

8.2 张量与 Python 标量的边界

规则：只要进了日志、列表、指标累加，就先 .item() 转成 Python 标量；留在张量形态会把整个计算图拖着不放，是显存缓慢上涨的隐形来源（第三章细讲）。
