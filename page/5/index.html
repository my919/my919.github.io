1. 概念说明

负载均衡：多台应用服务器分担流量——提升吞吐（横向扩展）与可用性（单点故障不影响）。

Nginx 负载均衡核心：upstream（后端服务器组）+ proxy_pass（转发）+ 调度算法（怎么分流量）。

高可用：Nginx 自身不能是单点——两台 Nginx 用 Keepalived 共享一个虚拟 IP（VIP），主挂备自动接管。

现代替代：K8s Ingress、云 LB（ALB/SLB）；但 Nginx 仍是自建与边缘网关主力。

1. 排查方法论

网络排障七层（从底到顶）：

核心原则：从底层往上排查，先确认”通不通”，再看”慢不慢”，最后看”应用层错误”。先 ping 通没 → 再端口通没 → 再 curl 看响应。

2. 连通性诊断

关键区分：ping 通 = 网络层通；业务不通还可能是：端口未监听、防火墙拦截、服务没起来。

3. 端口与连接状态

TIME_WAIT 过多（高并发短连接常见）：是 TCP 正常机制（2MSL 后回收），一般不用处理；服务器调优可开 net.ipv4.tcp_tw_reuse。

1. 概念说明

消息可靠性三问（面试与生产核心）：

  1. 不丢：消息从生产 → broker → 消费，任何环节都不能丢。
  2. 不重：网络重试导致重复投递，消费端必须幂等。
  3. 不乱：需要顺序的场景保证按序处理。

丢消息的三个环节：

可靠性铁律：消息丢失的责任最终在消费端兜底——生产者/Broker 尽量可靠，但消费端必须能容忍任意环节的重复与乱序（幂等 + 重试 + 对账）。

拆分决策前提（先回答）：
