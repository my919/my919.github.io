第一章：PyTorch 入门与张量

概念基础

  1. 动态图是 PyTorch 的性格：写 Python 即写模型，前向传播边执行边建图，调试跟普通程序一样打断点——科研与工业界均为主流选择。
  2. Tensor 是唯一主角：torch.Tensor 是带 GPU 加速与自动求导的多维数组，接口与 NumPy 高度相似，会 NumPy 就会一半 PyTorch。
  3. autograd 自动微分：requires_grad=True 的张量参与运算时自动记录计算图，backward() 一步拿到所有梯度，模型训练的地基。
  4. 形状思维：深度学习 90% 的报错是 shape 不对——view/reshape/squeeze/permute 这组变形记必须滚瓜烂熟。
  5. 生态覆盖全链路：torchvision/torchaudio 领域库、Hugging Face 预训练模型（见 第三章：LLM 大语言模型基础）、ONNX 导出部署、DDP 分布式训练。

本章是 PyTorch 系列起点：安装、张量运算、autograd。模型与训练见 第二章：PyTorch 模型与训练，GPU 与混合精度见 第三章：PyTorch GPU 加速与混合精度，部署与分布式见 第四章：PyTorch 部署与分布式。深度学习理论背景见 第二章：DL 深度学习基础。

说明：沙箱未安装 torch，本章代码按 PyTorch 2.x 官方 API 书写，未逐条运行验证。

第三章：LLM 大语言模型基础

概念基础

  1. 大语言模型（LLM）是在海量文本语料上以自监督方式预训练的超大 Transformer 网络，能理解与生成自然语言。
  2. 训练三阶段：预训练（下一词预测，学通用语言与知识）→ 监督微调（SFT） 对齐「助手」行为 → RLHF / DPO 对齐人类偏好。
  3. 交互单位是 Token：模型受上下文窗口（Context Window）限制，一次只能处理有限的 Token；长文档需分块或 RAG。
  4. 幻觉与增强：模型可能一本正经地编造内容，用**检索增强生成（RAG）接入私有知识、用工具调用（Function Calling）**连接真实 API 来缓解。
  5. 落地三路线：Prompt 工程最轻量，微调（LoRA/QLoRA）注入领域知识，RAG + Agent 组合解决知识时效与工具执行。

生命周期

阶段 说明
预训练 下一词预测（Causal LM）或掩码语言模型，学通用语言与知识
监督微调（SFT） 指令数据上对齐「助手」行为
RLHF / DPO 等 人类偏好或偏好对优化安全性与有用性
推理部署 量化、批处理、KV Cache、投机解码

代表模型族：GPT、Llama、Qwen、DeepSeek 等（以各开源/商用许可为准）。

Prompt 与上下文窗口

  • System / User / Assistant 角色消息构成对话。
  • Few-shot：在 Prompt 中给示例引导格式。
  • Context Window：模型一次可处理的 Token 上限；长文档需分块或 RAG。
  • Temperature / Top-p：控制采样随机性。

RAG 与 Agent

1. RAG（检索增强生成）

  Q[用户问题] --> E[Embedding]
  E --> V[(向量库)]
  V --> Ctx[相关文档片段]
  Ctx --> LLM[LLM + Prompt]
  Q --> LLM
  LLM --> A[回答]

降低幻觉、接入私有知识；向量库可与 第一章：Redis 概述、安装与 CLI 入门 向量检索、专用 DB 配合。

2. 工具调用（Function Calling）

模型输出结构化 JSON 调用 API（查天气、查订单），由应用执行后把结果回传模型。

微调方式

方式 说明
全量微调 更新全部参数，成本高
LoRA / QLoRA 低秩适配器，省显存
继续预训练 领域语料增强行业知识

训练栈常基于 第一章：PyTorch 入门与张量 + Hugging Face Transformers / PEFT。

评估与安全

  • 基准：MMLU、HumanEval（代码）等（仅作参考）。
  • 业务指标：任务成功率、人工抽检、延迟与成本。
  • 风险：幻觉、注入攻击、隐私泄漏；需权限控制、输出过滤与审计。

基础理论见 第一章：ML 机器学习基础、第二章：DL 深度学习基础。

本章小结

要点 结论
生命周期 预训练 → SFT → RLHF/DPO → 推理部署（量化、KV Cache、投机解码）
交互方式 System/User/Assistant 消息 + Few-shot；上下文窗口是 Token 上限
知识增强 RAG 检索私有知识降幻觉，Function Calling 让模型调用真实 API

评估安全 公开基准仅作参考，看业务指标；防幻觉、注入攻击与隐私泄漏

至此语言模型主线完成：ML 打好数据与算法基础，DL 掌握神经网络与训练工程，LLM 把这些能力放大到语言智能与应用落地。RAG 的完整工程实现（切块、向量库、检索评估）见 第四章：RAG 与向量检索实战；动手实验配合本站 第一章：PyTorch 入门与张量 等章节。

第二章：DL 深度学习基础

发表于 2026-05-01 更新于 2026-09-01 分类于 AI 本文字数： 1.4k 阅读时长 ≈ 5 分钟

第二章：DL 深度学习基础

概念基础

  1. 深度学习（DL）是机器学习的分支：用多层神经网络自动从数据中学习层次化特征表示，大幅减少手工特征工程。
  2. 核心机制：前向传播计算输出与损失，反向传播按链式法则求梯度，SGD/Adam 等优化器迭代更新权重。
  3. 非线性是关键：层间插入激活函数（ReLU / Sigmoid / GELU 等），否则多层线性堆叠仍等价于单层线性模型，无法拟合复杂模式。
  4. 架构按数据形态选：MLP 管表格向量、CNN 管图像空间模式、RNN/LSTM 管序列、Transformer 用 Self-Attention 建模长距离依赖并成为 LLM 的基座。
  5. 算力与工程：训练依赖 GPU/CUDA，配合 PyTorch 等框架与混合精度、学习率调度等技巧才能稳定高效。

神经网络基础



flowchart LR
  X[输入] --> F[前向传播]
  F --> L[损失 Loss]
  L --> B[反向传播梯度]
  B --> U[更新权重]
  • 前向传播：输入 → 各层线性变换 + 非线性激活 → 输出。
  • 损失函数：分类 Cross-Entropy、回归 MSE 等。
  • 反向传播：链式法则计算梯度，SGD/Adam 等优化器更新参数。

1. 为什么需要非线性激活

若每层只有线性变换 ，多层堆叠仍等价于单层线性模型，无法拟合 XOR、边界弯曲等复杂模式。激活函数 引入非线性，使网络能学习层次化特征。

2. 常见激活函数

函数 公式 值域 特点
ReLU 计算快；正区间梯度恒为 1，缓解梯度消失
Sigmoid 输出可解释为概率；两端饱和，易梯度消失
GELU 近似 平滑、非单调；Transformer 默认选择之一

ReLU： 时输出 0， 时等于 ；负半轴梯度为 0（Dead ReLU），实践中仍是最常用的隐层默认项。

Sigmoid：把实数压到 ，适合二分类输出层或门控（LSTM 门）；隐层深层堆叠时两端饱和导致梯度接近 0，训练变慢。

GELU：在 0 附近平滑过渡，负值有小幅度非零响应；BERT、GPT 等 Transformer 隐层常用，表达力与训练稳定性通常优于 ReLU，但计算略贵。

3. 如何选择（以及为什么）

场景 推荐 原因
CNN / MLP 隐层 ReLU 实现简单、收敛快；大量视觉与表格任务验证有效
输出层（二分类概率） Sigmoid 输出天然在 ，与 BCE 损失配套
输出层（多分类） Softmax（非 Sigmoid） 各类概率和为 1
Transformer / 大语言模型 GELU 平滑非线性利于深层 Self-Attention 训练；与 Layer Norm 等组合成熟
RNN / 门控结构 Sigmoid / Tanh 门控需要 或有界输出；Tanh 零中心，有时优于 Sigmoid
需要概率且要可导 Sigmoid / GELU Sigmoid 有界；GELU 在 0 附近更平滑，梯度更友好

经验法则：

  1. 没有特殊理由时，隐层先用 ReLU（或 Leaky ReLU 减轻 Dead ReLU）。
  2. 输出层跟任务走：回归用线性/无激活，分类用 Softmax 或 Sigmoid。
  3. 复现 Transformer 或 LLM 结构时用 GELU，与论文和主流实现一致。
  4. 深层旧架构（VGG 之前） 曾广泛用 Sigmoid/Tanh，现多被 ReLU 取代，除非门控或概率语义需要。

典型架构

架构 适用
MLP 表格、简单向量
CNN 图像、局部空间模式
RNN/LSTM/GRU 序列（较长依赖现多被 Transformer 补充）
Transformer NLP、多模态；Self-Attention 建模长距离依赖

ResNet、U-Net、BERT、GPT 等均建立在上述组件之上。

训练技巧

  • Batch Normalization / Layer Norm：稳定训练。
  • Dropout：减轻过拟合。
  • 学习率调度：Warmup、Cosine Decay。
  • 混合精度（AMP）：FP16/BF16 加速、省显存。
  • 梯度裁剪：RNN/大模型训练防爆炸。

数据：增强（随机裁剪、翻转）、归一化；划分训练/验证，早停（Early Stopping）。

框架与硬件

  • PyTorch：研究与应用主流（见 第一章：PyTorch 入门与张量）。
  • TensorFlow/JAX：生产与 TPU 生态。
  • GPU/CUDA：大规模训练依赖；推理可用 ONNX Runtime、TensorRT 等。

与 ML、LLM

  • 传统 第一章：ML 机器学习基础：小数据、表格、可解释场景仍常用 GBDT。
  • DL：表示学习为主。
  • 第三章：LLM 大语言模型基础：超大 Transformer 预训练 + 微调/对齐；视觉侧有 ViT、Diffusion 等并行发展。

计算机视觉入门可结合 OpenCV。

本章小结

要点 结论
训练循环 前向传播算损失 → 反向传播求梯度 → 优化器更新权重
激活函数 隐层默认 ReLU，二分类输出 Sigmoid，多分类 Softmax，Transformer 用 GELU
架构选型 MLP 表格、CNN 图像、RNN/LSTM 序列、Transformer 长依赖与多模态
训练技巧 Norm 稳训练、Dropout 防过拟合、学习率调度、AMP 提速、梯度裁剪防爆炸
生态分工 传统 ML 管表格小数据，DL 管表示学习，LLM 是超大 Transformer 的预训练 + 微调

第一章：ML 机器学习基础

第一章：ML 机器学习基础

概念基础

  1. 机器学习（ML）是让计算机从数据中自动学习规律，再用学到的模型对新数据做预测或决策，而无需为每条规则手工编程。
  2. 三大问题类型：监督学习（有标签，学输入→输出映射：分类、回归）、无监督学习（无标签，发现结构：聚类、降维）、强化学习（智能体与环境交互最大化回报）。
  3. 标准工作流：问题定义 → 数据收集与清洗 → 特征工程 → 模型训练与验证 → 部署与监控，从原始数据到线上服务是一条完整链路。
  4. 泛化是核心目标：模型要在没见过的数据上表现好，因此要防过拟合（正则、Dropout、交叉验证），并权衡偏差-方差。
  5. 定位与分工：表格数据、小样本、可解释性要求高的场景传统 ML（尤其树模型）仍很强；图像、语音等复杂表示交给 DL，自然语言任务交给 LLM。

问题类型

类型 目标 示例
监督学习 有标签，学输入→输出映射 分类（垃圾邮件）、回归（房价）
无监督学习 无标签，发现结构 聚类、降维、异常检测
强化学习 智能体与环境交互最大化回报 游戏、机器人控制

典型流程



flowchart LR
  Raw[原始数据] --> Clean[清洗特征]
  Clean --> Train[训练模型]
  Train --> Eval[验证集评估]
  Eval --> Deploy[部署推理]
  1. 问题定义与指标（准确率、F1、AUC、RMSE 等）。
  2. 数据收集与清洗：缺失值、异常值、泄漏（train/test 混用未来信息）。
  3. 特征工程：数值缩放、类别编码、时间特征。
  4. 模型训练与验证：训练集 / 验证集 / 测试集或 K 折交叉验证。
  5. 部署与监控：数据漂移、模型退化、在线 A/B。

常用算法（概览）

  • 线性模型：逻辑回归、线性回归、SVM（核方法）。
  • 树模型：决策树、随机森林、GBDT、XGBoost/LightGBM（表格数据仍强）。
  • 距离方法：KNN。
  • 无监督：K-Means、PCA、t-SNE（可视化）。

过拟合与正则

  • 过拟合：训练集很好、泛化差 → 更多数据、简化模型、L1/L2 正则、Dropout（神经网络侧）。
  • 偏差-方差权衡：模型容量与数据量匹配。
  • 交叉验证：稳定估计泛化性能。

与 DL、LLM 的分工

层次 说明
传统 ML 表格、小数据、可解释性要求高
DL（第二章：DL 深度学习基础） 图像、语音、复杂非线性表示
LLM（第三章：LLM 大语言模型基础） 自然语言理解与生成；下游常 微调 或 RAG

深度学习框架见 第一章：PyTorch 入门与张量；Python 工程见 第一章：Python 的 UV 工具：极速 Python 环境与包管理。

本章小结

要点 结论
问题类型 监督（分类/回归）、无监督（聚类/降维）、强化学习三大类
工作流 问题定义 → 数据清洗 → 特征工程 → 训练验证 → 部署监控
模型选型 表格数据优先树模型（GBDT/XGBoost），可解释场景用线性模型
泛化保障 更多数据、正则化、交叉验证，警惕数据泄漏与过拟合
技术分工 传统 ML 管表格小数据，复杂表示交给 DL，语言任务交给 LLM

第二章：Kubernetes 容器编排入门

概念基础

  1. Kubernetes（K8s） 是容器编排平台：把大量容器按声明式期望调度到多台机器上运行，并自动维持「实际状态 = 声明状态」。
  2. 为什么需要编排：单机 Docker 解决不了多机调度、故障自愈、扩缩容、服务发现与负载均衡——这些正是 K8s 的核心能力。
  3. 声明式 API：不写「怎么做」的脚本，而是提交 YAML 描述期望（副本数、镜像、端口），由控制循环持续把集群调到期望状态。
  4. 核心对象：Pod 是最小调度单元；Deployment 管理副本与滚动更新；Service 提供稳定访问入口；ConfigMap / Secret 管理配置与密钥。
  5. 定位：生产环境容器编排的事实标准；本地可用 minikube / kind / k3s 学习，集群上的应用包管理则交给 Helm（见第四章）。

第一章：Docker 容器基础

概念基础

  1. Docker 是基于容器的应用打包、分发与运行平台：把应用连同依赖环境一起封进镜像，实现「一次构建，到处运行」，解决「在我机器上是好的」的环境漂移问题。

第十六章：Zigbee：基于 802.15.4 的 Mesh 组网

概念基础

  1. Zigbee 是构建在 IEEE 802.15.4（2.4GHz 低速率无线 PHY/MAC）之上的完整协议栈：802.15.4 只管「把帧发出去」，Zigbee 在其上定义 NWK / APS / ZDO 与应用层 ZCL，解决「组网、路由、互操作」。
  2. Mesh 自愈网络：Coordinator 建网，Router 中继扩展覆盖，End Device 低功耗休眠——多跳 mesh 让覆盖随节点密度增长，单点故障可绕行。
  3. 互操作靠 ZCL：Cluster（集群） 把「灯开关 0x0006、调光 0x0008」等语义标准化，不同厂商设备因此可以混搭组网。
  4. 功耗与角色绑定：Router 必须常供电，End Device 靠休眠 + 父节点代收省电；设计网络前要先想清楚每个节点的角色。
  5. 定位：智能家居（灯、开关、传感器）、楼宇自动化的主流方案之一；手机直连场景选 BLE，公里级广域选 LoRaWAN，高吞吐选 Wi-Fi。

  R1 --> E2[End Device 开关]

一、802.15.4 基础

  • PHY/MAC：短帧、CSMA-CA、AES-128 链路加密。
  • Zigbee 在之上定义 NWK、APS、ZDO 与应用层 ZCL。

角色 说明

Mesh 多跳扩展覆盖；路由表由 AODV 类机制维护（依栈实现）。

Wi-Fi 高吞吐、功耗高

第十五章：USB 总线：拓扑、描述符与 CDC 虚拟串口

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 626 阅读时长 ≈ 2 分钟

第十五章：USB 总线：拓扑、描述符与 CDC 虚拟串口

概念基础

  1. USB（Universal Serial Bus，通用串行总线）是 主机中心（Host-centric） 的有线总线：所有事务都由 Host 发起，Device 只能被动响应——与 CAN 的多主对等、LIN 的主从调度都不相同。
  2. 树形寻址：Host 经 Root Hub → Hub 树形扩展挂载设备，靠枚举过程为每个设备分配唯一地址，再读描述符获知它是谁、能做什么。
  3. 描述符即自描述：设备描述符 → 配置 → 接口 → 端点层层描述，插入即枚举，无需跳线或硬编码地址——「即插即用」的机制本质。
  4. 速度分级演进：Low/Full/High Speed（1.5M/12M/480 Mbps）→ USB 3.x（5 Gbps+）→ USB4；MCU 侧 Full Speed 12 Mbps 仍最常见。
  5. 定位：PC 与外设的标准互联；嵌入式里最常见的玩法是 CDC 虚拟串口与 HID，Type-C 时代还要关注 PD 供电协商与 Alt Mode。

主机-设备树形拓扑：

主机–设备拓扑

  Host[USB Host PC] --> Hub[Hub 可选]
  Hub --> Dev1[Device 键鼠]
  Hub --> Dev2[Device CDC 串口]

一、拓扑

  • Host 发起事务；Device 响应。
  • OTG 设备可切换 Host/Device（手机接 U 盘）。

二、速度等级

版本 速率（量级）
USB 2.0 HS 480 Mbps
USB 3.x 5 Gbps+
USB4 基于 Thunderbolt 生态

Full Speed 12 Mbps 仍常见于 MCU Device。

三、描述符与 Class

  • 设备描述符 → 配置 → 接口 → 端点。
  • Class：HID（键鼠）、MSC（U 盘）、CDC-ACM（虚拟 第四章：UART）、Audio、Video 等。
  • Vendor Specific：自定义 Bulk/Interrupt 端点 + 主机驱动/libusb。

四、CDC 虚拟串口

MCU 通过 USB CDC ACM 暴露 /dev/ttyACM0（Linux）或 COM 口（Windows），应用层与 UART 类似发字节，物理层是 USB 包。

与 第五章：RS232：USB 转串口 芯片（CH340、CP2102、FT232）内部即 UART ↔ USB 桥接。

五、嵌入式开发要点

  • STM32 USB Device Library、TinyUSB、ESP32-S2/S3 USB OTG。
  • 枚举失败：检查 D+/D-、1.5k 上拉（Full Speed Device）、供电与描述符。
  • USB 3 / Type-C：PD 协商、Alt Mode（DP/Thunderbolt）另论。

第十四章：NFC 近场通信：工作模式与 NDEF

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 661 阅读时长 ≈ 2 分钟

第十四章：NFC 近场通信：工作模式与 NDEF

概念基础

  1. NFC（Near Field Communication，近场通信）工作在 13.56MHz，通信距离仅几厘米——「近」是刻意设计：贴一下才触发，天然防误触，适合支付与门禁。
  2. 有源与无源：Reader 产生射频场并为 passive Tag 供电（无源卡没有电池，靠感应取电通信），这是它与蓝牙等「双方都要电池」技术最本质的差别。
  3. 三种工作模式：读卡/写卡（碰 Tag）、卡模拟（手机变门禁卡/交通卡）、点对点（两设备交换小数据，已较少用）。
  4. NDEF 是通用数据格式：把 URI、文本、Wi-Fi 配置、蓝牙配对信息统一封装进 Tag，手机一碰即触发对应系统动作。
  5. 定位：身份识别、小额支付、设备配对加速器（给 BLE 递密钥）；大数据传输交给 Wi-Fi/蓝牙，NFC 只负责「握手」。

最典型的读卡交互：

读卡模式交互



sequenceDiagram
  participant R as NFC Reader 手机
  participant T as NFC Tag 卡
  R->>T: 射频场供电 + 轮询
  T-->>R: NDEF URL / 文本

一、工作模式

模式 说明
Reader/Writer 读或写 passive Tag
Card Emulation 手机模拟门禁/交通卡
Peer-to-Peer 两设备交换小数据（较少用）

二、Tag 标准

  • Type 1~4 Tag：不同容量与协议（NFC Forum）。
  • MIFARE Classic/Ultralight：交通、门禁（Classic 安全性已弱，新项目慎用）。
  • ISO 14443 A/B、ISO 15693（稍远，仍近场）。

三、NDEF（NFC Data Exchange Format）

常用 payload 格式，可封装：

  • URI（打开网页）
  • 文本
  • Wi-Fi 配置（WSC）
  • Bluetooth LE 配对 OOB 数据

手机贴近 Tag 即可触发系统动作（依 OS 策略）。

四、与其它接口

  • 第十三章：Bluetooth 与 BLE：GATT 模型与低功耗设计：NFC 传递配对密钥，BLE 传大数据。
  • 第十五章：USB 总线：拓扑、描述符与 CDC 虚拟串口：PC 用 USB NFC 读卡器 开发调试。
  • 支付：EMVCo、HCE（Host Card Emulation）在 SE/TEE 中存密钥。

五、开发

  • Android：NfcAdapter、enableReaderMode。
  • MCU：PN532、MFRC522（SPI/第七章：I2C）+ 天线设计。
  • 安全：Tag 可只读；支付与门禁依赖芯片级密钥，勿明文存敏感数据于可写 Tag。

要点 结论

数据格式 NDEF 统一封装 URI/文本/Wi-Fi/蓝牙配对数据
典型组合 NFC 递密钥加速 BLE 配对，大数据走 BLE/Wi-Fi

第十三章：Bluetooth 与 BLE：GATT 模型与低功耗设计

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 667 阅读时长 ≈ 2 分钟

第十三章：Bluetooth 与 BLE：GATT 模型与低功耗设计

概念基础

  1. Bluetooth（蓝牙）工作在 2.4GHz ISM 频段，是短距离无线技术；今天物联网的主角是 BLE（Bluetooth Low Energy，蓝牙低功耗，4.0 起），为纽扣电池供电的小设备而生。
  2. BLE 的核心是 GATT：设备暴露服务（Service）→ 特征值（Characteristic）的属性树，手机等 Central 通过读写/订阅特征值与 Peripheral 交互，数据模型像访问资源一样清晰。
  3. 广播先行：BLE 设备平时广播（可携带自定义数据，即 Beacon），Central 扫描后再发起连接——不连不上、先广播，这与 Wi-Fi「先关联再通信」完全不同。
  4. 为什么省电：深度休眠 + 快速建立连接，只在事件发生时短暂收发；配合 Notify/Indicate 让外设主动推送，避免轮询空耗电。
  5. 定位：手环、传感器、智能家居直连手机的场景；需要跨厂商标准化互操作时选 Zigbee（见 第十六章：Zigbee：基于 802.15.4 的 Mesh 组网），配对加速可用 NFC 递密钥。

BLE GATT 模型

一、BLE 角色

角色 说明
Central 发起连接，如手机、网关
Peripheral 广播、被连接，如手环、温湿度计
Broadcaster / Observer 仅广播/扫描（Beacon）

连接后通过 ATT/GATT 读写特征值（Characteristic）。

二、GATT 模型

  • UUID：16 位标准 UUID 或 128 位自定义。
  • Notify/Indicate：外设主动推送数据，省 polling 功耗。

三、配对与安全

  • Just Works / Passkey / OOB 等配对模式。
  • LE Secure Connections（ECDH）防中间人。
  • 与 第十四章：NFC 近场通信：工作模式与 NDEF tap-to-pair：NFC 交换临时信息辅助 BLE 配对。

经典 BLE
功耗 较高 极低

音频耳机等多用 经典 + BLE 双模芯片。

  • 芯片：Nordic nRF、ESP32（Bluedroid/NimBLE）、TI CC2340。
  • 与 第十五章：USB 总线：拓扑、描述符与 CDC 虚拟串口：BLE dongle 常通过 USB 接 PC；逻辑仍是无线 GATT。
