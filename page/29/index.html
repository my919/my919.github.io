第十二章：LoRaWAN：远距离低功耗星型组网

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 745 阅读时长 ≈ 2 分钟

第十二章：LoRaWAN：远距离低功耗星型组网

概念基础

  1. LoRaWAN 是构建在 LoRa 扩频射频之上的开放网络协议：终端节点通过网关接入 Network Server，典型覆盖公里级，专为电池供电、小数据量、上报为主的物联网场景设计。
  2. LoRa ≠ LoRaWAN：LoRa 是 Semtech 的物理层调制技术（Chirp Spread Spectrum，灵敏度高、抗干扰强）；LoRaWAN 是其上的 MAC 层协议（入网激活、速率自适应、双向调度）——「电台」与「通信规约」的关系。
  3. 星型拓扑换功耗：节点只与网关直连一跳，不做 mesh 路由转发，省去中继耗电，换来数年电池寿命；覆盖靠增加网关与 ADR 速率自适应来平衡。
  4. 速率换距离：SF（扩频因子）越大，速率越低、传得越远，网络侧按链路质量动态调整，本质是「速率-距离-容量」的三角权衡。
  5. 定位：智能抄表、资产追踪、农业监测等公里级、极低速率场景；高吞吐走 Wi-Fi/以太网 + MQTT/HTTP，局域 mesh 则选 Zigbee / 蓝牙 Mesh。

先看整体架构：

星型拓扑架构



flowchart TB
  Dev1[终端节点] --> GW[LoRa 网关]
  Dev2[终端节点] --> GW
  GW --> NS[Network Server]
  NS --> App[应用服务器]

一、架构

  • Gateway：只做射频转发，不解密应用 payload（取决于模式）。
  • ADR（Adaptive Data Rate）：网络侧调节 SF/功率平衡距离与容量。

二、区域参数

区域 典型频段
EU868 863–870 MHz
US915 902–928 MHz
CN470 470–510 MHz

需遵守当地无线电法规；模块需合规认证。

三、设备 Class

Class 下行窗口 功耗
A 仅上行后两个短窗口 最低，传感器常用
B 附加信标窗口 中
C 几乎常开接收 高，供电设备

四、安全

  • Join：OTAA（Over-The-Air Activation，推荐）或 ABP（预置密钥）。
  • AES-128：NwkSKey、AppSKey 分层加密与完整性。
  • 应用层仍可封装 第十一章：CoAP：REST over UDP 的物联网应用协议 或自定义二进制。

五、与其它物联网协议

  • 长距离、低带宽、电池 → LoRaWAN。
  • 有 Wi-Fi/以太网、高吞吐 → 第十二章：MQTT 详解：发布订阅、QoS 与 mosquitto / Python 示例、第二章：HTTP 详解：报文、方法、版本与 curl/nc 示例。
  • 局域 mesh → 第十六章：Zigbee：基于 802.15.4 的 Mesh 组网、第十三章：Bluetooth 与 BLE：GATT 模型与低功耗设计 Mesh。

开源栈：LoRaMac-node、Semtech LoRaWAN Stack；云平台：TTN、ChirpStack 等。

本章小结

要点 结论
架构 节点 → 网关（仅射频转发）→ Network Server → 应用服务器
功耗 星型无路由转发，Class A 可电池工作数年
速率 SF 越大越远越慢，ADR 动态平衡速率与距离
入网安全 推荐 OTAA 动态激活；NwkSKey/AppSKey 双层 AES-128
选型边界 公里级低速率选 LoRaWAN，局域 mesh 选 Zigbee/蓝牙 Mesh

第十一章：CoAP：REST over UDP 的物联网应用协议

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 714 阅读时长 ≈ 2 分钟

第十一章：CoAP：REST over UDP 的物联网应用协议

概念基础

  1. CoAP（Constrained Application Protocol，受限应用协议）是给单片机、低带宽网络用的应用层协议：把 Web 的 REST 模型（GET / PUT / POST / DELETE 操作资源）搬到 UDP 之上。
  2. 为什么轻量：报文头仅 4 字节起（对比 HTTP 动辄数百字节），二进制紧凑编码，默认端口 5683 / 5684（DTLS），RAM/Flash 占用极小，可直接跑在 6LoWPAN 等受限链路上。
  3. 请求/响应 + 订阅两种模式：既支持类 HTTP 的请求-响应，又通过 Observe（RFC 7641） 让服务器在资源变化时主动推送 NOTIFY，传感器上报无需反复轮询。
  4. 可靠性自选：UDP 本身不可靠，CoAP 用 CON / NON / ACK / RST 消息类型自己决定要不要确认重传——把「要不要可靠」交给应用按需选择。
  5. 定位：资源型设备（一台设备就是一组可读写的资源）的首选；海量消息汇聚与发布订阅则更适合 Broker 型的 MQTT，二者在同一系统里常互补出现。

一次典型交互长这样：

REST over UDP 交互



sequenceDiagram
  participant C as CoAP Client
  participant S as CoAP Server
  C->>S: GET /temp
  S-->>C: 2.05 Content 25.3
  C->>S: Observe 订阅
  S-->>C: 推送变化

一、设计目标

  • 低开销：适合 MCU、6LoWPAN、低带宽链路。
  • 异步：支持 Separate 响应（ACK 先回，结果稍后 CON 通知）。
  • 发现：.well-known/core 资源目录。

默认端口 5683（CoAPS 5684）。

二、报文（简化）

Type 含义
CON 需确认
NON 不需确认
ACK 确认
RST 复位

Code：0.xx 请求（GET=0.01），2.xx 成功，4.xx/5.xx 错误（类比 HTTP）。

三、Observe（RFC 7641）

客户端带 Observe Option 订阅资源；服务器在资源变化时 NOTIFY，适合传感器推送，比轮询省流量。

四、与 MQTT

CoAP 第十二章：MQTT 详解：发布订阅、QoS 与 mosquitto / Python 示例
模型 REST 资源 发布/订阅 Topic
传输 UDP 为主 TCP 常见
代理 CoAP-HTTP 代理 Broker 中心化

物联网选型：资源型设备、LwM2M（基于 CoAP）vs 海量消息经 Broker 的 MQTT。

五、应用

  • 智能抄表、楼宇传感器、Edge 网关 南向 CoAP、北向 HTTP/第十二章：MQTT 详解：发布订阅、QoS 与 mosquitto / Python 示例。
  • 安全：DTLS 预共享密钥或证书；与 第十二章：LoRaWAN：远距离低功耗星型组网 可组合（应用 payload 再解析）。

库：libcoap、aiocoap（Python）、Californium（Java）。

本章小结

要点 结论
模型 REST 风格操作资源，类 HTTP 但跑在 UDP 上
开销 头部 4 字节起，二进制紧凑，适合 MCU 与受限网络
可靠性 CON/NON/ACK/RST 自选确认与重传
推送 Observe 订阅-通知，比轮询省流量
安全 DTLS（PSK 或证书），默认端口 5683/5684

第十章：LIN 总线：单主多从与调度表

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 632 阅读时长 ≈ 2 分钟

第十章：LIN 总线：单主多从与调度表

概念基础

  1. LIN（Local Interconnect Network，局部互联网络）是低成本的单主多从串行总线：一根总线挂一个 Master 与若干 Slave，常见于车窗、座椅、雨刮等车身电子。
  2. 为什么便宜：基于普通 UART 硬件即可实现，物理层常用单线、12V 电平，收发器（如 TJA1021）远比 CAN 便宜，从节点甚至可用廉价 8 位 MCU——它就是 CAN 的「经济版补充」。
  3. 无仲裁、靠调度：与 CAN 的竞争仲裁不同，LIN 由 Master 固定调度：Master 发 Header（含 PID），对应 Slave 填 Response，时序确定、天然无冲突。
  4. 帧结构简单：Break + Sync(0x55) + PID + Data(1~8) + Checksum，速率约 20 kbps，只适合非安全、低带宽场景。
  5. 定位：动力底盘走 CAN、车身舒适系统走 LIN，网关 ECU 常同时挂两种总线；它的「单主轮询」思想与工业里的 Modbus 主从也一脉相承。

先看单主多从的拓扑：

单主多从拓扑



flowchart LR
  Master[LIN Master ECU] --- Bus[LIN 总线]
  S1[从节点 门窗] --- Bus
  S2[从节点 座椅] --- Bus

一、角色

  • Master：通常由 Body ECU 担任，发送 Header（含 PID）。
  • Slave：响应 Data 或发布自身数据；无仲裁，时隙由 Master 调度。

二、帧结构（简化）

  • Break：显性低电平较长，同步从机。
  • PID：含 6 位 ID + 2 位奇偶。
  • Checksum：Classic 或 Enhanced（LIN 2.x）。

三、调度表（Schedule Table）

Master 按固定周期发送各 Frame ID，保证确定性延迟；配置在 LDF（LIN Description File）中，工具链生成驱动代码。

四、与 CAN

LIN 第九章：CAN 总线：帧结构、多主仲裁与 CAN FD
成本 低（常单线） 收发器稍贵
速率 ~20 kbps 最高 Mbps 级
拓扑 单主 多主
用途 非安全、低带宽 动力、底盘、网关

网关 ECU 常同时接 CAN 与多条 LIN 总线。

五、硬件与调试

  • 物理层：12V 系统常见，收发器如 TJA1021。
  • 调试：LIN 分析仪、USB-LIN 适配器；协议依 LIN 2.0/2.1/2.2 与 ISO 17987。

与 第五章：RS232 不同：LIN 有固定 Break/Sync 与 PID 语义，不是裸串口文本。

本章小结

要点 结论
拓扑 单主多从：Master 发 Header、Slave 响应
成本 单线 12V + UART 级硬件，远低于 CAN
帧结构 Break + Sync + PID + Data(1~8) + Checksum
确定性 依赖调度表（LDF 配置），延迟固定可预期
适用边界 ~20 kbps、非安全相关，车身舒适系统首选

第九章：CAN 总线：帧结构、多主仲裁与 CAN FD

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 784 阅读时长 ≈ 3 分钟

第九章：CAN 总线：帧结构、多主仲裁与 CAN FD

概念基础

  1. CAN（Controller Area Network，控制器局域网）是 Bosch 为汽车电子设计的多主串行总线：所有 ECU 节点挂在一对差分线（CAN_H / CAN_L）上，以广播帧通信，各节点按 ID 自行过滤收帧。
  2. 为什么抗干扰：差分传输让共模噪声相互抵消，配合总线两端的 120Ω 终端电阻抑制信号反射，适合发动机舱等电磁环境恶劣的场景——这与单端电平的 RS232 是本质差别。
  3. 多主无损仲裁：总线空闲时任意节点都可发送，逐 bit 仲裁中发显性 0 的胜出、ID 越小优先级越高，败者自动退为接收方，既不丢帧也不需要中心主站。
  4. 硬件级可靠性：帧尾 CRC + ACK 硬件检错与确认，出错自动重发；故障节点经错误计数进入 bus-off 主动离线，不会拖垮整条总线。
  5. 定位：汽车动力、底盘、网关等实时、安全相关场景的主力总线，速率 125 kbps ~ 1 Mbps；CAN FD 把数据段扩到 64 字节并提升数据段速率；车身低成本传感器则交给 LIN（见 第十章：LIN 总线：单主多从与调度表）。

先看整体拓扑：

总线拓扑



flowchart LR
  ECU1[ECU 节点 1] --- BUS[CAN_H / CAN_L 总线]
  ECU2[ECU 节点 2] --- BUS
  ECU3[ECU 节点 3] --- BUS

一、经典 CAN 帧（概念）

字段 说明
仲裁 ID 11 位（标准）或 29 位（扩展），越小优先级越高
RTR 远程帧（较少用）
DLC 数据长度 0~8 字节
Data 载荷
CRC + ACK 硬件检错与确认

二、多主仲裁

总线空闲时多个节点可同时发送；ID 仲裁时逐 bit 比较，发显性 0 的胜出，失败者自动退为接收方，无中心主站。

三、速率与长度

速率 典型最大总线长度（粗估）
1 Mbps 数十米
500 kbps ~100m
125 kbps 更长

实际以收发器、电缆与拓扑仿真为准。

四、CAN FD

  • 数据段可 > 8 字节（最高 64），数据段波特率可高于仲裁段。
  • 新车载网络大量采用 CAN FD；旧 ECU 可能仅 Classic CAN。

MCU 侧：bxCAN、FDCAN 外设 + 收发器（TJA1050 等）。

五、与其它总线

总线 场景
第十章：LIN 总线：单主多从与调度表 车身低成本传感器，单主
第六章：RS485 + 第一章：Modbus RTU 工业 PLC
CAN 汽车、机器人关节、安全相关

上层协议：CANopen、J1939、UDS（诊断）等建立在 CAN 帧之上。

本章小结

要点 结论
物理层 CAN_H / CAN_L 差分 + 两端 120Ω 终端电阻，抗干扰强
仲裁 多主、逐 bit 非破坏性仲裁，ID 越小优先级越高
可靠性 CRC + ACK + 错误计数 bus-off，硬件级容错
速率与距离 125 kbps ~ 1 Mbps，速率越高可用距离越短
演进 CAN FD 数据段最大 64 字节，数据段波特率可独立提高

第八章：SPI

概念基础

  1. SPI（Serial Peripheral Interface）是 Motorola 提出的四线同步全双工总线：SCLK / MOSI / MISO / CS，板级高速外设互联的主力。
  2. 主驱时钟：主站产生 SCLK，数据按约定边沿采样；主从的 CPOL/CPHA 模式必须一致（Mode 0~3），这是 SPI 调试最常见的坑。
  3. 片选寻址：没有地址概念，每个从机一根独立 CS 线，多占一根线换取高速度；MISO 未选中时需保持三态。
  4. 为什么快：无地址开销、全双工、时钟可达几十 MHz，Flash、SD 卡、TFT 屏等高带宽外设首选。
  5. 取舍：线数多（每从机 +1 CS）、只适合短 PCB 走线；长距离/多机改用 RS485，少线低速场景可用 I2C，异步调试打印仍用 UART。

先看一主多从的连接：

一主多从



flowchart LR
  M[Master] -->|SCLK MOSI MISO| Flash[Flash CS0]
  M -->|独立 CS| SD[SD 卡 CS1]

一、信号

线 方向（相对 Master） 说明
SCLK 输出 时钟
MOSI 输出 Master Out Slave In
MISO 输入 Master In Slave Out
CS/SS 输出 低有效选中从机

二、CPOL / CPHA（模式 0~3）

  • CPOL：空闲时 SCLK 电平（0=低，1=高）。
  • CPHA：第几个边沿采样（0=第一边沿，1=第二边沿）。

主从 模式必须一致（数据手册会写 Mode 0 等）。

三、多从机

  • 独立 CS：每个从机一根 CS，MOSI/MISO/SCLK 共享（MISO 需三态，未选中不高驱）。
  • Daisy Chain：如部分 Shift Register、LED 驱动，数据串行穿过多芯片。

四、典型应用

  • Flash（W25Q）、SD 卡（SPI 模式）、ADC/DAC、TFT 屏、RF 模块（NRF24L01）。
  • 速率常 MHz~ tens of MHz，短 PCB 走线；长距离不如 第六章：RS485。

五、与 I2C

SPI 第七章：I2C
线数 4+（每从机 +CS） 2
速度 通常更快 400k/1M 常见
寻址 硬件 CS 7 位地址
双工 全双工 半双工

异步调试打印仍用 第四章：UART。

本章小结

要点 结论
信号 SCLK/MOSI/MISO/CS 四线，主驱时钟、全双工
模式 CPOL/CPHA 组成 Mode 0~3，主从配置必须一致
寻址 无地址，靠独立 CS 片选；MISO 未选中需三态
速度 无地址开销、全双工，可达几十 MHz，高带宽外设首选
局限 线多、仅短走线；远距离换 RS485，少线换 I2C

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 676 阅读时长 ≈ 2 分钟

第七章：I2C

概念基础

  1. I2C（Inter-Integrated Circuit）是 Philips 发明的两线同步总线：SCL 时钟 + SDA 数据，是板级互联传感器/存储器等外设的事实标准。
  2. 地址寻址多从：每个从设备有 7 位地址（0x00~0x7F），主设备以地址帧寻址——两根线即可挂多个器件，扩展外设几乎不加线。
  3. 开漏 + 上拉：SDA/SCL 均为开漏输出加上拉电阻，天然支持多主仲裁与时钟同步，也决定了速率上限（100k/400k/1M/3.4M）。
  4. 协议机制清晰：START/STOP 条件界定传输，逐字节 ACK/NACK 确认；读操作用重复 START 切换方向。
  5. 取舍：线最少、成本低，EEPROM/RTC/IMU/OLED 全支持；但速率不如 SPI，上拉取值需按总线电容与速率权衡。

先看总线拓扑：

总线拓扑



flowchart TB
  Master[主设备 MCU] --- SCL[SCL 时钟]
  Master --- SDA[SDA 数据]
  SDA --> S1[从设备 地址 0x48]
  SDA --> S2[从设备 地址 0x50]
  SCL --> S1
  SCL --> S2

一、信号与起始/停止

  • 空闲：SDA、SCL 均为高（靠上拉电阻）。
  • START：SCL 高时 SDA 下降沿。
  • STOP：SCL 高时 SDA 上升沿。
  • 数据位：SCL 低时 SDA 变化，SCL 高时采样。

二、7 位地址帧（写）

读操作：写寄存器指针 → 重复 START → 读地址 + 读数据 + NACK + STOP。

三、速率模式

模式 速率
Standard 100 kHz
Fast 400 kHz
Fast Mode Plus 1 MHz
High Speed 3.4 MHz（较少用）

上拉电阻：常见 2.2k~10k（3.3V、总线电容与速率相关）；长电缆或多设备需降低电容、可能用 I2C 缓冲器/扩展器。

四、典型设备

  • EEPROM（24Cxx）、RTC（DS3231）、IMU、OLED 小屏、PMIC、GPIO 扩展（PCF8574）。
  • 同一地址冲突：部分芯片有 ADDR 引脚改地址；否则需不同总线（I2C mux）。

五、与 SPI、UART

第八章：SPI 4+ 高 全双工、无标准地址
第四章：UART 2 + GND 中 点对点、异步

第九章：CAN 总线：帧结构、多主仲裁与 CAN FD 用于车载/工业现场总线，抗干扰与仲裁不同于 I2C。

第六章：RS485

概念基础

  1. RS485（TIA/EIA-485） 是差分电气标准：用 A/B 两线电压差表示信号，抗共模干扰强、可达上千米，是工业现场最常用的物理层。
  2. 总线型多机：一条双绞线手拉手（daisy-chain）挂多个节点，配合地址协议实现多机组网；总线两端各接 120Ω 终端电阻。
  3. 半双工：两线制同一时刻只能一个方向发送，收发器需 DE/RE 引脚切换方向。
  4. 只管电气不管语义：RS485 只解决「电信号怎么传」，上层要跑 Modbus RTU 等主从协议才能完成有效通信。
  5. 与 UART 的关系：MCU 的 UART 产生字节流，经 MAX485/SN65HVD 收发器转成差分信号——UART 管逻辑、485 管物理。

一、拓扑

  • 半双工：同一时刻只能一个方向发送；需 DE/RE 引脚控制收发器方向。
  • 共模范围：约 -7V ~ +12V，适合工业现场。

二、UART + RS485 收发器

发送前切换 DE；切换后需等待收发器稳定再发首字节，避免毛刺。

三、与 Modbus RTU

第一章：Modbus RTU 在 **RS485** 上最常见：**主站轮询**、**从站地址 1~247**、**CRC16** 帧尾。

与 第三章：Modbus ASCII 比，RTU 更紧凑、工业现场更常用。

四、对比 RS232

信号 单端 差分
距离 短 长
节点数 点对点为主 多机总线

五、布线注意

  • 双绞线、屏蔽层单端接地（现场依规范）。
  • 终端电阻 120Ω 仅在总线两端；中间节点不加。
  • GND 参考：虽为差分，仍建议可靠参考地，避免共模超范围。
  • ESD 与浪涌：户外/电机旁加保护器件。

拓扑 总线型手拉手，两端各接 120Ω 终端电阻，中间节点不加
双工 两线制半双工，发送前切 DE，切后等收发器稳定
组合 UART 控制器 + 485 收发器（MAX485/SN65HVD）
上层协议 最常见搭配 Modbus RTU（主站轮询、从站地址 1~247）

第五章：RS232

概念基础

  1. RS232 是 EIA 定义的串行物理层标准，规定电气电平、信号线与连接器（DB9）——「PC 老式 COM 口」背后的标准。
  2. 负逻辑电平：逻辑 1 是负电压（-5V~-15V），逻辑 0 是正电压（+5V~+15V），与 MCU 的 TTL UART（0/3.3V）完全不同，必须经 MAX232 等芯片做电平转换。
  3. 点对点、单端：一收一发加共地，抗干扰弱、典型距离 < 15m，速率与距离反相关。
  4. 为什么仍要学：工业仪器、老式 PLC、条码枪仍大量保留 DB9 口；PC 侧 USB 转 RS232 线依然是常用调试手段。
  5. 与 UART 的关系：UART 是控制器逻辑，RS232 是物理层电气标准；其上仍可跑 Modbus RTU 或自定义帧协议。

先看典型的 DTE-DCE 连接：

DTE-DCE 连接



flowchart LR
  PC[DTE PC] -->|TXD RXD GND| Conv[USB-RS232 转换]
  Conv --> Dev[DCE 设备]

一、电平与特点

  • 逻辑 1：负电压（如 -5V ~ -15V）
  • 逻辑 0：正电压（如 +5V ~ +15V）
  • 单端：抗干扰弱于 第六章：RS485 差分；距离通常 < 15m（与波特率反相关）。
  • 点对点：多机需额外切换，不像 RS485 总线型。

MCU 侧为 TTL 第四章：UART（0/3.3V），需 MAX232、SP3232 等芯片做电平转换。

二、最小三线连接

交叉连接 TX/RX；不要把 RS232 口直接接 MCU UART 引脚。

三、流控（可选）

DTR/DSR 设备就绪（Modem 时代遗留）
软件流控 XON/XOFF 字符

嵌入式调试常 115200 8N1 无流控。

四、应用场景

  • 工业仪器、老式 PLC、条码枪 DB9 口。
  • USB 转 RS232 dongle 在 PC 上模拟 COM 口。
  • 长距离、多机、抗干扰场景优先 RS485 或 以太网（第二章：Modbus TCP）。

协议层仍可能是 第一章：Modbus RTU 或自定义 ASCII 帧。

要点 结论
电平 负逻辑：1 = -5V-15V，0 = +5V+15V，与 TTL 不兼容
拓扑 点对点、单端，典型距离 < 15m，多机换 RS485
连接 最小三线 TXD/RXD/GND，TX/RX 交叉；禁止直连 MCU 引脚
电平转换 MCU TTL UART 经 MAX232/SP3232 接入
定位 老设备/仪器调试口；新设计长距离优先 RS485 或以太网

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 657 阅读时长 ≈ 2 分钟

第四章：UART

概念基础

  1. UART（通用异步收发器）是异步串行通信控制器：只用 TX/RX 两根信号线加共地，不传时钟，收发双方按约定的波特率各自采样。
  2. 异步帧：起始位(0) + 数据位(通常 8) + 可选校验位 + 停止位(1)；空闲为高电平，起始位拉低完成一次同步，数据 LSB 先发。
  3. 为什么无处不在：实现极简、调试直观，日志打印、AT 指令、GPS NMEA、Bootloader 都走 UART，是嵌入式最基础的调试与互联手段。
  4. 只是逻辑层：UART 引脚是 TTL 电平（0/3.3V），接 PC 老串口或工业总线需 MAX232（RS232）、MAX485（RS485） 等收发器转换物理层。
  5. 点对点：无从机地址、无仲裁，多机组网要靠上层协议或改用总线型物理层。

先看最基本的连接形态：

点对点连接



flowchart LR
  MCU1[MCU A TX] -->|RX| MCU2[MCU B RX]
  MCU2 -->|TX| MCU1

一、异步帧结构

  • 空闲：线路高电平。
  • 起始位：拉低，通知接收方开始采样。
  • LSB 先发：数据位从低位到高位。
  • 校验：None / Odd / Even（可选）。
  • 停止位：1 或 2 位高电平，恢复空闲。

二、波特率

常见：9600、115200、921600。收发双方波特率必须一致（误差通常 < 2%）。

三、电平与接口层

层次 说明
TTL UART MCU 引脚 3.3V/5V，直连 USB-TTL 模块
第五章：RS232 ± 电平，PC 老式串口、部分工业设备
第六章：RS485 差分、半双工、多机总线，常经 UART+收发器

UART 指控制器逻辑；对外物理层常加 MAX232、MAX485 等芯片。

四、应用与调试

  • 日志打印、AT 指令（4G/Wi-Fi 模块）、GPS NMEA、Bootloader。
  • Linux：/dev/ttyUSB0，minicom / picocom / screen。
  • 注意：TX 接 RX 交叉；共地 GND 必须连接。

与 第八章：SPI、第七章：I2C 对照：UART 线少、距离短（TTL）、协议简单，无硬件从机地址。

本章小结

要点 结论
本质 两线异步串行控制器，不传时钟，靠约定波特率采样
帧格式 起始位 + 数据位（LSB 先发）+ 可选校验 + 停止位
关键参数 双方波特率必须一致（误差 < 2%），常见 9600/115200
物理层 TTL 引脚直连需共地；上 RS232/RS485 需收发器转换
调试要点 TX/RX 交叉、必须共地；Linux 用 minicom/picocom/screen

第三章：Modbus ASCII

概念基础

  1. Modbus ASCII 是 Modbus 的文本编码变体：每个字节用两个 ASCII 十六进制字符（0-9 A-F）表示，帧以 : 开始、CR LF 结束。
  2. 为什么存在：早期调制解调器/串口终端时代，文本帧人眼可读、可直接粘贴调试，字符间容忍度也比 RTU 严格的 3.5 字符静默宽松。
  3. 校验不同：RTU 用 CRC16，ASCII 用 LRC（8 位求和取补码）——检错能力较弱但实现极简。
  4. 代价：同样数据传输长度约 2 倍、带宽利用率低，新项目工业现场几乎都选 RTU，ASCII 只保留在老设备与维护口。
  5. 同一套 PDU：与 RTU/TCP 的功能码与寄存器语义完全一致，切换链路层不影响上层应用逻辑。

一、帧格式

示例（读保持寄存器，概念）：

  • : 起始。
  • 每字节用 两个 ASCII 十六进制字符（0-9 A-F）。
  • CR LF 结束（0x0D 0x0A）。

二、LRC

对 地址到数据末字节 求和（8 位），取二进制补码（256 - sum），再转两个 ASCII 十六进制字符。

RTU 使用 CRC16；ASCII 用 LRC，检错能力较弱但实现简单。

三、与 RTU / TCP

变体 编码 效率 场景
RTU 二进制 高 RS485 主流
ASCII 文本 HEX 低（约 2× 字节） 调试、老设备
第二章：Modbus TCP 二进制 + MBAP 高 以太网

同一 PDU 功能码 语义一致；切换链路层时注意地址与寄存器映射相同。

四、调试

  • 串口终端可直接粘贴 : 帧（若设备支持 ASCII 模式）。
  • 物理层常为 第五章：RS232 或 第六章：RS485 + 第四章：UART。
  • 生产系统优先 RTU 或 TCP，ASCII 多用于维护口。

效率 传输体积约 2 倍，工业新项目首选 RTU
价值 可读可粘贴，适合调试与老设备维护
兼容 PDU 功能码语义与 RTU/TCP 完全一致
