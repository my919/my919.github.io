第五章：OpenSSL 非对称加密与密钥交换：RSA、Ed25519、X25519

概念基础

  1. 非对称加密：公钥 / 私钥成对，公钥公开分发、私钥绝对保密——解决了对称加密「密钥如何安全送达」的死结（对称加密见第四章）。
  2. 三大用途：数字签名（私钥签、公钥验，见第六章）、密钥交换（ECDHE/X25519 在不安全信道协商会话密钥）、小数据加密（RSA-OAEP 加密对称密钥）。
  3. 为什么 TLS 用混合方案：非对称慢（比对称慢几个数量级），只用于握手阶段；海量数据用协商出的对称会话密钥（AES-GCM）加密。
  4. 前向保密（PFS）：握手使用临时密钥对（X25519 / ECDHE），即使服务器长期私钥日后泄露，历史会话也解不开——静态 RSA 密钥传输因此被淘汰。
  5. 选型一句话：签名与证书新系统优先 Ed25519 / ECDSA P-256，密钥交换用 X25519，RSA 2048+ 仍是最普遍的兼容选择。

推荐选型（2020s）

用途 推荐 避免 / legacy
TLS 证书 / 代码签名 ECDSA P-256、Ed25519；RSA 仍普遍 RSA < 2048 bit
TLS 密钥交换 X25519（ECDHE） 静态 RSA 密钥传输、DHE 1024 bit
SSH / 现代签名 Ed25519 DSA
小数据 RSA 加密 RSA-OAEP 2048+（仅短载荷） PKCS#1 v1.5 加密、裸 RSA
长期根 CA RSA 4096 或 EC P-384 RSA 1024

第四章：OpenSSL 对称加密：AES-GCM、ChaCha20 与推荐用法

发表于 2026-05-01 更新于 2026-09-01 分类于 OpenSSL 本文字数： 1.1k 阅读时长 ≈ 4 分钟

第四章：OpenSSL 对称加密：AES-GCM、ChaCha20 与推荐用法

概念基础

  1. 对称加密：加密与解密使用同一把密钥，速度快、开销低，适合大块数据（文件、磁盘、TLS 记录层流量）。
  2. 两大要素：算法 + 工作模式（如 AES-256-GCM）决定安全性质；密钥来自随机数或口令派生（PBKDF2，见第七章）。
  3. 为什么推荐 AEAD：GCM / ChaCha20-Poly1305 属于认证加密，同时提供保密性 + 完整性（Auth Tag 防篡改）；裸 CBC / ECB 无认证，存在填充 oracle 等风险。
  4. Nonce 纪律：GCM 的 (key, nonce/IV) 绝不能重复，否则密钥流泄露、安全性崩塌——这是使用 AEAD 的头号大坑。
  5. 口令 ≠ 密钥：人类口令熵低、可猜测，必须经 KDF（salt + 高迭代） 派生密钥；生产环境更推荐随机 32 字节密钥。

推荐算法（2020s 生产）

优先级 算法 / 模式 用途
首选 AES-256-GCM 文件加密、磁盘、API 载荷（须唯一 nonce）
首选（无 AES 硬件加速时） ChaCha20-Poly1305 移动端、部分 TLS 1.3 套件
可用 AES-256-CBC + HMAC（Encrypt-then-MAC） 老系统；须正确实现
避免 AES-CBC 无 MAC、ECB、DES/3DES、RC4 填充 oracle、模式泄露、已淘汰

第三章：OpenSSL 哈希算法：SHA-256、SHA-3 与推荐用法

发表于 2026-05-01 更新于 2026-09-01 分类于 OpenSSL 本文字数： 1k 阅读时长 ≈ 3 分钟

第三章：OpenSSL 哈希算法：SHA-256、SHA-3 与推荐用法

概念基础

  1. 哈希（Hash）是单向函数：任意长度输入 → 固定长度摘要（SHA-256 输出 256 bit），不可逆——无法从摘要还原原文。
  2. 三大特性：确定性（同输入必得同输出）、雪崩效应（改动 1 bit，摘要面目全非）、抗碰撞性（极难找到两个不同输入对应同一摘要）。
  3. 为什么需要：完整性校验（下载包比对、防篡改）、签名输入（先哈希再签名，见第六章）、口令派生（加盐迭代，见第七章）、区块链 Merkle 树等。
  4. 哈希 ≠ 加密：哈希不可逆、无密钥，用于完整性与指纹；对称加密可逆、有密钥，用于保密性（本章末尾有对照表）。
  5. 选型一句话：新系统一律 SHA-256 / SHA-512，需要算法多样性时上 SHA-3；MD5、SHA-1 仅用于遗留系统兼容。

算法选型（推荐）

场景 推荐 避免
文件完整性校验、软件发布 SHA-256、SHA-512 MD5、SHA-1
密码存储 Argon2 / bcrypt（应用层库）+ 盐；OpenSSL 侧用 PBKDF2-HMAC-SHA256 见 第七章：OpenSSL 密钥派生与随机数：PBKDF2、rand 与推荐用法 裸 SHA-256(password)
证书/CSR 签名摘要 SHA-256 SHA-1
长数据流式哈希 SHA-256 —
新标准/长摘要需求 SHA-3-256 —

第一章：OpenSSL 命令行入门与常用操作总览

概念基础

  1. OpenSSL 是一个开源密码学工具包：对外提供 openssl 命令行工具（生成密钥、证书、加解密、签名），对内提供底层密码库（libcrypto / libssl），是 TLS/HTTPS 生态的事实标准。
  2. 它解决三类安全问题：保密性（对称 / 非对称加密）、完整性（哈希 / HMAC）、身份认证（数字证书 + CA 信任链）；HTTPS 正是三者的组合应用。
  3. 四个核心对象：私钥（.key / .pem，必须保密，用于解密、签名）；公钥（从私钥导出，公开分发，用于加密、验签）；证书（.crt / .pem，包含公钥 + 身份信息 + 签名，证明公钥合法）；CSR（证书签名请求，.csr，向 CA 机构申请正式证书的文件）。
  4. 为什么重要：Nginx、curl、Python、Java、手机系统等几乎所有软件的加密通信都依赖它——掌握 OpenSSL 命令行，等于掌握证书、加密、签名的通用钥匙。
  5. 本章定位：侧重命令行实操，给出从摘要、密钥到证书签发、格式转换的完整工作流；各算法的原理与选型详见后续章节。

OpenSSL 是生成、管理非对称密钥和数字证书的标准工具，广泛用于 第四章：HTTPS 详解：TLS 握手、证书与 openssl/curl 示例、SSL/TLS、身份认证等。能力概览见 第二章：OpenSSL 功能全景与自建局域网 CA 实战；算法分类与推荐用法见下表。

第三章：滤波与几何变换

概念基础

  1. 滤波 = 用邻域算出新值：每个像素根据周围邻域（核）重新计算——模糊、锐化、边缘、形态学都是滤波的不同形式。
  2. 频域直觉：低通滤波（模糊）去噪但模糊边缘，高通滤波（锐化/边缘）增强细节但放大噪声，二者是图像处理的阴阳。
  3. 几何变换改位置不改值：缩放、旋转、仿射、透视改变像素「在哪」，需插值填补新格点的值。
  4. 阈值二值化是分割起点：把灰度图按阈值切成前景/背景，是许多检测流水线的第一步。
  5. 本章目标：掌握常用滤波（高斯/中值/双边）、形态学（腐蚀/膨胀/开闭运算）、几何变换（缩放/旋转/仿射/透视）、阈值化，能组合去噪与分割。

本章承接 第二章：图像基础操作 的数组与色彩基础。

一、模糊（低通滤波）

模糊 特点 适用
均值 简单均匀 轻度降噪
高斯 中心权重高，自然 通用降噪、预处理
中值 去孤立噪点 椒盐噪声
双边 同时考虑空间与灰度差，保边 保边去噪（美颜）

核大小必须为正奇数（5×5、7×7），偶数报错。

二、锐化与边缘（高通滤波）

  • filter2D：任意卷积核，-1 表示输出与输入同深度。
  • Canny 双阈值：低阈值 50 连边、高阈值 150 确认为强边，中间的靠连接保留。
  • CV_64F：梯度有负值，需用浮点防截断，显示前 convertScaleAbs 转回 uint8。

三、形态学运算

形态学作用于二值图，用结构元素（kernel）做邻域极值：

运算 等价 用途
腐蚀 min 去除小白点、细化
膨胀 max 连接断裂、加粗
开运算 腐蚀→膨胀 去小白点（噪声）
闭运算 膨胀→腐蚀 填小黑洞
梯度 膨胀−腐蚀 提取边缘

形态学也可用于灰度图（取邻域 max/min），但最常见于二值图后处理。

五、阈值化

  • 全局阈值：光照均匀时够用。
  • 自适应阈值：光照不均（如文档阴影）按局部邻域二值化，11 是块大小（奇数），2 是减常数。

边缘阈值全靠猜 用 Otsu 自动选，或先 pyplot.hist 看直方图

要点 结论

形态学 腐蚀/膨胀为基础，开运算去噪、闭运算填洞、梯度取边

第五章：视频与深度学习

发表于 2026-05-01 更新于 2026-09-01 分类于 OpenCV 本文字数： 1.8k 阅读时长 ≈ 6 分钟

第五章：视频与深度学习

概念基础

  1. 视频 = 时序帧序列：在单图处理之上多了「帧间关系」——运动检测、光流、跟踪都依赖相邻帧对比，是视频理解的核心。
  2. 背景建模分离运动：固定摄像头下，建立背景模型后，当前帧与背景之差即运动前景，是安防检测的经典思路。
  3. cv2.dnn 是推理不是训练：OpenCV 能加载 ONNX/Caffe/部分 TF 模型做前向推理，跨平台部署轻量模型；训练仍在 PyTorch 等框架完成。
  4. 前后处理是 OpenCV 的主场：深度模型要的 resize、归一化、BGR/RGB 转换、NMS、画框，全是 OpenCV 擅长的数组操作。
  5. 本章目标：掌握视频读写、光流、背景减除、dnn 推理与后处理，把前四章能力串成完整 CV 流水线。

本章承接 第四章：特征与几何，面向时序与深度模型衔接。视频编解码底层见 第一章：FFmpeg 音视频处理入门。

一、视频读写

1. VideoCapture 读取

摄像头/网络流 CAP_PROP_FRAME_COUNT 不可用；网络流用 cv2.CAP_FFMPEG 后端读 RTMP/RTSP。

2. VideoWriter 写出

  • fourcc：mp4v/avc1/X264 等，依后端可用编码；写不出时先换 fourcc。
  • 尺寸必须与帧一致，否则写空。
  • 底层依赖 FFmpeg 编解码——这就是 OpenCV 与 第一章：FFmpeg 音视频处理入门 的联系。

二、帧差法与背景减除（运动检测）

更鲁棒的背景建模（自动更新背景）：

  • 帧差法：简单但对静止目标失效。
  • MOG2/KNN：自适应背景，相机轻微抖动也能用，detectShadows 标阴影需二次阈值过滤。

三、光流（密集与稀疏）

光流估计像素运动场，用于跟踪与运动分析：

  • 稀疏 LK：跟踪特定角点，快，适合实时跟踪。
  • 密集 Farneback：全图运动，慢但信息全，可视化运动方向。

四、cv2.dnn 推理（加载 ONNX）

1. 加载模型与预处理

  • blobFromImage：scalefactor 缩放、size 目标尺寸、swapRB BGR→RGB、crop 是否中心裁剪。
  • swapRB=True：模型多按 RGB 训练，OpenCV 读的是 BGR，需交换。
  • GPU：编译时启用 CUDA 后端可 DNN_TARGET_CUDA 加速。

2. YOLO 风格后处理（NMS）

深度检测模型输出需后处理成最终框——解码框 + 置信度过滤 + NMS：

  • NMS（非极大值抑制）：重叠框只保留置信度最高的，0.4 是 IoU 阈值。
  • 训练用 第一章：PyTorch 入门与张量，导出 ONNX 后用 OpenCV 部署，是常见的轻量推理链路。

五、多目标跟踪：ByteTrack 思路（简述）

检测 + 关联是跟踪的通用框架：

  1. 每帧用检测器（YOLO/dnn）出框。
  2. 用 IoU 或卡尔曼预测把当前框与上一帧轨迹关联。
  3. 未匹配的检测开新轨迹，未匹配的轨迹保留若干帧后删除。

OpenCV 自带轻量跟踪器（单目标）：

多目标跟踪生产级多用 ByteTrack/ SORT + 深度检测器组合，OpenCV 负责检测前后处理与可视化。

六、完整流水线：视频检测可视化

七、常见陷阱

陷阱 说明
VideoWriter 尺寸不符 帧尺寸与构造参数不一致，写出空文件
fourcc 不支持 某些编码依赖后端，写失败先换 mp4v
blobFromImage 漏 swapRB BGR 送进 RGB 模型致检测错乱

dnn 后端未编译 CUDA 设了 CUDA 后端但 OpenCV 未编译支持会回退或报错

第四章：特征与几何

发表于 2026-05-01 更新于 2026-09-01 分类于 OpenCV 本文字数： 1.6k 阅读时长 ≈ 5 分钟

第四章：特征与几何

概念基础

  1. 特征 = 图像中可辨识的局部模式：角点、斑点、边缘交点等，在不同光照、尺度、视角下仍能被稳定检测与匹配，是图像配准、拼接、跟踪的基础。
  2. 检测 + 描述两步：先检测关键点位置，再计算描述子（高维向量）表征其邻域；匹配即比较描述子距离。
  3. 几何从像素到世界：单应性（Homography）描述两视图间的平面映射，4 对匹配点即可解出，用于拼接、AR、文档矫正。
  4. 轮廓是连通区域边界：从二值图提取轮廓，可算面积、外接矩形、近似多边形，是传统目标检测与计数的利器。
  5. 本章目标：掌握角点/特征检测与匹配、单应性求解、轮廓分析，理解传统 CV 几何处理的边界与深度模型的分工。

本章承接 第三章：滤波与几何变换。生产级检测/分割多交由 第一章：PyTorch 入门与张量 深度模型，OpenCV 负责几何与前后处理。

一、角点检测：Harris 与 Shi-Tomasi

角点在两方向都有强梯度，是稳定的特征点：

  • Harris：返回角点响应图，需自行阈值化。
  • goodFeaturesToTrack：直接返回前 N 个角点坐标，参数为（最大点数、质量阈值、最小间距）。

二、特征检测与描述：ORB/SIFT

1. SIFT（尺度不变）

SIFT 对尺度、旋转、光照变化鲁棒，4.x 起主包可用：

2. ORB（快速，免费）

ORB 速度远快于 SIFT 且无专利，实时场景首选：

3. 特征匹配

  • NORM_HAMMING：ORB 等二进制描述子用汉明距离；SIFT 等浮点描述子用 NORM_L2。
  • crossCheck=True：双向匹配，过滤误匹配。
  • 比值检验（Lowe’s ratio test）进一步筛优：近邻距离 / 次近邻 < 0.7 才保留。

三、单应性矩阵与图像拼接

由 4 对以上匹配点解 3×3 单应性矩阵，把一幅图「贴」到另一幅的平面：

应用：全景拼接、AR 平面贴合、文档/车牌矫正（第三章透视变换的进阶）。

单应性要求场景中存在平面（或纯旋转相机），非平面场景会有视差错位。

四、轮廓检测与分析

  • RETR_EXTERNAL：只取最外层轮廓；RETR_TREE 取全部层级。
  • CHAIN_APPROX_SIMPLE：压缩水平/垂直/对角冗余点，省内存。
  • 形状识别：approxPolyDP 顶点数 → 三角形 3、矩形 4、圆 >8。

五、模板匹配

在图中滑动模板找最相似位置（限定于平移、无尺度旋转）：

局限：matchTemplate 只对平移有效，目标有旋转/缩放则失效——这种情况改用特征匹配或深度模型。

六、传统 CV 与深度模型的分工

任务 传统（本章） 深度模型
图像配准/拼接 SIFT/ORB + 单应性 优势 少用
物体检测 模板匹配（仅平移）/轮廓 YOLO/DETR 优势
语义分割 阈值/分水岭 U-Net/Mask R-CNN 优势
几何测量 轮廓面积/周长 优势 —
实时跟踪 KCF/光流 Siamese 等深度跟踪

经验：几何与配准用传统 CV，识别与分割用深度模型，二者常组合——深度模型出框，OpenCV 做几何后处理。

七、常见陷阱

陷阱 说明
Harris 输入未转 float32 cornerHarris 需 float32 灰度，uint8 报错
ORB 用 L2 距离 ORB 二进制描述子须用 NORM_HAMMING
无比值检验误匹配多 只取最近邻会有大量误匹配，加 Lowe ratio test
单应性点不足 需 ≥4 对点，且不能共线，否则解不稳
轮廓忘过滤小面积 不滤噪点轮廓会画出一片碎点
模板匹配遇旋转 matchTemplate 不抗旋转缩放，需改特征匹配
findContours 改原图 该函数会修改输入图，传副本

要点 结论
角点 Harris 响应图、Shi-Tomasi 直接出点（goodFeaturesToTrack）
特征 SIFT 鲁棒、ORB 快且免费；检测+描述两步
匹配 BFMatcher/FLANN；二进制用汉明距离、浮点用 L2；加比值检验
单应性 4+ 对点 RANSAC 解 3×3，全景拼接/AR/矫正
轮廓 findContours + 面积/外接矩形/多边形近似，可识别形状
模板匹配 仅平移有效，旋转缩放失效
分工 几何配准用传统，识别分割用深度（见第五章）
