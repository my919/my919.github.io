1. 概念说明

人工智能（AI）是让机器具备”智能”的技术总称，包含三个层次：

  • 机器学习（ML）：从数据中自动学习规律，不显式编程。典型任务：回归（预测房价）、分类（识别垃圾邮件）、聚类（用户分群）。
  • 深度学习（DL）：用多层神经网络（NN）学习，是机器学习的子集，擅长图像、语音、文本等高维数据。
  • 大语言模型（LLM）：基于 Transformer 架构、在海量文本上预训练的超大模型，能理解并生成自然语言，是当前 AI 应用的主流形态。

核心流程：数据收集 → 数据清洗 → 特征工程 → 模型训练 → 模型评估 → 部署上线。本项目将从经典机器学习入手，再到深度学习，最后用 LLM 完成一个可落地的应用。

10. 常见误用与陷阱

坑 现象 解法
改了 _config.next.yml 不生效 本地预览菜单/样式无变化 该文件需复制到 node_modules/hexo-theme-next/_config.yml 才生效；改完务必跑 ./startup.sh 或手动 cp _config.next.yml node_modules/hexo-theme-next/_config.yml
zh-CN.yml 键名与 menu 键不一致 菜单显示英文键名（如 redis）而非中文 翻译键名必须与 _config.next.yml 的 menu 键完全一致，逐项核对大小写
子目录文章链接漏掉分类前缀 分类页链接写成 /标题/ 导致 404 permalink: :title/ 下子目录文章 URL 为 /分类/标题/，分类页与互链必须带分类前缀
未 hexo clean 直接 generate 改动不生效、旧页面残留 每次改配置/主题后先 npx hexo clean 再 generate，避免 db.json 与 public/ 缓存污染
sync-posts.sh 删文章后未重跑 分类页残留指向已删文章的失效链接 删除/移动文章后立即执行 ./sync-posts.sh，脚本会清空失效列表
permalink 用 :title/ 致同标题冲突 不同分类下同名文章 URL 互相覆盖 改用 :year/:month/:title/ 或显式带分类前缀，避免标题碰撞

15. 常见误用与陷阱

坑 现象 解法
GORM 软删除 + uniqueIndex 冲突 删除某用户后用相同 email 新建报 Duplicate entry gorm.Model 的 deleted_at 使记录仍存在；唯一索引改为 (email, deleted_at) 联合，或 gorm:"uniqueIndex:idx_email,where:deleted_at IS NULL"
gin.Context 在 goroutine 里用 请求结束后偶发 panic / 读到脏数据 c 非线程安全；跨 goroutine 必须 cCopy := c.Copy() 传副本，原 c 仅在请求生命周期内可用

*gorm.DB 连接池未限制 高并发下 DB 连接数飙升、被拒连 sqlDB, _ := db.DB(); sqlDB.SetMaxOpenConns(50); SetMaxIdleConns(10)，默认 0=无上限

14. 常见误用与陷阱

坑 现象 解法
Feign 调用 404 / 找不到实例 @FeignClient(name="user-service") 调用报 404 或负载均衡报无可用实例 name 必须等于提供方 spring.application.name（区分大小写/连字符）；确认提供方已注册到 Nacos 且 namespace 一致
Feign 不透传请求头 下游拿不到 Authorization/traceId，鉴权失败、链路追踪断 Feign 默认不传上游 header；实现 RequestInterceptor 把需要的头塞进 RequestTemplate
Gateway lb:// 报 503 路由 uri: lb://user-service 返回 503 Service Unavailable 缺 spring-cloud-starter-loadbalancer 依赖；Spring Cloud 2021+ 不再默认带，需显式引入才能解析 lb://
Sentinel fallback 不生效 调用失败不进降级类、直接抛异常 feign.sentinel.enabled: true 必须开；fallback 类要注册为 Bean 且 @FeignClient(fallback=...) 指定；fallback 方法签名须与接口一致
@GlobalTransactional 不回滚 远程调用失败但本地写入未回滚 tx-service-group 必须与 Seata 服务端 vgroup-mapping 一致；业务库需建 undo_log 表；AT 模式下所有分支须用支持本地事务的数据源
Nacos 服务注册了但发现不到 消费方报 “No instances available” 注册中心与消费方的 namespace/group 不一致；dev/prod 命名空间隔离，跨 namespace 不可见，须对齐
bootstrap.yml 不生效 Nacos 配置没加载、@Value 取不到值 Spring Cloud 2020+ 默认停用 bootstrap；加 spring-cloud-starter-bootstrap，或改用 spring.config.import=nacos:...
@RefreshScope 改配置不刷新 Nacos 改了配置但接口返回旧值 data-id 须为 服务名-环境.后缀（如 user-service-dev.yaml）；Bean 须加 @RefreshScope；检查 namespace/group 与配置一致

坑 现象 解法
FromRow 字段顺序与 SQL 列不一致 ColumnNotFound / 解析出错 #[derive(FromRow)] 默认按列名匹配，但 SELECT * 列序须与结构体字段对齐；用 SELECT id, name, email 显式列举，或加 #[sqlx(rename = "real_col")]
