1. 概念说明

分布式系统是把一个系统拆成多个独立部署、通过网络协作的节点。带来的核心矛盾：网络不可靠 + 节点会失败。

CAP 定理：分布式系统无法同时保证一致性（C）、可用性（A）、分区容错性（P），网络分区必然发生（P 必选），只能在 C 和 A 之间取舍。

BASE 理论（AP 系统的落地指导）：

  • Basically Available：基本可用（降级、限流）
  • Soft State：软状态（允许中间态）
  • Eventually Consistent：最终一致

分布式系统三大基础设施问题：分布式锁（多节点互斥）、分布式 ID（全局唯一）、分布式事务（跨库一致性）。

设计 · 模式

从 0 到实战应用。设计原则 · 创建型/结构型/行为型模式 · 模式选型 · 项目落地案例 · 反模式避坑。代码带详细注释。

技术栈速查

类别 选型 用途
语言 Java 21 模式示例
核心原则 SOLID 设计指导原则
实战载体 Spring Boot 4 框架中的模式应用
测试 JUnit 5 验证模式行为

1. 概念说明

设计模式（Design Pattern）是软件设计中经过验证的、可复用的解决方案模板，解决特定场景下的重复问题。它不是代码库，而是一套”经验公式”。

为什么要学：不是所有代码都需要模式，但理解模式能让你：

  1. 用准确词汇描述设计（沟通成本低）
  2. 复用成熟方案，避免重复造轮子
  3. 看懂主流框架（Spring、Netty、JDK 大量使用模式）

六大设计原则（SOLID）：

原则 含义
S 单一职责 一个类只做一件事
O 开闭原则 对扩展开放，对修改关闭
L 里氏替换 子类可替换父类且行为不变
I 接口隔离 用多个专用接口代替一个胖接口
D 依赖倒置 依赖抽象，不依赖具体实现

三类模式：创建型（怎么创建对象）、结构型（怎么组合对象）、行为型（怎么交互协作）。

2. 模式全景速查

分类 模式 一句话场景
创建型 单例 全局唯一实例（配置、连接池）
创建型 工厂方法/抽象工厂 由工厂创建对象，客户端不 new
创建型 建造者 复杂对象分步构建（Lombok @Builder）
创建型 原型 克隆对象（深/浅拷贝）
结构型 适配器 接口不兼容时转接（类库集成）
结构型 装饰器 动态增强功能（IO 流、日志）
结构型 代理 控制访问、附加逻辑（AOP）
结构型 外观 统一门面简化调用（Facade Service）
结构型 组合 树形结构统一处理
行为型 策略 算法可替换（支付方式、排序）
行为型 模板方法 固定流程骨架，子类填细节
行为型 观察者 状态变化通知订阅者（事件监听）
行为型 责任链 请求逐级处理（过滤器、审批）

从 0 到项目落地。DDD 概念 · 战略设计（限界上下文/上下文映射）· 战术设计（聚合/实体/值对象）· 分层架构 · 落地案例。核心代码带详细注释。

技术栈速查

类别 选型 用途

1. 概念说明

**领域驱动设计（DDD, Domain-Driven Design）**是一套应对复杂业务的方法论，核心思想：让软件模型与业务语言保持一致。业务专家和开发用同一种语言（通用语言）沟通，软件结构围绕领域模型而非技术框架设计。

DDD 解决什么问题：业务逻辑复杂时，按”数据库表/技术分层”组织代码会导致业务规则散落各处、改一处坏一片。DDD 把业务规则收敛到领域层，让代码可读、可维护、可演进。

两大阶段：

  • 战略设计：先划清业务边界（限界上下文），确定系统间的协作方式。
  • 战术设计：在边界内设计聚合、实体、值对象、领域服务、仓储等模型要素。

2. 核心概念速查

概念 说明 示例
通用语言 业务与代码共用词汇 “下单””支付””取消订单”
限界上下文 业务边界，每个上下文一个模型 订单上下文、库存上下文
聚合 一组内聚对象，聚合根是唯一入口 订单（含订单项）
聚合根 聚合的根实体，外部只能通过它操作 Order
实体 有唯一标识、可变化的对象 User、Order
值对象 无标识、不可变、描述性对象 Money、Address
领域服务 不属于某个实体的业务动作 订单超时关单服务
仓储 聚合的存取接口，屏蔽持久化细节 OrderRepository
领域事件 领域内发生的事实 OrderCreatedEvent

7. 常见误区（避坑）

误区 正确做法
把 DDD 当技术框架 DDD 是设计方法，不绑定任何框架
所有模块都用 DDD 核心业务用 DDD，简单 CRUD 用普通分层

1. 概念说明

PostgreSQL 是功能最强大的开源关系型数据库，与 MySQL 的核心差异：

  • MVCC 机制：读不阻塞写、写不阻塞读，多版本并发控制。
  • 丰富数据类型：JSONB、数组、范围、枚举、几何类型。
  • 强大扩展生态：pgvector（AI 向量检索）、PostGIS（地理）、TimescaleDB（时序）。
  • 标准 SQL 支持完善：窗口函数、CTE、递归查询开箱即用。
  • PL/pgSQL：内置存储过程语言。

选型建议：MySQL 侧重简单易用、生态广；PostgreSQL 适合复杂查询、JSON、地理位置、AI 向量检索等场景。新项目数据模型复杂时优先 PostgreSQL。

1. 概念说明

1. 概念说明

**数据访问层（DAL, Data Access Layer）**是业务逻辑与数据库之间的隔离层，职责包括：

  • 屏蔽 SQL 细节：业务层不写 SQL，只调用方法。
  • 统一管理连接：连接池复用连接，避免频繁建连。

分层职责：Controller（入参出参）→ Service（业务规则）→ Mapper/Repository（数据访问） → DB。DAL 只做”怎么取数据”，不做业务判断。

并发 · 编程

从 0 到高并发服务。进程/线程/协程 · Java 并发体系（JDK 21 虚拟线程）· Go goroutine · 锁与原子 · 并发任务落地。代码带详细注释。

技术栈速查

类别 选型 用途
语言 Java 21 / Go 1.25 并发主力语言

1. 概念说明

**并发（Concurrency）**指多个任务在时间上交替执行（宏观并行、微观串行），**并行（Parallelism）**指多个任务真正同时执行（多核）。并发解决的是”多任务协同”，并行解决的是”更快”。

三个层次：

  • 进程（Process）：操作系统资源分配单位，内存隔离，切换开销大。
  • 线程（Thread）：进程内执行单位，共享进程内存，切换开销较小。
  • 协程（Coroutine）：用户态调度，栈极小，可创建十万级（Java 虚拟线程、Go goroutine、Python async）。

核心问题：多个线程同时读写共享变量会产生竞态条件（Race Condition），导致结果不确定。解决方案：互斥（锁）、原子操作、不可变对象、线程本地存储。

CICD · 持续集成与部署

从 0 到自动化流水线。CI/CD 概念 · GitHub Actions · GitLab CI · 构建/测试/镜像/部署 · 质量门禁。配置带详细注释。

技术栈速查

类别 选型 用途

部署 SSH / K8s / 云函数 发布目标

1. 概念说明

CI/CD 是”自动化交付”的三种实践的合称：

  • 持续集成（CI, Continuous Integration）：每次代码提交都自动触发构建 + 测试，尽早发现集成问题。核心是”频繁合并、快速反馈”。
  • 持续交付（CD, Continuous Delivery）：CI 通过后自动把产物（镜像/包）准备好，处于”随时可发布”状态。
  • 持续部署（Continuous Deployment）：产物自动部署到生产环境，全流程无人干预。

**流水线（Pipeline）**是这些阶段的编排：提交代码 → 安装依赖 → Lint → 单元测试 → 构建镜像 → 推送制品 → 部署。**质量门禁（Quality Gate）**指某一步失败即中断流水线，保证坏代码无法进入下一步。
