第一章：Modbus RTU

发表于 2026-05-01 更新于 2026-10-29 分类于 嵌入式与机器人 本文字数： 5.3k 阅读时长 ≈ 5 分钟

第一章：Modbus RTU

概念基础

  1. Modbus 是 Modicon 于 1979 年为 PLC 设计的应用层主从协议，如今是工业通信最通用的事实标准之一；RTU 是其中「二进制编码 + 异步串口」的变体。
  2. 主从轮询模型：一个主站（PLC/SCADA）按从站地址轮询，从站永不主动上报，只有被寻址才应答——模型简单、时序确定、实现成本低。
  3. 帧结构极简：地址 + 功能码 + 数据 + CRC16，一帧即一次完整的请求/应答；统一的寄存器语义（线圈、保持寄存器等）让不同厂商设备能用同一套报文访问。
  4. 为什么选 RTU：跑在 RS485 差分总线上，一根双绞线可挂多设备、传数百米，抗干扰强、布线便宜，是工业现场最常见组合。
  5. 边界：RTU 只定义数据读写语义，不含认证加密；帧界定靠静默时间而非特殊字符，底层串口由 UART 控制器提供。

理解了定位，先看最典型的主从轮询交互：

主从轮询

一、RTU 帧结构

  • 地址 0：广播（从站不应应答）。
  • CRC：对地址到数据末字节计算 Modbus CRC16。

示例（读保持寄存器 0x03）：主站发 01 03 00 00 00 0A C5 CD（含义依上下文解析）。

逐字段剖析

字段 长度 取值 说明
从站地址 1 B 1~247 0 为广播地址；248~255 保留
功能码 1 B 0x01~0x7F 最高位在异常应答中置 1（+0x80）
数据域 0~252 B 依功能码 起始地址、数量、字节计数、寄存器值
CRC16 2 B 多项式 0xA001 低字节先发，初值 0xFFFF

二、常用功能码

码 名称 说明
0x01 Read Coils 读线圈（位）
0x03 Read Holding Registers 读保持寄存器（16 位）
0x04 Read Input Registers 读输入寄存器
0x06 Write Single Register 写单寄存器
0x10 Write Multiple Registers 写多寄存器

异常应答：功能码 + 0x80，后跟异常码。

数据模型与地址映射

Modbus 把设备数据抽象为四张表：

数据区 访问 宽度 文档惯例地址
线圈 Coils 读写 1 bit 00001~
离散输入 Discrete Inputs 只读 1 bit 10001~
输入寄存器 Input Registers 只读 16 bit 30001~
保持寄存器 Holding Registers 读写 16 bit 40001~

文档地址 40001 对应报文中的偏移 0x0000，转换时务必减 1，这是最经典的 off-by-one 坑。

异常码表

异常码 名称 含义
0x01 Illegal Function 功能码不支持
0x02 Illegal Data Address 寄存器地址越界
0x03 Illegal Data Value 数据值非法
0x04 Slave Device Failure 从站内部故障
0x06 Slave Device Busy 从站忙，需重试

三、时序（RTU 特有）

帧间静默 ≥ 3.5 字符时间（与波特率相关），用于帧界定；波特率高时该间隔很短，实现需精确。

  • 115200 下对 MCU 中断延迟更敏感。
  • 半双工 第六章：RS485 需在发送前使能 DE。

3.5 字符时间怎么算

一个字符 = 起始位 + 8 数据位 + 校验/停止位 ≈ 11 bit（8N1 时）。则：

波特率 1 字符时间 3.5 字符时间
9600 ~1.146 ms ~4.01 ms
19200 ~0.573 ms ~2.01 ms
115200 ~95.6 µs ~335 µs

实现要点：

  • 用定时器 + 接收中断：每收到一字节重置定时器，定时器超时即判帧结束。
  • 高波特率（>19200）时规范允许固定 1.75 ms 简化实现。
  • 帧内字节间隔不得超过 1.5 字符时间，否则从站应丢弃该帧。
  • 从站应答前需保证 ≥ 3.5 字符的静默，避免与主站残余发送交叠。

八、调试与抓包

  • Modbus Poll / Slave（Windows）、pymodbus、QModMaster（Linux）。
  • 抓包：串口监听或 RS485 分析仪。
  • 与 第四章：UART 关系：RTU 是应用层协议，底下是异步串口 + 485 收发器。

常用手段：

  • 串口监听：用一个 USB-485 适配器「搭车」接在总线上，用 SerialMon / AccessPort 或 Python 脚本记录双向字节流，对照协议规范逐字节解析。
  • 逻辑分析仪：接在 UART 侧（DI/RO 引脚）可同时看到 DE 切换时刻与字节流，排查「首字节丢失」「尾字节截断」类问题最直观。
  • 示波器：看 A/B 差分波形幅度、反射与畸变，定位终端电阻与布线问题。
  • 软件对拍：用 Modbus Slave 模拟从站验证主站程序，用 Modbus Poll 验证自研从站，先软后硬。

常见问题清单

现象 可能原因
完全无应答 地址/波特率不对；A/B 接反；DE 未切换；共地缺失
偶发 CRC 错误 干扰、线缆过长、终端电阻缺失、波特率误差过大
首字节丢失 DE 使能后立即发送，收发器未稳定（需延时数 µs）
尾字节被截 发送未完成就拉低 DE，应等 TC（发送完成）标志
数据整体偏移一位 40001 ↔ 0x0000 的减 1 转换漏掉
32 位数据错乱 寄存器字序（大端/小端/字交换）各厂商不同，需试

字节序特别注意：Modbus 只规定寄存器内高字节在前；一个 float 占两个寄存器时，四个字节的排列常见 ABCD / CDAB / BADC 三种，务必查设备手册或实测。
