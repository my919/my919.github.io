第九章：CAN 总线：帧结构、多主仲裁与 CAN FD

发表于 2026-05-01 更新于 2026-10-29 分类于 嵌入式与机器人 本文字数： 4.2k 阅读时长 ≈ 4 分钟

第九章：CAN 总线：帧结构、多主仲裁与 CAN FD

概念基础

  1. CAN（Controller Area Network，控制器局域网）是 Bosch 为汽车电子设计的多主串行总线：所有 ECU 节点挂在一对差分线（CAN_H / CAN_L）上，以广播帧通信，各节点按 ID 自行过滤收帧。
  2. 为什么抗干扰：差分传输让共模噪声相互抵消，配合总线两端的 120Ω 终端电阻抑制信号反射，适合发动机舱等电磁环境恶劣的场景——这与单端电平的 RS232 是本质差别。
  3. 多主无损仲裁：总线空闲时任意节点都可发送，逐 bit 仲裁中发显性 0 的胜出、ID 越小优先级越高，败者自动退为接收方，既不丢帧也不需要中心主站。
  4. 硬件级可靠性：帧尾 CRC + ACK 硬件检错与确认，出错自动重发；故障节点经错误计数进入 bus-off 主动离线，不会拖垮整条总线。
  5. 定位：汽车动力、底盘、网关等实时、安全相关场景的主力总线，速率 125 kbps ~ 1 Mbps；CAN FD 把数据段扩到 64 字节并提升数据段速率；车身低成本传感器则交给 LIN（见 第十章：LIN 总线：单主多从与调度表）。

一、经典 CAN 帧（概念）

字段 说明
仲裁 ID 11 位（标准）或 29 位（扩展），越小优先级越高
RTR 远程帧（较少用）
DLC 数据长度 0~8 字节
Data 载荷
CRC + ACK 硬件检错与确认

数据帧逐段剖析（标准帧）

  • SOF：1 个显性位，标志帧开始，所有节点据此硬同步。
  • 仲裁段：标准帧 11 位 ID；扩展帧拆为 11 位基本 ID + SRR + IDE + 18 位扩展 ID。
  • IDE 位：区分标准（显性）与扩展（隐性）帧。
  • ACK 槽：发送方发隐性，任一正确接收的节点拉显性——发送方只知道「至少有人收到」，不知道是谁。
  • 位填充（Bit Stuffing）：连续 5 个相同电平后强制插入反相位，保证时钟同步；计算帧长时要计入。

远程帧与错误帧

  • 远程帧（RTR=1）：请求对方发送某个 ID 的数据帧，无数据段；现代设计多用周期发送替代。
  • 错误帧：任一节点检出错误立即发送 6 个显性位「打破」当前帧，所有节点丢弃该帧，发送方稍后自动重发。
  • 过载帧：接收方来不及处理时请求延时，极少使用。

二、多主仲裁

总线空闲时多个节点可同时发送；ID 仲裁时逐 bit 比较，发显性 0 的胜出，失败者自动退为接收方，无中心主站。

要点：

  • 非破坏性：赢家的帧不受任何影响，无需重发，总线利用率因此可以很高。
  • ID 即优先级：设计报文 ID 分配表就是设计系统的实时性——越关键的信号 ID 越小。
  • 饥饿风险：低优先级帧在总线持续繁忙时可能长期发不出去，调度设计要留带宽裕量。

三、速率与长度

速率 典型最大总线长度（粗估）
1 Mbps 数十米
500 kbps ~100m
125 kbps 更长

实际以收发器、电缆与拓扑仿真为准。

工程经验：1 Mbps ≤ 40 m；500 kbps ≤ 100 m；125 kbps ≤ 500 m。限制本质是信号传播延迟——仲裁要求发送位在总线最远端往返后仍能正确采样，位时间越短允许的距离越小。支线（stub）长度建议 ≤ 0.3 m。

过滤器是关键：总线上所有帧广播，不过滤会让 MCU 被无关报文淹没；掩码模式按位筛选 ID 范围。

五、CAN FD

  • 数据段可 > 8 字节（最高 64），数据段波特率可高于仲裁段。
  • 新车载网络大量采用 CAN FD；旧 ECU 可能仅 Classic CAN。

MCU 侧：bxCAN、FDCAN 外设 + 收发器（TJA1050 等）。

CAN FD 与经典 CAN 对照

项目 Classic CAN CAN FD
数据段长度 0~8 B 0~64 B（DLC 编码到 64）
波特率 全程同一速率 仲裁段 ≤1M，数据段可达 5~8 Mbps
CRC 15 位 17/21 位（随数据长度）
兼容性 — FD 帧与经典帧不能混在同一直通总线（经典节点会把 FD 帧当错误）

混合网络需经网关隔离两种总线段。选型时注意收发器也要支持 FD（如 TJA1051 不行，需 TJA1044/TJA1462 等 FD 型号）。

六、错误处理与 bus-off

每个节点维护 TEC（发送错误计数）/ REC（接收错误计数）：

  • 自动重发：发送失败硬件自动重试，应用层无感；但持续故障会让 TEC 累积。
  • bus-off 恢复：监测到 128 次 × 11 个隐性位后可重新上线；应用层应记录 bus-off 事件用于诊断。
  • 常见诱因：终端电阻缺失、波特率不一致、收发器未供电——「自己能发但全网报错」多半是该节点参数错了。

常见问题清单

现象 可能原因

上层协议：CANopen、J1939、UDS（诊断）等建立在 CAN 帧之上。

再细化一下与 RS485+Modbus 的对比维度：CAN 是事件驱动 + 多主广播，适合「状态变了立刻广播」的实时信号；Modbus 是主从轮询，适合「定期采集」的工控场景。CAN 把冲突处理、检错、重发都做进了硬件；RS485 上这一切都要协议与软件自己兜底。

本章小结

要点 结论
物理层 CAN_H / CAN_L 差分 + 两端 120Ω 终端电阻，抗干扰强
仲裁 多主、逐 bit 非破坏性仲裁，ID 越小优先级越高
可靠性 CRC + ACK + 错误计数 bus-off，硬件级容错
速率与距离 125 kbps ~ 1 Mbps，速率越高可用距离越短
演进 CAN FD 数据段最大 64 字节，数据段波特率可独立提高
