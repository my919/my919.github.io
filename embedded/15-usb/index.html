第十五章：USB 总线：拓扑、描述符与 CDC 虚拟串口

发表于 2026-05-01 更新于 2026-10-25 分类于 嵌入式 本文字数： 3.8k 阅读时长 ≈ 3 分钟

第十五章：USB 总线：拓扑、描述符与 CDC 虚拟串口

概念基础

  1. USB（Universal Serial Bus，通用串行总线）是 主机中心（Host-centric） 的有线总线：所有事务都由 Host 发起，Device 只能被动响应——与 CAN 的多主对等、LIN 的主从调度都不相同。
  2. 树形寻址：Host 经 Root Hub → Hub 树形扩展挂载设备，靠枚举过程为每个设备分配唯一地址，再读描述符获知它是谁、能做什么。
  3. 描述符即自描述：设备描述符 → 配置 → 接口 → 端点层层描述，插入即枚举，无需跳线或硬编码地址——「即插即用」的机制本质。
  4. 速度分级演进：Low/Full/High Speed（1.5M/12M/480 Mbps）→ USB 3.x（5 Gbps+）→ USB4；MCU 侧 Full Speed 12 Mbps 仍最常见。
  5. 定位：PC 与外设的标准互联；嵌入式里最常见的玩法是 CDC 虚拟串口与 HID，Type-C 时代还要关注 PD 供电协商与 Alt Mode。

一、拓扑

  • Host 发起事务；Device 响应。
  • OTG 设备可切换 Host/Device（手机接 U 盘）。

补充规则：

  • 最多 5 级 Hub、127 个设备（7 位地址，地址 0 保留给未枚举设备）。
  • Host 轮询：连 Interrupt 端点也是 Host 按声明周期来「问」设备有没有数据——USB 没有真正意义上的设备中断。
  • 帧定时：Full Speed 每 1 ms 一个 SOF 帧，所有传输被调度进帧里，这是 USB 带宽分配的基本节拍。

二、速度等级

版本 速率（量级）
USB 2.0 HS 480 Mbps
USB 3.x 5 Gbps+
USB4 基于 Thunderbolt 生态

Full Speed 12 Mbps 仍常见于 MCU Device。

完整分级：

等级 速率 典型场景
Low Speed 1.5 Mbps 键鼠（延迟不敏感、线材便宜）
Full Speed 12 Mbps MCU CDC/HID，绝大多数 STM32F1/F4
High Speed 480 Mbps U 盘、摄像头、高速数据采集（需专用 PHY）
SuperSpeed 5/10/20 Gbps USB 3.x，独立差分对全双工
USB4 20/40 Gbps Type-C 隧道化 PCIe/DP

MCU 内置的多为 FS 控制器；HS 需外挂 ULPI PHY 或选带 HS PHY 的型号（STM32F7/H7、ESP32-S3 等仍多为 FS）。

三、描述符与 Class

  • 设备描述符 → 配置 → 接口 → 端点。
  • Class：HID（键鼠）、MSC（U 盘）、CDC-ACM（虚拟 第四章：UART）、Audio、Video 等。
  • Vendor Specific：自定义 Bulk/Interrupt 端点 + 主机驱动/libusb。

描述符层级详解

一个设备可以有多个接口：如「CDC + HID」复合设备——调试串口与用户按键共存，PC 上同时出现 COM 口和 HID 设备。

四种传输类型

类型 特点 用途
Control 双向、必支持（EP0） 枚举、类请求
Interrupt 周期轮询、小数据、有界延迟 HID 键鼠、CDC 通知
Bulk 大数据、无延迟保证、带宽填满 U 盘、虚拟串口数据
Isochronous 定带宽、不重传 音频、视频

枚举流程（插入后发生了什么）

任何一步失败都表现为「无法识别的 USB 设备」，按此流程逐步排查即可定位。

四、CDC 虚拟串口

MCU 通过 USB CDC ACM 暴露 /dev/ttyACM0（Linux）或 COM 口（Windows），应用层与 UART 类似发字节，物理层是 USB 包。

与 第五章：RS232：USB 转串口 芯片（CH340、CP2102、FT232）内部即 UART ↔ USB 桥接。

TinyUSB 实现要点（概念）

虚拟串口的波特率是摆设：Bulk 传输按 USB 全速跑，PC 侧设 9600 或 921600 实际速度一样；只有 SET_LINE_CODING 请求会通知设备（设备可用它触发 Bootloader 之类的魔法——Arduino 的 1200 bps touch 就是这个原理）。

CDC 与真 UART 对比

维度 USB CDC UART + 转换芯片
速率 12 Mbps 链路，实际吞吐数百 KB/s 受波特率限制
接线 一根 USB 线 USB 线 + 转换器 + 杜邦线
缓冲 USB 控制器 FIFO，不易丢字节 需流控防溢出
固件成本 需跑 USB 协议栈 UART 裸驱即可

五、嵌入式开发要点

  • STM32 USB Device Library、TinyUSB、ESP32-S2/S3 USB OTG。
  • 枚举失败：检查 D+/D-、1.5k 上拉（Full Speed Device）、供电与描述符。
  • USB 3 / Type-C：PD 协商、Alt Mode（DP/Thunderbolt）另论。

规范：https://www.usb.org/documents

Full Speed 硬件检查清单

项目 要求
D+ 上拉 1.5kΩ（FS 设备标识）；由 MCU 内部/三极管控制，可控上拉实现软件重枚举
D-/D+ 走线 等长、90Ω 差分阻抗（普通板放宽些也能用）、远离时钟
时钟 FS USB 通常要求 48 MHz ±0.25%，很多 MCU 必须外晶振（HSI 精度不够）
供电 总线供电设备要在描述符里如实申报电流（≤500 mA @USB2）
ESD USB 接口外露，TVS 管必备

常见问题清单

现象 可能原因
设备完全无反应 1.5k 上拉没使能；USB 时钟没到 48 MHz；DP/DM 接反
「无法识别的 USB 设备」 描述符长度字段错；EP0 响应超时；供电不足
枚举到一半断掉 堆栈太小（USB 栈吃 RAM）；描述符在 Flash 对齐问题
高速收发丢数据 应用层读太慢，端点 NAK 溢出；加大缓冲或提高读取频率
Windows 要装驱动 Win10 之前 CDC-ACM 需 inf；或换 HID（免驱）/WinUSB

本章小结

要点 结论
拓扑 Host 中心 + Hub 树形扩展，事务全部由 Host 发起
即插即用 枚举分配地址 + 分层描述符自描述
复用机制 Class 驱动标准化（HID/MSC/CDC 等），免装驱动
嵌入式常用 CDC 虚拟串口、HID；协议栈可上 TinyUSB
排障要点 枚举失败先查 D+/D-、1.5k 上拉、供电与描述符
