第十二章：LoRaWAN：远距离低功耗星型组网

发表于 2026-05-01 更新于 2026-10-29 分类于 嵌入式与机器人 本文字数： 4k 阅读时长 ≈ 4 分钟

第十二章：LoRaWAN：远距离低功耗星型组网

概念基础

  1. LoRaWAN 是构建在 LoRa 扩频射频之上的开放网络协议：终端节点通过网关接入 Network Server，典型覆盖公里级，专为电池供电、小数据量、上报为主的物联网场景设计。
  2. LoRa ≠ LoRaWAN：LoRa 是 Semtech 的物理层调制技术（Chirp Spread Spectrum，灵敏度高、抗干扰强）；LoRaWAN 是其上的 MAC 层协议（入网激活、速率自适应、双向调度）——「电台」与「通信规约」的关系。
  3. 星型拓扑换功耗：节点只与网关直连一跳，不做 mesh 路由转发，省去中继耗电，换来数年电池寿命；覆盖靠增加网关与 ADR 速率自适应来平衡。
  4. 速率换距离：SF（扩频因子）越大，速率越低、传得越远，网络侧按链路质量动态调整，本质是「速率-距离-容量」的三角权衡。
  5. 定位：智能抄表、资产追踪、农业监测等公里级、极低速率场景；高吞吐走 Wi-Fi/以太网 + MQTT/HTTP，局域 mesh 则选 Zigbee / 蓝牙 Mesh。

先看整体架构：

一、架构

  • Gateway：只做射频转发，不解密应用 payload（取决于模式）。
  • ADR（Adaptive Data Rate）：网络侧调节 SF/功率平衡距离与容量。

LoRa 物理层速览

  • Chirp Spread Spectrum：信号在带宽内线性扫频，扩频带来处理增益，接收灵敏度低至 -137 dBm（比 FSK 好 20 dB 以上）。
  • SF7~SF12：SF 每加 1，速率减半、距离增加、空中时间翻倍。
  • 正交性：不同 SF 的信号可在同频同时存在互不干扰，网关 8 通道并行接收。
  • 带宽：常用 125 kHz（EU868/CN470）、500 kHz（US915 上行）。

各角色职责

角色 职责
End Device 采集数据、按 Class 调度收发、维护会话密钥
Gateway 纯射频中继：把 RF 帧加元数据（RSSI/SNR/时间戳）转 IP，不做协议裁决
Network Server 去重（多网关收到同一帧）、ADR 控制、帧计数校验、路由到应用
Application Server 解密 AppSKey payload、业务逻辑

「网关笨、服务器聪明」让网关可以做到几十美元级，是 LoRaWAN 部署成本低的关键。

二、区域参数

区域 典型频段
EU868 863–870 MHz
US915 902–928 MHz
CN470 470–510 MHz

需遵守当地无线电法规；模块需合规认证。

区域差异不止是频率：

  • EU868：占空比限制（Duty Cycle，常见子带 1% 或 0.1%）——设备每小时最多发 36 秒，直接限制上报频率。
  • US915：频率跳变（FHSS），上行 64+8 信道；无占空比但有 400 ms 驻留时间限制，限制单包大小。
  • CN470：96 上行信道，国内合规主流选择。
  • 选型红线：硬件模块、固件 region 参数、网络服务器频段计划三者必须一致，否则入网即失败。

三、设备 Class

Class 下行窗口 功耗
A 仅上行后两个短窗口 最低，传感器常用
B 附加信标窗口 中
C 几乎常开接收 高，供电设备

Class A 时序（必须掌握）

  • 节点发完才听：RX1 用上行的同信道/速率（或由网络指定），RX2 用固定信道与 SF12（EU868 为 869.525 MHz）。
  • 两个窗口都没收到 → 回去睡觉，下行丢失。下行永远是「发上行时的副产品」，这就是 Class A 省电的本质。
  • 服务器想主动下发？只能等节点下一次上行——做「远程控制路灯」这类需求要么接受分钟级延迟，要么上 Class C。
  • Class B 增加网关周期广播的 Beacon，节点按预约时隙额外开窗；Class C 常供电、常开窗，下行近乎实时（电表、路灯控制器）。

四、MAC 帧结构（概念）

字段 说明
MHDR 消息类型（Join-Request / Confirmed-Up / Unconfirmed-Up 等）
DevAddr 4 字节设备地址，入网后分配
FCnt 帧计数器，防重放；ABP 模式下掉电归零会导致服务器拒收
FOpts 捎带 MAC 命令（如 ADR 应答）
FPort 0 = 纯 MAC 命令；1~223 = 应用端口（应用层多路复用）
MIC 4 字节消息完整性码，NwkSKey 计算

Confirmed 消息要求对端回 ACK，未收到则重发（默认 8 次）——但占空比宝贵，上行通常用 Unconfirmed，靠周期冗余保证到达率。

五、安全

  • Join：OTAA（Over-The-Air Activation，推荐）或 ABP（预置密钥）。
  • AES-128：NwkSKey、AppSKey 分层加密与完整性。
  • 应用层仍可封装 第十一章：CoAP：REST over UDP 的物联网应用协议 或自定义二进制。

OTAA 入网流程

  • 根密钥 AppKey/NwkKey 只出厂烧录一次，永不上空口传输；OTAA 每次入网派生新会话密钥，设备换网络也安全。
  • ABP 直接预置 DevAddr + 两把会话密钥，省一步握手，但密钥固定、FCnt 复位问题多，仅建议实验室用。
  • 双层加密的边界：NwkSKey 管到 Network Server 的完整性，AppSKey 端到端加密到应用服务器——网关和 NS 看不到应用数据明文（诚实网关模型）。

调试手段：

  • 网关日志：ChirpStack/TTN 控制台可看每帧的 SF、RSSI、SNR、FCnt，入网失败先在这里看请求到没到。
  • 频谱仪/SDR：确认节点真的发射了（AT 模组可能返回 OK 但射频参数错）。
  • 常见坑：天线频段买错（868 天线用在 470）；CN470 信道掩码与网关不匹配导致 90% 丢包；SF12 下空中时间超 1 s 触发占空比限制；ADR 把边缘节点速率越调越慢形成恶性循环。

七、与其它物联网协议

  • 长距离、低带宽、电池 → LoRaWAN。
  • 有 Wi-Fi/以太网、高吞吐 → 第十二章：MQTT 详解：发布订阅、QoS 与 mosquitto / Python 示例、第二章：HTTP 详解：报文、方法、版本与 curl/nc 示例。
  • 局域 mesh → 第十六章：Zigbee：基于 802.15.4 的 Mesh 组网、第十三章：Bluetooth 与 BLE：GATT 模型与低功耗设计 Mesh。

开源栈：LoRaMac-node、Semtech LoRaWAN Stack；云平台：TTN、ChirpStack 等。

选型对照表：

需求 选择
城市级抄表、农业传感器 LoRaWAN（公里级、年级电池）
厂房内百节点mesh、毫秒响应 Zigbee / 有线 485
手机直连交互 BLE
视频、大文件、云平台直连 Wi-Fi / 4G Cat.1

链路预算与部署规划

  • 链路预算：发射 14 dBm + 灵敏度 -137 dBm ≈ 151 dB，是 LoRa 公里级覆盖的物理基础；城市环境实际按 110130 dB 可用预算估算（穿墙损耗 1020 dB/堵）。
  • 网关选址：越高越好、天线视距覆盖；室内网关穿楼板后 SF 普遍抬到 10+，容量急剧下降——宁可多加网关，不要全靠提高 SF。
  • 容量估算：单网关理论数千节点，但受占空比与 SF 分布制约；大量 SF11/12 节点会挤占空中时间，规划时让节点尽量落在 SF7~9。
  • 天线：频段匹配、驻波比 < 2；节点小天线效率低是常态，预算里要留损耗余量。

生态与相关技术

  • 私有 LoRa：只用 LoRa 物理层做点对点/私有星型，不走 LoRaWAN 协议——园区自组网常见，省去 NS 部署但失去漫游与生态。
  • Amazon Sidewalk / Helium：基于 LoRa 的公共网络变体，商业模式各异。
  • LR-FHSS：LoRaWAN 新增的跳频模式，为海量卫星/密集场景扩容。
  • 中继（Relay）：LoRaWAN 1.0.4 引入的电池中继节点，补盲区覆盖。
  • 与 NB-IoT 对比：NB 走运营商基站、SIM 计费、免自建网；LoRaWAN 自建网络、无月租——「买服务 vs 买设备」的路线之争。

本章小结

要点 结论
架构 节点 → 网关（仅射频转发）→ Network Server → 应用服务器
功耗 星型无路由转发，Class A 可电池工作数年
速率 SF 越大越远越慢，ADR 动态平衡速率与距离
入网安全 推荐 OTAA 动态激活；NwkSKey/AppSKey 双层 AES-128
选型边界 公里级低速率选 LoRaWAN，局域 mesh 选 Zigbee/蓝牙 Mesh
