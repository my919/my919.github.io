第三章：字符串与常用标准库

发表于 2026-05-01 更新于 2026-10-25 分类于 C 语言 本文字数： 8.5k 阅读时长 ≈ 8 分钟

第三章：字符串与常用标准库

概念基础

  1. 字符串即约定：C 没有字符串类型，只有「以 '\0' 结尾的 char 数组」这一约定——所有 str* 函数都依赖这个约定，长度信息不存在于类型中，越界由此而生。
  2. 安全边界是第一课：strcpy/sprintf/gets 不检查边界，是缓冲区溢出漏洞的历史源头；现代代码一律 snprintf/strncat（小心）/长度校验。
  3. 标准库分层清晰：stdio.h（IO）、string.h（内存/串）、stdlib.h（分配/转换/退出）、time.h（时间）、math.h（数学）覆盖 80% 日常需求。
  4. 格式串即契约：printf/scanf 的格式符必须与实参类型严格匹配（%zu 对 size_t、%lld 对 long long），不匹配是 UB；gcc -Wformat 能查出大半。
  5. 本章目标：把日常高频库函数串成速查手册，每个函数标注安全用法与替代方案。

本章承接 第二章：指针、数组与内存管理。示例在 gcc 14 下编译运行验证。

一、string.h：字符串与内存

1. 常用函数速查

函数 作用 安全提示
strlen(s) 长度（不含 '\0'） O(n)；传非 NUL 结尾缓冲是 UB
strcmp(s1,s2) 字典序比较 返回 <0/0/>0，勿当布尔用
strncmp(s1,s2,n) 前 n 字符比较 前缀匹配首选
strcpy(dst,src) 拷贝 不查边界，弃用→snprintf
strncpy(dst,src,n) 最多 n 字符 不保证 NUL 结尾，坑；见下方
strcat/strncat 追加 strncat 追加后总是补 NUL（与 strncpy 不同）
strstr(h,nd) 子串查找 返回首地址，找不到 NULL
strchr/strrchr 查字符 首次/末次出现
strtok(s,delim) 分词 内部静态状态，非线程安全
memcpy/memmove 内存拷贝 区间重叠必须 memmove
memset 填充字节 只适合 0/-1 等按字节模式

2. 安全拷贝的推荐姿势

strncpy 从不安全：要么截断不补 NUL、要么补零填满缓冲。新代码用 snprintf；接旧代码时记住「strncpy 后手动补 '\0'」。

3. memmove vs memcpy

4. C23 与 Annex K 安全函数现状

  • strdup/strndup：POSIX 出身，C23 已收入标准（<string.h>），复制字符串到堆上，调用方负责 free。
  • Annex K（strcpy_s 等 _s 函数）：可选附录，仅 MSVC 实质支持，glibc 不实现——跨平台代码不要依赖，继续用 snprintf + 显式长度。
  • memset_explicit（C11 起可选）：防编译器优化掉「擦除敏感数据」的 memset，写密钥清零场景用。

2. 文件 IO 四件套

2.1 读整行的稳妥范式：fgets + sscanf

scanf 直接读stdin 的最大痛点是换行残留与格式失败时输入不前进。工程惯例是「fgets 读整行 + sscanf 解析」，错误可控、缓冲行为可预期：

fgets 换 gets（后者已从标准删除）；scanf("%s") 必须域宽限定；行尾换行残留是 scanf 经典坑（getchar() 吃掉或统一 fgets+sscanf）。

三、stdlib.h：分配、转换与退出

函数 说明
strtol/strtod 带错误检测的转换，替代 atoi/atof
qsort/bsearch 通用排序/二分（见第二章函数指针）

strtol 完整错误检查范式

atoi 失败返回 0 且无法区分「真 0」与「解析失败」，溢出还是 UB——新代码一律 strtol/strtod/strtoull。

四、time.h：时间处理

time_t 是秒、clock_t 是 CPU 滴答，单位随实现——测量耗时用 clock()/CLOCKS_PER_SEC（CPU 时间）或 POSIX clock_gettime(CLOCK_MONOTONIC)（墙钟，测性能首选单调钟）。

时区与历法换算

  • localtime/gmtime 返回内部静态缓冲，多线程用 localtime_r（POSIX）/ localtime_s（MSVC）。
  • mktime 把分解的 struct tm 转回 time_t，会自动规范化越界字段（如「1 月 32 日」滚到 2 月 1 日），适合做日期加减。
  • time_t 与 2038 问题：32 位 time_t 在 2038-01-19 溢出；现代 64 位系统已无虞，但维护嵌入式老系统时需留意。

四·补充、locale 与字符编码提醒

C 标准库默认在 "C" locale 下工作，strcoll、strftime("%A") 等才受 setlocale 影响。标准 C 不提供 Unicode 字符串处理——char 串在 UTF-8 环境下只是字节序列，strlen("中") 返回 3（UTF-8 字节数）而非 1。需要真正的 Unicode 处理时，用 ICU 等第三方库，或确保全程只按字节透传不截断多字节字符。

五、math.h 与字符处理

isdigit(c) 的 c 必须是 unsigned char 值或 EOF——传 char（可能为负）是 UB，惯用 isdigit((unsigned char)c)。链接 math.h 需 -lm。

六、常见陷阱

陷阱 说明
scanf("%s") 无边界 缓冲区溢出，用 %31s 域宽
strncpy 不补 NUL 截断时无结尾，手动补丁或改 snprintf
格式符不匹配 %d 打印 size_t 等为 UB，用 %zu/%lld 对应
gets 类无界读 已删标；一律 fgets
atoi 无错误检测 改 strtol 检查 errno/endptr
memcpy 重叠区间 UB，改 memmove
strtok 非线程安全 多线程用 strtok_r（POSIX）或手写分词
ctype 传负 char UB，(unsigned char)c
浮点 == 用误差域 fabs(a-b) < eps
忘 fclose/检查 资源泄漏；fclose 返回值也应检查

本章小结

要点 结论
字符串 NUL 结尾约定贯穿一切；strlen O(n)、无长度内建
C23 安全函数 strdup 入标；Annex K _s 系列仅 MSVC，跨平台别依赖
输入范式 fgets 整行 + sscanf 解析，胜过裸 scanf（残留/失败不前进）
安全拷贝 snprintf 首选；strncpy 必补 NUL；strncat 反而总补
格式化 格式符与类型严格匹配：%zu/%lld；gcc -Wformat 把关
文件 IO fopen 判空 + fclose 成对；fgets 替代 gets；二进制读写查返回值
转换 strtol/strtod 带 errno+endptr，弃用 atoi
时间 time_t 秒 / clock CPU；localtime_r 线程安全；性能测单调钟
数学字符 -lm；ctype 参数转 unsigned char；浮点误差域比较
