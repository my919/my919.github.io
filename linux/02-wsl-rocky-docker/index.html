第一章：Windows 上 WSL（Rocky Linux）与 Docker Desktop

发表于 2026-05-01 更新于 2026-10-29 分类于 Linux 本文字数： 7.5k 阅读时长 ≈ 7 分钟

第一章：Windows 上 WSL（Rocky Linux）与 Docker Desktop

概念基础

  1. WSL 是什么：WSL（Windows Subsystem for Linux）让 Windows 直接运行真正的 Linux 发行版，无需双系统或整机虚拟机，一条命令即可进出 Linux 环境。
  2. WSL2 的意义：WSL2 基于轻量级虚拟机，系统调用兼容性完整，是 Docker Desktop 官方推荐的运行后端——没有 WSL2 就没有流畅的容器体验。
  3. 为什么选 Rocky Linux：与 RHEL 同源的企业级发行版，dnf 生态与生产服务器一致，作为本地演练环境最贴近真实运维。
  4. Docker Desktop 的角色：提供图形化引擎管理（更新、证书、镜像加速），通过 WSL integration 把 docker CLI 注入各发行版，Rocky 内无需再装 dockerd。
  5. 适用场景：在 Windows 机器上做 Linux 运维演练与容器开发；代码放在发行版内的 Linux 文件系统中可获得最佳 I/O 性能。

环境与版本说明

  1. 操作系统：Windows 10（建议 22H2 及以后）或 Windows 11。
  2. 体系结构：下载 Rocky Linux 镜像时选 x86_64 或 aarch64，与 Windows、Docker Desktop 安装包一致。
  3. WSL：使用 WSL2；Docker Desktop 的 WSL 2 后端依赖此版本。
  4. Rocky Linux：官方 .wsl 镜像（推荐）或 wsl --import。
  5. 权威文档：
    • Rocky Linux（本文默认 10，文档内可切换版本）：Import Rocky Linux to WSL or WSL2
    • Microsoft：安装 WSL
    • Docker：Docker Desktop on Windows、WSL 与 Docker Desktop

WSL2 网络模式与资源限制（.wslconfig）

1. 网络模式：NAT vs mirrored

模式 行为 适用
NAT（默认） WSL 有独立 IP，经 Windows 转发上网；localhost 默认已直通（Windows 访问 WSL 里起的服务直接 localhost:端口） 绝大多数开发场景
mirrored（Win11 22H2+） WSL 与 Windows 共享同一网络栈：Linux 里绑 0.0.0.0 的端口，局域网可直接通过 Windows IP 访问 需要局域网设备访问 WSL 内服务（如在 Rocky 里跑 Web 服务给手机调试）

切换方式：在 Windows 用户目录新建/编辑 C:\Users\你的用户\.wslconfig：

执行 wsl --shutdown 后重新进入生效。mirrored 模式下注意：防火墙规则由 Windows 侧管控（需在 Windows 防火墙放行端口），且部分 VPN/代理软件兼容性以实测为准，出问题随时改回 NAT。

2. 命令行安装

将路径、--name 改成你的实际值。安装后 Windows Terminal 下拉里可出现 Rocky-10。

3. 双击安装（可选）

资源管理器中双击 .wsl 按向导安装。

安装与配置 Docker Desktop（配合 WSL2）

1. 下载并安装

  1. 打开 https://www.docker.com/products/docker-desktop/ ，下载 Docker Desktop for Windows。
  2. 安装向导中保持 Use WSL 2 instead of Hyper-V（或等价选项，以当前安装界面为准）。
  3. 安装结束若提示注销或重启，按提示操作。

2. 确认使用 WSL 2 后端

打开 Docker Desktop → Settings（设置）→ General（常规）：

  • 勾选 Use the WSL 2 based engine（使用基于 WSL 2 的引擎）。

应用后必要时 Restart Docker Desktop。

3. 与 Rocky Linux 发行版集成（核心）

Settings → Resources → WSL integration（WSL 集成）：

  1. 打开 Enable integration with my default Wsl distro（与默认 WSL 发行版集成）（按需）。
  2. 在 Enable integration with additional distros 中，打开你的 Rocky Linux 名称（例如 Rocky-10）。
  3. 点击 Apply & restart。

之后在 wsl -d Rocky-10 的 shell 中应能直接执行 docker、docker compose，实际引擎由 Docker Desktop 提供，无需在 Rocky 里再装 dockerd 或配置 rootful 独立引擎（避免与 Desktop 抢端口、重复占资源）。

4. 验证（在 Rocky Linux 内）

若提示找不到 docker：回到上一步检查该发行版集成开关，并执行 wsl --shutdown 后重新打开 Docker Desktop 与 WSL 终端。

5. 镜像加速与构建缓存（Docker Engine）

在 Docker Desktop → Settings（设置）→ Docker Engine 中编辑 JSON（与引擎配置同源，保存后 Apply & restart 生效）。若已有其它键（如 insecure-registries），请把下面片段合并进现有对象，不要整段覆盖导致丢配置。

  • registry-mirrors：拉取镜像时优先走列表中的镜像站，减轻访问 docker.io 的延迟与失败（镜像站可用性与合规以你网络环境为准，可日后替换为团队提供的地址）。
  • builder.gc：为 BuildKit 构建缓存开启自动回收，defaultKeepStorage 限制默认保留量（示例 20GB），避免构建缓存占满磁盘。

修改后点击 Apply & restart；再在 Rocky 或 PowerShell 中执行 docker info，在输出里确认 Registry Mirrors 已包含上述地址。

6. 文件与性能建议

  • 项目代码放在 WSL 发行版自己的 Linux 文件系统里（例如在 wsl -d Rocky-10 里用 ~/project，即 /home/你的用户/project），不要放在 /mnt/c/... 下做大量编译与 Docker 构建，可减少跨系统 I/O 延迟。

  • Docker Desktop 的 Settings → Resources 可调 CPU、内存、磁盘镜像上限，与 Rocky 其它进程共用本机资源，按机器配置酌情调大。

7. 与「在 Rocky 里单独装 Docker Engine」的区别

方式 说明
Docker Desktop + WSL 集成（本文推荐） 一个图形界面管理引擎、更新与证书；Rocky 内仅 CLI 连到 Desktop
Rocky 内 dnf install docker-ce 并跑 dockerd 与 Desktop 两套引擎易冲突，一般不叠加以 Desktop 为主场景

若必须仅用发行版内 dockerd（无 Desktop），应关闭 Docker Desktop 的 WSL 集成或卸载 Desktop，并自行处理 iptables/cgroup 等与 WSL 文档差异。

2. 是否需要「登录」、如何设置与验证 root 密码

是否要登录：WSL 从 Windows Terminal、wsl -d Rocky-10 等方式进入时，一般是直接进入已配置的默认 Linux 用户的 shell，不会像 SSH 那样再在终端里提示输入一次用户名（除非你主动执行 login、su 等）。首次安装某些发行版时会交互式让你创建 UNIX 用户名与密码；Rocky 官方 .wsl 导入后的默认用户以该镜像说明为准（常见为 root 或需自行建普通用户，见下节）。

root 密码是什么、要不要设：root 账户始终存在；若从未执行过 passwd，root 可能没有可用登录密码（或镜像预置了密码，以发行版文档为准）。日常维护建议用带 sudo 的普通用户；需要 root shell 时再切。

互操作注意点：

事项 说明
PATH 追加 WSL 默认把 Windows PATH 附加进 Linux PATH（所以能直接调 code）；不想要可在 /etc/wsl.conf 加 [interop] 段 appendWindowsPath=false
路径换算 Linux 路径 ↔ Windows 路径用 wslpath：wslpath 'C:\Users\x' → /mnt/c/Users/x
性能铁律 跨文件系统（/mnt/c 上跑 Linux 构建）I/O 慢一个数量级，代码放 Linux 侧
行尾差异 Windows CRLF ↔ Linux LF：Git 配 core.autocrlf=input，编辑器统一存 LF

全流程回顾

步骤 内容
基础 BIOS 虚拟化、WSL + 虚拟机平台、WSL2、wsl --update
Rocky Linux 默认 10：Rocky-10-WSL-Base.latest.*.wsl + --name Rocky-10；9 同理换包名与 --name
Docker Desktop 安装时选 WSL 2 引擎；Settings → WSL integration 勾选 Rocky 发行版
镜像加速 Settings → Docker Engine：registry-mirrors + builder.gc（见「安装与配置 Docker Desktop」一节）
验证 Rocky 内 docker run hello-world
用户与 root WSL 一般无二次「登录」；sudo passwd root 设密码，su - 验证；必要时 wsl -u root（见「Rocky Linux 首次进入与基础配置」一节）
网络与资源 默认 NAT + localhost 直通；局域网访问切 mirrored；.wslconfig 限内存/CPU
发行版配置 /etc/wsl.conf 控 systemd；dnf 源可换国内镜像；互操作走 /mnt/c、interop、wslpath
实践建议 代码放 Rocky 等发行版内 Linux 路径（如 ~/project）；勿长期用 /mnt/c 做重编译；避免与发行版内独立 dockerd 混用

Rocky Linux 9 / 10 切换请对照官方 WSL 文档对应版本页；Docker Desktop 与 Windows 大版本兼容性以 Docker 发行说明为准。

本章小结

要点 结论
环境前提 BIOS 开虚拟化 + 启用 WSL/虚拟机平台 + WSL2 + wsl --update
安装 Rocky 官方 .wsl 镜像 + wsl --install --from-file，Windows Terminal 直接进入
安装 Docker Docker Desktop 选 WSL2 引擎，在 WSL integration 中勾选 Rocky 发行版
关键配置 registry-mirrors 镜像加速 + builder.gc 构建缓存回收
网络/资源 NAT 默认 localhost 直通；.wslconfig 切 mirrored、限内存与核数
Rocky 配置 dnf 换国内镜像提速；/etc/wsl.conf 的 [boot] systemd=true 按需开
互操作 /mnt/c 互通文件、wslpath 换算路径；重 I/O 一律放 Linux 文件系统
排障要点 找不到 docker 先查集成开关并 wsl --shutdown；忘密码用 wsl -u root 重置
