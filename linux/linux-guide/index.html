1. 概念说明

Linux 是开源操作系统内核，服务器端事实标准。一切皆文件：硬件设备、进程信息都以文件形式暴露（/dev、/proc）。

目录结构速记：

目录 作用
/etc 系统与软件配置
/var 日志（/var/log）、缓存
/home 用户目录
/opt 第三方软件
/tmp 临时文件
/usr 系统程序与库
/proc 运行时内核信息（伪文件）

Shell 是命令解释器：你输入命令，内核执行。学习路径：命令 → 组合管道 → 脚本自动化。

案例：磁盘 100% 但 du 找不到大文件

问题背景：告警显示 / 使用率 100%，服务写日志报错。登录后 du -sh /* 汇总却只有 40% 左右，du 与 df 严重对不上——典型嫌疑是进程仍持有已删除的大文件。

方案：df 确认分区 → du 逐层定位目录 → lsof 找已删除文件 → 重启进程/截断句柄释放 → 配 logrotate 防复发。

踩坑点：

  • rm 一个正被写入的大日志不会释放空间：inode 仍被进程引用，df 照样满。要么重启服务，要么 truncate -s 0。
  • du 统计文件系统可见文件，df 看块分配，口径不同——对不上先想 deleted 文件和挂载点覆盖。
  • 不要直接 rm -rf /var/log 清理，会连带删掉还在写的日志目录；用 find -mtime +7 -delete 按时间删。
  • 治本：给应用日志配 logrotate（见运维自动化篇），监控同时加磁盘与 inode 告警（df -h / df -i）。

14. 实战：CasOS —— 构建在 Kubernetes 之上的云操作系统

CasOS 是一个构建在 Kubernetes 之上的云操作系统，口号是「一个文件装下你自己的云」。与传统方案的最大区别：它把 Kubernetes API server、controller-manager、scheduler 全部嵌进单个可执行文件，双击或一条命令就能在笔记本、游戏 PC 或服务器上拉起一个真实的 K8s 集群，附带 Web UI、应用商店、私有 AI 和 AI Agent 接入能力——无需 YAML，无需预先准备集群。

14.1 定位：和 k3s、CasaOS、Coolify 的差别

工具 给你什么 CasOS 的差异
k3s / minikube 一个裸 K8s 集群 CasOS 在集群之上加了 UI、应用商店、私有 AI、Agent 接入，且原生支持 Windows（节点跑在 WSL，缺 WSL 会自动装）
CasaOS / Coolify Docker 上的一键应用 CasOS 把同样体验放在真实 Kubernetes 上，后续可通过 SSH 加机器扩容成多节点

14.2 安装（单文件，跨平台）

装完打开 Web UI（默认端口），整个集群、应用、数据库、GPU 任务都在浏览器里管理。

14.3 核心能力速览

能力 说明
单文件集群 控制面三件套嵌入一个二进制，启动即集群，起步节点=本机
私有 AI 一键装 Ollama + Open WebUI，按 GPU 显存自动选最大可跑模型（Qwen3/DeepSeek R1 等），对外提供 /v1 OpenAI 兼容 API，数据不出本机
AI Agent 驱动 内置 MCP server，Claude Code/Cursor/Codex 可直接部署应用、读日志、回滚、开沙箱跑 GPU 任务
DevBox 浏览器版 VS Code 或 SSH 远程开发，可从 Git 仓库一键起带 GPU 的开发环境
应用商店 sealos 模板目录 + Helm Chart，托管数据库自带备份与控制台
Git 部署 给个公开仓库，集群内按 Dockerfile（或 Node/Python/Go/静态项目）构建并分配地址，无需自建镜像仓库
compose 兼容 直接粘贴 docker-compose.yml 运行，每个服务独立 namespace、按名互访，GPU 预留走 NVIDIA 卡

14.5 踩坑点

  1. Windows 节点依赖 WSL：首次启动若系统无 WSL 会自动安装，公司域控机器可能因策略失败，需先手动启用 WSL2。
  2. 单文件≠单机的限制：起步是单节点，但要发挥「加机器扩容」的价值，需保证节点间 SSH 互通与端口放行。
  3. 私有 AI 吃显存：自动选模型按显存上限来，多卡机器要留意模型副本在 GPU 间的分布，避免单卡 OOM。
  4. 别把单节点当生产：单文件集群适合个人/边缘/开发场景，生产仍需多节点 + etcd 高可用（CasOS 支持加节点，但控制面冗余要按官方文档单独规划）。

15. 常见误用与陷阱

坑 现象/后果 解法
rm -rf $DIR/* 变量为空 展开成 rm -rf /*，整盘被删 变量加引号并判空：[ -n "$DIR" ] && rm -rf "$DIR"/*
chmod -R 777 /var/www 全目录可写；SSH 私钥因权限过开放被拒登 目录 755 / 文件 644 / 密钥 600，按需 chown 解决访问问题
kill -9 代替优雅停止 进程没机会刷缓冲、释放锁，数据损坏 先 kill（SIGTERM），等 30 秒无效再 kill -9
> 与 >> 混淆 > backup.tar 覆盖了昨天的备份 追加一律 >>；覆盖前先 ls -l 确认目标存在与否
管道下游提前退出触发 SIGPIPE `cmd head 令 cmd 被 SIGPIPE 杀掉，set -o pipefail` 的脚本莫名失败
tail -f 跟踪已轮转文件 轮转后文件被改名，tail 盯着旧 inode”日志不动了” 用 tail -F（跟随文件名而非 inode）
