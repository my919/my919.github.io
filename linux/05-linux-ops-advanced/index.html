第五章：系统运维进阶

概念基础

  1. SSH 是远程运维的生命线：服务器只在机房里亮灯，日常工作全靠 ssh 进入；密钥免密、~/.ssh/config 别名、端口转发是三件必修装备。
  2. systemd 是 PID 1：现代 Linux 的 1 号进程，统一管理服务、日志（journald）、定时任务（timer）——把自己的脚本注册成服务，才算真正「上线」。
  3. 日志先行：排障顺序永远是「先看日志，再猜原因」；journalctl 统一了服务的 stdout 与系统日志，带 --since、-f、-p err 精确定位。
  4. 资源要主动观测：磁盘（df/du）、内存（free）、文件句柄（lsof）、进程（top/ps）是容量与故障预警的四个仪表盘。
  5. 重复的事交给调度器：临时脚本用 cron，需要依赖关系、日志、错峰的服务级调度用 systemd timer。

本章承接 第三章：Bash 脚本编程 的脚本能力，命令语法基于 RHEL 9/10（Rocky）与 systemd 25x 验证；rsync/lsof 未在沙箱安装，按官方语法书写。

句柄泄漏征兆：Too many open files 报错、lsof 数量持续上涨——先查连接/文件是否 close()，再调 ulimit 与 systemd 的 LimitNOFILE=65535（写在 unit 的 [Service] 段）。

4. 性能观测四件套（sysstat）

判读口诀：CPU 高看 %user（应用）还是 %system/%iowait（内核/IO）；%iowait 高 + iostat 里 %util 满 = 磁盘瓶颈；vmstat 的 si/so 非 0 = 内存不够在换页。

2. 如何选择

维度 cron systemd timer
语法 五字段简单直接 OnCalendar 更强（Persistent 补跑）
日志 需自己重定向 自动进 journald，journalctl -u xxx 可查
依赖 无 After=/Requires= 可声明依赖
秒级/错峰 不支持 支持更精细调度
建议 用户级小脚本 生产服务级任务首选

cron 环境变量极简（PATH 不含你的自定义路径）：脚本里一律用绝对路径，或在 crontab 顶部显式 PATH=。

本章小结

要点 结论
SSH ed25519 密钥免密 + ~/.ssh/config 别名；-L 本地转发调内网服务
rsync --delete 先 -n 预览；结尾斜杠决定「内容」还是「目录本身」
systemd 服务 unit 文件四段式；改完 daemon-reload；enable --now 一步到位
依赖与加固 排序 After=；依赖用 Wants= 弱依赖；ProtectSystem/NoNewPrivileges 收紧权限
资源控制 cgroup v2 原生：MemoryMax/CPUQuota 写进 unit，systemd-cgtop 观测
日志 journalctl -u xxx -f --since -p err；OOM 去 dmesg -T 找；文本日志配 logrotate
磁盘/资源 df -h/du -sh 查容量；free 看 available；lsof 查句柄与 deleted 文件
性能观测 vmstat 看换页、iostat 看磁盘、sar 看趋势、perf top 找热点
调度 临时用 cron（绝对路径！），生产用 systemd timer（有日志、可补跑）
