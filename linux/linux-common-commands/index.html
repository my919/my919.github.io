15. 排障组合命令（场景速查）

症状 命令组合（差异已标注）
服务起不来 systemctl status 服务 → journalctl -u 服务 -n 50
Rocky 服务异常 先查 SELinux：getenforce → ausearch -m avc -ts recent
端口不通 ss -tlnp → 防火墙（Ubuntu ufw status / Rocky firewall-cmd --list-all）
磁盘满了 df -h → du -sh /* | sort -hr | head → 清日志
CPU 100% top -b -n1 | head → top -Hp <pid>
内存不足 free -h → ps aux --sort=-%mem | head
端口被占 ss -tlnp | grep :8080 → lsof -i :8080
网络不通 ping → mtr → ss -tan → tcpdump
域名解析失败 dig → cat /etc/resolv.conf
登录不了 journalctl -xe → 登录日志（Ubuntu auth.log / Rocky secure）
负载高但 CPU 低 iostat -x 1 → 磁盘 IO 瓶颈 → vmstat 1
文件删不掉 lsof | grep deleted → 找占用进程重启

17. 典型案例

案例：CPU 100% 排查（从进程到线程）

问题背景：告警显示某应用服务器 CPU 持续 95%+，业务接口变慢。需要在几分钟内定位是哪个进程、哪个线程在烧 CPU。

方案：top 找进程 → top -Hp 下钻线程 →（Java 场景）线程号转十六进制对 jstack → 用 strace/perf 看系统调用与热点函数。

关键命令：

踩坑点：

  • top 里 %Cpu(s) 的构成先分清：us 高查应用代码、sy 高查 syscall/上下文切换、wa 高查磁盘 IO——wa 高时杀进程无济于事。
  • 多核机器”100%”可能只是单核打满，top 按 1 展开每核确认。
  • 容器环境还要看 cgroup CPU limit 是否被打爆（throttling 指标），宿主机 top 看不出来。

18. 常见误用与陷阱

坑 现象/后果 解法
rm -rf "$VAR"/* 变量为空 展开成 rm -rf /*，灾难 判空 + 引号；高危命令先 echo 看展开结果
df 与 du 数字对不上 明明删了文件，df 还是满 进程仍持有已删除文件：lsof +L1 找到并重启
kill -9 成习惯 丢数据、锁文件残留、服务起不来 先 SIGTERM，超时再 -9；systemd 服务用 systemctl stop
find -mtime +7 理解错 以为删”7 天前”却删错范围 +7=超过 7 天，-7=7 天内；先 -ls 预览再 -delete
sed -i 直接改生产配置 改错无备份回不去 sed -i.bak 留备份，或先输出临时文件 diff 确认
apt upgrade 前不 update 装的还是旧版本，误以为已升级 口诀：update 刷索引，upgrade 升级包
