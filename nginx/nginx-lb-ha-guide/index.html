1. 概念说明

负载均衡：多台应用服务器分担流量——提升吞吐（横向扩展）与可用性（单点故障不影响）。

Nginx 负载均衡核心：upstream（后端服务器组）+ proxy_pass（转发）+ 调度算法（怎么分流量）。

高可用：Nginx 自身不能是单点——两台 Nginx 用 Keepalived 共享一个虚拟 IP（VIP），主挂备自动接管。

现代替代：K8s Ingress、云 LB（ALB/SLB）；但 Nginx 仍是自建与边缘网关主力。

9. 典型案例：API 限流防刷

问题背景：某开放 API 平台被恶意刷接口，单 IP 每秒发起上千次请求，导致后端数据库连接池打满、正常用户请求超时。需要在 Nginx 层做多层限流：按 IP 限请求速率、按 IP 限并发连接数、对登录等敏感接口单独加严，保护后端服务。

方案：

限流维度 配置 阈值 作用
请求速率 limit_req 10r/s + burst 20 防刷接口
并发连接 limit_conn 单 IP 20 防连接耗尽
敏感接口 limit_req 2r/s + burst 5 防爆破登录
限流响应 limit_req_status 429 返回 Too Many Requests

关键配置：

踩坑点：

  1. limit_req 的 burst + nodelay 组合：burst=20 nodelay 表示突发 20 个请求立即处理，超过的返回 429。不加 nodelay 则突发请求会排队延迟处理，可能导致请求超时。
  2. 限流区共享内存大小：zone=api_limit:10m 中 10m 是共享内存大小，约可存 16 万个 IP 状态。高并发场景若太小会导致限流失效（Nginx 会丢弃无法存储状态的请求），需按 IP 数量调大。
  3. $binary_remote_addr vs $remote_addr：用 $binary_remote_addr（二进制，4 字节）比 $remote_addr（字符串，7-15 字节）省内存，限流区能存更多 IP。

10. 常见误用与陷阱

坑 现象/后果 解法
proxy_pass 末尾斜杠语义不清 路径被错误替换，后端 404 无斜杠保留 URI，有斜杠替换前缀
if 判断陷阱 if 内逻辑行为不可预期 用 try_files/return 替代，避免复杂 if
worker_connections 误解 认为是全局连接数 全局 = worker_processes × worker_connections
缓冲区大小不合理 大响应缓冲到磁盘，性能下降 调大 proxy_buffer_size/proxy_buffers
超时未分级 慢接口拖累整体 按接口设 proxy_connect/read/send_timeout
限流区内存太小 高并发时限流失效 按 IP 数量调大 zone 内存（10m≈16 万 IP）
