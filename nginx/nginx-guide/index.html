1. 概念说明

Nginx 是高性能 HTTP 服务器与反向代理，事件驱动 + 异步非阻塞模型，单机可支撑数万并发连接。三大用途：

用途 说明
静态文件服务 HTML/CSS/JS/图片，QPS 极高
反向代理 接收外部请求，转发到内部服务（隐藏后端、统一入口）
负载均衡 多后端实例按策略分发

正向代理 vs 反向代理：

  • 正向代理：代理客户端（翻墙、缓存），客户端知道目标。
  • 反向代理：代理服务器（用户访问 Nginx，Nginx 转发后端），客户端无感知。

进程模型：一个 master（管理）+ N 个 worker（处理请求）。nginx -s reload 平滑重载配置，不中断服务。

7. HTTPS 配置

生产用 certbot 自动签发 Let’s Encrypt 证书（sudo certbot --nginx -d example.com，自动改配置并续期）；手动配置核心三项：ssl_certificate/ssl_certificate_key 指证书与私钥、ssl_protocols TLSv1.2 TLSv1.3 只放行安全协议、add_header Strict-Transport-Security 开 HSTS；另起一个 80 端口 server 用 return 301 https://$host$request_uri 全站跳转。

8. 限流与安全

limit_req_zone 按 IP 限请求速率（rate=5r/s + burst=10 nodelay），limit_conn_zone 限每 IP 并发连接数；server_tokens off 隐藏版本号，location ~ /\.(git|env|ht) { deny all; } 拒敏感路径。

限流区内存估算、访问控制（allow/deny、auth_basic）与安全响应头全家桶：深入了解：第三章：Nginx HTTPS 与安全

9. 缓存（反向代理缓存）

两段式配置：http 作用域 proxy_cache_path 定义缓存区（目录分层 + keys_zone 共享内存 + max_size 磁盘上限），server/location 里 proxy_cache mycache 启用 + proxy_cache_valid 200 10m 定有效期；add_header X-Cache-Status $upstream_cache_status 调 HIT/MISS。

10. 性能调优基线

基线四件套：worker_processes auto（= CPU 核数）+ worker_connections 10240（每 worker 连接数）+ sendfile on（零拷贝）+ keepalive_timeout 65；worker_rlimit_nofile 65535 抬文件描述符上限。压测用 wrk（wrk -t8 -c1000 -d30s）。

12. 典型案例：前后端分离 + 反向代理 + 负载均衡

问题背景：某电商站点前端是 Vue SPA（静态资源），后端是 Spring Boot API，还有 WebSocket 实时通知。需要用 Nginx 做统一入口：静态资源直接服务、API 反向代理到后端集群、WebSocket 升级、HTTPS 全站加密。

方案骨架：一个 443 server 内按路径分流——/ 静态文件（try_files $uri $uri/ /index.html 做 SPA 路由回退）、/api/ 转发 upstream backend（least_conn + weight + max_fails 被动摘除 + backup 兜底）、/ws/ 转发 WebSocket（必配 Upgrade $http_upgrade + Connection "upgrade"，proxy_read_timeout 3600s 保长连接）；80 端口 return 301 跳转 HTTPS。

三大踩坑点：① proxy_pass 末尾有无斜杠语义完全不同（无斜杠保留完整 URI，有斜杠替换前缀）；② WebSocket 不配 Upgrade 头无法升级；③ SPA 不配 try_files 刷新页面 404。

完整可落地的配置全文与 upstream 参数详解：深入了解：Nginx · 反向代理、负载均衡与高可用

13. 常见误用与陷阱

坑 现象/后果 解法
proxy_pass 末尾斜杠语义不清 路径被错误替换，API 404 无斜杠保留完整 URI，有斜杠替换前缀；按需选择
if 判断陷阱 if 指令在 location 中行为不可预期 尽量用 try_files/return；避免 if 内复杂逻辑
worker_connections 误解 认为是全局连接数，实际是每 worker 全局连接数 = worker_processes × worker_connections
缓冲区大小不合理 大请求/响应被缓冲到磁盘，性能下降 调大 proxy_buffer_size/proxy_buffers；大文件用 sendfile
超时未分级 所有接口用同一超时，慢接口拖累快接口 按接口设 proxy_connect/read/send_timeout
未透传真实 IP 后端收到的全是 Nginx 的 IP 配 X-Real-IP 和 X-Forwarded-For
