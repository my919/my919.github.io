第十四章：自定义注解与AOP实现业务逻辑

概念基础

在 Spring Boot 中，自定义注解 + AOP 是横切业务逻辑的常用方式：把「操作审计、防重、幂等、权限、租户隔离」等从 Controller/Service 方法里抽离，做到声明式、可复用、可开关。

  1. 切面（Aspect）：横切关注点（审计、防重、幂等、权限）不写进业务方法，而是由切面统一织入，业务代码零侵入。
  2. 自定义注解：注解只描述元数据（如 @BizCheck(scene = ...)），不含业务实现；@Retention(RUNTIME) 保证运行时切面可读取。
  3. 环绕增强：@Aspect + @Around("@annotation(...)") 在 proceed() 前后写逻辑，可计时、可拦截、可放行；用 @Order 控制多切面顺序。
  4. 为什么选它：与 Filter / Interceptor（全站 HTTP 层）、@ControllerAdvice（统一异常与校验）各司其职；核心领域规则仍写在 Service，AOP 只做入口守卫或记录。
  5. 本仓库样板：@OperLog、@RepeatSubmit、@Idempotent 均按「注解 → 切面 → Properties 开关 → 测试」四步落地，本文以示例 @BizCheck 贯穿全文。

本仓库已落地：

注解 切面 文档
@OperLog OperLogAspect 第十章：AOP日志与操作审计

本文说明从零实现一套注解切面的通用步骤，读者可照此模式扩展自己的业务注解。

何时用注解 + AOP

方式 适用
自定义注解 + AOP 与具体方法绑定、可带参数、需环绕/前后增强（日志、锁、审计）
Filter / Interceptor 全站 HTTP 层（鉴权头、TraceId），与具体业务方法弱相关
@ControllerAdvice 统一异常、参数校验（见 第八章：SpringBoot 统一返回体与全局异常）
纯 Service 调用 强业务分支、需单元测试的核心规则

原则：横切、重复、可配置 → 注解 + AOP；核心领域规则 → 仍写在 Service，AOP 只做入口守卫或记录。

AOP 调用链



flowchart TD
  Client[HTTP 请求] --> Proxy[Spring CGLIB 代理]
  Proxy --> A1[RequestLog / BizCheck]
  A1 --> A2[RepeatSubmit / Idempotent]
  A2 --> A3[OperLog]

元注解详解

写一个自定义注解时，元注解决定它在哪些位置有效、存活多久、能否被继承与文档化。下表是 Java 提供的 5 个标准元注解：

元注解 取值 含义 常见错误
@Target METHOD / TYPE / FIELD / PARAMETER… 注解可以贴在哪里 漏写 METHOD 时 @annotation 切点匹配不到方法
@Retention SOURCE / CLASS / RUNTIME 注解存活到哪一级 写成 CLASS 时切面读不到——必须 RUNTIME
@Documented — 进入 Javadoc 仅影响文档，可省略
@Inherited — 子类继承父类的类级注解 只对 @Target(TYPE) 有效，对方法注解无效
@Repeatable 容器注解类 同位置可重复标注 需配套定义「容器」注解

@AliasFor：属性别名

@AliasFor 让注解属性互为别名，是组合注解的关键：

@OrderScene("order-create") 等价于 @BizCheck(scene = "order-create")，语义更聚焦。Spring 内部大量使用此模式（如 @GetMapping 之于 @RequestMapping）。

注意：用 @AliasFor 时切面需通过 AnnotatedElementUtils.findMergedAnnotation(method, BizCheck.class) 才能拿到合成结果；直接 method.getAnnotation(BizCheck.class) 拿到的是元注解上的默认值。

注解继承的边界

@Inherited 仅作用于类层级，且只继承父类上的注解（不继承接口、不继承方法）。Spring 项目里更可靠的方案是 AnnotationUtils.findAnnotation(method, BizCheck.class)，它会沿方法 → 类 → 父类 → 接口整条链查找。

1. 定义注解

注解只描述「元数据」，不含业务实现：

要点：

  • @Retention(RUNTIME)：运行时切面才能读到。
  • @Target(METHOD)：标在接口方法上；若标在类上需改切点或额外解析。
  • 属性用基本类型 / String / enum，避免复杂对象。

2. 编写切面

说明：

  • @Around("@annotation(bizCheck)")：绑定带 @BizCheck 的方法；参数名 bizCheck 与注解参数一致。
  • 也可用 @annotation(org.my919.springboot.annotation.BizCheck) 全限定名。
  • 校验失败抛 BusinessException，由全局异常处理器转为 Result（见 第八章：SpringBoot 统一返回体与全局异常）。

通知类型怎么选

4. SpEL 动态参数（可选）

注解属性可写 SpEL，在切面里用 MethodBasedEvaluationContext 解析方法参数，例如 @BizCheck(scene = "#dto.type")。适合场景码依赖入参；复杂度较高时更推荐在 Service 内显式校验。

5. 异步与事务

  • @Async：切面在调用线程执行，proceed() 之后才进入异步（除非切面内再开线程）。
  • @Transactional：默认仅对 public 代理方法生效；@Around 若在外层，注意事务边界与 proceed() 的关系（事务切面通常 Order 较低）。

常见坑

现象 原因 处理
注解不生效 同类自调用（this.create()） 注入自身代理或拆到另一个 Bean
注解不生效 方法 private / final Spring AOP 默认 CGLIB/JDK 仅代理 public（Boot 常用 CGLIB）
注解不生效 切面类未被扫描 @Component + 在主应用包路径下
顺序混乱 多个 @Around 使用 @Order
测试失败 无 Redis / 未关切面 测试 application.yaml 设 app.*.enabled: false（见防重文档）
参数日志泄密 logArgs=true 脱敏密码、Token；生产默认关闭

要点 结论
