第八章：SpringBoot 统一返回体与全局异常

发表于 2026-05-16 更新于 2026-10-25 分类于 SpringBoot 本文字数： 6.7k 阅读时长 ≈ 6 分钟

第八章：SpringBoot 统一返回体与全局异常

概念基础

  1. 统一契约：成功与失败均使用同一 JSON 结构，便于前端统一解析；Result<T> 三字段 code / msg / data。
  2. 两层语义：HTTP 状态码表达协议层语义（400/409/500 等），code 字段表达业务语义（可与 HTTP 一致或自定义）。
  3. 异常即响应：业务错误抛 BusinessException，由 @RestControllerAdvice 的 GlobalExceptionHandler 全局捕获并转换为 Result.fail，Controller 免写 try-catch。
  4. 校验联动：@Valid / @Validated 触发的 MethodArgumentNotValidException 与 ConstraintViolationException 同样统一处理为 400。
  5. 模板复用：完整 GlobalExceptionHandler 源码模板见 第五章：Java 全局异常处理：@RestControllerAdvice 与统一 Result；本章描述 springboot 仓库中的落地方式与验证。

错误码规范

code 字段是前后端联调与日志检索的关键，建议遵循分段约定：

区间 语义 示例
200 成功 —
400-499 客户端错误，与 HTTP 语义对齐 400 参数错误、401 未登录、403 无权限、409 状态冲突、429 频率限制
500-599 服务端错误 500 通用异常、502 下游失败
10000+ 业务自定义错误（可选） 10001 库存不足、10002 订单已关闭

约定原则：

  • 通用错误复用 HTTP 语义，前端拦截器可按 code 统一处理（401 跳登录、403 提示无权限）。
  • 业务错误自定义五位数，全局唯一，配合文档可检索；不要为了细分而滥用，能用 400/409 表达的不新开码。
  • msg 面向用户可读；技术细节（堆栈、SQL）只进服务端日志，不进响应体。

ResponseBodyAdvice：自动包装（可选进阶）

若希望 Controller 直接返回裸对象、由框架自动套 Result，可实现 ResponseBodyAdvice：

本项目未采用自动包装，选择显式 Result.success(...) 的原因：

维度 显式包装（本项目） 自动包装（Advice）
可读性 Controller 一眼看清返回契约 需知道 Advice 存在才理解响应结构
特殊端点 文件下载/Actuator 天然不受影响 需额外排除二进制端点
异常路径 异常处理器与正常路径结构天然一致 两处包装逻辑易不一致
团队成本 无隐式魔法，新人零学习成本 调试时多一层「谁包了返回值」

两种方案没有绝对优劣，全项目统一才是关键。

全局异常处理

@RestControllerAdvice + GlobalExceptionHandler：

异常 处理
BusinessException Result.fail(code, msg)，HTTP 按 code 映射
MethodArgumentNotValidException 首个字段错误 → 400
ConstraintViolationException @Validated 参数校验 → 400
InvalidFormatException JSON/枚举格式错误 → 400
Exception 未捕获 → 500，日志记录

BusinessException HTTP 映射示例：401、403、404、409、429（与 第十一章：防重提交与接口幂等 中 429 一致）。

处理器核心骨架：

要点：

  • @ExceptionHandler 匹配顺序：Spring 按最具体优先匹配，子类异常会命中父类处理器，兜底 Exception 永远最后。
  • 返回 ResponseEntity：让业务 code 与 HTTP 状态码同步（如 429 同时出现在两处），网关/前端拦截更顺畅。
  • 兜底分支不泄细节：生产环境 msg 固定话术，堆栈只进日志，防止泄露表结构、路径等敏感信息。

常见问题

现象 原因 处理
异常仍返回 HTML 白页 抛在 Filter/拦截器层，未经 DispatcherServlet 用 HandlerExceptionResolver 或把校验下沉到 Controller 内
校验错误信息是英文 注解 message 未写中文 DTO 注解统一写中文 message
500 堆栈出现在响应里 兜底分支直接 e.getMessage() 固定话术 + log.error 记堆栈
异步方法异常没被处理 @Async 异常不走 Web 异常链 异步方法内自行 try-catch 或配置 AsyncUncaughtExceptionHandler

搭建步骤（新项目复用）

  1. 复制 controller/entity/Result.java
  2. 复制 exception/BusinessException.java、GlobalExceptionHandler.java
  3. 引入 spring-boot-starter-validation
  4. Controller 统一返回 Result<T>

与 第九章：全局跨域与参数校验 配合：@Valid 触发校验异常后由本 Handler 统一返回。
