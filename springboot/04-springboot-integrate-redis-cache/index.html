第三章：SpringBoot 集成 Redis 与缓存

概念基础

缓存把热点数据放进内存数据库，用空间换时间，降低数据库压力、缩短响应时间：

  1. 三种接入方式：本项目集成 Spring Data Redis（StringRedisTemplate）、Redisson（分布式对象、Bucket 等）、Spring Cache（@Cacheable，底层为 Redis），按场景选用。
  2. 统一连接层：三者最终都经 Lettuce 连接访问同一个 Redis（见架构图），连接与超时配置集中管理。
  3. TTL 必设：缓存写入务必带过期时间（如探针 120 秒），防止脏数据长期滞留与内存膨胀。
  4. 业务耦合点：防重、幂等、缓存探针均依赖 Redis——防重用 SET NX + TTL，幂等缓存首次成功的 Result JSON。
  5. 测试隔离：单测排除 Redis 自动配置、缓存切换 simple 并注入 Mock Bean，保证无 Redis 也能跑通测试。

@Cacheable 注解体系

Spring Cache 提供四个核心注解，覆盖「读、写、删、组合」四类操作：

注解 语义 典型场景
@Cacheable 先查缓存，未命中才执行方法并回填 查询类接口
@CachePut 总是执行方法，结果写入缓存 更新后同步刷新缓存
@CacheEvict 执行方法后删除缓存（allEntries 可清整区） 删除/失效数据
@Caching 同一方法组合多个缓存操作 一处更新影响多缓存

选型建议：key 一律 String；value 用 GenericJackson2JsonRedisSerializer（带 @class 类型信息，反序列化不丢泛型）；纯字符串场景直接 StringRedisSerializer 最省。

缓存三兄弟：穿透 / 击穿 / 雪崩



flowchart TB
  Q[查询请求] --> C{缓存命中?}
  C -->|是| H[直接返回]
  C -->|否| DB[查数据库]
  DB --> F[回填缓存 + TTL]
  F --> H

1. 缓存穿透——查询根本不存在的数据，缓存永不命中，流量直达 DB：

  • 方案 A：缓存空值（短 TTL，如 60s），cache-null-values: true 时配合短过期。
  • 方案 B：布隆过滤器（Redisson RBloomFilter）前置拦截非法 key，适合海量不存在的 ID。

2. 缓存击穿——热点 key 恰好在高并发时过期，大量请求同时回源：

  • 方案 B：逻辑过期（value 里带过期时间戳，后台线程异步续期），热点 key 永不过期。

3. 缓存雪崩——大量 key 同时过期或 Redis 宕机：

  • TTL 加随机抖动：30min + random(0~10min)，打散过期时间点。
  • 多级缓存：本地 Caffeine（秒级）+ Redis（分钟级），Redis 挂了还有一层。
  • 兜底降级：Redis 异常时走 @Cacheable(sync = true) 无效，需在切面捕获后降级直查 DB + 限流。

对照速查：

问题 触发条件 核心防御
穿透 查不存在的数据 空值缓存 / 布隆过滤器
击穿 热点 key 瞬间过期 互斥锁回源 / 逻辑过期
雪崩 批量过期 / Redis 宕机 TTL 抖动 / 多级缓存 / 降级
