第六章：SpringBoot 集成 Spring Boot Admin 监控

概念基础

  1. 定位：Spring Boot Admin 用于集中查看应用健康、指标、日志等，是 Actuator 数据的可视化面板。
  2. Server / Client 模型：Client 读取 Actuator 端点并向 Server 注册实例，Server 提供 Web UI 汇总展示；版本需与 Spring Boot 匹配。
  3. 本仓库形态：在 同一进程 内同时启用 Admin Server 与 Client（适合本地演示）；生产建议拆分为独立 Admin 服务并加认证。
  4. 暴露面管控：dev 全量暴露端点便于调试；prod 收紧为 health,info,metrics,prometheus，健康详情 when_authorized，端点暴露即攻击面。
  5. 测试隔离：单测关闭 Client 注册（spring.boot.admin.client.enabled=false），避免测试进程向外注册实例。

Client 端点安全

服务端有认证后，Client 注册与拉取端点都要带凭证；业务应用的 /actuator 也应独立保护：

要点：

  • 账号分离：Admin UI 登录账号、Client 注册账号、Actuator 访问账号三者可不同，权限最小化。
  • 独立管理端口让 /actuator 与业务流量隔离，网关层可整段禁外网。
  • 健康详情 show-details: when_authorized，未认证只能看到 UP/DOWN。

告警通知（Notifier）

Admin 不仅是面板，还能在实例状态变更（UP → DOWN）时主动告警。内置 Notifier SPI，常用渠道：

1. 邮件通知

2. 自定义 Webhook（钉钉 / 企业微信）

3. 告警治理建议

项 建议
告警粒度 只报 DOWN / OFFLINE，UP 恢复可合并为一条
防轰炸 同一实例抖动时做静默窗口（如 5 分钟内只报一次）
升级路径 简单场景用 Admin 通知；严肃生产用 Prometheus + Alertmanager（见 服务）
上下文 通知里带实例名、IP、最近日志链接，缩短定位时间

常见问题

现象 原因 处理
实例列表为空 Client url 不可达或被 Security 拦 查 Client 日志的 401/403
实例一直 DOWN Actuator 端点未暴露或需认证 检查 exposure.include 与 metadata.user.*
UI 静态资源 404 反向代理路径前缀未配 spring.boot.admin.ui.public-url 配置代理路径或 public-url
告警不触发 Notifier 未被扫描或事件过滤过严 确认 @Component 生效、事件类型匹配

生产建议

项 建议
部署 独立 Admin Server 集群
安全 Spring Security + 账号；限制 Actuator 暴露
网络 Client 通过内网注册，勿将 Admin 暴露公网
测试 src/test/resources/application.yaml 中 spring.boot.admin.client.enabled=false
