第六章：UV 项目开发添加 Pytest：单元测试

概念基础

pytest 是 Python 事实标准的单元测试框架：

  1. 断言极简：直接用普通 assert 语句写断言，无需记忆 xUnit 风格的 assertEquals 等方法；失败时 pytest 自动展示表达式各部分的实际值，排障高效。
  2. 自动收集：按 test_*.py / *_test.py 文件名与 test_ 前缀函数自动发现用例，无需继承基类、无需注册。
  3. 工程化配置：通过 pyproject.toml 的 [tool.pytest.ini_options] 约定测试目录（testpaths）、标记（markers）与默认参数（addopts），团队与 CI 行为一致。
  4. 生态丰富：pytest-cov 出覆盖率报告、pytest-xdist 多核并行、marker 分组筛选（-m "not slow"），并可与 uv、pre-commit（见第五章）、CI 无缝衔接。

九、常见坑 FAQ

坑 现象 处理
用例没被收集 跑完全绿但少了几条用例 检查文件名是否 test_*.py、函数是否 test_ 前缀；类名须 Test 开头且不能有 __init__
import 报错找不到包 ModuleNotFoundError: mypkg pyproject.toml 配 pythonpath = ["."]，或改用 src 布局 + uv sync 安装本包
fixture 顺序依赖 单独跑通过、全量跑失败 用例间共享了可变状态；检查 scope 过大的 fixture 是否被用例修改
assert 用了 == 比较浮点 偶发失败 用 pytest.approx(0.1 + 0.2) == 0.3
测试里真发 HTTP / 连真库 慢、不稳定、CI flaky 用 pytest-mock / responses 打桩；集成测试打 integration marker 分开跑
覆盖率数字虚高 只 import 了模块就算覆盖 看 --cov-report=term-missing 的未覆盖行号，别只看百分比
Windows 路径断言失败 硬编码 / 分隔符 用 pathlib.Path 构造路径，断言前 str(p) 归一化

十、最佳实践清单

  1. 一个用例只验证一件事，断言失败时能立刻定位意图。
  2. 用例名即文档：test_refund_fails_when_balance_insufficient 胜过 test_1。
  3. 快速反馈：默认 addopts 保持安静输出；慢测打 @pytest.mark.slow 日常 -m "not slow"。
  4. 测试互不依赖：不按执行顺序共享状态；共享资源走 fixture + 合适 scope。
  5. CI 全量 + 本地快速子集：本地 pytest -x -q，CI 跑全量加 --cov。
  6. 确定性：不在用例里依赖当前时间、随机数、外部网络；需要时注入/打桩。

十一、常用命令速查

目的 命令
安装 uv add --dev pytest
版本 uv run pytest --version
默认收集运行 uv run pytest
匹配标记 uv run pytest -m "not slow"
覆盖率 uv run pytest --cov=包或路径 --cov-report=term-missing

官方文档：pytest。

本章小结

要点 结论
框架定位 Python 事实标准测试框架，普通 assert 断言、自动收集用例
用例组织 推荐 tests/ 与源码平级；test_*.py + test_ 前缀函数即用例
工程配置 [tool.pytest.ini_options] 约定 testpaths、markers、addopts
常用技巧 -m "not slow" 标记筛选、-x 失败即停、pytest-xdist 并行、pytest-cov 覆盖率
协作约定 CI uv sync 后全量跑；pre-commit 只做轻量检查，全量测试留给 CI
Fixture @pytest.fixture 依赖注入 + yield 清理；conftest.py 目录级共享
参数化 @pytest.mark.parametrize 一组输入一个用例；pytest.raises 断言异常
