第五章：UV 项目开发添加 pre-commit：Git 提交钩子

概念基础

pre-commit 是一个 Git 提交钩子管理框架，在 git commit 前自动执行质量检查：

  1. 质量门禁前置：把 Ruff、BasedPyright、pytest 等检查放到提交时刻自动执行，不合格代码进不了仓库，避免「CI 跑一半才发现格式问题」。
  2. 配置即代码：所有钩子集中在 .pre-commit-config.yaml，团队成员克隆仓库后 pre-commit install 一次接入，执行同一套检查链。
  3. 钩子链有序执行：本站推荐顺序为通用清理（pre-commit-hooks）→ Ruff → BasedPyright → pytest，由轻到重、快速失败。
  4. 与 uv 协作：工具钩子用 repo: local + uv run 调用，版本与 uv.lock 完全一致，本地与 CI 行为统一。

下面从安装、配置到接入 Git 钩子逐步实操：

一、安装 pre-commit 与前置工具

1. 开发依赖（一次装齐）

提交前若要跑 Ruff / BasedPyright / pytest，需先作为开发依赖安装（若已装可跳过对应包）：

  • Ruff：Lint 与格式化（见《第三章：UV 项目开发添加 Ruff：代码检查与格式化》）。
  • BasedPyright：静态类型检查（见《第四章：UV 项目开发添加 Pyright：静态类型检查》）。

  • Ruff：local + uv run，版本与 uv.lock 中 ruff 完全一致；pass_filenames: true 时仅对暂存 .py / .pyi 跑 check --fix 与 format。建议顺序为先 ruff check --fix 再 ruff format（与常见习惯一致）。若某次提交未包含 Python 文件，这两个钩子会被跳过。
  • BasedPyright：pass_filenames: true 时把暂存路径传给 uv run basedpyright（需与 pyproject.toml 里 [tool.pyright] 的 include 等不矛盾）；若要整仓与 CI 一致可改为 pass_filenames: false。
  • pytest：示例为 pass_filenames: false，每次 uv run pytest（范围由 pyproject.toml 中 testpaths 等决定）；若需减负可改为 pass_filenames: true 并加 files: ^tests/ 等。

2. 与 uv.lock 对齐

Ruff、BasedPyright、pytest 均通过 uv run 调用，与本地及 CI 的 uv sync 结果一致；仅 pre-commit-hooks 仍由 pre-commit 按 rev 拉取，与 Python 工具链版本无关。

五、性能与拆分建议

  • pytest 全量放在每次 commit 可能偏慢：可只在 CI 跑全量，本地 pre-commit 保留 Ruff + BasedPyright，或给 pytest 加 stages: [manual] 改为手动 pre-commit run pytest。

八、常见坑 FAQ

坑 现象 处理
钩子把文件改了但提交仍成功 --fix 修改了文件，提交内容其实未包含修复 pre-commit 会判定失败并阻拦；git add 修复结果后重新提交即可——这是特性不是 bug
首次运行卡很久 拉取远程 rev 仓库与依赖慢 属正常；团队可统一 uv run pre-commit autoupdate 后锁版本
uv run 在钩子里找不到 uv 钩子在极简 PATH 下执行 确认 uv 装在用户级目录（默认安装即满足）；CI 里先 setup-uv
大仓库 pytest 每次全量跑 commit 慢到无法忍受 pytest 钩子改 stages: [pre-push] 或 manual，全量交给 CI
--no-verify 被滥用 脏代码入库，CI 才暴雷 团队约定禁止；可在 CI 用同一套钩子兜底
YAML 语法错导致钩子不生效 修改配置后钩子没变化 uv run pre-commit run --all-files 立即全量验证配置
Windows 上 language: system 路径问题 找不到可执行文件 uv 在 PATH 即可；避免在 entry 里写绝对路径

九、最佳实践清单

  1. 钩子链由轻到重：清理类 → Ruff → BasedPyright → pytest，快速失败省时间。
  2. 工具钩子一律 repo: local + uv run，版本跟着 uv.lock 走，杜绝「我本地是新版、CI 是旧版」。
  3. 本地与 CI 同配置：CI 用 --all-files 跑同一 YAML，不做双份维护。
  4. 重检查下沉：全量 pytest 放 pre-push 或 CI，commit 保持秒级反馈。
  5. 定期 autoupdate：每月更新 pre-commit-hooks 的 rev 并 review 变更。
  6. --no-verify 视为事故通道：用了就要在 PR 描述里说明原因。

十、常用命令速查

目的 命令
安装开发依赖 uv add --dev pre-commit ruff basedpyright pytest
安装 Git 钩子 uv run pre-commit install
全量跑 hooks uv run pre-commit run --all-files
更新远程 rev uv run pre-commit autoupdate

官方文档：pre-commit.com。

本章小结

要点 结论
工具定位 Git 提交钩子管理框架，把质量门禁前置到 git commit 时刻
前置链顺序 通用清理 → Ruff → BasedPyright → pytest，由轻到重快速失败
核心配置 钩子集中在 .pre-commit-config.yaml；工具钩子用 repo: local + uv run 与 uv.lock 对齐
接入与验证 pre-commit install 安装钩子；pre-commit run --all-files 手动全量预演
CI 协作 流水线 uv sync 后跑同一套钩子链；--no-verify 仅限应急
阶段拆分 commit 跑轻检查、push/CI 跑全量测试；CI 必须 --all-files
