发表于 2026-05-01 更新于 2026-10-25 分类于 Python 本文字数： 4.5k 阅读时长 ≈ 4 分钟

第十章：Jupyter 入门：经典 Notebook、安装与内核

概念基础

Jupyter 是交互式计算生态的名字（源自 Julia / Python / R 三大语言），核心产品就是「浏览器里的笔记本」：

  1. 代码-输出-说明同页共存：在浏览器里写代码、立即看结果、随手记 Markdown 笔记，一个 .ipynb 文件同时是草稿、报告与教学讲义。
  2. 前端与内核解耦：Notebook / JupyterLab 只是「前端界面」，真正执行代码的是独立的**内核（Kernel）**进程，二者通过协议通信——所以一个环境可注册多个内核，前端也可互换。
  3. .ipynb 文件格式：本质是 JSON，保存单元格代码、输出与元数据；是数据分析与算法实验的「可复现草稿纸」。
  4. 为什么需要它：探索性数据分析需要「改一行、马上看结果」的反馈回路，传统「写脚本 → 运行 → 看日志」的循环太慢，Notebook 正是为这类探索而生。
  5. 学习路径：本章掌握经典 Notebook；需要多标签工作台升级 第十一章：JupyterLab 入门：安装、工作区与扩展，团队多用户上 第十二章：JupyterHub 入门：多用户架构与部署要点。

官网与组成

  • Jupyter 项目主页：https://jupyter.org/
  • Notebook 文档（经典界面）：https://jupyter-notebook.readthedocs.io/
  • .ipynb 格式说明：以当前 nbformat 文档为准（Notebook 文件为 JSON，含代码单元、输出与元数据）。

Jupyter 与具体「前端」解耦：Notebook 与 JupyterLab 都能打开同一 .ipynb；底层常由 jupyter_server 提供 HTTP 与 WebSocket 服务。团队若只需单用户本机或单容器写分析，Notebook 或 JupyterLab 二选一即可。

环境准备

  1. 安装 Python 3.10+，终端可执行 python --version（或 python3，下文统一写 python，请按本机替换）。
  2. 建议使用虚拟环境（venv、conda 或站内 uv 工具），避免把 Jupyter 装进全局 site-packages 难以清理。

内核与 .ipynb 要点

1. 内核（Kernel）

内核是执行代码的进程；Python 环境装了 ipykernel 并注册后，Notebook 右上角可选该内核。

2. 单元格类型

常见为 Code（运行代码）与 Markdown（写说明）；Shift+Enter 执行当前单元并跳到下一单元（具体快捷键以界面 Help 为准）。

3. 保存与版本

.ipynb 含输出时体积会变大；纳入 Git 前团队可约定是否清空输出再提交，或使用 nbstripout 等工具（按需查阅文档）。

内核管理进阶

1. 查看与删除已注册内核

内核注册信息只是指向某个 Python 环境的 JSON 描述，真正的依赖装在各环境自己的 site-packages 里——所以「内核列表里有但 import 失败」多半是该环境里没装包。

2. 一个 Jupyter 服务挂多个环境

推荐做法：Jupyter 本体装一个干净环境，各项目环境只装 ipykernel 并注册内核：

启动 Jupyter 后在右上角切换内核即可，避免「每个项目装一套 Jupyter」的重复。

3. 内核卡死与重启

代码死循环或内存爆掉时，用工具栏 Interrupt（中断）→ Restart（重启）；重启会清空内存中所有变量，但单元格代码与已保存的输出保留。顽固卡死可直接在服务器上 kill 内核进程（jupyter kernelspec list 不含进程信息，需用系统工具按 Python 进程排查）。

Magic 命令速查

Notebook 中以 %（单行）或 %%（整单元格）开头的魔法命令是提效核心：

命令 作用
%time / %%time 测单行 / 整单元格耗时
%timeit 多次运行取最优耗时，微基准更准
%matplotlib inline 图直接嵌入单元格输出
%load_ext autoreload + %autoreload 2 改了本地模块不重启内核即生效
%pwd / %ls / %cd 常用 shell 操作
!pip install pkg 单元格内执行 shell 命令
%who / %whos 查看当前变量列表
%%writefile a.py 把单元格内容写成文件
%run script.py 在核内运行外部脚本

完整列表用 %lsmagic 查看。

常用快捷键（命令模式下，按 Esc 进入）

按键 作用
A / B 上方 / 下方插入单元格
DD 删除当前单元格
M / Y 切换为 Markdown / Code 单元格
Shift+Enter 执行并跳到下一单元格
Ctrl+Enter 执行并留在当前单元格

调试技巧

  1. 单元格内断点：Python 3.13+ 直接用 breakpoint()，触发后进入 ipdb 交互调试（需 pip install ipdb）。
  2. 事后分析：异常发生后执行 %debug 进入事后调试器，可检查崩溃时各栈帧变量。
  3. 打印优于猜测：探索期多用 display()（比 print 对 DataFrame 等对象渲染更好）。
  4. 大对象内存排查：%memit（需 memory_profiler）测单行内存；del + gc.collect() 释放。

远程访问与安全

1. SSH 端口转发（推荐）

远程服务器上只监听本机，本地转发：

本地浏览器访问 http://127.0.0.1:8888（带 token），流量全程走 SSH 加密。

2. 密码替代 token

此后可用密码登录，不必每次复制 token 链接。

3. HTTPS 直接对外（谨慎）

确需公网直连时，准备证书后在 jupyter_server_config.py 配置 certfile / keyfile；更常见的做法是前面挂 Nginx/Caddy 反向代理终结 TLS。务必：强密码或 OIDC、防火墙白名单、关闭未使用的端口。

常见坑 FAQ

坑 现象 处理
内核里 import 不到刚装的包 ModuleNotFoundError 装包装进了别的环境；单元格里用 %pip install pkg（装进当前内核环境）而非 !pip install
改了本地 .py 模块不生效 还是旧行为 Python 会缓存已导入模块；用 %autoreload 2 或重启内核
token 链接打不开 浏览器拒绝/404 确认终端里完整复制含 token= 的 URL；远程服务器先配端口转发
输出过大浏览器卡死 打印了万行 DataFrame 用 df.head()；在配置里限制 iopub_data_rate_limit
.ipynb diff 没法看 JSON 输出噪音淹没代码改动 提交前清空输出，或引入 nbstripout / jupytext 配对 .py 文本格式
多内核选错环境 结果与预期依赖版本不符 单元格首行 %pip list 或 import sys; sys.executable 确认当前内核环境

最佳实践清单

  1. 每个项目一个内核：ipykernel install --user --name=<项目>，环境隔离、切换清晰。
  2. 探索归探索、交付归脚本：Notebook 里跑通后把可复用逻辑沉淀到 .py 模块，Notebook 只做编排与展示。
  3. 提交前 Restart & Run All：确认从头到尾顺序执行能复现，避免「隐藏状态依赖」。
  4. 大输出不进 Git：清空输出提交，或用 nbstripout 自动剥离。
  5. 远程访问首选 SSH 转发，公网暴露必须 HTTPS + 强认证。
  6. 耗时单元格留 %time：性能敏感代码随时可回归对比。
