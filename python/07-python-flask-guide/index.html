第七章：Flask 入门：轻量级 Python Web 框架

概念基础

Flask 是 Python 轻量级 Web 框架（微框架）：

  1. 微内核：核心只提供路由与 WSGI 请求处理（底层为 Werkzeug），ORM、表单、认证等能力皆以扩展按需拼装，项目再大也不被框架绑架。
  2. 视图函数极简：一个函数 + @app.route 装饰器即一个接口；视图返回 dict 会被自动序列化为 JSON，非常适合 API 开发。
  3. 模块化组织：用 Blueprint（蓝图） 把路由按业务拆分（如 /api/v1），Jinja2 模板负责 HTML 渲染，大型项目也能保持结构清晰。
  4. 与 uv 无缝协作：延续前几章的项目化工作流——uv add flask 安装、uv run flask --app app run --debug 启动开发服务器，本地与 CI 环境一致。

视图执行期间可直接导入使用的四个代理对象：

对象 作用
request 当前请求（args 查询串、form 表单、get_json() JSON 体）
g 单次请求内的全局暂存（如当前登录用户）
session 基于签名 Cookie 的会话
current_app 当前应用实例（取配置用 current_app.config）

它们由 Flask 的上下文机制按请求隔离，不要在请求外（如模块顶层、后台线程）直接使用。

十、常见坑 FAQ 与最佳实践

坑 现象 处理
开发服务器上生产 并发一高就挂、安全警告 换 Gunicorn/Waitress；--debug 仅限本机
请求外操作 request / db RuntimeError: Working outside of request context 把逻辑移进视图；测试里用 app.test_request_context()
循环导入 蓝图与 app 互相 import 用应用工厂 create_app() + 延迟 register_blueprint
JSON 中文乱码 返回被转义成 \uXXXX app.json.ensure_ascii = False（Flask 3.x）
密钥硬编码 SECRET_KEY = "123" 入库 读环境变量；.env 加 .gitignore

最佳实践：应用工厂模式组织代码、蓝图按域拆分、数据库迁移用 Flask-Migrate、配置走环境变量、生产必上 WSGI 服务器 + 反向代理。

十一、命令速查

场景 命令

同步环境 uv sync
开发运行 uv run flask --app app run --debug
指定端口 同上，加 --port 8000

蓝图、Jinja 模板、SQLAlchemy、生产部署（Gunicorn 等）见 Flask 文档。

本章小结

要点 结论
框架定位 微框架：核心只管路由与 WSGI（Werkzeug），其余靠扩展按需拼装
最小应用 @app.route 装饰器声明路由；视图返回 dict 自动转 JSON
项目化集成 uv init + uv add flask + uv run flask --app app run --debug 一条龙
开发调试 --debug 开启调试器与自动重载，仅限开发环境
蓝图拆分 Blueprint + url_prefix 按业务域组织路由，应用工厂消除循环导入
请求上下文 request / g / session / current_app 按请求隔离，请求外禁用
数据层 Flask-SQLAlchemy 集成 ORM，生产迁移用 Flask-Migrate
生产部署 Gunicorn / Waitress 替代开发服务器；Docker 镜像 uv sync --frozen --no-dev；密钥走环境变量
进阶方向 Blueprint 拆分路由、Jinja 模板、SQLAlchemy、Gunicorn 生产部署
