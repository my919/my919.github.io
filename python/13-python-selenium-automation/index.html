第十一章：网页自动化：Python + Selenium 入门与实战

概念基础

Selenium 是浏览器自动化的事实标准，让 Python 代码替你「亲手」操作浏览器：

  1. 驱动真实浏览器：用代码控制 Chrome / Edge / Firefox 完成打开网页、点击、填表、读取数据等人类操作，所见即所得。
  2. 工作原理：脚本遵循 W3C WebDriver 协议，经驱动程序把指令翻译给浏览器——因为跑的是真浏览器，JS 动态渲染后的页面内容也能拿到，这是它与普通 HTTP 爬虫库的本质区别。
  3. 免管驱动：Selenium 4.6+ 内置 Selenium Manager，自动匹配本机浏览器与驱动版本，不再手动下载 chromedriver。
  4. 两大典型场景：端到端（E2E）测试——模拟用户行为验证系统能否走通；数据采集——处理需要登录、翻页、JS 渲染的页面。
  5. 稳定性心法：页面加载是异步的，固定 sleep 不可靠；显式等待 + 稳定定位器才是自动化脚本不脆弱的关键。

等待与元素定位（避免「找不到元素」）

页面加载有异步请求时，固定 sleep 不稳，建议：

  1. 显式等待：WebDriverWait + expected_conditions，在超时时间内轮询条件。
  2. 定位方式：优先 id / data-testid / 稳定 name；少用绝对 XPath。
  3. 点击被挡：先滚动到视区 element.location_once_scrolled_into_view，或等待浮层消失。

常用显式等待条件速查

条件 用途
presence_of_element_located 元素出现在 DOM（不要求可见）
visibility_of_element_located 元素可见（渲染完成）
element_to_be_clickable 可点击（按钮、链接首选）
url_contains / title_is 等待跳转完成
invisibility_of_element_located 等待 loading 浮层消失

配合隐式等待兜底（driver.implicitly_wait(5)）可以共存：隐式等待管「找元素」的默认轮询，显式等待管「特定条件」。但不要只靠隐式等待处理复杂交互。

与 Playwright 对比选型

维度 Selenium 4.x Playwright
协议 W3C WebDriver 标准 私有 CDP 协议（自带自动等待）
浏览器支持 Chrome/Firefox/Safari/Edge 全系 Chromium/Firefox/WebKit（无 Safari 正式版差异）
自动等待 需手写显式等待 内置自动等待，脚本更短
生态年龄 2004 年至今，资料最多 2020 年起，增长快
多语言 Java/Python/C#/JS/Ruby Python/JS/Java/.NET
Grid 分布式 成熟 需配合第三方

选型建议：存量 Selenium 资产继续用，新起纯 E2E 项目可评估 Playwright；需要 Safari 真机或对接老 Grid 仍选 Selenium。

常见坑 FAQ

坑 现象 处理
NoSuchElementException 元素还没渲染出来 显式等待 visibility_of_element_located，别写死 sleep
ElementClickInterceptedException 点击被弹窗/浮层挡住 等浮层 invisibility_of_element_located，或 ActionChains 滚动到元素再点
StaleElementReferenceException 页面刷新后旧元素引用失效 不要缓存 element 跨页面使用；每次操作前重新定位
无头模式布局不同 有头能过、无头找不到元素 显式设 --window-size=1280,900；必要时无头截图对拍
iframe 里元素找不到 定位器没错但报 no such element 先 driver.switch_to.frame(...)，出来用 switch_to.default_content()
CI 上随机失败（flaky） 本地全绿、CI 偶红 失败时自动截图+保存 page_source；加长显式等待超时；用 -x --lf 复跑定位
下载文件不知道存哪 默认进系统下载目录 options.add_experimental_option("prefs", {"download.default_directory": ...}) 固定目录

最佳实践清单

  1. 显式等待为默认，sleep 只在调试时临时用。
  2. 定位器优先级：id > data-testid > 稳定 name/class > CSS > XPath；推动前端给关键元素加 data-testid。
  3. PO 模式管理页面结构，用例只描述业务行为。
  4. 每个用例独立：自备数据、结束时清理（driver.quit() 用 fixture 保证）。
  5. CI 无头 + 失败截图：--headless=new + 失败自动保存 screenshot/page_source。
  6. 版本对齐：Selenium 4.6+ 靠 Selenium Manager，但仍要跟进浏览器大版本升级节奏。

与 pytest 搭配（可选）

  1. 安装：pip install pytest。
  2. 测试文件命名 test_*.py，用 assert 断言页面结果。
  3. 每个用例结束务必 driver.quit()，或用 pytest fixture 统一创建与销毁浏览器，避免僵尸进程。
