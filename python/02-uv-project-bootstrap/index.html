第二章：UV 从 0 到 1 创建项目：初始化、依赖与运行

概念基础

项目化开发指以 pyproject.toml 为中心管理 Python 项目的完整工作流，uv 让它变得极简：

  1. 单一事实来源：项目元数据、依赖声明、Python 版本约束统一写在 pyproject.toml，告别手工维护 requirements.txt。
  2. 锁文件保证可复现：uv.lock 精确锁定每个依赖版本，团队成员与 CI 用 uv sync 一条命令即可得到完全一致的环境。
  3. 0 到 1 主线流程：初始化（uv init）→ 固定解释器（uv python pin）→ 建环境（uv venv）→ 加依赖（uv add）→ 同步（uv sync）→ 运行（uv run），每步一个命令，无需额外记忆。
  4. 国内网络加速：在 pyproject.toml 配置 [[tool.uv.index]] 镜像源，拉包不再超时，官方源可作备用索引。

十、常见报错处理 FAQ

报错 / 现象 原因 处理
No solution found when resolving dependencies 两个依赖的版本约束无交集 读报错中的冲突链，放宽 pyproject.toml 里过紧的约束后 uv lock
error: No Python interpreters found 系统无可用解释器 uv python install 3.14 让 uv 自己管理
.python-version 与 requires-python 冲突 pin 的版本不满足项目约束 同时修改两处，或 uv python pin --no-project（慎用）
uv sync --frozen 在 CI 失败 有人改了 toml 没更新锁 本地 uv lock 后把 uv.lock 一并提交
拉包超时 / 连接重置 默认走官方 PyPI 配置 二、§4 的国内镜像，或临时 -i 指定
.venv 里 Python 版本不对 换过 pin 但旧环境残留 删 .venv 后 uv venv && uv sync

十一、最佳实践清单

  1. 每个项目都 uv python pin，.python-version 提交仓库，团队/CI 版本一致。
  2. uv.lock 必须入库；CI 用 uv sync --frozen 守住一致性。
  3. 依赖变更只用 uv add / uv remove，不手改 toml 后忘记 uv lock。
  4. 工具类依赖（pytest、ruff）进 --dev 组，生产镜像 --no-dev。
  5. 国内环境把镜像写进 [[tool.uv.index]]，不依赖每个人的环境变量。
  6. 日常执行统一 uv run，避免「忘了激活 venv」类问题。

本章小结

要点 结论
项目初始化 uv init 生成 pyproject.toml 骨架，--name 可指定包名
固定解释器 uv python pin 写入 .python-version，团队与 CI 使用同一版本
依赖管理 uv add 声明依赖并更新 uv.lock；uv sync 按锁文件还原环境
镜像加速 [[tool.uv.index]] 配置国内源（清华/阿里云/腾讯云/华为云），官方源作备用
运行入口 uv run python main.py 免激活执行；[project.scripts] 可注册控制台命令
依赖分组 --dev 进开发组、optional-dependencies 做可选依赖，生产 --no-dev
CI 集成 setup-uv + uv sync --frozen --dev，锁文件不一致即失败
排错套路 解析冲突看约束交集、解释器缺失用 uv python install、换 pin 先删旧 .venv
