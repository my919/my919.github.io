问题背景：电商 App 用 Flutter 落地商品列表：首版把几百个卡片一次塞进 ListView(children: [...])，滚动掉帧明显；触底加载无防重导致数据重复；支付必须走原生 SDK（Flutter 侧无能力）。

踩坑点：

  • 普通 ListView(children:) 会一次性 build 全部子项——长列表必须 ListView.builder + itemCount。
  • loadMore 无防重：触底哨兵一帧内触发多次，同一页请求多遍、数据重复，必须 loading 门闩。
  • MethodChannel 回调在 Android 主线程执行，UI 更新需要切回 Flutter 侧处理；channel 名两端拼错只会得到 MissingPluginException。
  • iOS 刘海屏内容被状态栏遮挡：列表外层包 SafeArea，别手写顶部偏移。

7. 常见误用与陷阱

坑 现象/后果 解法
Flutter 普通 ListView 塞全量 children 长列表掉帧、内存飙高 ListView.builder 惰性构建 + const 卡片
setState 滥用 整页重建、越写越难维护 状态下沉到局部 Widget；全局用 Riverpod 精准刷新
该加 const 不加 Widget 每帧不必要的重建 能 const 则 const（Widget 构造、列表项）
MethodChannel 线程/命名不一致 MissingPluginException 或崩溃 channel 名两端常量统一；原生在主线程回传
RN 继续依赖旧架构 Bridge 瓶颈、新库不兼容 升级 New Arch（Fabric + JSI + TurboModules）
忽略安全区/刘海 内容被状态栏/小白条遮挡 SafeArea + MediaQuery.padding
图片无缓存 反复下载、流量浪费、闪烁 CachedNetworkImage + 占位图 + 内存/磁盘缓存
