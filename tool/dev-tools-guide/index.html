1. 概念说明

开发工具链是把”编辑 → 搜索 → 调试 → 构建 → 部署 → 排查”各环节的高效工具串联起来的工作流。目标：减少上下文切换、少点鼠标、命令直达。

核心思路：GUI 适合”看得见”的操作（数据库浏览、接口调试），CLI 适合”可脚本化”的操作（搜索、批量、管道）。两者结合最高效。

10. 工具选型原则

原则 说明
少而精 每类只留 1-2 个主力工具
可脚本化优先 重复操作必须能写成命令/脚本
数据本地可控 敏感数据尽量本地工具（Bruno 而非云 Postman）
定期升级 跟随 LTS/主流版本，避免老工具安全风险

11. 典型案例：新人入职环境一键搭建脚本

问题背景：团队每来一名新人，配本地环境平均耗时 1-2 天：装 JDK/Node/工具链、配 Git、装编辑器插件，各人环境还不一致，联调时”我这边好好的”频发。

方案：沉淀一份 dev-setup.sh，配合 mise 固定运行时版本、VS Code 统一推荐插件，入职当天 30 分钟出可用环境。

配套把 .mise.toml、.vscode/extensions.json、settings.json 提交进仓库，环境随代码走。

关键实践：脚本幂等（重复执行不报错）；版本管理工具统一用 mise；IDE 配置进版本库。

踩坑点：macOS 与 Linux 包管理器命令不同导致脚本中断——用 brew install x || apt install x 兜底；mise activate 只对当前 shell 生效，忘记写进 rc 文件会”下次打开终端就没 node 了”。

12. 常见误用与陷阱

坑 现象/后果 解法
工具装一堆从不复盘 菜单臃肿，真正高频的还是那几个 每季度盘点，卸载 30 天未用的工具
敏感请求丢云端 Postman token/生产数据外泄 换 Bruno/curl，集合进 Git 私库
无版本管理的”一次配好” 同事环境互不相同，问题难复现 mise/asdf 锁版本，配置随仓库走
盲目追新工具全量替换 迁移成本高过收益，团队一半人在用旧的 新工具先个人试用 2 周再推团队
依赖 GUI 做重复操作 批量任务手点几十次且不可复现 可脚本化的操作一律 CLI 化
容器当虚拟机使 镜像里堆 ssh/vim/systemd，越滚越大 容器单进程，排查用 k9s/docker exec
忽略工具更新 老版本插件带已知漏洞 定期升级，关注 LTS 版本
