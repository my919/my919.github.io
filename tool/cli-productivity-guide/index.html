8. 效率原则与习惯

原则 说明
别名常驻 高频命令设别名
历史利用 Ctrl+R 搜历史（配 fzf 更强）
管道思维 输出→过滤→处理→呈现
一行完成 能管道就别多行中间文件
脚本沉淀 重复 3 次的命令写成脚本
环境一致 项目用 mise 固定版本

9. 典型案例：从零搭建一套日志分析工具链

问题背景：某后端小组每天人工翻日志排查线上错误，平均每次 30 分钟起，且多人重复劳动。

方案：用 rg + jq + awk + fzf 组合，把”日志定位 → 错误统计 → 下钻报告”沉淀为脚本。

关键实践：脚本放 ~/.local/bin 并加入 PATH；重复 3 次的管道立即沉淀为脚本；set -e 出错即停。

踩坑点：日志被轮转切割时 rg 漏读新文件——改用 journalctl 或对目录通配 rg ERROR logs/*.log；grep -oP 依赖 GNU grep，macOS 需 brew install grep 或改用 rg -o。

10. 常见误用与陷阱

坑 现象/后果 解法
用 grep 递归搜大仓库 全量扫描 node_modules/日志，等几十秒 改用 rg（默认遵循 .gitignore）
kill -9 先上 进程来不及落盘/释放锁，数据损坏 先 kill（TERM）等几秒，无效再 -9
管道中间文件满天飞 tmp 文件堆积、脚本不可读 尽量一条管道；确需中间文件用 mktemp
别名写进临时会话 换个终端就失效 持久化到 ~/.bashrc / ~/.zshrc
盲信历史命令直接回车 Ctrl+R 翻到 rm -rf 误执行 回车前看一眼完整命令；高危命令加确认
sed -i 无备份原地改 配置改坏无法回滚 先 cp file file.bak 或 sed -i.bak
PATH 里放当前目录 . 被恶意同名可执行文件劫持 绝不把 . 放入 PATH，用 ./xxx 显式执行
