16. 常见误用与陷阱

坑 现象 解法
环境变量缺 VITE_ 前缀 import.meta.env.API_BASE 为 undefined Vite 只暴露 VITE_ 开头的变量；改名 VITE_API_BASE，或 define 注入；前端别放敏感密钥（会打包进产物）
Pinia 在 setup 外调用报错 axios 拦截器 / 路由守卫里 useUserStore() 报 getActivePinia called without installing 须先 app.use(pinia)；在模块顶层调 useUserStore() 会在 import 时执行（pinia 未装），改为在函数内部调用
解构 store / reactive 丢响应式 const { token } = store 后 token 不再响应式更新 用 storeToRefs(store)（store）或 toRefs(state)（reactive）解构；方法可直接解构
v-for 用 index 作 :key 列表增删项时输入框/状态错位 :key 用数据唯一 id（item.id）；index 作 key 在排序/增删时会导致 DOM 复用错乱
Vite proxy 生产不生效 部署后接口跨域 CORS 报错 server.proxy 仅 dev 生效；生产用 Nginx 反向代理 /api → 后端，或后端开 CORS
Naive UI useMessage 返回 undefined 调 message.success() 报 Cannot read of undefined useMessage 必须在 <n-message-provider> 后代组件中调用；App.vue 顶层包一层 provider，或用 window.$message 全局挂载
ref 在模板 vs 脚本 模板里 count 自动解包，脚本里写成 count.value 模板自动 unwrap；JS/TS 里必须 count.value；reactive 对象的 ref 属性在模板/解构时才自动解包
