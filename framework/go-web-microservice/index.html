15. 常见误用与陷阱

坑 现象 解法
GORM 软删除 + uniqueIndex 冲突 删除某用户后用相同 email 新建报 Duplicate entry gorm.Model 的 deleted_at 使记录仍存在；唯一索引改为 (email, deleted_at) 联合，或 gorm:"uniqueIndex:idx_email,where:deleted_at IS NULL"
gin.Context 在 goroutine 里用 请求结束后偶发 panic / 读到脏数据 c 非线程安全；跨 goroutine 必须 cCopy := c.Copy() 传副本，原 c 仅在请求生命周期内可用
生产用 AutoMigrate schema 漂移、删列删索引不生效、并发启动冲突 AutoMigrate 只增不删；生产用 golang-migrate 或 Atlas 管理迁移，AutoMigrate 仅限开发
Viper 配置不识别环境变量覆盖 设了 APP_PORT 但 Unmarshal 仍是 yaml 值 需 viper.AutomaticEnv() + viper.SetEnvKeyReplacer(strings.NewReplacer(".","_"))，且 key 与 SetDefault 对齐才生效
*gorm.DB 连接池未限制 高并发下 DB 连接数飙升、被拒连 sqlDB, _ := db.DB(); sqlDB.SetMaxOpenConns(50); SetMaxIdleConns(10)，默认 0=无上限
goctl 重新生成覆盖手改代码 改了 handler 又跑 goctl，业务逻辑被覆盖 go-zero 业务写 logic/ 层（不被覆盖），handler 只做参数转换；用 //goctl:ref 标记保护自定义段
