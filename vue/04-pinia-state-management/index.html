发表于 2026-09-02 更新于 2026-10-25 分类于 Vue 本文字数： 11k 阅读时长 ≈ 10 分钟

第四章：Pinia 状态管理实战

概念基础

  1. 为什么需要状态管理：组件树越深，props 逐层透传越难维护；跨兄弟/跨路由共享的数据（登录态、购物车、主题）抽到全局 Store，单向数据流让变更可追踪。第一章：Vue 3 核心概念与组件开发 的组合式 API 正好与 Store 天然契合。
  2. Pinia vs Vuex：Pinia 是 Vue 官方推荐的新一代方案，移除 mutations、天然 TypeScript、模块扁平（每个 store 独立注册，无需 modules 嵌套）；Vuex 4 仍兼容旧项目，新项目首选 Pinia。
  3. Store 三种类型：基于 defineStore 的 Option Store（state/getters/actions 三段式）、Setup Store（返回 ref/computed/function）、组合式 Store（跨 store 组合复用），写法按团队习惯选择。
  4. 响应式设计：Pinia 状态本质是 reactive / ref，在 <script setup> 里直接解构会丢响应式，需用 storeToRefs 转换；getter 即 computed，自带缓存。
  5. 持久化：默认状态存内存，刷新即丢；用 pinia-plugin-persistedstate 把关键 store 同步到 localStorage / sessionStorage / cookie，SSR 场景需注意 hydration 一致性。

本章承接 第一章：Vue 3 核心概念与组件开发 的组件与组合式 API，并依赖 第三章：前端工程化实战 的工程化基座；状态管理的下一步是样式与性能，见 第五章：CSS 现代方案与 Tailwind CSS。

七、Store 设计规范

粒度划分 —— 按「业务域」而非「页面」拆 store：

做法 评价
一个巨型 appStore 装所有状态 ❌ 改一处全量订阅者重渲染，测试困难
每页一个 store ❌ 跨页共享状态被复制多份
按业务域拆（user / cart / order） ✅ 边界清晰，可独立测试与持久化

命名约定：文件名与 store id 一致（stores/order.ts → defineStore('order', ...)），导出函数统一 useXxxStore。

单一职责检查清单：

  1. state 只存原始数据，推导值一律放 getter（即 computed）。
  2. action 只编排本 store 的状态变更；跨域流程（如下单后清购物车）放 composable。
  3. 接口请求封装在 api/ 层，store 不直接写 fetch——换 HTTP 库时不动 store。
  4. 组件私有状态（弹窗开关、表单草稿）留在组件，不进 store。

常见避坑

坑 现象 正确做法
直接解构 store 模板里数据不更新 用 storeToRefs(store) 包裹再解构
Setup store 调 $reset 报错 not available Setup 写法无 $reset，手动实现或用 Option 写法
循环依赖 两个 store 顶层互相 import 报错 在 action 内部调用对方 store，顶层不互相 import
action 里 this 丢失 解构后调用报 undefined 调用时用 store.login() 而非解构出的裸函数
持久化存敏感 token localStorage 被脚本窃取 敏感字段不放白名单，或改用 httpOnly cookie
SSR hydration 不一致 服务端/客户端首屏渲染报错 持久化用 cookie 两端统一；避免组件挂载前读 localStorage
$patch 函数式改数组 推送后视图不更新 $patch(state => state.list.push(x)) 而非外部 push 后整体赋值
订阅未解绑 组件卸载后仍触发回调 onUnmounted(unsubscribe) 或 detached:false
store 命名重复 DevTools 状态混乱、互相覆盖 defineStore 的 id 全局唯一，按业务域命名
滥用全局 store 小状态也塞进 store、组件难复用 组件内 ref 足够时别上 store，props/emit 优先

本章小结

要点 结论
选型 Pinia 是 Vue 3 官方推荐，移除 mutations、TS 友好；Vuex 仅旧项目维护
写法 Option 三段式直观，Setup 与组合式 API 一致、更易复用，新项目首选
响应式 解构 state/getter 必经 storeToRefs；action 方法可直接解构
异步 action 直接 async/await；跨 store 在 action 内部引用避免循环依赖
持久化 pinia-plugin-persistedstate 按 pick 白名单；SSR 用 cookie 统一两端
调试 Vue DevTools 状态树 + 时间旅行；开发态可挂 window 便于排查
设计 按业务域拆 store；推导值放 getter；接口层与 store 分层
测试 createPinia 隔离测逻辑；@pinia/testing 打桩测组件
