1. 概念说明

入门篇掌握了 <script setup> 基础。进阶核心：

  • 组合式函数（Composable）：把可复用逻辑抽成函数（替代 mixin 的缺陷）。
  • 响应式原理：ref/reactive 基于 Proxy；理解 computed 缓存与 watch 时机。
  • 状态管理：跨组件共享状态用 Pinia（store），而非 props/emit 层层传。
  • 性能：虚拟列表、懒加载、缓存、减少响应式开销。

何时需要 Pinia：多个页面/组件共享同一状态（用户信息、购物车、主题）→ 用 store；只在父子组件 → props/emit。

2. 组合式函数（核心技能）

组合式函数规范：useXxx 命名；返回响应式对象；可接受参数配置；内部状态不泄漏。

3. 响应式深入

性能注意：大数组/深层对象避免深度响应式（用 shallowRef）；循环里避免创建计算属性。

4. Pinia 状态管理

Pinia 要点：store 是单例；解构用 storeToRefs 保响应式；异步逻辑放 action。

11. 常见误用与陷阱

坑 现象/后果 解法
解构 reactive 对象 const { name } = reactive(obj) 后改 obj.name 视图不更新，响应式断开 用 toRefs(obj) 再解构，或整体使用不解构
ref 忘写 .value JS 里改了值视图不动，或赋值覆盖了整个响应式对象 ref 在 JS 中必须 .value；模板里才自动解包
watch 监听 reactive 对象整体 对象内部属性变化不触发回调（默认浅层） 监听 getter：watch(() => obj.x, cb)，或加 { deep: true }
props 解构后失响应式 父组件更新数据，子组件界面无感 3.5+ 支持响应式解构；旧版本用 props.title 或 toRef(props, 'title')
v-for 用 index 当 key 删除/排序后 DOM 状态错乱、输入框内容串行 用数据里稳定唯一的业务 id 作 key
卸载时不清理定时器/监听 组件销毁后回调仍执行，内存泄漏 onBeforeUnmount 里 clearInterval、removeEventListener
computed 里写副作用 在 computed 中发请求/改状态，重渲染时重复执行且难追踪 computed 只做纯计算；副作用放 watch / watchEffect
