1. 概念说明

入门篇掌握了 <script setup> 基础。进阶核心：

  • 组合式函数（Composable）：把可复用逻辑抽成函数（替代 mixin 的缺陷）。
  • 响应式原理：ref/reactive 基于 Proxy；理解 computed 缓存与 watch 时机。
  • 状态管理：跨组件共享状态用 Pinia（store），而非 props/emit 层层传。
  • 性能：虚拟列表、懒加载、缓存、减少响应式开销。

何时需要 Pinia：多个页面/组件共享同一状态（用户信息、购物车、主题）→ 用 store；只在父子组件 → props/emit。

Pinia vs Vuex：Pinia 是 Vue 官方推荐的新一代方案，移除 mutations、天然 TypeScript、模块扁平（每个 store 独立注册，无需 modules 嵌套）；Vuex 4 仍兼容旧项目，新项目首选 Pinia。

2. 组合式函数（核心技能）

组合式函数规范：useXxx 命名；返回响应式对象；可接受参数配置；内部状态不泄漏。

3. 响应式深入

性能注意：大数组/深层对象避免深度响应式（用 shallowRef）；循环里避免创建计算属性。

4.6 DevTools 与调试

Pinia 与 Vue DevTools 深度集成，安装浏览器插件后可在 Pinia 面板：

  • 状态树检查：实时查看每个 store 的 state / getters 当前值。
  • 时间旅行：每次变更生成快照，可回放历史状态定位 bug。
  • action 追踪：action 调用栈可追溯；生产环境可关掉省开销。

4.7 Store 设计规范

粒度划分 —— 按「业务域」而非「页面」拆 store：

做法 评价
一个巨型 appStore 装所有状态 ❌ 改一处全量订阅者重渲染，测试困难
每页一个 store ❌ 跨页共享状态被复制多份
按业务域拆（user / cart / order） ✅ 边界清晰，可独立测试与持久化

命名约定：文件名与 store id 一致（stores/order.ts → defineStore('order', ...)），导出函数统一 useXxxStore。

单一职责检查清单：

  1. state 只存原始数据，推导值一律放 getter（即 computed）。
  2. action 只编排本 store 的状态变更；跨域流程（如下单后清购物车）放 composable。
  3. 接口请求封装在 api/ 层，store 不直接写 fetch——换 HTTP 库时不动 store。
  4. 组件私有状态（弹窗开关、表单草稿）留在组件，不进 store。

12. 常见误用与陷阱

坑 现象/后果 解法
解构 reactive 对象 const { name } = reactive(obj) 后改 obj.name 视图不更新，响应式断开 用 toRefs(obj) 再解构，或整体使用不解构
直接解构 store 模板里数据不更新 用 storeToRefs(store) 包裹再解构；方法可直接解构
ref 忘写 .value JS 里改了值视图不动，或赋值覆盖了整个响应式对象 ref 在 JS 中必须 .value；模板里才自动解包
watch 监听 reactive 对象整体 对象内部属性变化不触发回调（默认浅层） 监听 getter：watch(() => obj.x, cb)，或加 { deep: true }
props 解构后失响应式 父组件更新数据，子组件界面无感 3.5+ 支持响应式解构；旧版本用 props.title 或 toRef(props, 'title')
v-for 用 index 当 key 删除/排序后 DOM 状态错乱、输入框内容串行 用数据里稳定唯一的业务 id 作 key
卸载时不清理定时器/监听 组件销毁后回调仍执行，内存泄漏 onBeforeUnmount 里 clearInterval、removeEventListener
computed 里写副作用 在 computed 中发请求/改状态，重渲染时重复执行且难追踪 computed 只做纯计算；副作用放 watch / watchEffect
Setup store 调 $reset 报错 not available Setup 写法无 $reset，手动实现或用 Option 写法（见 4.8 插件）
两个 store 循环依赖 顶层互相 import 报错 在 action 内部调用对方 store，顶层不互相 import
action 里 this 丢失 解构后调用报 undefined 调用时用 store.login() 而非解构出的裸函数
持久化存敏感 token localStorage 被脚本窃取 敏感字段不放 pick 白名单，或改用 httpOnly cookie
SSR hydration 不一致 服务端/客户端首屏渲染报错 持久化用 cookie 两端统一；避免组件挂载前读 localStorage
订阅未解绑 组件卸载后仍触发回调 onUnmounted(unsubscribe) 或 detached: false
滥用全局 store 小状态也塞进 store、组件难复用 组件内 ref 足够时别上 store，props/emit 优先
环境变量缺 VITE_ 前缀 import.meta.env.API_BASE 为 undefined Vite 只暴露 VITE_ 开头的变量；前端别放敏感密钥（会打包进产物）
Pinia 在 setup 外调用报错 axios 拦截器/路由守卫里 useUserStore() 报 getActivePinia called without installing 须先 app.use(pinia)；模块顶层调用会在 import 时执行（pinia 未装），改为函数内部调用
Vite proxy 生产不生效 部署后接口跨域 CORS 报错 server.proxy 仅 dev 生效；生产用 Nginx 反向代理 /api → 后端，或后端开 CORS
Naive UI useMessage 返回 undefined 调 message.success() 报 Cannot read of undefined 必须在 <n-message-provider> 后代组件中调用；App.vue 顶层包一层 provider
