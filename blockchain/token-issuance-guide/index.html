发币从 0 到 1 实战指南：ERC-20 · 部署 · 流动性 · 合规

发表于 2026-10-11 更新于 2026-10-25 分类于 区块链 本文字数： 16k 阅读时长 ≈ 15 分钟

区块链 · 发币实战

从一个空目录到一个有流动性的代币：合规红线 · 选链决策 · ERC-20 合约（OZ v5）· 测试 · 测试网/主网部署 · Etherscan 验证 · Slither 安全自查 · Uniswap 建池 · 权限收敛。全程代码可运行、注释中文。本文仅作技术学习用途。

技术栈速查

类别 选型 用途
合约语言 Solidity 0.8.24 EVM 智能合约
合约库 OpenZeppelin v5 经过审计的标准实现
开发框架 Hardhat + ethers v6 编译、测试、部署、验证
测试网络 Sepolia / Base Sepolia 免费演练全流程
静态分析 Slither 自动漏洞扫描
交易场所 Uniswap V2（教学版） 创建初始流动性
多签 Safe 收敛管理权限

1. 合规红线：写第一行代码之前

「发币」在技术上是一个下午的事，在法律上是一条高压线。先看这段再动手：

中国大陆：

  • 2017 年「九四公告」与 2021 年《关于进一步防范和处置虚拟货币交易炒作风险的通知》明确：代币发行融资（ICO）属非法金融活动，向公众售卖、变相募资、撮合交易均被禁止。
  • 个人在测试网上学习代币技术完全没问题；但任何「卖币收钱」「承诺收益」的行为在中国大陆都不合法。

海外项目：

  • 多数司法辖区用 Howey Test 判定代币是否构成证券（是否投入资金、投向共同事业、期待收益、收益来自他人努力）。四条命中越多，越可能被按证券监管。
  • 正规流程：先拿目标辖区的法律意见书，再做公开销售；社区积分/治理凭证与「预期回报的销售」在法律上完全不同。

预期管理：你发行的是链上记账的代币（token），不是主权法币。它的价值不来自「发了币」，而来自三件事——流动性（买得到也卖得掉）、用途（治理/支付/权益）、共识（有人愿意持有）。后面所有工程步骤，本质上都是在为这三件事打地基。

2. 三个关键决策：目的 · 形态 · 链

2.1 目的决定形态

目的 形态 标准 说明
学习/实验 可增发的基础代币 ERC-20 本文主线，半天走通
社区积分/会员 固定总量代币 ERC-20 + Cap 禁止超发
游戏道具/收藏品 非同质化 ERC-721 每枚不同
批量道具/票券 半同质化 ERC-1155 一合约多资产
需要合规转移限制 证券型代币 ERC-3643/1400 白名单 + 合规层

2.2 链的选择

链 部署成本 安全性 适合
以太坊 L1 高（数百美元级） 最强 大额结算、最终锚点
Base / Arbitrum 等 L2 低（几美元到几十美元） 继承以太坊 起步首选
BSC 极低 一般 已有社区存量
Solana 极低 独立体系 高频交易场景（用 SPL，非 EVM）
自建链（Cosmos/Substrate） 高（需自己养验证人） 自己负责 专用场景，不建议起步

为什么起步选 L2：安全继承以太坊（结算与 DA 在 L1），Gas 是 L1 的百分之一量级，且工具链与 L1 完全一致——同一份合约、同一套脚本，改个网络参数就能部署。

2.3 代币经济：上链之前在纸上完成

合约写错可以重新部署，但经济模型混乱无法补救。至少回答清楚：

  • 总量：固定总量还是带上限增发？上限写进合约（ERC20Capped），不要靠承诺。
  • 分配：团队/社区/金库/流动性各占多少？团队份额是否有锁仓与线性释放（vesting）？
  • 增发权：谁有权铸新币？铸币权是否最终要放弃或交给治理？（见 §11）
  • 估值叙事：这个币凭什么被持有？给不出答案就停在这里。

4.1 最小可用版（10 行，学习用）

ERC20 基类已经实现转账、余额、授权（approve/allowance）、事件等全套标准接口——永远不要手写这些，2016-2018 年无数手写 ERC-20 的项目栽在整数溢出与授权竞态上（_update 钩子 + SafeERC20 已在 OZ 内解决）。

设计要点：

  • ERC20Capped 把「总量不超过 X」变成代码保证而非承诺，Slither 也能据此检查。
  • pause 是双刃剑：它是事故止损工具，但也意味着「中心化开关」。上线稳定后应考虑移除（发新版合约）或把权限交给多签/Timelock——社区会用区块浏览器检查这一点，留着不说明会直接影响信任。
  • 构造参数里直接传入 initialOwner（OZ v5 要求），建议首次部署就填 Safe 多签地址，而不是个人钱包。

6.3 部署脚本

7. 源码验证：让所有人能读到你的代码

未验证的合约在浏览器里只有字节码——等于主动声明「我不想被审计」，DEX 与社区工具都会将其标记为高风险。

验证通过后，区块浏览器上会出现 Read/Write Contract 标签页，任何人都能核对：总量、上限、mint 权限归谁、pause 状态。这一步是「透明度」的起点。

8. 安全自查：Slither 与人工清单

Slither 对纯 OZ 标准库组合通常只报低危提示（外部调用、时间依赖类误报），重点看它有没有报 High。人工清单逐条过：

貔貅自检尤其重要：测试网建池后，用一个非 Owner 钱包完整模拟「买入 → 卖出」，确认没有隐藏税、黑名单、禁止卖出逻辑。社区工具检测的就是这些行为，提前自查等于提前排除信任危机。

9. 部署到主网

前置确认：§8 清单全过、合约在测试网稳定运行、initialOwner 已改为多签地址、部署钱包里的 Gas 预算充足。

成本量级（24h 内可能波动）：Base 上部署 + 验证通常在个位数到几十美元；以太坊 L1 视 Gas 价格数百美元级。部署交易确认后，合约代码永久不可改——有 bug 只能发新合约并迁移（重新部署 → 引导持有人换仓），所以宁可多测一轮。

10. 创建流动性：让币可以被交易

没有流动性的代币 = 有余额但卖不掉的数字。以教学友好的 Uniswap V2（addLiquidityETH）为例，在测试网演练。

建池后立刻做三件事：

  1. 用非 Owner 钱包试买卖（§8 貔貅自检）——买一点、卖掉、看成交价与是否有税。
  2. 锁 LP：把拿到的 LP Token 存入锁仓服务（Team Finance / UNCX 等）或转入 Timelock 合约，锁定期与解锁条件提前公告。LP 不锁 = 任何人都默认你会抽池（rug pull），这是社区的第一条筛查项。
  3. 公开初始价格锚定逻辑：V2 池定价 = ETH 储备 / 代币储备，你投入的比例就是初始市值，写清楚它，避免「为什么第一天就跌 90%」的误解。

11. 权限收敛：从「我能铸币」到「没人能偷偷铸币」

上线后的信任进阶路径（每一级都比上一级可信）：

阶段 Owner 是谁 社区观感
1 个人 EOA 随时可能 rug，高风险
2 Safe 多签（3/5 等） 团队共管，可接受
3 多签 + Timelock（延迟执行） 每笔操作提前公示，可撤回
4 mint 权限放弃（renounce）+ 治理接管 终态：规则即代码

配合 DAO 治理 一文的 Governor + Timelock 体系，可以把 mint/pause 等管理动作全部纳入「提案 → 投票 → 延迟执行」流程。升级路线要在第一天就写进文档：社区不会因为你今天保留权限而离开，只会因为你永远保留权限且不说明而离开。

12. 后续生态：从「有币」到「有生命」

  • 信息页：官网/文档列出合约地址（各链）、总量、分配与锁仓表、审计报告链接。
  • 浏览器收录：向 Etherscan/Basescan 提交代币信息（logo、官网、社交），防假币冒名。
  • 治理：需要社区决策时，迁移到 ERC20Votes + Governor（快照机制天然防闪电贷投票，见 DAO 文章 §2/§8）。
  • 多链分发：要跨链时优先采用原生发行模型（OFT：一条合约多链部署，而非各链发一份「包装币」），对比见跨链桥一文 §5-6。
  • 持续监控：给大额转账、pause 事件、Owner 操作配告警（免费方案：Tenderly alerts / Dune 看板）。

13. 常见误用与陷阱

陷阱 后果 正确做法
手写 ERC-20 而不用 OZ 溢出/授权竞态漏洞 只做组合与裁剪，不重造轮子
私钥写进代码或 git 资产被扫链机器人瞬间搬空 .env + gitignore；主网用硬件钱包
精度用 number 而非 bigint 大数值精度丢失、铸造量错 脚本一律 10n ** 18n bigint
Owner 一直是个人钱包 被社区视为 rug 风险 部署即多签，路线图写明 Timelock/放弃计划
LP 不锁仓 默认判定 rug，没人敢买 建池即锁（UNCX/Team Finance/Timelock）
忘记 verify 源码 工具标红、无人敢交互 部署后 5 分钟内完成验证
建池滑点全设 0 上主网 被三明治攻击夹 amountMin 设 99% 等合理滑点
承诺「只发这么多」但合约可无限 mint 信任崩塌 Capped 写进代码；放弃 mint 权限并公示 tx
部署前没跑貔貅自检 被标记 honeypot，DEx Screener 拒收 测试网模拟第三方买卖，Token Sniffer 扫描
以为发币=有价值 币价归零 价值来自流动性/用途/共识，三者都要运营
