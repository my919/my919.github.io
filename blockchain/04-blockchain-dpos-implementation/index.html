第四章：区块链代码示例：DPoS 委托权益证明

概念基础

  1. 定义：DPoS（Delegated Proof of Stake，委托权益证明）——持币者投票选出少数代表节点（Top N），由代表轮流生产区块，是 EOS、TRON 等公链采用的模式。
  2. 为什么高效：出块者从「全网矿工竞争 / 全体验证者抽签」收缩为固定的少数代表，轮询顺序可预测，吞吐量显著高于 PoW 与 PoS。
  3. 与 PoS 的差别：PoS 是所有质押者按权重抽签；DPoS 先用投票选出代表，再把出块权轮询分配给代表——在权益之上引入了「选举」这层治理。
  4. 本示例如何模拟：Candidate.Votes 模拟投票结果 → 按票数取 Top N 成为代表 → blockIndex % N 决定当前轮次的出块代表 → 验证出块者是否合法。
  5. 权衡：代表数量少意味着更中心化，需要配合投票更替与罚则来维持去中心化（本示例未展开）。

DPoS 与 PoS / PoW 的区别（本示例）

对比项 PoW PoS DPoS
出块者 算力最强者 质押权重抽签 投票选出的代表轮询
参与人数 任意矿工 验证者 少数代表（如 21 个）
吞吐量 低 中 高（代表固定、轮询可预测）
典型项目 比特币 以太坊 2.0 EOS、TRON

DPoS 核心流程（本示例）：

  1. 持币者给候选人投票（Votes 字段模拟）
  2. 取票数最高的 Top N 成为代表节点
  3. 代表按区块高度轮流生产区块（blockIndex % N）
  4. 全网验证出块者是否为当前轮次代表

DPoS 治理：效率与权力的天平

DPoS 把「谁来出块」从密码学问题变成了政治学问题——效率的提升是真实的，权力的集中也是真实的。

效率侧：为什么 DPoS 快

  1. 出块快：EOS 21 个出块节点、0.5 秒一块，TPS 可达数千——PoW 与 PoS 望尘莫及；
  2. 纠错快：代表作恶，持币者链上改票即可实时罢免，无需硬分叉；
  3. 能耗低：无挖矿环节，能耗可忽略。

权力侧：集中的代价

  1. 半中心化：21~27 个固定节点，信任模型更接近「企业联盟链」；
  2. 贿选与票仓：代表把出块收益返给投票大户换选票，形成固化利益集团；
  3. 投票率低迷：散户不投票，少数鲸鱼决定全部席位归属；
  4. 富人议会循环：当选 → 拿收益 → 买更多票 → 继续当选，席位趋于世袭。

贿选的典型玩法：代表承诺把大部分出块收益按投票比例返还给投票者 → 大户把票押给「返利最高」的代理账户 → 散户托管在交易所的票被「代投」给关联方。治理权就这样完成了市场化定价。

链 代表数 / 出块间隔 治理注记
BitShares 101 见证人 DPoS 概念发源地（2014，Dan Larimer）

治理全流程（含罢免回路）：



flowchart LR
  H[持币者] -->|质押投票| V[投票池]
  V -->|票数 Top N| D[当选代表]
  D -->|按序轮流出块| B[区块链]
  D -->|作恶/掉线| X[改票罢免]
  X -.->|席位重选| V

罢免回路是 DPoS 区别于现实议会选举的关键：改票即时生效，不必等任期结束——前提是投票率足够高、且票没有托管在交易所账户里（Steem 事件的教训）。

DPoS 变体

变体 代表链 特点
LPoS（流动权益证明） Tezos 委托不锁仓、可随时撤回，「烘焙师」自由进出
NPoS（提名权益证明） Polkadot 提名人与验证者共担罚没，投票不再无风险
混合 BFT 新一代公链 DPoS 选代表 + BFT 投票定终，兼顾效率与确定性

三种变体的共同方向：保留「少量代表高出块效率」的同时，用罚没共担和即时退出修复 DPoS 最受诟病的治理惰性。

把投票搬上链：本示例的升级路径

  1. 投票交易上链：Votes 不再是初始化常量，而是累加链上「投票交易」的结果；
  2. Epoch 换届：每 N 个区块重新统计票数、重选代表，模拟真实换届周期：
  1. 押金与处罚：代表须缴押金，出无效块或双签即没收（呼应第三章 Slashing）；
  2. 缺席处理：代表超时不出块则跳过并记录缺席次数，累犯自动除名。

完成这四步，示例就从「轮询演示」升级为「可换届、可问责」的迷你治理系统。
