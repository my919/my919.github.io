1. 概念说明

DApp（去中心化应用） = 智能合约（链上逻辑）+ 前端（链下界面）+ 钱包（用户身份）。

关键差异 vs 传统应用：

维度 传统应用 DApp
后端 中心化服务器 智能合约（公开可验证）
数据 私有数据库 链上公开账本
登录 账号密码 钱包签名
部署 服务器发布 合约上链（不可变）

技术栈选择：Foundry（Rust 写的现代框架）替代 Hardhat/Truffle；wagmi+viem 是当前 React 生态标准；The Graph 解决”合约事件查询慢”的问题。

核心流程：编写合约 → 本地测试（Anvil）→ 部署到测试网 → 前端连接 → 上生产（主网）→ 验证与监控。

9. 典型案例：限量 NFT 铸造（防机器人 + 防重入）

问题背景：项目方发 10000 枚限量 NFT，单价 0.01 ETH。首次开放铸造 10 分钟被机器人脚本批量扫走 8000 枚，普通用户一个没抢到；提款函数又被重入攻击盯上，差点资金受损。

方案：合约层每地址限购 + ReentrancyGuard + 先改状态后转账（CEI）；前端层铸造按钮防连点、先预估 gas；链上层用事件 + The Graph 索引铸造记录。

踩坑点：

  • 只靠前端限制购买数量没用——机器人绕过页面直接调合约，限购必须写在链上。
  • payable 函数不校验 msg.value，0.0001 ETH 也能 mint，等于白送。
  • 提款先转账后改状态，重入攻击一次掏空合约（The DAO 就是这么挂的）。
  • 上线前在 Foundry 写「攻击者合约」用例验证防重入，别指望审计兜住一切。

10. 常见误用与陷阱

坑 现象/后果 解法
把 gas 优化理解成”到处删 require” 省不了几个 gas，反而留下安全漏洞 优化重点放存储：变量打包（uint128 代替 uint256）、calldata 代替 memory、缓存 storage 到 memory
以为链上数据是私密的 把密钥、白名单原文写进合约，链上浏览器直接读走 链上只有公开数据；私密信息放链下（merkle 树存根、签名校验）
单位混淆 ether / wei 1 ETH 写成 1 wei（或相反），金额差 18 个数量级 统一用 0.01 ether 字面量 / 前端 parseEther，禁止裸数字
信任前端校验 机器人绕过页面直接调合约，限购/价格形同虚设 一切业务规则放合约层，前端校验只做体验优化
拿事件当存储 想靠 events 恢复合约状态，节点不保证历史事件可查 链下建索引（The Graph），状态查询用 public 变量 / view 函数
测试网行为等同主网 测试网无 MEV、gas 稳定，上线后被三明治攻击/抢跑 主网前用 fork 测试（forge test --fork-url）模拟真实 MEV 环境
忘记处理链切换 用户钱包停在错误网络，交易发到错误链 wagmi useSwitchChain 自动切链，错误网络时禁用按钮
