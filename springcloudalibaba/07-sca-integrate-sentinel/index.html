第六章：集成 Sentinel：流控、熔断与服务保护

概念基础

Sentinel 是面向分布式服务架构的流量防卫组件，提供流控、熔断降级、系统保护能力：

  1. 为什么需要：微服务链路中，流量突增、下游变慢都可能引发雪崩；Sentinel 以「资源 + 规则」模型对调用做实时统计与控制，在故障扩散前快速失败，保护服务自身。
  2. 接入方式：本仓库通过 Spring Cloud Alibaba Sentinel 集成；Web 接口、Feign 调用、Gateway 路由都会自动被识别为资源，基本无需侵入业务代码。
  3. 控制台（Dashboard）：默认 http://192.168.1.22:30012（K8s NodePort，Pod 内端口 8858），可视化查看资源与监控，并临时下发流控/熔断规则。
  4. 客户端与控制台通信：使用 8719 端口（可 SENTINEL_TRANSPORT_PORT 覆盖）；传输层使用 netty-http，需排除默认的 simple-http。
  5. 规则存放：默认在内存中（重启失效）；生产可通过 spring.cloud.sentinel.datasource 接 Nacos 等实现持久化，本仓库默认未配置。

理解客户端与控制台如何协作，再看整体架构：

与其它组件的关系

  • Gateway：cloud-gateway 使用 Sentinel Gateway 适配，资源名多为路由 ID。
  • Feign：cloud-app 等调用下游时产生独立资源名。
  • Seata / 下单：限流触发 BlockException，与事务回滚无关。

规则类型速查

流控规则（FlowRule）：

阈值类型 说明 适用
QPS 每秒请求数超限即拒绝 常规接口保护
并发线程数 同时在处理的请求数上限 慢调用隔离，防线程池耗尽

流控效果（controlBehavior）：直接拒绝（默认）、Warm Up（冷启动期内缓慢放量，防系统刚启动被冲垮）、匀速排队（漏桶，削峰填谷，适合定时任务突发）。

熔断规则（DegradeRule）：

策略 触发条件 适用
慢调用比例 RT 超阈值且比例达标 下游变慢时自我摘流
异常比例 时间窗内异常占比达标 下游不稳定
异常数 时间窗内异常次数达标 粗粒度兜底

熔断后进入半开探测：放行少量请求试探，成功则闭合恢复，失败继续熔断。三种策略都要求设置统计时长与最小请求数，样本过少时不会触发，避免零星异常误伤。

系统规则：按全局 Load / CPU / RT / 线程数 / 入口 QPS 兜底，是最后一道防线而非主力手段；热点参数规则见下文。

要点：

  • 规则改由 Nacos 推送后，控制台的修改不会写回 Nacos（控制台默认只读数据源）；「修改入口」应统一在 Nacos 或控制台二选一，避免两边漂移。
  • rule-type 对应解析器（flow / degrade / param-flow / system / authority）；groupId 建议用独立 SENTINEL_GROUP 与业务配置分开。
  • Web 资源名形如 POST:/order/place；Gateway 路由的资源名即路由 ID；@SentinelResource 注解的 value 也是资源名。
  • 本仓库默认未配置规则数据源，仍以控制台临时规则为主，上线前按上文接入。

热点参数限流

按参数值限流（如按 userId、商品 ID 防刷单/防热点）：

控制台「热点规则」对 goodsDetail 资源的第 0 个参数配置 QPS，并可为例外项单独放量（如 id=1 的爆款单独 200 QPS，其余 20 QPS）。注意热点规则只对带 @SentinelResource 注解的资源生效，普通 Web URL 资源不支持。

blockHandler 与 fallback 的分工

@SentinelResource 的两个回调容易混淆：

回调 触发时机 典型用途
blockHandler 被 Sentinel 规则拦截（BlockException 及其子类） 返回限流/降级提示
fallback 业务代码抛出异常 业务降级（返回缓存、默认值）

两者方法签名须与原方法一致（blockHandler 末尾追加 BlockException 参数）。只配 fallback 不配 blockHandler，被限流时调用方收到的就是 500 而非友好提示。

与 Gateway 联用

cloud-gateway 引入 Sentinel Gateway 适配后，可对路由 ID 或自定义 API 分组配置流控。规则持久化可接 Nacos（本仓库默认未配规则 DataSource，规则以控制台临时配置为主）。调试时建议先对 单机直连 cloud-order 验证，再在网关上配置 routeId 级规则。

验证

  1. 启动 cloud-order，调用任意接口（如 GET /stock/goods/1 经网关）触发 Sentinel 初始化。
  2. 控制台 机器列表 出现 cloud-order（延迟数十秒属正常）。
  3. 在控制台配置流控规则，压测 POST /order/place 观察是否 Block。

常见问题

Q：控制台看不到客户端？
A：检查 SENTINEL_DASHBOARD 是否为 30012；防火墙放行；客户端是否排除 simple-http 并使用 netty-http；是否已有流量触发 Sentinel。

Q：日志里连 8858 或 wrong port？
A：Nacos 覆盖了 transport；保证 application-sentinel-client.yml 在 import 链最后，dev yml 再写一遍 dashboard。

Q：eager: true 要不要开？
A：本仓库 eager: false，首请求后才注册；调试可改 true 提前连控制台。

Q：Feign 与 Sentinel 资源名？
A：feign.sentinel.enabled=true 时，下游调用会作为独立资源，可在控制台按资源名配规则。
