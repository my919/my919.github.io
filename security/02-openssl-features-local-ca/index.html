第二章：OpenSSL 功能全景与自建局域网 CA 实战

概念基础

  1. OpenSSL 有两层身份：一是命令行工具（生成证书、密钥、加解密、签名等日常操作）；二是底层密码库（libcrypto / libssl，几乎所有软件的加密都靠它：Nginx、Python、Java、curl、安卓、iOS 等）。
  2. 事实标准：90% 的互联网加密通信，底层都在用 OpenSSL；HTTPS、TLS、QUIC、VPN、SSH 全覆盖。
  3. 命令行能做什么：证书体系（生成/查看/转换）、文件加解密、哈希校验、随机密码/密钥、测试 HTTPS 连接、模拟 HTTPS 服务器、签名验签——本章逐条给出命令。
  4. 为什么需要自建 CA：局域网/内网服务（如 https://192.168.1.22）无法从公网 CA 获取证书；自己做根 CA 签发服务器证书并导入设备信任，即可实现浏览器绿标、无不安全警告。
  5. 本章定位：先给出功能全景，再用一条条可复制的命令完成局域网全套可信证书实战。

命令行生成证书、CSR、格式转换等逐步操作见 第一章：OpenSSL 命令行入门与常用操作总览。

进阶：把”玩具 CA”升级为”可管理 CA”

上面的 openssl x509 -req -CAcreateserial 适合一次性签发；长期运营的 CA（要签发几十上百张证书、要能吊销）需要规范化结构。

1. 两种签发方式对比

维度 openssl x509 -req（本文实战） openssl ca（正规 CA）
签发记录 无（只留 .srl 序列号文件） index.txt 数据库：谁签的、何时过期、是否吊销一目了然
证书吊销 不支持 支持 CRL / OCSP
配置 命令行参数 openssl.cnf 集中管理默认策略
适用 个人内网、几台设备 团队内网、物联网设备群、需要审计

2. 规范化 CA 目录结构

目录职责：

路径 作用
private/cakey.pem CA 私钥（chmod 600，泄露=全部证书作废）
cacert.pem CA 证书（分发给各设备导入）
newcerts/ 每签发一张证书自动存一份副本，文件名即序列号
index.txt 签发台账：状态（V有效/R吊销）、过期时间、序列号、主题
crl/ 证书吊销列表

5. 中间 CA：根密钥不进生产

规范做法是根 CA 离线保存，日常签发放到中间 CA：

好处：中间 CA 私钥泄露只需吊销中间 CA 并重签，根 CA 与已导入设备的信任不受影响；浏览器链式验证 服务器 → 中间 → 根 照常工作。签发中间 CA 证书时扩展里写 basicConstraints=critical,CA:TRUE,pathlen:0（pathlen:0 禁止它再签下级 CA）。

本章小结

要点 结论
是工具 命令行生成证书、加密文件、测试 HTTPS
是库 几乎所有软件的加密都靠它，互联网加密的基石
全覆盖 HTTPS、TLS、QUIC、VPN、SSH 全支持
自建 CA 根 CA 自签 → SAN 绑 IP 签发服务器证书 → 设备导入根证书；换 IP 只需改 SAN 重新签发
可管理 CA openssl ca + index.txt 台账 + newcerts/ 归档；吊销走 ca -revoke → ca -gencrl
吊销分发 CRL 有缓存期（默认 30 天）；要实时用 OCSP 在线查询
根密钥安全 根 CA 离线，日常签发用中间 CA（pathlen:0），泄露可单独吊销
