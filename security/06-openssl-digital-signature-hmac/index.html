发表于 2026-05-01 更新于 2026-10-25 分类于 安全 本文字数： 5.3k 阅读时长 ≈ 5 分钟

第六章：OpenSSL 数字签名与 HMAC：完整性、身份与推荐用法

概念基础

  1. 数字签名 = 私钥签名 + 公钥验证：一次性保证完整性（内容未被篡改）、身份认证（签名者身份可信）与不可否认（只有私钥持有者能签出）。
  2. 标准流程：先对消息做哈希（SHA-256，见第三章），再用私钥对摘要签名；验证方用公钥复算比对——这也是「对大数据直接 RSA 签名」是错误做法的原因。
  3. HMAC 是对称认证：双方共享同一 secret，用 HMAC-SHA256 计算带密钥的摘要；快、实现简单，但双方都能生成，因此不可否认。
  4. 怎么选：公开分发场景（软件发布、证书、JWT）→ 数字签名；双方已有共享密钥的场景（API / Webhook 鉴权）→ HMAC。
  5. 常见坑：对明文直接 RSA 签名大数据、HMAC 密钥硬编码进代码、验签时不检查证书链——本章末尾「常见错误」逐条纠正。

场景选型

场景 推荐 说明
软件发布、固件、JWT（RS256/ES256） RSA-PSS / ECDSA / Ed25519 + SHA-256 公钥可公开分发
TLS 证书链 CA 私钥签名 + SHA-256 见 第一章：OpenSSL 命令行入门与常用操作总览
API 请求鉴权（双方已有密钥） HMAC-SHA256 Webhook、AWS Signature V4 同类思路
口令验证存储 不适用裸 HMAC 用 PBKDF2 / Argon2 见 第七章：OpenSSL 密钥派生与随机数：PBKDF2、rand 与推荐用法

二、HMAC（对称认证）

特点

  • 双方共享 secret key；无公钥 Infrastructure。
  • 算法：HMAC-SHA256（推荐）、HMAC-SHA512；避免 HMAC-MD5。

实战：Webhook 鉴权（带时间戳防重放）

GitHub/Stripe 等 Webhook 的标准做法——对「时间戳 + 请求体」算 HMAC，接收方双校验签名与时效：

常数时间比对是硬要求：bash 的 [[ a == b ]] 会短路泄露时序；代码里用 hmac.compare_digest（Python）、crypto.timingSafeEqual（Node）等专用函数。

与数字签名对比

HMAC 数字签名
密钥 共享秘密 公钥 / 私钥对
适用 服务间 API、会话 token 公开分发软件、证书
抵赖 双方都能算 仅私钥持有者能签
性能 极快（µs 级） 慢 2~4 个数量级
分发 需预共享 公钥可公开

JWT 与签名的关系

JWT 的 alg 字段本质是本章算法的直接映射：

JWT alg 底层 分类
HS256 HMAC-SHA256 对称（签发与验证同密钥）
RS256 RSA PKCS#1 v1.5 + SHA-256 非对称
PS256 RSA-PSS + SHA-256 非对称（推荐替代 RS256）
ES256 ECDSA P-256 + SHA-256 非对称
EdDSA Ed25519 非对称（现代首选）

微服务体系推荐 EdDSA / ES256：网关只需公钥验签，私钥集中在签发服务，泄露面最小；坚决禁用 alg=none 与不校验 alg 的库配置。

五、常见错误

错误 正确做法
对明文直接 RSA 签名大数据 先 SHA-256 再签；或签 digest
HMAC 密钥硬编码在代码 环境变量 / KMS
验签不检查证书链 信任 CA + hostname + 有效期
用字符串相等比对 MAC 常数时间比较（compare_digest 等）
签名不覆盖时间戳 加 timestamp 字段防重放
RSA-PSS 参数两端不一致 显式统一 -sigopt
用 SHA-1 做签名摘要 碰撞已破，SHA-256 起步
ECDSA 随机数复用（k 泄露） 换 Ed25519（确定性签名天然免疫）

本章小结

要点 结论
签名算法 新系统 Ed25519；TLS 证书 ECDSA P-256；互操作 RSA-PSS + SHA-256；DSA 勿用
命令要点 dgst -sha256 -sign 签名、-verify 验签；RSA-PSS 显式 -sigopt 且两端一致
HMAC dgst -sha256 -hmac "$KEY"；密钥走环境变量 / KMS；比对必须常数时间；带时间戳防重放
性能 签名选 Ed25519/ECDSA；验签 RSA 最快；用 openssl speed 实测
场景区分 公开分发 → 签名；共享密钥 API 鉴权 → HMAC；口令存储 → PBKDF2（见第七章）
后量子 ML-DSA 已进 OpenSSL 3.5；长寿命签名可评估混合部署
