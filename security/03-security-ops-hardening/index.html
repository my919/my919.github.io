安全运维与生产加固

发表于 2026-09-02 更新于 2026-10-29 分类于 安全 本文字数： 8.9k 阅读时长 ≈ 8 分钟

安全运维与生产加固

概念基础

  1. 最小暴露面：线上系统应只暴露完成业务必需的端口、接口、路径与依赖。能内网访问的不放公网，能用 VPN 的不开公网端口，能关的调试端点一律关闭。暴露面越小，攻击者可试探的入口越少，运维与监控也越聚焦。
  2. 纵深防御：代码层防护之外，还需在网络（防火墙/WAF）、传输（TLS）、存储（加密 Secret）、主机（基线/审计）、容器（镜像扫描/Pod 策略）各层叠加控制。任一层被攻破，下一层仍能拦截，避免”单点失守即全线失守”。
  3. 安全基线：操作系统、中间件、框架都有官方安全配置基线（如 CIS Benchmarks）：禁用 root 登录、关闭无用服务、设文件最小权限、删除默认账号。基线是”已知良好”的起点，新机器上线即套用，定期漂移检测纠正偏离。
  4. 密钥管理：密钥（数据库口令、API Key、证书私钥、加密主密钥）是系统的命门，应做到生成强、存储加密、轮换勤、访问审计、泄露可吊销。禁止硬编码进代码或明文入 Git，应统一由 Vault/KMS/Sealed Secrets 等密钥管理服务托管。
  5. 审计日志：可观测才有响应。关键操作（登录、越权访问、密钥读取、配置变更、特权命令）必须记录谁、何时、做了什么、结果如何，并集中收集、防篡改、设告警。日志是事后取证与实时检测的依据，无审计等于”裸奔”。

本章是安全系列的收官篇。延伸阅读：第三章：Nginx HTTPS 与安全 提供反向代理侧的 HTTPS 配置，OpenSSL 对称加密 提供证书与密钥的命令行生成实操。

一、HTTPS 与 TLS 加固

1. 证书管理（Let’s Encrypt）

2. TLS 1.2/1.3 配置

要点：ECDHE 前向保密（即便私钥泄露，历史流量也无法解密）、禁用旧协议、HSTS 防降级。Nginx 侧完整配置见 第三章：Nginx HTTPS 与安全。

3. HSTS 与证书续期

  • HSTS：通过响应头告诉浏览器”本站以后一律走 HTTPS”，有效期 max-age 建议 ≥ 1 年，并逐步推进 preload 列表，彻底防中间人首次降级。
  • 自动续期：Let’s Encrypt 证书 90 天过期，靠 certbot renew + cron/systemd timer 自动续，避免”凌晨证书过期全站不可用”事故。

二、网络安全加固

1. 防火墙（iptables/nftables）

新系统建议用 nftables（语法更统一、性能更好），逻辑与 iptables 一致：默认 drop + 显式放行。

firewalld vs nftables vs iptables（Rocky 9/10 视角）：

工具 定位 何时用
iptables 旧语法前端（RHEL9 起底层已转 nft 内核） 兼容老脚本，不再新写
nftables 内核现行框架，规则原子加载、集合类型强 直接写规则的推荐方式
firewalld 区域化动态管理（trusted/public/dmz），firewall-cmd 热更新不断线 多网卡多区域的服务器，运维友好

2. WAF 规则

WAF（Web 应用防火墙）在 HTTP 层拦截注入、扫描、滥用。ModSecurity + OWASP CRS 是开源标配：

按业务设为 DetectionOnly（仅记录）观察一段周期，确认无误杀再切 On（阻断）。

3. 端口最小化与堡垒机

  • 仅对外暴露 443（必要时 80）；管理端口（SSH、监控、DB）一律内网或 VPN。
  • SSH 禁用密码登录、改非默认端口、限制来源、用堡垒机（跳板）集中审计操作。

sshd_config 加固清单（/etc/ssh/sshd_config，改完 sshd -t 校验再 systemctl reload sshd）：

配套 fail2ban（sudo dnf install -y fail2ban）按失败次数临时封 IP，作为白名单之外的兜底。

4. VPN 与网络分段

通过 VPN/堡垒机进入管理网络，业务网段与办公网段隔离，DMZ 与内网用防火墙隔离。一旦某主机被攻破，分段可显著拖慢横向移动。

1. 环境变量 vs 密钥管理服务

环境变量简单但会泄露：可被 env、/proc/PID/environ、子进程继承、容器 inspect 看到。生产应使用专业密钥管理服务：

2. Sealed Secrets（K8s GitOps 场景）

明文 K8s Secret 不能入 Git；Sealed Secrets 用集群公钥加密成 SealedSecret，可安全提交，仅在集群内解密：

3. 密钥轮换

  • 定期轮换（如 90 天），密钥泄露或人员离职立即轮换。
  • 用双密钥并行（新旧同时有效一段窗口）实现无中断轮换。
  • 主密钥加密数据密钥（信封加密），轮换只换数据密钥，不必重加密全量数据。

证书与密钥的命令行生成、签名验签可参考 OpenSSL 对称加密。

五、安全审计与应急响应

1. 日志审计（auditd）

auditd 深入：监控敏感命令执行（-w 只管文件，抓命令用 -a 系统调用规则）：

注意：-a 型规则默认重启丢失，持久化写入 /etc/audit/rules.d/hardening.rules 后 augenrules --load；execve 全量记录量大，生产建议限定目录或仅保留特权命令监控。

2. 漏洞与基线扫描（上线前/定期）

工具 类型 典型用法
Trivy 镜像 + IaC + 主机文件系统 trivy rootfs / 扫整台服务器的已知 CVE
OpenVAS / Greenbone 网络漏洞扫描器 定期从外部扫主机开放端口与服务版本漏洞
Lynis 主机加固体检 lynis audit system，输出可逐项整改的 hardening 建议
OpenSCAP CIS 基线合规 见下文「六、CIS 基线与漂移检测」

3. 入侵检测

  • HIDS：主机入侵检测（如 Wazuh/AIDE），比对关键文件指纹，发现篡改告警。
  • NIDS：网络入侵检测（如 Suricata），基于规则识别异常流量。
  • 日志告警：登录失败突增、异地登录、特权命令、大流量外传等设阈值告警，接入告警平台。

4. 应急响应流程

阶段 关键动作 产出
准备 建预案、备工具、定值守 应急手册、联系人树
检测 告警/上报触发，初判范围 事件单、影响评估
遏制 隔离主机、封禁 IP、停服 止损，避免扩散
根除 清后门、删恶意账号、补漏洞 消除攻击路径
恢复 验证后恢复服务、加强监控 业务回归
复盘 写根因与改进项、落地修复 事后报告、整改清单

铁律：遏制前不要轻易重启/重装，否则证据丢失难以根因；优先取证后处置，保留内存/磁盘镜像。

六、CIS 基线与漂移检测

CIS Benchmarks 是业界公认的主机/组件安全基线（Rocky Linux 9/10、Nginx、Docker、Kubernetes 均有对应文档），每条规则给出”为什么 + 怎么查 + 怎么改”。手工逐条核对不现实，用 OpenSCAP 自动化：

报告中标红（fail）的条目逐条整改；其中自动化修复（Ansible/Bash 修复脚本）可随扫描一起生成：

漂移检测：基线不是一次性动作。把扫描做成 systemd timer 每周跑，结果 diff 与上次比对——新出现的 fail 项即”配置漂移”（有人改了配置或装了新软件），触发告警并回溯变更记录。

简化版做法：不想上 SCAP 的话，先用 Lynis（上节）拿 hardening 分数起步，再逐步引入 CIS 全量基线。

常见避坑

坑 现象 正确做法
还开 TLS 1.0/1.1 被降级攻击、浏览器报不安全 仅启用 TLS 1.2/1.3
证书不设自动续期 凌晨过期全站不可用 cron/systemd timer + dry-run 验证
SSH 开公网 + 密码 被爆破 仅内网/堡垒机 + 密钥登录
Secret 明文入 Git 仓库泄露即凭据泄露 Sealed Secrets/Vault，加 pre-commit 扫描
容器以 root 运行 逃逸后权限大 runAsNonRoot + readOnlyRootFilesystem
不扫镜像就上线 带已知漏洞进生产 CI 阻断 HIGH/CRITICAL
NetworkPolicy 不设默认拒绝 Pod 任意互通 默认 deny + 最小白名单
关键文件无审计 被改无人知 auditd 监控 passwd/sudoers
应急时先重启 后门与证据丢失 先取证后处置
只依赖 WAF 业务逻辑漏洞不拦 WAF 是补充，非代码防护替代
日志存本机 被入侵即清空 集中收集、防篡改、只追加
主密钥不轮换 长期暴露风险 定期轮换 + 信封加密
SSH 密码登录 + root 直连 被爆破后直达最高权限 PasswordAuthentication no + PermitRootLogin no + fail2ban
基线”凭感觉” 各机器配置参差、无人知晓偏离 CIS/OpenSCAP 定期扫描 + 漂移比对
auditd 规则不落盘 重启后监控全失效 写入 /etc/audit/rules.d/ 并 augenrules --load

本章小结

要点 结论
最小暴露面 仅暴露必需端口/接口，管理面走内网/VPN
TLS 加固 仅 TLS 1.2/1.3 + ECDHE + HSTS + 自动续期
密钥管理 不入 Git，用 Vault/Sealed Secrets，定期轮换
容器安全 镜像扫描 + restricted Pod + RBAC + NetworkPolicy
审计日志 关键操作可追溯，集中收集防篡改；auditd 规则落盘 /etc/audit/rules.d/
漏洞扫描 Trivy 扫主机/镜像，Lynis 体检，OpenSCAP 对齐 CIS 基线并做漂移检测
SSH 加固 禁密码、禁 root、白名单、限来源，fail2ban 兜底
应急响应 准备→检测→遏制→根除→恢复→复盘
纵深防御 多层叠加，单点失效不致全盘失守
基线与漂移 CIS 基线起步，定期检测纠正偏离

安全运维是代码层防护的兜底。Web 认证授权基础详见 第一章：Web 安全与认证授权，接口层注入与漏洞防护详见 第二章：API 安全与漏洞防护。此外，HTTPS 在 Nginx 侧的完整落地见 第三章：Nginx HTTPS 与安全，证书与密钥的命令行生成见 OpenSSL 对称加密。至此，”设计—编码—运维”三章闭环完成，安全没有终点，持续加固与复盘才是常态。
