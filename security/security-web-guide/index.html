9. 典型案例：OWASP Top 10 修复实战

9.1 问题背景

某电商 App 被渗透测试报告命中 5 类 OWASP Top 10：水平越权（A01）、手机号明文存储（A02）、SQL 注入（A03）、生产环境回显堆栈（A05）、无 MFA 撞库成功（A07），要求 60 天内闭环复测通过。

9.2 解决方案

按「高危先行」排期：第一周止血（注入参数化 + 关闭调试信息 + 撤销长期 token），第二个月补认证与加密（MFA + argon2id 迁移），持续性防护进 CI（密钥扫描 + 依赖扫描 + SAST），每个漏洞修复后由测试方复测验收。

9.4 踩坑点

  • CSP 直接全量上线把第三方埋点全拦了，先 report-only 观察两周再强制生效
  • 越权修复只隐藏了前端按钮，渗透直接打接口照样过——鉴权必须做在服务端
  • argon2id 迁移没兼容旧 bcrypt 哈希，存量用户全被登出，改为「登录时透明重哈希」渐进迁移
  • 修复完没有复测环节，3 个漏洞修复姿势不对被测试方打回，补上复测验收流程

10. 常见误用与陷阱

坑 现象/后果 解法
对称加密用 ECB 模式 相同明文块密文相同，结构泄露 AES-256-GCM，nonce 唯一
密钥硬编码进代码 Git 历史永久泄露，翻历史即沦陷 Vault/KMS，gitleaks CI 拦截
只做前端鉴权 直接调 API 即越权 服务端逐请求策略引擎鉴权
token 长期有效不轮换 泄露后无法止损 15min access + refresh 轮换 + 吊销
错误信息直接回显 堆栈/SQL 报错给攻击者递地图 统一错误码，详情留服务端日志
依赖扫描跑一次就完 新 CVE 持续曝出无人知 CI 门禁 + 每日定时扫描
