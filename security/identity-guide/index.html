9. 典型案例：OIDC 登录打通

9.1 问题背景

公司 5 个子系统各有账号密码，用户要记 5 套凭据，离职回收靠 Excel 核对。目标：统一 OIDC Provider 实现一次登录全站通行，30 天完成切换，存量密码用户渐进迁移 Passkey。

9.2 解决方案

新建 IdP 作为唯一签发方，各子系统改造为 OIDC 客户端：Web 端授权码 + PKCE，后端只验 JWT 不存密码；令牌进服务端会话（BFF 模式）；登出统一走 end_session + back-channel；灰度期新旧登录并存，按部门切流。

9.4 踩坑点

  • token 存 localStorage 被 XSS 脚本整包带走，改为内存保存 + HttpOnly Cookie 的 BFF 模式
  • refresh_token 不轮换，泄露后无限续期；开启轮换 + 重用检测（旧令牌再现即吊销整个链）
  • IdP 轮换签名密钥后所有请求 401，验签改为按 kid 缓存、未命中自动重拉 JWKS
  • redirect_uri 尾斜杠不一致报 mismatch，两端配置逐字对齐
  • 服务器时钟漂移 90s 导致 nbf 校验偶发失败，加 60s leeway 并上 NTP 监控

10. 常见误用与陷阱

坑 现象/后果 解法
token 存 localStorage XSS 一偷一个准 内存 + HttpOnly Cookie（BFF 模式）
缺 state/nonce 校验 回调伪造、code 重放 随机 state+nonce，会话比对后即焚
刷新令牌不轮换 旧 refresh_token 可长期重放 每次刷新换新 + 重用检测吊销
JWKS 缓存不更新 IdP 换密钥后全站 401 按 kid 查缓存，未命中重拉
忽略时钟偏移 nbf/exp 校验偶发失败 允许 ±60s leeway
登出只清前端 IdP 会话仍在，秒回登录 跳 end_session + back-channel

总结

2026 身份认证趋势

趋势 说明
Passkey 主流化 操作系统 + 浏览器全面支持跨设备 Passkey
Zero Trust 常态化 持续认证 + 自适应策略成为标配
密码消亡 新应用默认无密码，遗留系统渐进迁移
Cedar / ReBAC 细粒度授权模型替代传统 RBAC
去中心化身份 DID / Verifiable Credentials 开始落地
合规驱动 EU AI Act / SOC2 推动认证审计标准化
