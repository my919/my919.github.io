第三章：OpenSSL 哈希算法：SHA-256、SHA-3 与推荐用法

概念基础

  1. 哈希（Hash）是单向函数：任意长度输入 → 固定长度摘要（SHA-256 输出 256 bit），不可逆——无法从摘要还原原文。
  2. 三大特性：确定性（同输入必得同输出）、雪崩效应（改动 1 bit，摘要面目全非）、抗碰撞性（极难找到两个不同输入对应同一摘要）。
  3. 为什么需要：完整性校验（下载包比对、防篡改）、签名输入（先哈希再签名，见第六章）、口令派生（加盐迭代，见第七章）、区块链 Merkle 树等。
  4. 哈希 ≠ 加密：哈希不可逆、无密钥，用于完整性与指纹；对称加密可逆、有密钥，用于保密性（本章末尾有对照表）。
  5. 选型一句话：新系统一律 SHA-256 / SHA-512，需要算法多样性时上 SHA-3；MD5、SHA-1 仅用于遗留系统兼容。

算法选型（推荐）

场景 推荐 避免
文件完整性校验、软件发布 SHA-256、SHA-512 MD5、SHA-1
密码存储 Argon2 / bcrypt（应用层库）+ 盐；OpenSSL 侧用 PBKDF2-HMAC-SHA256 见 第七章：OpenSSL 密钥派生与随机数：PBKDF2、rand 与推荐用法 裸 SHA-256(password)
证书/CSR 签名摘要 SHA-256 SHA-1
长数据流式哈希 SHA-256 —
新标准/长摘要需求 SHA-3-256 — 


flowchart LR
  Data[文件或消息] --> H[SHA-256 / SHA-512]
  H --> Digest[固定长度摘要 hex/base64]
  Digest --> Use[校验 / 签名输入 / 区块链 Merkle 等]

一、常见算法特点

1. SHA-2 系列（首选）

算法 输出长度 特点
SHA-256 256 bit 默认推荐；TLS、Git、证书、区块链广泛使用
SHA-384 384 bit 更高安全余量
SHA-512 512 bit 大文件、64 位 CPU 上常更快

2. SHA-3 系列

基于 Keccak，与 SHA-2 结构不同；适合需要与 SHA-2 算法多样性的场景（合规、新标准）。

3. SHA-1 / MD5（仅兼容）

算法 状态 说明
SHA-1 已破碰撞 勿用于签名、证书；老 Git 对象可能仍见
MD5 已破碰撞 仅文件非安全校验或遗留系统

4. BLAKE2（OpenSSL 3.x）

高性能现代哈希；若本机 openssl list -digest-algorithms 含 BLAKE2b512 可用：

BLAKE2 在纯软件实现下通常快于 SHA-2 系列，且设计上自带抗长度扩展特性，适合日志指纹、去重存储等高性能场景。

5. 国密 SM3（合规场景）

SM3 是中国国家密码管理局发布的杂凑算法（GM/T 0004），输出 256 bit，结构与 SHA-256 同属 Merkle–Damgård 家族，常配合 SM2 签名、SM4 加密 出现在等保、金融、政务合规场景中。

选型建议：仅在有明确国密合规要求时启用 SM3；面向国际互操作的系统仍以 SHA-2 / SHA-3 为主。

5. 性能基准对比（openssl speed）

不同硬件上哈希吞吐差异巨大，选型前用 openssl speed 实测本机性能（OpenSSL 3.5 LTS，x86_64 开启 SHA-NI 的参考量级）：

算法 1KB 块参考吞吐 说明
SHA-256 高（SHA-NI 加速） 通用默认
SHA-512 64 位平台常高于 SHA-256 内部按 64 位字运算
SHA-3-256 明显低于 SHA-256 无专用指令集时
BLAKE2b512 常优于 SHA-512 纯软件实现友好

结论：有 SHA-NI / ARMv8 SHA 扩展的 CPU 上 SHA-256 性价比最高；没有硬件加速时 SHA-512 与 BLAKE2 反而更快。

三、常见误用与避坑

1. 误用场景对照表

误用 风险 正确做法
用 MD5/SHA-1 做签名校验 碰撞已破，可伪造同摘要文件 SHA-256 / SHA-512
裸 SHA-256(password) 存口令 彩虹表 + GPU 秒破 PBKDF2 / Argon2（见第七章）
SHA-256(secret || data) 当 MAC 长度扩展攻击 用 HMAC-SHA256（见第六章）
把 Base64 当哈希 / 加密 可逆编码，无安全性 只用于传输编码
大文件一次性读入内存哈希 OOM 流式分块（命令行天然流式；代码用 EVP_DigestUpdate）

五、与「加密」的区别

哈希 对称加密
可逆 否 是（有密钥）

OpenSSL 命令 dgst enc

Base64（openssl base64）只是编码，不是哈希也不是加密。

3. TLS 1.3 中的哈希分工

用途 算法
握手 transcript 摘要 SHA-256 / SHA-384（随套件）
证书签名摘要 SHA-256 起步，禁止 SHA-1
HKDF 派生流量密钥 SHA-256 / SHA-384
记录层完整性 由 AEAD 的 Auth Tag 承担（不再需要单独 HMAC）

这就是为什么 TLS 1.3 套件名里直接写哈希算法（如 TLS_AES_256_GCM_SHA384）——哈希已从「可协商选项」变成「与套件绑定的固定组件」。
